# 扫雷小队 · 开发文档

组队扫雷迷宫竞速：最多 5 支小队、每队最多 5 人从各自入口进入迷宫，扫描迷雾、标记并排除地雷，
抢先抵达右侧出口。支持单人 / 本地双人，其余队员与对手由 AI 接管，赛后可倍速回放复盘。

## 分层约定

依赖只允许向下，无循环引用：

```
core → world → sim → render/ui → input → main
```

- `core/config.js` 是**唯一**的可调数值来源（网格、配色、按键、时序、采样率），其它模块不得硬编码同类常量。
- `world/` 只负责「造世界」：迷宫、地雷、队伍容器（每队一份 known / fog / trail 位图）、实体、碰撞与寻路。
- `sim/` 推进一切规则。`stepMatch(dt)` 是「对局进行中」的一步，被正式对局与菜单演示局共用；
  `update(dt)` 额外处理开局倒计时并返回 `true` 表示本局结束，由 `main.js` 转交 `ui/flow.endGame()`——
  **模拟层不依赖界面层**。
- `render/` 只读传入的 `scene`（实时对局传 `game`，回放传回放场景），不产生任何游戏副作用；
  视野与路径合成在渲染前由 `sim/vision.js` 计算。
- `ui/result.js` 只把数据画成 DOM，按钮回调节由 `ui/flow.js` 注入，避免 UI 内部互相引用成环。

## 核心规则

| 机制 | 说明 |
| --- | --- |
| 规模 | 2–5 支队伍 × 每队 1–5 人（同场最多 25 名角色） |
| 扫描 | 按一下动作键，0.5 秒出结果，半径 2 格，把圈内格子标记为已知安全 / 已知有雷 |
| 排雷 | 扫描完成后继续按住 ≥0.5 秒自动开始，耗时 2 秒，**中途松开即取消** |
| 地雷 | 80% 即炸，20% 为 1 秒延迟雷；爆炸波及中心 + 上下左右四格 |
| 爆炸 | 清除波及格上的地雷，并同步所有队伍的认知——「用一条命换一片已知安全区」 |
| 倒地 | 5 秒后原地复活，2.5 秒无敌，路线重新规划 |
| 路径 | 按队伍记录，**永不消失**；画面上只呈现玩家所属队伍走过的路径（每格按队伍上色） |
| 结算 | 首个到达后进入 60 秒倒计时；队伍成绩 = 队员用时之和，越小越靠前 |
| 旗帜 | 数量 = 队伍数，全图可见；每面让该队**每人**最终用时 −`FLAG_BONUS`(5) 秒 |
| 排雷 | 每排除一颗雷，该队**每人**最终用时 −`DEFUSE_BONUS`(1) 秒 |
| 减秒 | 两项都按**队伍总数**算（不是个人），在 `sim/scoring.js` 里统一折算，不改动实时计时 |
| 视野 | 画面只呈现玩家所属队伍看到的内容；无真人玩家时迷雾拉满 |

## 录像与回放

- `sim/recorder.js`：对局进行中以 30Hz 采样实体状态、5Hz 采样地形快照（已知信息 / 迷雾 / 路径）。
  采样必须发生在 `render()` 之后，此时 `unionKnown / displayFog / displayTrail` 才是本帧的值。
  帧数上限 `REPLAY_MAX_FRAMES` 防止超长局撑爆内存。
- `sim/replay.js`：只做数据——播放头推进、倍速、`seek()`、二分定位与线性插值，
  输出与 `game` 字段对齐的 `scene`，渲染层无需区分实时 / 回放。
- `ui/replay.js`：**独立回放页**（`openReplay / closeReplay / tickReplay / isReplayOpen`）——
  画布 + 控制条（播放暂停、0.5×~4× 倍速、±2 秒快进退、进度拖拽、时间显示），
  快捷键 `空格` 播放暂停、`←/→` 快进退、`ESC` 返回；播完自动循环，点画布也能暂停。
  退出去向由 `ui/flow.js` 注入，回放页本身不知道「结算」的存在。
- 进入回放时收起结算层、切到 `#replayScreen`；返回时把结算层放回来，DOM 不重建。
- 主循环每帧 `tickReplay(dt)` 推进播放头并重绘；回放页打开时跳过对局画布的绘制。

## 画布分辨率（放大不糊）

两套尺寸要分清：

- **逻辑尺寸**恒为 `CW × CH`（912×432），所有绘制代码按逻辑坐标书写，不关心屏幕多大。
- **位图尺寸** = 显示尺寸 × DPR（`canvas.width/height`）。

把位图固定在 912×432、再用 CSS 拉到 1896 宽，本质是把小位图插值放大 → 糊。
正确做法是 `syncResolution(cv)` 把位图分辨率提到「显示宽度 × DPR」，
再由 `render()` 开头 `ctx.setTransform(s,0,0,s,0,0)`（`s = canvas.width / CW`）把逻辑坐标映射到设备像素：
矩形、圆弧、渐变、文字全部按高分辨率重新栅格化，放大后依然锐利。

- DPR 上限 `MAX_DPR = 2`；位图总像素上限 `MAX_BACKING_PX = 8e6`，
  4K / 带鱼屏上按比例降采样，避免每帧填充量拖垮帧率（1080p 通常不触发，仍是满分辨率）。
- 因此**不要**给对局 / 回放画布加 `image-rendering:pixelated`（只在位图确实被放大时才有意义）；
  菜单背景画布是被 CSS `object-fit:cover` 拉满屏幕的，保留 pixelated + 位图 × DPR。
- 菜单背景画布用 `setResolutionScale(cv, dpr())` 单独设置；窗口 resize 时重算。

## 布局适配（等比铺满可视区）

`js/ui/fit.js` 负责让对局 / 回放的内容「按原始比例放大到刚好铺满屏幕」，不拉伸也不留大片空白：

1. 量出**围栏高度** = `wrap.offsetHeight - canvas.offsetHeight`（顶栏 + HUD + 提示 / 回放的头 + 控制条，含间距）；
2. `scale = min((可视宽 - 24) / CW, (可视高 - 24 - 围栏高) / CH)`，取整后写回 `wrap.style.width`；
3. 画布是 `width:100%; height:auto`，高度按 912:432 原始比例跟随，**顶栏 / HUD / 提示与画布同宽**，整体作为一个单元缩放。

- 宽度变化会让提示行与队伍卡片换行、围栏高度也变，所以**迭代 3 次收敛**。
- 开局时 HUD 还是空的，此时量不准：`flow.startGame()` 只打 `requestFit()` 标记，
  主循环在第一帧 `renderHUD()` 之后才真正测量（`consumeFit()`）。
- `window.resize` → `fitAll()`；回放页打开时也调一次 `fitReplayStage()`。
- 不可见（`offsetParent` 为空）时直接跳过，`display:none` 下量出来的高度没有意义。
- 下限 320px 宽；回放页另有 CSS `max-width:1500px` 兜底。

## 主菜单背景演示局

`sim/demo.js` 用全 AI 配置跑一局当作动态壁纸：复用真实的世界构建与 `stepMatch`，
构建前后临时换回 `settings`（避免污染玩家在选项里选的设定），
视野合成走 `vision.js` 的 demo 分支（取 0 号队认知 + 迷雾压暗），到点自动重开。
画布由 `body.at-menu` 类点亮，CSS 做透明化（`opacity:.3`）、模糊（`blur(3px)`）与暗角。

## 结算统计

- 概览小卡：总时长、到达人数、排除地雷（−Ns）、扫描次数、倒地次数、夺旗数（−Ns）、**全队总减秒**、迷宫探索度。
- **称号**：`assignTitles()` 按「最值得说道的一项」给每人发一个，顺序即优先级——
  ⚡闪电先锋（最先到达）→ 🎏夺旗王 → 🧨拆弹专家 → 📡侦察尖兵 → 💥雷区硬汉 → 🛡零失误 → 👣远征者 → 🏁完赛者 → 🌫迷途者。
  允许并列，标在角色名后面（表格里是金色徽章，柱状图上是柱底小字，>12 人时柱子上的隐藏）。
- 柱状图：真人玩家用 45° 斜条纹区分（P1 金 / P2 粉），AI 用队伍纯色渐变；
  冠军队伍与全场最快的柱子带闪烁描边。
- 队伍排名：到达人数 → 总用时排序，副行给出「原始 − 减秒 = 总成绩」。
- 完整统计表：名次 / 角色（含称号）/ 队伍 / 分工 / **原始** / **减秒** / **最终用时** / 状态 / 排雷 / 扫描 / 倒地 / 夺旗 / 路程。
- **用时公式**：表格上方一张公式卡写清 `最终 = max(0, 原始 − 🎏×5s − 🧨×1s)` 与三条规则；
  点任意一行展开该角色的完整算式（`64.35 − 🎏2×5 − 🧨1×1 = 53.35`）、每一项减秒的原因与本人贡献，
  以及「未到达按总时长计 / 减到负数按 0 计」的说明；「展开全部公式」一键切换。
- 底部三个按钮：`🎞 观看回放`（无录像时禁用）→ 独立回放页、`再来一局`、`返回主菜单`。
- **两个 tab**：`⏱ 用时 · 排名`（柱状图独占一整行 + 队伍排名在下）与 `📊 完整统计`，
  切换只是给 `.tab-page` 加 `active`，DOM 不重建。柱状图独占一行是为了解决人多时横轴标签挤成一团。

### 自适应

- 尺寸一律用 `clamp()` 随视口缩放，卡片网格用 `repeat(auto-fit, minmax(min(100%,320px), 1fr))`：
  宽屏两栏、窄屏自动堆叠，320px 窗口也不会横向溢出。
- 遮罩层用 `align-items:flex-start` + 面板 `margin:auto`，内容超高时顶部不会被裁切（flex 居中 + overflow 的经典坑）。
- 人数 > 12 时柱状图进入 `dense` 模式：隐掉次要文字，只保留真人标签，柱子不会被挤成一团。
- **面板不超过一屏**：`.result-panel` 是 flex 列且 `max-height:calc(100dvh - 32px)`，
  头部（标题 + 冠军 + 概览卡）`flex:0 0 auto` 固定在顶部、底部按钮区同样固定在底部，
  只有中间的 `.result-scroll` 滚动；矮屏（≤620px / ≤480px）逐级隐掉概览卡与冠军行。
- **完整统计 tab 不外层滚动**：切到该 tab 时给面板加 `.stats-mode`——`.result-scroll` 变 `overflow:hidden`，
  表格卡 `flex:1`、`.table-wrap` 的 `max-height` 解除，高度全部让给表格，**只有表格内部滚**
  （表头 `position:sticky` 依旧吸顶）。切回「用时·排名」时移除该类，恢复外层滚动。
  矮屏下公式卡逐级隐掉规则列表与展开按钮，保证表格有高度。

## AI 决策优先级

0. **有限救援**：只救同队；每个倒地者最多一名救援者（`downed.rescuer` 双向引用）；
   半径 `RESCUE_RADIUS` 内、守候 `RESCUE_MAX_TIME` 秒后放弃并进入冷却。
   （旧逻辑任何人倒地附近所有角色都会涌过去，队形瞬间散掉——已修。）
1. **共享视野 / 新情报反应**：`known` 位图是**队伍级**的，谁扫出来全队都知道。
   `team.minesFound` 当版本号，AI 存 `intelVersion`，一有新雷就检查自己路径前
   `MINE_LOOKAHEAD + 2` 格有没有被挡，挡了立刻重算——否则会照着几秒前缓存的旧路径一脚踩上去。
2. **角色目标**（`computeGoal`，结果缓存 0.6 秒，避免每帧跑 A*）：
   `runner` 直奔出口；`flagRunner` 选「绕路 ≤ `FLAG_MAX_DETOUR` 格」的最近旗
   （旗上带 `claim`，同队不会两人抢同一面）；`defuser` 清理附近 `DEFUSER_SEARCH_R` 格内的已知雷
   （清够 `DEFUSER_MAX_JOBS` 颗或有人到达后转回冲刺）。
2. **角色目标**（`computeGoal`，结果缓存 0.6 秒，避免每帧跑 A*）：
   `runner` 直奔出口；`flagRunner` 选「绕路 ≤ `FLAG_MAX_DETOUR` 格」的最近旗
   （旗上带 `claim`，同队不会两人抢同一面）；`defuser` 清理附近 `DEFUSER_SEARCH_R` 格内的已知雷
   （清够 `DEFUSER_MAX_JOBS` 颗或有人到达后转回冲刺）。
3. **路线 / 排雷 vs 绕路**：`mineAhead()` 前瞻 `MINE_LOOKAHEAD` 格找已知雷（只看 `path[0]` 来不及），
   按 `mineLockKey = "x,y,adj|far"` 对同一颗雷的同一阶段只决策一次，避免站着反复掷骰。
   - 雷在几格外：直接重算绕开它的路径；
   - 雷就在脚边：把两边都换算成**秒**再比——排雷 = 靠近时间 + `DEFUSE_DURATION`；
     绕路 = 额外格数 × `TILE` ÷ 速度，以 `MINE_BEST_CHANCE` 的概率取真正更优的一侧，其余随机。
4. **探索**：岔路口重新评估路径；未知格占比 > 0.4 时主动扫描。
5. **终点冲刺**：直线距离进入 `EXIT_RUSH_TILES` 格后掷一次骰子，`EXIT_RUSH_CHANCE` 概率锁定直冲——
   目标恒为出口、遇到雷能绕就绕、路口不再停下思考；否则继续按角色权衡，过 `EXIT_RUSH_RETRY` 秒再评估。

**三道不踩雷的闸**（旧版队友扫出雷之后其他人还会照旧路径踩上去，已修）：

1. `reactToNewIntel()`：新雷挡路 → 立刻丢弃缓存路径；
2. `wantToDefuse` 期间：排雷冷却没好就**原地等**，不照着路径继续走（那等于自己踩上去）；
3. `moveAlongPath()` 末尾：这一步把身体带进已知雷格就**回滚坐标**并重算，
   覆盖侧向滑动、贴墙蹭角这类 A* 看不到的情况。

严格绕不开（雷把走廊封死）时退回「软」路径：`findPath(..., { softMines: true })` 把已知雷降级为
`SOFT_MINE_COST` 的高代价而不是不可走，走到跟前自然会转成排雷意图——总比原地罚站好。
另外 `tileCost()` 里「已知有雷」只在 `game.mines[i] > 0` 时才算不可走：
延迟雷被踩掉、或被别人拆掉之后 `known` 可能仍是 2，那时格子其实是安全的。

排雷手要走到雷跟前，但「已知有雷」的格子默认不可通行，
所以 `findPath` 还有 `{ allowMineGoal: true }` 选项——只放开**终点**那一步。
