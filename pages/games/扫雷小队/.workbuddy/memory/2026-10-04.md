## 扫雷小队：单文件 → 多目录多文件重构

- 原 `扫雷小队.html`（约 2000 行，HTML+CSS+JS 三合一）已删除，改为与同级项目（`回声躲猫猫`、`田字木头人`）一致的标准结构：
  `index.html` + `css/*.css`（6 个）+ `js/**`（ES Module，`<script type="module" src="js/main.js">`）。
- 分层：`core`（config/utils/state/canvas）→ `world`（maze/mines/teams/entities/collision/pathfind）
  → `sim`（scan/player/ai/hazard/effects/vision/scoring/simulation）→ `render`（tiles/entities/effects/renderer）
  → `ui`（screens/options/hud/result/flow）→ `input/keyboard` → `main.js`。依赖单向，无循环引用。
- 关键设计：`sim/simulation.js` 的 `update(dt)` 返回 `true` 表示本局结束，由 `main.js` 调 `ui/flow.endGame()`，
  使模拟层不依赖界面层；`ui/result.js` 的按钮回调节由 `flow.js` 注入，避免 UI 内部成环。
- 顺手修复：原版暂停面板的「继续 / 重新开始 / 返回主菜单」三个按钮**未绑定事件**（只有 ESC 能用），重构后已全部绑定。
- 玩法逻辑（扫描 0.5s / 按住 0.5s 接排雷 2s / 60s 结算倒计时等）保持原样未改。
- 校验方式：临时 DOM 桩 + node 跑通模块装配、三种队伍配置各 4000 帧模拟与渲染、结算面板，无异常（临时脚本已删除）。

## 扫雷小队：画布等比铺满可视区（去掉居中小块）

- 新增 `js/ui/fit.js`：量「围栏高度」= wrap.offsetHeight - canvas.offsetHeight（顶栏+HUD+提示 / 回放头+控制条），
  `scale = min((innerW-24)/CW, (innerH-24-围栏)/CH)`，写回 `wrap.style.width`；画布 `width:100%;height:auto` 按 912:432 跟随。
  这样顶栏/HUD/提示与画布同宽，整体等比缩放（纯 CSS 的 max-width/max-height 只会让画布缩在中间、顶栏仍整宽）。
- 宽度变化会改变换行 → 围栏高度也变，所以迭代 3 次收敛；`offsetParent` 为空（display:none）时直接跳过。
- 开局 HUD 为空量不准：`flow.startGame()` 只打 `requestFit()` 标记，主循环在首帧 `renderHUD()` 后 `consumeFit()` 才真测。
- 去掉 `#gameScreen.active{max-width:1000px}`；回放页 stage 宽度也交给 fit（CSS 保留 max-width:1500px 兜底）。
- `window.resize` → `fitAll()`。
- 实测（node 桩）：1920×1080→1896px 宽、800×600→776、360×640→336、3440×1440→2803。

## 扫雷小队：画布放大不糊（位图分辨率跟上显示尺寸）+ 结算头尾固定

- 之前只是 CSS 把 912×432 的位图拉到 1896 宽 → 糊。**正确做法**：
  逻辑坐标恒为 CW×CH（绘制代码不改），位图 `canvas.width = 显示宽 × DPR`（`core/canvas.js:syncResolution`），
  `render()` 开头 `ctx.setTransform(canvas.width / CW, 0,0, …)`（`drawScale()`）把逻辑映射到设备像素，
  矩形/圆弧/文字按高分辨率重新栅格化。
- `MAX_DPR=2`；`MAX_BACKING_PX=8e6` 总像素上限（4K/带鱼屏按比例降采样，1080p 不触发）。
  实测 1920×1080→位图 3792×1796；3440×1440→4109×1946（被上限压到）。
- 对局/回放画布**不要** `image-rendering:pixelated`（位图已 1:1，pixelated 反而制造锯齿）；
  只有 `#menuCanvas`（CSS object-fit:cover 拉满屏）保留 pixelated，位图单独 `setResolutionScale(cv, dpr())`。
- 结算面板改为 flex 列 + `max-height:calc(100dvh-32px)`：头部与底部按钮 `flex:0 0 auto` 固定，
  中间 `.result-scroll{overflow-y:auto}` 是唯一滚动区；矮屏 media query（620/480px）逐级隐概览卡与冠军行。
  表格自身 `max-height:min(38vh,360px)` + 表头 sticky（嵌套滚动）。

## 扫雷小队：旗帜系统 + AI 分工 + 救援修复 + 结算 tab

- 旗帜：`world/flags.js:placeFlags(count)`（数量=队伍数，旗间 ≥7 格、离出口 ≥6 格、旗格清雷）；
  `simulation.updateFlags()` 踩格即归属该队（加 ripple+粒子）；`scoring` 里统一折算
  `time = max(0, raw - flags*FLAG_BONUS)`，队伍总成绩自然等于 Σ成员时间 − 5×人数×旗数。
  渲染 `render/flags.js` 画在 **drawFog 之后**（全图可见）；`recorder` 帧里加 `fg:[takenBy]`，
  `replay.buildScene` 还原旗帜归属。HUD 队伍卡显示 🚩n/总数 与 每人 -Xs。
- AI 三角色（按队内座次轮转 runner/flagRunner/defuser）：
  `computeGoal()` 结果缓存 0.6s（`e.goal/goalTimer`），避免每帧跑 A*；
  flagRunner 只在绕路 ≤FLAG_MAX_DETOUR(22) 格时去，旗上带 `claim` 防同队撞车；
  defuser 清附近 24 格内 known==2 的雷，≤3 颗后回归；有人到达（endCountdown≠null）全队转冲刺。
  排雷vs绕路改为**统一折秒**比较 + `MINE_BEST_CHANCE=0.85` 取最优侧。
  ⚠ 排雷手要走到雷跟前，但 known==2 的格子不可通行 → `findPath` 加 `{allowMineGoal:true}` 只放开终点那一步。
- 救援 bug 修复：旧逻辑任何人倒地、附近所有人（含半径内所有队友）都涌过去。
  现在 `tryRescue()`：仅同队 + 每个倒地者最多 1 名（`downed.rescuer` / `rescuer.rescueTarget` 双向引用）
  + 半径 120px + 到位保持 26px + 最多守 2.5s 后放弃并冷却 8s；`hazard` 倒地/起身时清理引用。
  诊断脚本逐帧断言「同一倒地者的救援者 ≤1」= 0 次违规。
- 结算：两个 tab（用时·排名 / 完整统计），切换只加 `.active`；柱状图**独占一整行**（不再与排名并排）
  + 50% 虚线参考线 + 右上/右下 0~max 刻度；表格加「分工」「夺旗」两列（11 列）并标 `-Xs`。

## 扫雷小队：排雷减秒 + 称号 + 用时公式 + AI 共享视野

- 减秒规则统一在 `sim/scoring.js` 折算（不动实时计时）：
  `最终 = max(0, 原始 − 🎏夺旗数×FLAG_BONUS(5) − 🧨全队排雷数×DEFUSE_BONUS(1))`。
  两项都按**队伍总数**算，同队每人减得一样多；未到达者原始 = 本局总时长。
  新增 `buildBreakdown()` 产出 `terms[]`（icon/label/amount/unit/delta/note）与 `expr`
  文本（`64.35 − 🎏2×5 − 🧨1×1 = 53.35`），供结算页展示完整算式。
- 称号 `assignTitles()`：优先级 ⚡闪电先锋（按到达时刻，不含减秒）→ 🎏夺旗王 → 🧨拆弹专家 →
  📡侦察尖兵 → 💥雷区硬汉 → 🛡零失误 → 👣远征者 → 🏁完赛者 → 🌫迷途者，保证每人都有（允许并列）。
- 结算：表格拆成 原始 / 减秒 / 最终用时 三列（共 13 列），点行展开 `.fx-row` 明细（chip + 逐项原因），
  tab 顶部公式卡 + 「展开全部公式」按钮。
- **完整统计 tab 不外层滚动**：切 tab 时给 `.result-panel` 加 `.stats-mode` →
  `.result-scroll{overflow:hidden}` + 表格卡 `flex:1` + `.table-wrap{max-height:none}`，只有表格内部滚。
- AI 共享视野（修「队友扫出雷之后其他人还照旧路径踩上去」）：
  1) `team.minesFound` 当版本号，AI 存 `intelVersion`，`reactToNewIntel()` 一有新雷就检查
     路径前 `MINE_LOOKAHEAD+2` 格是否被挡，挡了立刻重算；
  2) `mineAhead()` 前瞻 3 格，`mineLockKey="x,y,adj|far"` 保证同一颗雷同一阶段只决策一次；
  3) `wantToDefuse` 期间排雷冷却没好就**原地等**（否则照路径走 = 自己踩上去）；
  4) `moveAlongPath()` 末尾若这一步踏进已知雷格就**回滚坐标 + 重算**（覆盖侧滑/蹭角）。
  兜底：`findPath(...,{softMines:true})` 把雷降级为 SOFT_MINE_COST(40) 而非不可走，
  走到跟前自动转排雷意图（总比原地罚站好）。
  ⚠ `tileCost()` 里 known==2 只在 `game.mines[i]>0` 时才算不可走——延迟雷被踩掉/被拆掉后
  known 仍是 2，那格其实安全。
- 终点冲刺：`updateRushMode()` 用直线距离（A* 太贵）判进入 `EXIT_RUSH_TILES(12)` 格后掷一次骰，
  `EXIT_RUSH_CHANCE(0.85)` 锁定直冲（目标恒出口、遇雷能绕就绕、路口不思考），否则过 1.5s 再评估；
  锁定后不再重掷，倒地/复活时清空。
- 验证（node 桩，6 局 + 满规模 25 人）：踩「本队已知雷」0 次（修复前 1~2%），
  结算 div 开闭配平、12 个称号齐全；25 人 7409 帧仅 674ms（0.09ms/帧）。
