# 2026-10-22

## 第 25 轮：照料下限 / 偷菜好感 / 采收机与永久工具

用户三项需求：照料随机最小值改成「已处理次数 × 1 小时」；偷菜掉好感改成「作物等级 / 3」；
商店新增采收机（一键收获，200）。确认时补了三条：0 次下限严格取 0、排不下就本轮结束（不扣产量）、
采收机同时提供永久版（10 万），洒水器 / 杀虫剂也各加一个永久版（各 5 万）。

- **`data/care.js`**：`nextCareAt` 区间改成 `[次数×1h, (次数×2+1)h]`，再夹到「成熟前 15 分钟」；
  `下限 > 上限` 时返回 0（本轮不再需要、不算欠账）。之前下限固定 1 分钟，会出现
  「刚浇完一分钟又缺水」。0 次时下限是 0，种下就可能立刻要浇（用户明确要求严格取 0）。
- **`data/relation.js`**：`stealRelLoss(售价)` → `stealRelLoss(等级)` = `max(1, round(等级/3))`。
  三处调用点（玩家偷成功 / 被狗逮住 / 邻居互相偷）全部改成传 `crop.lv`。
  按售价折算时高阶作物一份上千，偷一次掉几十上百，跟「偷一把菜」完全不匹配。
- **新道具**（`data/items.js`）：`harvester`（200，一次性）+ 三个永久版
  `sprinklerPro` / `pesticidePro`（各 5 万）/ `harvesterPro`（10 万），`permanent: true`；
  新增 `TOOL_KINDS` 映射 `kind → {consumable, permanent}`。
- **新模块 `store/tools.js`**：`hasTool / toolUses / useTool / toolCountText`，
  **先查永久版再查消耗版**（顺序反了有永久版也会白吃消耗品）；`toolUses` 返回 `Infinity`，
  UI 显示 ∞。自家（`farm.js`）与邻居家（`social.js`）的一键照料共用这一套。
- **`farm.harvestAll()`**：把 `harvest()` 的核心抽成 `collectPlot(plot)`，两者共用 ——
  产量 / 照料减产 / 被顺走 / 再生轮 / 经验都只在一处算。一键收获一次落盘、一条汇总日志
  （「收了 N 块地，共 M 份，经验 +E，K 块照料不周」）。
- **UI**：农场页底部 `.farm-tool-row` 变三个按钮（🚿 浇水 / 🧴 杀虫 / 🚜 收获），
  文案压短（括号里只放块数，完整说明进 `title`），`flex-wrap` 兜住 360px 小屏；
  按钮出现条件是「拿得出工具」，存量 `×3` / `∞`。邻居弹窗的一键按钮同样支持永久版。
- **商店 / 包裹 / 冒险三处连带**：
  商店买过硬拦重复购买、按钮变「已拥有」并置灰（价格用 `formatCoins` 显示成 5.0万 / 10.0万）；
  包裹里永久道具显示 `∞` 且**不给丢弃按钮**（点错一次十万就没了）；
  藏宝图奖励池 `REWARD_ITEM_IDS` **排除永久版**（否则 10 万的道具会把预算算法打乱）。

## 验证

- 复查过的边界：`times=0` → `randInt(0, 60)`；`times=2` 且剩余 100 分钟 → `120 > 100` → 返回 0；
  `hasTool` 在永久版存在时不会动消耗品；`harvestAll` 的筛选用 `isUnlocked`，UI 计数用 `plotStatus`。

## 第 26 轮：图鉴瘦身 / 作物原型 / 邻居弹窗与排序

用户七项：图鉴只留图标+名称、点开走统一弹窗；图鉴加「可点亮」筛选；作物成长时间重做（各有特色）；
送礼确认框加数量；NPC 一键浇水杀虫移到农场标题行右侧；NPC 记录日期标题置顶 + 扩到两天；
邻居排序改成 等级/财富/好感 三态循环。确认时补了：**重新核对 220 个作物图标**（有些完全对不上）。

- **作物原型**（`tools/gen-data.mjs`）：`ARCHS` 六种 —— 速生（`0.5h+lv×25s`，30 分~2 小时）、
  丰产（×1.5 时间、×2.6 产量）、精品（×1.9、×0.28 产量、2 茬）、慢生（×3、≤4 天）、
  多茬（手写名单 + **regrow 0.16**）、常规。分配用 `ARCH_PATTERN` 10 格轮转（速生/丰产/精品各 2 格），
  形态不允许的退回首选（树不会是速生）。`crops.js` 新增 `arch` 字段 + `CROP_ARCHS` 元数据。
  ⚠️ 售价公式**没动**，仍由整轮收益倒推；按用户要求速生**严格按公式**，所以它每小时金币最高
  （Lv3 实测：速生洋葱 ~220/h、常规黄瓜 ~60/h、丰产番茄 ~53/h），已在文档里写明「想改就加 rateBias」。
- **图标**：生成器 emoji 上限 3→8，把 ⬛🟫🤍🟡🟢🔴 这类色块全换成语义正确的 emoji
  （蘑菇统一 🍄、豆类 🫘、香草 🌿、咖啡豆/可可豆不再用 ☕🍫…），共 50 余个。
- **生成器校验同步放宽/改写**：相邻成熟时间不再比较（同级差 50 倍是设计），改成
  全局 15 分钟~4 天 + 同级离散 ≤60 倍；整轮收入倍率 8→12；同形态产量单调改成「同形态+同原型」；
  限定作物收益校验改成「与目标的偏差 ≤ 容差」（低等级 sell 取整会漂）。
- **图鉴**：卡片只剩 `codex-emoji` + `codex-name`，删掉 lv/detail/stats/按钮与对应 CSS；
  三档筛选 全部 / 可点亮 / 已收集；未解锁 ❔+??? 不可点，已解锁未点亮 ❔+未收集 可点开。
- **送礼数量**：确认框左下角 `.qty` 步进器 + 「全送」，改动时剩余/好感/关系三格实时重算，
  按钮文案变「确认送出 N 份」。`social.sendGift(id, cropId, n)` 好感 = 单份 × 份数（线性）。
  ⚠️ `paint()` 只能取 `#modal .modal-card`（叠层只留一张，下层是快照）。
- **邻居弹窗**：`secToolsHTML` 把 🚿/🧴 放到「🟫 农场（N 块）」右侧（`.npc-tool` 图标 + 橙色角标），
  底部 `.npc-quick` 只剩送礼；记录改成今天+昨天（`records.js` 新增 `since` 选项，先筛窗再截条数），
  `.npc-log` 改成 `padding: 0 11px`（**这就是日期标题没置顶的原因**：sticky 只贴 padding 内缘），
  高度 168→220。
- **邻居排序**：筛选 `filterKey`（全部/可偷摘/可帮忙）与排序 `sortKey/sortDir` 彻底分开，
  排序三态循环 降序→升序→取消；芯片选中带 ↓/↑，筛选与排序之间加 `.filter-sep`。

## 第 27 轮：图鉴「收集」与「点亮」拆开

用户一句：「已收集的应该是只要在仓库中出现过的都算收集」。原来 已收集 = 点亮 = 做过标本，
等于只有 50 个产出换一张卡才算「见过」，太苛刻。

- **新模块 `store/collected.js`**：`isCollected(cropId)` / `noteProduce(itemId)`。
  记录挂在 `player.progress.collected`（`{ 作物id: true }`），**只增不减** ——
  卖掉、送人、做成标本之后依然算收集过。
- **唯一埋点在 `inventory.add()`**：所有产出入包都走它（收获 / 偷菜 / 收礼 / 签到 /
  冒险产出），不用逐个业务加代码，将来新增来源也不会漏。种子（`seed_*`）与认不出的
  key 不计。⚠️ 不要改成在 `harvest()` 里单独埋点，会漏掉偷菜与送礼。
- **`store/codex.js`**：`ensureStats` 补 `collected`；`codexEntries` 新增 `collected`，
  老档兜底 `isCollected || harvested>0 || owned>0`；`codexSummary` 新增 `collected`，
  `percent` 改成按收集算（顶栏与图鉴进度条都吃这个）。
- **UI**：卡片剪影判定 `!entry.collected`（不再是 `!lit`）；标题「已收集 X / 220」，
  副标题「已点亮 Y 种 · 已解锁 Z 种 · 收集进度 P%」；筛选键 `lit` → `collected`；
  详情弹窗多一行「📖 图鉴　已收集 · 未点亮　做一份标本就点亮」。
- **点亮保持原样**（`progress.specimens`，50 个产出一份），图鉴称号仍按点亮数判定
  （`store/titles.js` 与称号页文案没动）。
