用户：「我改成了14点出昨天的榜单，但现在似乎逻辑不对」。按他的确认，语义是

用假 IndexedDB 跑真实 `store/daily.js` 复核结算链路，机械层面是对的：

- `bump` 按 `boardDayKey(at)` 归期、`settled` 冻结、`latestSettled` 取最大已结算，均正常。

真正的问题在**呈现**与**历史数据**：

1. 行的 `date` 是**账期开始日**，但界面只写「上期 · 10-22」，玩家会按自然日理解 ——

2. 0 点账期时代留下的行与新账期**同一把键、不同时间窗**，混用会互相覆盖，
   `bump` 撞上 settled 还会静默丢数据。

## 排行榜第二轮：本期从 14:00 起算 + 打理王口径

用户两点：①今日排行（本期实时）要从 14:00 起算，该清空的数据要清空；
②打理王的今日/实时统计 = 每个人「自己农场里加成最高的那一个数值」，不是累计。

### ① 本期一定从 14:00 起算

原来只靠 `boardDayKey` 取键，存档里残留的旧口径行（同键不同时间窗）会被当成「本期」，
看起来就是「14 点没清空、今天上午的数还在」。改成三道闸门：

- 行里存 `start = boardPeriodStart(date)`，`storage.writeDailyRows` / `loadSave` 都带上；
- `rowOf(key)`：start 对不上 → 当前期直接删掉重开、历史期返回一个 settled 空行（bump 静默丢弃）；
- `currentRow()`：读的时候 start 对不上就当空行 —— 界面绝不显示旧数；
- `checkRollover` 只结算 start 对得上的行；
- `migrateBoardRows()` 升到 `BOARD_VERSION = 3`，只丢 start 对不上的行（新行保留），
  日志里打印清了几行。

### ② 打理王口径

- 新增 `mergeLiveManage(stats)`：遍历 `state.farm.plots` 与每位邻居的 plots，取
  `farmMaxBonus`（全场最高的那一个角标），与记账里的峰值取较大值合并。
- `todayRank` / `todayValue` 对 `manage` 走这个合并 —— 不依赖「收获过」这个事件，
  地里挂着 +37% 但今天没收，也能上榜。
- `settleDay(row, now)` 里对**期结束后 2 小时内**的那一期再量一次
  （`now - (start + 24h) < 2h`），久远补算不追溯；`pending.map((row) => settleDay(row, now))`。
- 文案：`BOARDS.manage.desc` 改成「自己农场里最高的那一个「+加成」角标」，手册加一条。

### 验证（假 IndexedDB + 真实 store，脚本用完即删）

## 修：改了文件浏览器不更新（PWA cache-first）

用户：「我现在在浏览器中没有更新文件了，是不是pwa的问题呢」—— 是。

`sw.js` 的 v1 是**纯 cache-first + 手写 `VERSION='ximi-farm-v1'`**，版本号从建起来就没升过，
于是 `/src/*.js`、`/styles/*.css`、页面 HTML 全部永远命中缓存，网络请求不发出来。
`server.mjs` 的 `Cache-Control: no-cache` 对此无效 —— SW 拦截后压根不走网络。

### 落地

- `sw.js` 重写为**网络优先**：导航请求 + `/src` `/styles` `/vendor` 先 fetch
  （成功顺手写回缓存），失败才回退缓存；图标 / manifest 仍缓存优先。`VERSION='v2'`。
- `install` 里 `cache.addAll(CORE).catch(()=>{})`（某个图标改名不该让整个安装失败），
  CORE 补上 192/512 PNG。
- `activate`：有「非当前版本缓存」= 从旧版升级 → 删旧缓存 + claim + **对受控页面
  `client.navigate()` 自动重载一次**（旧页面跑的是旧代码，claim 换不掉；首次安装不刷）。
- `main.js` 抽出 `mountServiceWorker()`：`register('./sw.js', { updateViaCache:'none' })`
  后立刻 `reg.update()`；**不再监听 controllerchange 去 reload**（会和 SW 的 navigate 双刷）。
  `?nosw` 开关：注销所有 SW + 清空所有 cache，开发环境一次性擦干净。
- 文档：`docs/01-快速开始.md` 加「改了代码刷新还是旧画面？」排查段（顺序 SW → 磁盘缓存 → 保存），
  README 的 PWA 段写清网络优先生效方式。

### 验证（puppeteer + 真 Chrome，脚本用完即留 workspace）

- `e2e-sw.mjs` 5/5：SW 接管 → 缓存版本 v2 → 改 css 后刷新取到新内容（网络优先）→
  断网仍能打开且 css 可用（缓存兜底）→ `?nosw` 注销 + 清空（regs 0 / cache 0）。
- `e2e-sw-upgrade.mjs` 4/4：手动造 `ximi-farm-v1` 缓存 → 改动 sw.js 一个字节 →
  **页面自动重载一次**（framenavigated ×1）、旧缓存清掉、重载后仍能进游戏。

## 第 39 轮：荒地卡排序 / toast .75 透明度

用户两点：①「开垦土地后，要自动把下一个需要开垦的土地放在土地列表后面，
而不是现在这种放在下面」；②「toast使用.75透明度，不要太遮挡内容」。先确认后动手。

### ① 荒地卡串到汇总行下方

根因：`.plot-fold` 汇总行节点首次渲染后就待在 grid 末尾；开垦一块地后
「下一块荒地」卡片节点才新建，`append` 落到汇总行**后面** —— 首次加载不会
（那时两者按顺序新建），所以表现为「开垦后错位、刷新后又对」。

- `renderFarm` 里 `updateNode(foldNode, …)` 之后加 `grid.appendChild(foldNode.el)`：
  把汇总行挪回末尾（移动已有节点，没有新节点时是空操作）。顺序固定为
  「已解锁地块 → 荒地卡 → 汇总行」，与首次加载一致。汇总行本身不删（用户确认保留）。
- docs/08「未解锁地块折叠」补了这条顺序规则。

### ② toast .75

- `.toast` 背景 `rgba(34,48,31,.92)` → `.75`；`.toast.gold` 渐变两色标
  `#f5a623/#e8871e` → `rgba(...,.75)`（金色用得最多，遮挡感主要来自它）。
- 用**背景 alpha** 而非 `opacity` 属性：文字保持纯白不泛白，只是背后内容透出来。
  冒险页 `adv-toast`（挖到/空手小条）用户明确不改。
- `npm run check` 全绿。未跑浏览器测试（按用户约定）。
