# 2026-10-30 · 第 57 轮：好友系统

## 落地范围

好友关系（玩家↔NPC、NPC↔NPC）全套：底部 tab「👥 邻居」→「好友」（只列已是好友的），
全村名单挪进村中心的村民总览（三芯片：全部 / 在线 / 好友）。非好友**只禁偷菜与催上线**，
送礼 / 交易 / 照料 / 喂狗照旧。偷菜**彻底不掉好感**（被狗抓住也只罚款）。

## 关键实现

- **好友标记复用 `relation` 表同一行**：`state.relations` 从 `{ "a|b": v }` 改成 `{ "a|b": { v, friend } }`。
  不新开表、不动复合主键、不升 `DB_VERSION`、备份导出零改动。
- ⚠️ **v=0 的好友行必须保留**，四处同一条件「好感非 0 **或** 是好友」：
  `store/relation.js setRelation` / `data/relation.js readRelations` /
  `core/storage.js writeRelations` / `core/backup.js relationsOf`。少一处重开就掉好友。
- 门槛（`FRIEND_THRESHOLD`）：热心30 勤勉40 爱钻研45 场面人60 精打细算75 悠闲80 生意人100 爱占便宜120；
  主动申请 ×0.8（24/32/36/48/60/64/80/96）、自动解除 ÷2 向下取整（15/20/22/30/37/40/50/60）。
  一对关系两个性格门槛不同时**各判各的**（`pairFriendThreshold` 取高值）。
- 开局好感 = `baseRelation(friendly, 0)` = `round(friendly/2)`：热心 **+38** / 勤勉 +23 / 爱钻研 +18 /
  场面人 +13 / 精打细算 +5 / 悠闲 +3 / 生意人 −7 / 爱占便宜 −22。**只有热心那 7 位开局即好友**。
  ⚠️ `relation.js` 里曾写「+37」，`Math.round(37.5)=38`，已改正。
- `seedFriends()` 用 `progress.friendSeeded` 做一次性开关，否则手动解除会被自动加回。
- NPC 侧走 `ACTIONS.friend`（`sweep`）+ `ctx.friendTick` 注入，`npc-sim` 不 import `store/friend.js`。
  每次上线 20% 概率，先试玩家（信箱 `action:'friend-request'` 点头才成），不够格再找村民互加（直接成 + 寄信告知）。
- 信箱新增 `action` / `pending` 语义：带 `action` 的条目 `claimed` 恒 false、**不进一键收下**、**永不过期**。
- 新增 `src/store/friend.js`（requestFriend / answerFriendRequest / unfriend / friendTick）。

# 第 58 轮 · 公共用地

## 需求落点

村中心新增「🏞 公共用地」（占满一行，第三枚入口）。弹窗形似邻居农场弹窗，
块数 `2 × 村庄等级`（2/4/6/8/10），系统播种、谁都能浇水捉虫、熟了先到先得
（每块地每人 1 个），作物等级 `[(级−1)×10, 级×20]` 里随机，日志保留 7 天。

## 关键实现

- **公共用地 = 一座没有主人的农场**：`state.commons`，`farm` 表里
  `id:'commons'` / `kind:'commons'` 的一行，地块与日志照样落在 `plot` / `log` 表。
  存储层 / 备份 / 导入校验一行不改，**不升 `DB_VERSION`**。
- ⚠️ `initState()` 两处顺序死穴：`rows` 过滤必须**排除 `COMMONS_ID`**（否则被
  `dropFarms()` 当孤儿邻居连地删掉）；`villageLevel` 必须**先于** `normalizeCommons`
  算出来（块数看它）。
- 补地块只增不减：`ensurePlots()` 由 `advanceCommons` 与 `commonsSnapshot` 两处调，
  `village.js` 不认识这个模块，依赖不成环。
- 世界时钟第 ⑥ 步 `advanceCommons`：补地块 → 清空拿光的 → 摇产量 → 补种，
  返回 true 置 `report.dirty`（**循环里不 commit**）。
- 先到先得账本 `plot.taken` + `plot.takers`（玩家与 NPC 共用），
  `commonsCanTake(plot, who)` 同时判「还剩」与「这人没拿过」。
- 照料复用 `scheduleCare` / `serveCare` / `needsWater` / `needsPest` / `careExp`，
  经验照给；**收获不给经验**（白拿还给经验就成了刷分线）。
- 村民走 `ACTIONS.commons`（`sweep`）+ `ctx.commonsTick` 注入（`simCtx`），
  `npc-sim` 不 import `store/commons.js`。先抢收 65%（进 `npc.bag`）再照料 50%。
- 新事件 `EVENTS.COMMONS`；限定作物（`crop.special`）不进公共地作物池。

## 收尾时补掉的三个坑

1. ⚠️ **落盘缺口**：`persistFriends()` / `flushAwards()` 原来只写
   `[state.farm, ...state.friends]`，漏了 `state.commons` —— 村民抢收的账本
   （`taken` / `takers`）会回滚，下次开机玩家能原地再拿一遍。两处都补上。
2. ⚠️ 公共地照料给的经验在 `state.farm` 上，`commons.js` 的 `persist()` 原来只写
   `[state.commons]`，浇十次水关页面经验全丢。改成 `[state.farm, state.commons]`，
   升级时再带 `news`。
3. ⚠️ 弹窗顶部 `data-role` 从 `board` 改名 `commons-board`：邻居弹窗用
   `document.querySelector('#modal [data-role="board"]')` 整块重绘控制台，撞名会互相覆盖。
4. `commonsSnapshot()` 顺手 `sowCommons()`：刚开新档 / 世界时钟一步没走时，
   不补种玩家会看到一片「空地」。

## 收尾复查（第二轮：调整 + 找遗漏）

审查了全仓所有 `commit({...})` 调用点（store 层 14 个模块），结论与改动：

1. **抽 `state.js` 的 `farmRows(...)`**：批量落盘统一走它（自动追加 commons、去重、滤空值），
   以后再加第四类数据只改一处。三个批量出口：`social.persistFriends` /
   `daily.persistNow(true)` / `social.runLiveStep`。
2. ⚠️ **第三处真遗漏**：`runLiveStep`（在线演出单步提交）原来 `farms: [state.farm, npc, ...extra]`，
   演出队列里排着 `commons` 动作时会漏 —— 账本留在内存，重开能再拿一遍。
3. ⚠️ **`commonsSnapshot()` 不再播种**：它是 `renderCenter` 每 tick 调的渲染函数，
   在里面写 `plantedAt` 又不落盘 = 「刚才明明是西瓜，回来变成萝卜」。
   播种移到 `advanceCommons` 与 `openCommonsModal`，后者种过就 `flushCommons()`。
4. `sowCommons()` 内部先 `ensurePlots()`：村庄刚升级时新地块也要一起种上。
5. 删掉死常量 `COMMONS_LOG_DAYS`（裁剪实际走 `data/friends.js` 的 `trimLog`/`LOG_KEEP_DAYS`）。
6. `center.js` 的 `commonsHint` 兜住「一片空地」（新档第一屏真的是六块全空）。
7. `commons-modal` 的加成档位改成与 `friend-modal` 同口径的写法（`pct / 30` 再 ceil）。
8. `manual.js` 新增「🏞 公共用地」一节（9 条），放在「村庄建设」之后。
9. **提示口径确认**：村民在公共地抢收，在线演出那条路**会**弹 toast（一趟才几次，
   正好提醒玩家「有人去抢了」）；在线空闲那条路不弹（每 1~3 分钟一次会刷屏）。
   文档原先写「不弹」，已按实现改正。

审查结论（**不需要改**的）：
- 玩家主动操作邻居的 10 处单点提交不带 commons —— 那些操作不碰公共地，带上只是白写；
- `village.js` 的 invest/pray 不带 commons —— 升级后块数由下次 `advanceCommons` 补，`normalizeCommons` 兜底；
- `bulkAdvance` 降级段不推进公共地 —— 公共地不循环，最多长到成熟停住，不需要补算历史；
- 公共地照料不记排行榜 —— care 是「帮人」、work 是「自家」，记哪张都会让口径变形；
- `records.js` 不看 `by`，所以公共地日志复用 `recordItemsHTML` 不会重复显示来源；
- 弹窗打开期间村民抢收不会重绘（与邻居弹窗同一约定，数字滞后但操作时重算，不会出错）。
