
## 第 46 轮 · 离线补算换成世界时钟

需求原文：「玩家重新打开页面时的离线模拟换成时间推进算法，获取下线时间，
每次循环 +1 分钟，按正常游戏逻辑运行（农场状态、NPC 上下线、互动、操作），
允许重构 NPC 行动框架，未来还会有更多 NPC 行动」。
用户拍板：步长按跨度自适应（7 天内 1 分钟、之后每翻倍翻倍）、行动框架一起重构、
订单/榜单/签到挖宝/收炉全进时钟、>2 小时弹离线时间轴否则仍用摘要。

### 新增

- `src/data/world.js`：`stepMsFor(span)`（≤7d 1min，之后每翻倍 ×2，封顶 60min）、
  `REPORT_MIN_SPAN=2h`、`VISIT_BUDGET=30_000`（超预算降级聚合）、`FRAME_MS=12`、
  `REPORT_NOTES_PER_DAY=6`。
- `src/store/world.js`：`advanceWorld({from,to,ctx,deferFrom,onVisit,onProgress,report})`，
  `createReport` / `reportDays`。每步顺序：到点上线（按 nextVisitAt 升序）→ 订单过期 →
  跨 14:00 结算榜单（`checkRollover(now,{quiet:true})`）→ 收炉。
- `src/ui/offline-report.js`：离线时间轴弹窗（`.offline-modal` / `.or-*`）。

### 重构

- `npc-sim.js`：`STEPS` 静态表 → **`ACTIONS` 注册表**（`main` 权重键 / `sweep` 顺路再试 /
  `can` 只过滤 main 候选池 / `run`）。`planVisit(npc, at, ctx)` 先过滤再加权不放回抽，
  收尾按声明顺序挂 sweep（已抽到的不重复）。`runVisit` 导出并返回 `{levelBefore, results}`；
  新增 `estimateVisits`；删 `estimateWork` / `simulateNpcUntil` / `DETAILED_WINDOW`。
- `social.js`：`settleWorld` 改走 `advanceWorld`；新增 `worldCursor`、`lastSeen()`、
  `pendingSpan()`、`touchLastSeen()`。报告起点 = `lastSeenAt`（新档不会误报），
  **模拟起点 = min(worldCursor, lastSeen)**（新档那批「排在十几小时前」的上线照样要跑）。
- `daily.checkRollover(now, {quiet})` + `flushAwards()`；`expireOrders(now,{quiet})`、
  `claimJobs(now,{quiet})`。
- `orders/workshop` 的 quiet 是**性能必需**：早年每条订单过期都 commit，headless 实测
  365 天要 18 秒；改成补算结束统一落盘后 0.4 秒。

### 坑

- **每步都 commit 会把启动拖成十几秒**（IndexedDB 事务），补算期间一律 quiet + 最后写一次。
- `requestAnimationFrame` 让出在 headless 里很慢（但 setTimeout(0) 更慢，被夹到 4ms）：
  保留 rAF，真正的问题是 commit 次数。
- 新档 `progress.lastSeenAt` 必须给 `Date.now()`；给 0 会退回「最早的待办上线」，
  一进游戏就弹「你不在的 16 小时」。
- 「不在的几天」按 elapsed 算不按桶数（23 号 16:37→26 号 16:37 是 3 天 4 个桶），
  不足一天按小时说。
- 离线时间轴要等 `celebratePending()` 清零再弹，否则和出榜庆祝叠在一起。

### 实测（headless 430×900）

3 天 ~520 次上线 0.2s；30 天 ~6000 次 0.6s；365 天（触发降级）~1400 次 1.3s。
