
## 第 46 轮 · 离线补算换成世界时钟

需求原文：「玩家重新打开页面时的离线模拟换成时间推进算法，获取下线时间，
每次循环 +1 分钟，按正常游戏逻辑运行（农场状态、NPC 上下线、互动、操作），
允许重构 NPC 行动框架，未来还会有更多 NPC 行动」。
用户拍板：步长按跨度自适应（7 天内 1 分钟、之后每翻倍翻倍）、行动框架一起重构、
订单/榜单/签到挖宝/收炉全进时钟、>2 小时弹离线时间轴否则仍用摘要。

### 新增

- `src/data/world.js`：`stepMsFor(span)`（≤7d 1min，之后每翻倍 ×2，封顶 60min）、
  `REPORT_MIN_SPAN=2h`、`VISIT_BUDGET=30_000`（超预算降级聚合）、`FRAME_MS=12`、
  `REPORT_NOTES_PER_DAY=6`。
- `src/store/world.js`：`advanceWorld({from,to,ctx,deferFrom,onVisit,onProgress,report})`，
  `createReport` / `reportDays`。每步顺序：到点上线（按 nextVisitAt 升序）→ 订单过期 →
  跨 14:00 结算榜单（`checkRollover(now,{quiet:true})`）→ 收炉。
- `src/ui/offline-report.js`：离线时间轴弹窗（`.offline-modal` / `.or-*`）。

### 重构

- `npc-sim.js`：`STEPS` 静态表 → **`ACTIONS` 注册表**（`main` 权重键 / `sweep` 顺路再试 /
  `can` 只过滤 main 候选池 / `run`）。`planVisit(npc, at, ctx)` 先过滤再加权不放回抽，
  收尾按声明顺序挂 sweep（已抽到的不重复）。`runVisit` 导出并返回 `{levelBefore, results}`；
  新增 `estimateVisits`；删 `estimateWork` / `simulateNpcUntil` / `DETAILED_WINDOW`。
- `social.js`：`settleWorld` 改走 `advanceWorld`；新增 `worldCursor`、`lastSeen()`、
  `pendingSpan()`、`touchLastSeen()`。报告起点 = `lastSeenAt`（新档不会误报），
  **模拟起点 = min(worldCursor, lastSeen)**（新档那批「排在十几小时前」的上线照样要跑）。
- `daily.checkRollover(now, {quiet})` + `flushAwards()`；`expireOrders(now,{quiet})`、
  `claimJobs(now,{quiet})`。
- `orders/workshop` 的 quiet 是**性能必需**：早年每条订单过期都 commit，headless 实测
  365 天要 18 秒；改成补算结束统一落盘后 0.4 秒。

### 坑

- **每步都 commit 会把启动拖成十几秒**（IndexedDB 事务），补算期间一律 quiet + 最后写一次。
- `requestAnimationFrame` 让出在 headless 里很慢（但 setTimeout(0) 更慢，被夹到 4ms）：
  保留 rAF，真正的问题是 commit 次数。
- 新档 `progress.lastSeenAt` 必须给 `Date.now()`；给 0 会退回「最早的待办上线」，
  一进游戏就弹「你不在的 16 小时」。
- 「不在的几天」按 elapsed 算不按桶数（23 号 16:37→26 号 16:37 是 3 天 4 个桶），
  不足一天按小时说。
- 离线时间轴要等 `celebratePending()` 清零再弹，否则和出榜庆祝叠在一起。

### 实测（headless 430×900）

3 天 ~520 次上线 0.2s；30 天 ~6000 次 0.6s；365 天（触发降级）~1400 次 1.3s。

## 第 47 轮 · 土地升级修复 + 互动弹窗 + 催上线 + 村中心排行榜

需求原文：「土地升级弹窗的升级按钮点了不生效；NPC 农场增加互动按钮，把送礼、
交易收进互动弹窗，互动按钮放控制台首行右侧做成大按钮，日志放到土地数量旁；
互动弹窗加催促上线（花 20 好感，好感低等 5~10 分钟、好感高等 1~30 秒，用算法
定上下限）；NPC 之间与对玩家的互动频率翻倍；排行榜放进村中心按两列排
（榜单列表 + 昨日第一名，多个显示 +几），点击进排行榜弹窗；NPC 也要完成订单，
按性格保留部分或全部产出，上线把订单处理加进行动列表」。

### ① 土地升级「点了不生效」的根因

`SOILS` 是**按 id 索引**的表，每条记录里**没有 `id` 字段**。
`views/farm.js` 的 `nextSoilOf()` 直接返回 `SOILS[nextId]`，
弹窗里写 `next.id` → `undefined` → `upgradeSoil(plotId, undefined)` →
`SOILS[undefined]` 查不到 → **静默 return false**（连提示都没有）。
修法：`nextSoilOf` 返回 `{ ...SOILS[nextId], id: nextId }`。
⚠️ 凡是「按 id 索引的数据表」，从表里取出来的对象都不带自己的 id。

### ② 邻居弹窗控制台重排

`.npc-board-top` 四组：`🟫 农场 N 块` → `📜` → `🚿🧴` → 行尾 `💬 互动`
（`.npc-interact`：32px 高、实心绿、`margin-left:auto`）。
`.npc-quick`（原来的送份礼/交易两颗并排按钮）整块删除，包括它的 CSS。

### ③ 互动弹窗（`openInteract` / `.ia-list` / `.ia-row`）

一行一件事：36px 图标方块 + 标题 + 说明，右边「代价或状态」标签，行尾 `›`。
三行：🎁 送份礼 / 💰 交易（离线压淡）/ 📣 催促上线。
联机好友只有送礼一行。点行再叠一层，关掉回互动弹窗。
⚠️ `data-action` 又踩了一次模板坑：用 `${action}` 拼出来 `check.mjs` 扫不到
（122 → 117），改成三行写字面量才回来。

### ④ 催促上线

`data/relation.js`：`SUMMON_REL_COST = 20`、`summonDelayRange(rel)`（指数插值）：
```
t = (rel+200)/400；下限 1s×300^(1-t)；上限 30s×20^(1-t)
```
→ 挚交 1~30s，0 分 17s~2min，结怨 5~10min。
`store/social.js` 的 `summonNpc()`：只做 `nextVisitAt = min(原值, now+延迟)` + 扣好感
+ 落盘 + `scheduleSummon()`（setTimeout +300ms 缓冲 → `pollOnline()` 叫醒世界时钟）。
**不新造「被催促的上线」通道**：到点走正常 `beginVisit`/`planVisit`/在线演出。
实测：好感 200 → 13.6 秒后真的上线，动作一件件演出来。

### ⑤ 互动频率翻倍

`npc-sim.js` 新增 `interactChance(c) = 1 - (1-c)²`（**掷两次、有一次算数**），
套在 顺菜 / 串门帮忙 / 送礼 / 喂狗 四处。
⚠️ 不能用 `c × 2`：`STEAL_CHANCE` 的 often(.65) 与 always(.95) 会一起顶到 0.99，
两档偷菜倾向直接没区别。新式子 0.18→0.33、0.65→0.88、0.95→0.998，档次关系保留。

### ⑥ 村中心排行榜卡 + 排行榜弹窗

- `subpages/rank.js` 新增 `yesterdayBoardSummary()`（两列数据）与 `openRankModal()`；
  `rankPage.render` 的底栏改用 `ctx.footEl`（原来写死 `#subpageFoot`，弹窗里拿不到横滚接力）。
- `views/center.js` 加 `.center-rank`：两列 grid（`auto 1fr`）、6 行；
  左列榜单名、右列昨日冠军（并列 → `+N`，没有 → `—`），整卡 button 开弹窗。
- 排行榜**从子页面里摘掉**（`subpages/index.js` / `SUBPAGE_TITLES` / `MORE_MENU_ITEMS`
  三处都删），和订单同一个原则：一处一个入口。

### ⑦ 订单链路（本来就有，这轮补强）

已有 `actFill`（上线接单，优先玩家单）+ `KEEP_RATIO`。这轮：
- `KEEP_RATIO` 上限从 0.70 抬到 **1.00**（精打细算 / 爱占便宜一件不卖），
  靠 `NPC_BAG_CAP=60` 兜底（塞满就照卖）；
- `actPlant` **看榜种地**：榜上有人收的作物排进播种候选的最前 ——
  267 种作物随机种，仓库恰好压着订单要的那一味概率太低，不这么排订单永远是理论。
实测：给某 NPC 备 40 份小麦 + 发一条收 10 份的玩家单，一次上线就「📦 帮 农场主 凑齐了 小麦 ×10」。

### 验证

`npm run check` 全绿（122 个 data-action）。headless 430/360 两档截图过：
控制台首行不溢出（rowScrollW == rowW）、互动弹窗三行等高 58px、
催促确认四格完整、村中心两列对齐、排行榜弹窗 6 个 TAB 一行放得下、叠层回退正常、无 console 报错。

## 第 48 轮 · 在线空闲 / 上线提醒顺序 / 村庄建设

需求原文：「NPC 在线时会时不时做操作（打理农场、访问其他 NPC 与玩家），
避免出现 NPC 在线但自家农田要打理/要收获；在线时操作更有活人感；
NPC 下线也有 toast；重新调整上线提醒（催上线后他先操作、过一会才显示上线通知）；
村中心加村庄建设与等级（1~5 级），升级要金币 + 对应等级升级水晶（冒险获得）
+ 村民祈福总次数（升级清空），1 级要 10000 金币 + 5 个 1 级水晶，玩家与 NPC
随时投入不定数量直到达标；祈福像签到，每天一次，5% 概率抽对应等级藏宝图奖励池；
离线模拟里同一 NPC 可能多天多次祈福；先列等级要求给用户看；增加建设日志记近 7 天」。

用户拍板：金币曲线再陡一点（10k/36k/130k/460k）、祈福总量不变但曲线更陡
（60/200/470/770）、村庄等级**另加全村产量 +2%/级**、水晶额外掉落 50% 给 1 个、
NPC 在线反馈「只在有意义的动作上提示」。

### ① 在线空闲（新增能力，world.js + npc-sim.js）

- `npc.idleAt` 新字段（`beginVisit` 排、跟存档走）。`planIdle(npc, at, ctx)` 优先级
  **自家 → 别人**：harvest → tend → plant → 掷 `IDLE_SOCIAL_CHANCE=0.35` 抽
  steal/care/gift/feed/adventure/order/fill/pray。
- `world.js` 的 `tick` 加 ①' 步 `runIdleActions(prev, next, ...)`，每段跑一遍。
- ⚠️ **刚上线 90 秒不做空闲动作**（`IDLE_AFTER_VISIT_MS`）：玩家在线时一趟上线是
  3~7 秒一步演的，空闲一起插进来会「抢跑」，队列里那个收获变成空动作。
- ⚠️ 只有动到玩家农场的（偷/帮/送礼/被狗赶走）才 `notify`；他自家收菜只写动态。
- `report.idles` 计数：`settleWorld` 的落盘条件改成 `visits.length || report.idles`，
  否则在线空闲做的事白做（改了内存没写库）。

### ② 上线提醒顺序（根因）

`enqueueVisit` 早先把「上线了」塞进 `pendingArrivals`，等 60 秒后
`checkOnlineVisits` 才 `takeArrivals()` 弹 toast —— 而演出队列 3~7 秒后就开演。
催上线尤其出戏：先看到「金链哥收了一茬菜」，过一会儿才被告知他上线了。
改成 `emit(EVENTS.ARRIVAL)` **当场发**，`ui/views/friends.js` 订阅后用 400ms
窗口合并一批（同一刻可能好几位一起上线），`pendingArrivals` / `takeArrivals` 删掉。

### ③ 村庄建设（新领域）

- `src/data/village.js`（纯数据）：`VILLAGE_TIERS`（金币/水晶档+数量/祈福次数）、
  `villageYieldMul(level)=1+0.02×level`、`PRAY_CHANCE=0.05`、`CRYSTAL_META`、
  `rollCrystalDrop(tier)`（50%）、`rollPrayReward(level, buildPool)`、日志上限。
- `src/store/village.js`：`villageState/villageSnapshot/invest/prayCore/pray/prayNpc/
  addCrystal/villageLogs/villageYield`。状态挂 `state.farm.village`
  （`{level, coins, crystals, pray, stock, prayDay, logs}`），零改表。
- **升级自动**：`checkUpgrade()` 每次投入/祈福后跑，三项同时达标就升，三项清零，
  写建设日志 + 时报 + toast。不做「升级按钮」（祈福一天一次，不该守点）。
- ⚠️ **`pray` 必须拆同步内核**：`prayCore` 只改内存（邻居走这条，时钟里 await 会拖垮补算），
  `pray` 再补一次 commit（玩家走这条，奖励进背包要立刻写）。
- ⚠️ **`prayDay` 只留今天**：唯一用途是「今天祈过没有」，攒着会长成 33×N 的表；
  写档时 `normalizeVillage` 再清一次。
- ⚠️ **`stock` 水晶不进背包道具表**：它是村庄材料，塞进 `ITEMS` 会让商店、包裹、
  图鉴、联机校验全都要跟着改。冒险结算直接 `addCrystal` 进库存。
- NPC 祈福奖励**折金币**（`npcPrayValue`）：他没有装种子/道具的地方，塞进 `bag`
  会污染订单链路。

### ④ 产量加成与水晶掉落

- 玩家：`store/farm.js` 的 `rollYield` 乘 `villageYield()`。
- 邻居：`npc-sim.js` 的 `actHarvest` 乘 `ctx.villageYield`（simCtx 注入）。
- 玩家冒险：`store/adventure.js` 的 `finishRun` 里 `rollCrystalDrop(run.tier)`。
- NPC 冒险：`data/adventure.js` 的 `rollNpcAdventure` 返回 `crystal`，
  `actAdventure` 调 `ctx.addCrystal(tier, npc, at)`。

### ⑤ 村中心 UI

`views/center.js` 顶部新增 `.center-village`：卡片头（名字/等级徽章/产量）+
「还差 N 项」+ 三行进度（`auto 1fr auto` grid）+ 三按钮。
⚠️ **数字用千分位不用 `formatCoins`**：那边是 HUD 紧凑写法（10,000 → 1.0万），
这里是「X / 门槛 Y」，混着写会让人一愣（截图才发现）。
投入弹窗默认值 = min(还差, 持有)；`.cvi-ok` 撑满整行（`.btn` 是行内宽度、
`.modal-foot` 不是 flex）。建设日志复用 `recordItemsHTML` + `board-modal`。
`EVENTS.VILLAGE` → `paintVillage()` 只重绘那一张卡；跨 0 点由 `refreshMarks` 检查。

### 验证

`npm run check` 全绿（96 文件 / 127 action）。headless 实测：
1→2 自动升级（三项清零、stock 剩 1）；上线事件在 settleWorld 返回时已发
（`seenRightAway: ['王大爷']`）；在线空闲把熟地收了（`ripeGone: true`）；
祈福中奖真进背包（朱雀花种子 ×1）且写进建设日志；
430 三按钮各 121px、360 各 97px，无溢出无裁切。
