补算不封顶并加等待画面 / 邻居展示等级+财富+最近几条动态 / 多季度收获用「再生次数」实现 /
作物生长分阶段 / 地块扩到 40 块。

## 产出
- `tools/gen-data.mjs`：数值生成器，产出 crops(145) / soils(8档) / progression(40地块+200级经验+26称号)
- `src/data/stages.js`：生长阶段（播种/发芽/生长/开花/结果/成熟）按权重分配时间
- `src/store/npc-sim.js`：邻居离线模拟引擎（纯计算，不碰存储与 DOM）
- `src/ui/sim-overlay.js`：离线结算等待画面（rAF 分帧 + 最短 650ms 展示）

## 关键设计决策

### 经验曲线是「反推」的（最重要的一个决策）
```
每轮经验 = 已解锁地块数 × 作物基础经验 × 土地经验倍率 × 多次收获收益系数
升级所需 = 每轮经验 × 每级需要的轮数
```
好处：调土地倍率 / 再生次数 / 地块数 / 作物经验时，经验曲线自动跟随，
不会出现「前期飞快后期劝退」。改平衡只改生成器一处。

### 补算分两段，保证不封顶也不卡
- 远期（>7 天）走聚合公式，只推进总量不记日志
- 近期（7 天内）逐条执行上线会话，写动态日志给玩家看
- 实测：15 个 NPC、离线 1 天 ~ 10 年，结算稳定 **2~3ms**
- 每个 NPC 另有 MAX_VISITS_PER_NPC=4000 兜底

### 被偷过的地改用 `stolenAt` 时间戳
原来是 `stolen` 布尔 + 全局 20s tickFriends 定时清理。现在时间到了自然恢复，
**完全不需要任何后台定时器**，这正好契合「只在进页面更新」的要求。

### 成熟时间刻意允许非单调
风味（甜/酸/鲜/辛/平）会调制成熟时间与价值，所以相邻作物的时间可能倒挂，
这是有意的调调剂（甜菜快、蘑菇慢）。但做了硬约束：相邻不能差出一倍。
售价则强制单调累计（`max(本次, 上次+1)`），避免「高等级种子更便宜」。

## 踩过的坑
1. emoji 数量客观不够 145 种唯一 → 放宽为「同一 emoji 最多 2 次」，
   并把阶段列表按真实品类裁剪（根茎/叶菜/谷物/花卉/菌菇/豆类各用不同序列）
2. `legume` 形态一开始漏配 STAGE_PATHS → 生成器现在有断言会拦截
3. 地块解锁检查误判：开局送 6 块都是 Lv1，不是「未严格递增」
4. ripe 阶段参与权重分配会导致 90% 就显示「成熟」但还不能收
   → 改为 ripe 只做终点标记，不参与时间分配

## 验证方式（用户要求不做测试，只做静态验证，所以用一次性脚本验证后丢弃）
- 8 项静态校验，每项都用反向用例验证过能真的报错退出 1
- 用最小 IndexedDB 桩跑通了「多次收获作物」完整链路：
  播种 → 阶段推进 → 收获 1 次（背包 +4、harvested=1、进入再生 156s）→
  收获 2 次（背包 +4、清空地块）；一次性作物收获后正确清空；
  加 1e12 经验后正确停在 Lv200 且 exp 归零

## 关键实现

### 下拉关闭手势（ui/drag-close.js）
Pointer Events 统一鼠标与触摸。三条判定规则：
- 只有向下拖且超过 8px 才接管，向上推还给内部滚动
- `scrollArea.scrollTop > 0` 时完全不接管
- 位移 > 72px 松手关闭，否则回弹
配合 CSS `touch-action: pan-y`，拖动过程中才写内联 transform，
松手清空内联样式把动画交还 CSS

### 三个浮层统一
底部浮窗 / 子页面 / 模态弹窗共用一套 CSS 状态机：
`transform: translateY(100%)` → `.show` → `translateY(0)`，
最大宽度 640px（桌面居中）。废弃了 `@keyframes pop`（原本是居中弹窗用的）。

### 商店筛选条必须放在滚动容器之外
`.shop-panels` 开了 `overflow-x: auto` 就是滚动容器，
里面的 `position: sticky` 会相对它定位，横向滚动时会被带走。
所以结构是 `.shop-top`（sticky，含 tabs + filter）在 `.shop-panels` 之外。

### 顶栏悬浮展开
`.hud-detail { position: absolute; top: 100% }` 盖在内容之上，不占布局流。
顶栏高度由 `hud.js` 用 offsetHeight 量出来写进 `--hud-h` CSS 变量，
base.css 里有兜底值 `--hud-h: 64px`（JS 未执行时不失效）。

### 图鉴统计
`player.cropStats = { 作物名: { planted, harvested } }`，
farm.js 的 plant/harvest 里埋点。点亮 = harvested > 0，解锁 = level >= crop.lv。
老存档不追溯历史统计。

## 踩过的坑
1. `scroll` 事件**不冒泡**，用 `delegate()` 无效 —— 商店的横向面板改成
   每次重绘后直接挂在新建的容器上
2. tab 同步里写成「切换后补渲染筛选条」会**无限递归**（重绘后 hasFilter 仍为 false）。
   改成筛选条容器常驻、非种子 tab 用 `hidden` 收起
3. `farm.js` 里 `export const unlockedPlotCount = () => unlockedPlotCount(...)`
   自引用会无限递归 —— 把 import 改名成 `countUnlocked` 解决
4. 静态校验第 6 项抓到 `var(--hud-h)` 没有 CSS 定义（只在运行时由 JS 写入），
   逼出了兜底值写法
5. 静态校验第 7 项抓不到 `delegate(root,'click','[data-action="visit"]',...)` 这种
   选择器里写动作名的形式 —— 补成 `const FRIEND_ACTIONS = { visit: ... }` 对象才能被扫到

# 第四轮：修启动崩溃 + 补静态校验盲区

## 用户报的崩溃
```
main.js:68 ReferenceError: ensureDailyReset is not defined
    at initState (state.js:129:3)
```

## 根因
上一轮删除「每日任务」功能时删掉了 `state.js` 里的 `ensureDailyReset()` 函数，
但 `initState()` 里还留着 `await ensureDailyReset()` 这行调用。

## 全量排查后发现是**同一类错误有两处**
| 位置 | 问题 | 触发时机 |
| --- | --- | --- |
| `state.js:129` | 调用已删除的 `ensureDailyReset()` | 游戏启动即崩 |
| `farm.js:183` | 调用已删除的 `player.countWater()` | 浇水时崩 |

还有两处因此失效的 import（`commit`、`dayKey`）和一个死变量 `missing`（收集了
新建地块但从没被用过），一并清掉。

## 关键反思：静态校验为什么没抓到

原有 8 项检查里，语法 / 路径 / 具名导入这三项全都能通过，因为
`player.countWater()` 是**通过命名空间访问**的（`import * as player`），
而第 3 项只检查 `import { a } from` 的具名导入。

## 新增第 9 项检查：命名空间成员调用
```js
const NAMESPACE_IMPORT_RE = /import\s+\*\s+as\s+([A-Za-z0-9_$]+)\s+from\s+['"](\.[^'"]+)['"]/g;
// 再用 new RegExp(`\\b${ns}\\.([A-Za-z0-9_$]+)\\s*\\(`, 'g') 扫调用
```
只匹配 `ns.member(` 的**调用**形式，不匹配 `ns.member` 属性访问（误报率高）。
当前项目 50 处这类调用，全部通过。反向用例已验证能报错：
`✗ player.countWater() 调用的成员没有从 ./player.js 导出`

## 验证方式

# 第五轮：修商店崩溃 + 建立端到端校验

## 用户报的崩溃
```
main.js:68 TypeError: Cannot read properties of undefined (reading 'key')
    at syncTabFromScroll (shop.js:169:68)
```

## 根因
`Math.round(panels.scrollLeft / panels.clientWidth)` —— **商店页在启动时是隐藏的**
（`.page` 只有 `.active` 才显示），`clientWidth` 为 0，`0/0 = NaN`，
`TABS[NaN]` 是 undefined，`undefined.key` 就崩了。
修法：`if (!panels || !panels.clientWidth) return;` + `Number.isFinite` 兜底。

## 重要转折：静态校验抓不到这类问题
用户要求「重新整体校验一下」。我意识到静态校验（语法/导入/DOM id/CSS 变量/数据一致性）
对运行时问题几乎无能为力，于是搭了一套**真实 Chrome 端到端校验**：
- 用托管 node 工作区里已有的 `puppeteer-core` + 系统 Chrome
- 脚本**不进仓库**（项目坚持零依赖），放工作区里跑
- 关键技巧：在页面里 `import('/src/store/state.js')` 拿到与游戏**同一份**模块实例，
  可以精确准备测试前提并直接断言领域层结果

两套脚本（已删除）：
- 表层回归 26 步：启动/HUD/顶栏展开/三主页面/商店tab/邻居弹窗/五个子页面/刷新持久化
- 深度游戏循环 15 步：播种→浇水→施肥→有机肥→收获→卖出→买种→升级土地→偷菜→喂狗→刷新→触摸下拉

## 端到端校验抓出的 5 个真实 bug（静态校验全都没抓到）
1. **`openSubpage` 顺序颠倒** —— `renderCurrent()` 里有 `isOpen()` 判断，
   而 `.show` 是之后才加的，导致**所有子页面内容永远是空的**（仓库/包裹/签到/图鉴/引导全废）
2. **HUD 展开层点开即关** —— `document` 的「点别处收起」监听没排除顶栏本身，
   点击事件冒泡到 document 又把它关掉了
3. **商店 `clientWidth = 0`**（用户报的那个）
4. **拖拽手势把弹窗甩飞**（最隐蔽，桌面端必现）
5. **favicon 404** —— Chrome 默认请求 /favicon.ico

## 第 4 个 bug 的排查过程（值得记住）
症状：点种子卡的「种植」按钮，弹窗自己关掉了，什么都没种上。
- `elementFromPoint(按钮中心)` 返回按钮 —— 看起来按钮在最上层
- 但真实鼠标点击落在 `.modal-mask` 上
- 量 `getBoundingClientRect`：按钮 y=322、卡片 y=126，都对
- 用 rAF 逐帧记录浮层位置 → **点击瞬间卡片跑到了 y=461，还在动画中**
- 顺着查到 `drag-close`：`mousemove` 挂在 window 上，而 puppeteer 的 `mouse.click`
  是 move → down → up，**move 先于 down**，此时 `startY` 还是 0，
  「鼠标绝对 Y 坐标」被当成拖动位移写进了 `panel.style.transform`

修法三条：
1. `move()` 必须检查 `tracking` 标志（有没有按下过）
2. 鼠标的 move/up 只在按下期间 addEventListener，松开立刻 remove
3. 改用 **Touch 事件而不是 Pointer 事件** —— `touch-action: pan-y` 下浏览器接管纵向手势、
   忽略 touchmove 的 preventDefault，Pointer 方案会收到 pointercancel 而中断；
   要用 touchmove + preventDefault 才能抢回手势。
   对应的 CSS：把手和标题栏 `touch-action: none`，滚动容器保持 `pan-y`。
