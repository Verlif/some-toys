# 2026-10-29

## 村庄水晶「挖到却不投入」的排查（未改代码，待定方案）

用户反馈：建设日志里村民已经挖到水晶，但村庄的水晶进度不推进。

### 结论：不是 bug，是设计失衡 —— 挖到的绝大多数是「废档」

`contributeCore`（`src/store/village.js`）有**三道门槛 + 一条频率限制**：

1. **档位必须匹配**：`npc.crystals?.[tier.crystal]`，村庄当前升级要哪一档就只认哪一档。
2. **至少 2 枚才动手**：`if (mine >= 2 && share > 0)`（代码注释「至少留 1 枚给自己」）。
3. **`floor(mine × 性格比例) > 0`**：`greedy 0.15 / merchant 0.2 / leisurely 0.25` 分别要囤 **7 / 5 / 4** 枚才投得出第一枚；其余性格 2 枚即可。
4. `v.giveDay[npc.id] === day` → **一人一天只投一次**。

### 根本问题：水晶档位跟着藏宝图档位走，村民等级追不上

- `rollCrystalDrop(mapTier)` = 50% 概率，档位 = **藏宝图档位**。
- `rollNpcAdventure` 只买「等级够 + 钱够」的**最高档**图；`MAP_TIERS.unlock` = 10 / 30 / 60 / 80 / 100。
- `rollNpcLevel()` = `1 + floor(36 × r^1.7)`，平均约 14 级。
- 实测 20 万次抽样：**能买 1 级图 43.7%、2 级图 12.0%、3 级及以上 0%**，另有 **44.3% 连 1 级图都买不起**。
- 村庄升级要的档位：1→2 要 1 级×20、2→3 要 2 级×48、3→4 要 3 级×88、4→5 要 4 级×144。
- 于是 **3 级、4 级水晶实际上无人能产出**（要 Lv.60 / Lv.80 的图），村庄 3→4 级永久卡死。

### 实测（headless Chrome + 真实 `settleWorld`，把 `nextVisitAt/lastVisitAt/onlineUntil/idleAt/dog.at` 整体回拨 N 天再结算）

> ⚠️ 探针要点：应用启动时已经把世界推到「现在」，只改 `lastSeenAt` 不够 —— 各邻居 `nextVisitAt` 都在未来，4 天窗口里一个人都不会上线（`report.visits` 恒为 0）。必须把时间轴整体回拨。

| 跑了几天 | 上线次数 | 村庄等级 | 当期进度 | 村民手上囤积 | 投入带水晶的条数 |
|---|---|---|---|---|---|
| 6 天 | 1287 | 升到 Lv.2 | 2→3：7/48 水晶 | 1 级 **54** + 2 级 6 | 56 次投入里只有 **3** 次带水晶 |
| 20 天 | 4638 | 升到 Lv.3 | 3→4：**0/88** 水晶 | 1 级 **99** + 2 级 **37** | 61 次投入里 **0** 次带水晶 |

金币与祈福都跟得上（20 天时 130k/260k、177/940），**只有水晶是瓶颈**；囤着的 136 枚水晶档位全对不上。

### 顺带发现的小 bug

`npc-sim.js` 的 `bulkAdvance()` 里 `rollNpcAdventure(npc)` 的返回值被直接丢弃 —— 离线超过 `VISIT_BUDGET`（约半年）时那一段挖到的水晶**直接蒸发**（金币因为函数内部已经改了 `npc.coins`，没丢）。

### 待用户拍板的修复方案

- **A（推荐）**：水晶档位改成「不超过村庄当前需要的档位」——`rollCrystalDrop(mapTier, needTier)` 返回 `min(mapTier, needTier)`，玩家与 NPC 同一条规则。低等级村民挖 1 级图也能为当前的 3 级目标出力，同时玩家也不会囤一堆废料。要改 `rollNpcAdventure` 与玩家侧的调用点，把 `villageTier(level).crystal` 传进去。
- **B**：放宽门槛 `mine >= 1`，`share = max(1, floor(mine × ratio))`（「≥2 才留 1 枚」）。
- **C**：升级时把旧档水晶按 3:1 折算成新档，别让 99 枚 1 级水晶永久滞留存档。

## 第 55 轮：水晶可卖 + 仓库/包裹标签分类（用户方案落地）

用户原话：「把村庄建设中，玩家和NPC获得升级水晶的日志去掉，只是获得就还不算建设，要投入才算；另外把包裹中的分类变成标签分类，仓库也增加标签分类，然后把升级水晶放在"其他"标签中，可以卖出（按升级水晶等级可以卖出500、1000、2000、5000、100000），这样，允许村民根据需要来卖出或是投入了（按照个性，但不能获得就只卖，至少要有一定概率投入）」

### 落地清单

1. **日志语义**：`addCrystal()` 里删掉 `note()`，签名去掉 `at`（三处调用点：`adventure.js` / `social.js` / `npc-sim.js`）。`contributeCore` 的 `note` 用 `if (coins || crystals)` 包住 —— 纯卖水晶不写建设日志。日志里每条都必须是实打实的进度。
2. **仓库标签**：`ui/subpages/bag.js` 重写，`TABS = [🌾农产品, 💠其他]`，`activeTab` 挂模块变量（每动作后 `renderCurrent()` 整页重绘，状态不能进 DOM）。「其他」档放水晶行。
3. **包裹标签**：`ui/subpages/package.js` 删 `section()`，改三档 `🌱种子 / 🧭藏宝图 / 🧪道具`，`EMPTY_TIPS` 按档给空态。
4. **水晶可卖**：`data/village.js` 加 `CRYSTAL_SELL = {1:500, 2:1_000, 3:2_000, 4:5_000}` + `crystalSellPrice(tier)`；`store/village.js` 加 `sellCrystal(tier, n)`。
5. **村民决策**：`CONTRIB_STYLE` 每档加 `crystalInvest`（friendly .85 / diligent .8 / boss .7 / scholar .65 / thrifty .55 / leisurely .45 / merchant .35 / greedy .3）。

### ⚠️ 关键约束（写代码前先读这三条）

- **`crystalInvest` 最低 0.3 是硬约束**：水晶能卖之后若让性格把它推到 0，村民会一拿到就卖光，村庄进度反而比改动前更慢。
- **`floor(2 × 0.15) = 0`** —— 投水晶必须 `max(1, floor(mine × ratio))`，否则「愿意投却投不出」，白掷一次。
- **水晶不进 `state.bag`**：它挂 `farm.village.stock`（玩家）/ `npc.crystals`（村民），卖出入口直接读 `v.stock`。搬进背包要动存档结构、联机校验、图鉴、包裹，只换来「少一处读取」，不值。

### 村民的两条岔路（`contributeCore` 重写的水晶段）

- ① **旧档全卖**：`tier.crystal` 之外的所有档位一律折现（`npc.coins += n × price`）。实测「1 级囤 99 枚、村庄却在要 3 级」正是从这堵死的。
- ② **当前档掷一次**：`mine >= 2` 才动。`< style.crystalInvest` → 投 `min(needCrystals, max(1, floor(mine × style.crystal)))`；否则卖 `mine - 1`（**留 1 枚**，下一天还有机会投）。

### 顺手修的旧 bug

`npc-sim.js bulkAdvance()` 里 `rollNpcAdventure(npc)` 返回值被丢弃 —— 离线超 `VISIT_BUDGET`（约半年）聚合补算那一段挖到的水晶凭空蒸发（金币没丢）。已接上 `ctx?.addCrystal?.(trip.crystal, npc)`。

### 踩坑

- **卖完水晶列表不刷新**：`sellCrystal` 只发 `EVENTS.VILLAGE`，而 `main.js` 挂 `renderCurrent` 的是 `EVENTS.INVENTORY`。补 `emit(EVENTS.INVENTORY)` 才动。
- `.sub-tabs` **不能 `position: sticky`**：子页面自己就是滚动容器，再吸顶会和顶栏抢层级。
- 芯片复用商店 `.filter-chip` + `.chip-num`，与村中心「全部/在线」同一套长相。

### 验证

| 项 | 结果 |
|---|---|
| `npm run check` | ✓ 107 JS / 137 data-action / 271 作物 全通过 |
| 挖到不写日志 | `logBefore 0 → logAfterDug 0`，`stock[1] 5→6` |
| 投入才写日志 | `invest({crystals:2})` → 「农场主 投入了 🔹 1 级升级水晶 ×2」 |

### 遗留

用户给的价位是 **5 个**（500/1000/2000/5000/**100000**），但水晶只有 4 档，第 5 个无档位对应 —— 已按 4 档实现，**待用户拍板**是笔误还是要加第 5 档水晶。

## 第 56 轮：关掉地块文本区内滚动 + 修邻居按钮被卡片裁掉

用户报的两个问题：「把土地格内的文本区域滚动关掉，影响页面滚动了」「邻居页面上，土地按钮在边缘内被吞掉了，按钮的另一半没有出来，直接被土地下边缘截断」。

### ① `.plot-body` 不再滚（`styles/components.css`）

`overflow-y: auto` → `overflow: hidden`，同时删掉 `overscroll-behavior: contain` 与 `scrollbar-width: none` / `::-webkit-scrollbar` 两条（没有滚动条也没有滚动可言）。

**根因**：格子只有一百来像素高，手指落在作物名上就被这个内层滚动容器接管，整页滚不动（想往下翻农场，只在格子里挪几像素）。`overscroll-behavior: contain` 只解决「滑到底传染」，解决不了「手势一开始就被抢」。

**代价实测为零**：最挤的一格（长名 + `+69%` 角标 + 💧缺水 🐛生虫 + 进度条 + 倒计时）紧凑档 `scrollHeight == clientHeight == 73`，一行都没裁。

⚠️ 裁切方向：首尾 `margin: auto` 溢出时归 0，从顶部排、**底部**被裁（留头不留尾）。别用 `justify-content: center`（上下各裁一半，作物名都可能没了）。

### ② `.npc-plot` 删掉 `overflow: hidden`

**根因**：`.plot-hang` 是 `.npc-plot` 的**直接子元素**，卡片自己 `overflow: hidden` 就把探出底边的那 1/4 切平。玩家那边没事，是因为裁切落在 `.plot-main` 上、而按钮是 `.plot-main` 的**兄弟**。

裁切改由 `.plot-body` 承担（它只管文字），卡片保持 `overflow: visible`。

**验证口径**：`.plot-hang` 的 `rect.bottom - 卡片.rect.bottom` 必须 == 按钮高度 × 1/4（30px → **7.5px**）。实测手机 430 / 桌面 1200 都是 7.5，`getComputedStyle(npc-plot).overflow === 'visible'`。
