## 1. 公共用地只占一半宽度

- `.center-main` 从 `1fr 2fr` 改成 `1fr 1fr`。原来公共用地一个人占 2/3，
  公告栏和订单被压进 1/3 里，副标题全成了省略号。
- 现在公告栏/订单 1/2，公共用地 1/2 且仍跨两行 —— 它比上面那条 2fr 的排行榜窄一截。
- 收窄后 `ca-hint` 那行「先到先得 · 熟了摆 1 天换种」放不下，**压短成「先到先得 · 1 天换种」**。
- `.center-act.orders .ca-body` 补 `padding-right: 24px`：徽标绝对定位不占布局，
  会直接盖在「有活干了」的尾字上。

## 2. 从村民弹窗进邻居农场打理后，列表不更新

根因是**弹窗叠层机制**：`modal.js` 的压栈是 `innerHTML` 快照，`closeModal()` 还原出来的
是「打开那一瞬间」的旧内容 —— 刚浇过的水、刚涨的好感都还是旧的。

- `bus.js` 新增 `EVENTS.MODAL_RESTORE`，`modal.js` 还原上一层后 emit。
- `center.js` 的 `mountCenter` 订阅一次，发现当前弹窗里真有
  `[data-role="villager-list"]` 才调 `paintVillagers()`（别的弹窗关掉不受影响）。
- ⚠️ **滚动位置手动接力**：`.modal-body` 是唯一滚动容器，换 list 的 `innerHTML`
  会让内容高度先塌一下、浏览器当场把 scrollTop 夹到 0。存一下、写完再放回去。
- ⚠️ `input.value` **不进 innerHTML**：还原后搜索框是空的而列表还是过滤过的，
  所以搜索词存模块变量 `villagerQuery`，`paintVillagers` 里回填。

## 3. 村民总览卡的头像行改两排

- 总览卡与排行榜卡 `align-items: stretch` 等高，下面本来就空着一截。
- `.co-faces` 改回 `flex-wrap: wrap`，`min-height: 47px`（22×2 + 3）锁住两排的位置，
  人少时也不会忽高忽低。
- `fitFaces()` 改成按 `perRow × FACE_ROWS` 算总容量，仍给「…」留一格。

## 4. 村民弹窗：搜索框 + 底栏标签

- 标题栏右侧加 `.v-search`（`width: 138px` + `min-width: 74px`，空间不够先让输入框收缩）。
  按名字做「包含」匹配，纯前端过滤。
- ⚠️ 输入事件**委托挂 `#modal` 根**，不绑 `<input>` 自己 —— 压栈还原后节点是新的，
  绑在旧节点上的监听跟着一起消失。
- 筛选芯片从列表上方挪进 `.modal-foot`：手机上翻到第 20 位想换档不用滑回顶端。
  `.villager-bar` 的 `margin-bottom: 9px` 归零（底栏自己有 padding）。
- 空态分三种：搜不到 / 这个档位没人 / 全部档就是空的（不显示）。

## 5. 排行榜右列加回名字 + 横滚

- 第 60 轮删名字是因为卡片压到 100px 放不下；现在右列有 1/2 宽，加回来。
- `fitMarquees()`：渲染后量一次 `scrollWidth - clientWidth`，写进
  `--cr-shift` / `--cr-dur`，动画走 `transform` 的 `@keyframes`（合成层，不碰布局与绘制）。
- ⚠️ **不写 `will-change`**（`.yield-pile` 的教训：静态小元素挂它白占显存）；

  `prefers-reduced-motion` 下直接关掉动画。
- ⚠️ checker 要求 CSS 变量必须先声明，默认值写在 `.cr-name` 上（不能只靠 `var()` 的回落值）。

# 第 62 轮：承包地比赛

村中心加一种新玩法：挑一位在线村民下战书，两人各占一块地种同一种作物，
**谁第一次收获的产量高谁赢，赢家拿走两块地的全部产出**。

四个先问清的设计点（用户选的）：

| 问题 | 结论 |
|---|---|
| 熟了能不能自己收 | **都不能收**，可收获时只显示数量 |
| 有没有期限 | **不设期限**，但可中途认输 |
| 种子谁出 | **比赛方出**，不扣玩家背包 |
| 入口放哪 | 村中心**单独一整行**，紧挨公共用地下面；比着的时候那行直接显示两块地状态 |

## 1. 又是一座「没有主人的农场」

沿用第 61 轮公共地的套路：`state.contract` 就是 farm 表里 `id:'contract'` /
`kind:'contract'` 的一行，地块照旧落 plot 表、日志照旧落 log 表 ——
**存储层 / 备份 / 导入校验零改动，不升 `DB_VERSION`**。`farmRows(...)` 现在同时补
commons 与 contract，所以任何走它的落盘都会自动带上这两座。

为什么不塞进玩家农场：两块地要能被**任何人**照料（村民上线顺路也浇一瓢），
而玩家农场那套照料流程只认玩家自己。独立成一行之后，玩家操作和 `npcContractTick`
改的是同一份数据，谁浇水都算数。

## 2. ⚠️ 不能手收 → 产量必须在成熟那一刻摇定

用户原话：「都不能收获，可收获时显示可收获的数量」。

于是 `pendingYield` 这个字段的含义变了 —— 公共地是「熟了才摇」，这里是
**成熟瞬间就必须摇好**，界面上那个「可收获 N 个」直接读它。等结算再摇的话，
两块地摆在那儿熟透，玩家却看不到任何数字，只能干等。

`rollContractRipe(now)` 用 `pendingYield` 非 0 当「摇过了」的哨兵，**幂等**，
两处都调：

- `world.js` tick 的第 ⑦ 步 `advanceContract(next)` —— 正常时间流逝靠它；
- `contractSnapshot(now)` —— 页面开着不动、靠心跳重绘时也靠它。

在失败的情况下必须能重试，所以判重只看 0，不看时间。

## 3. ⚠️ 拒绝概率必须有冷却

`CONTRACT_REFUSE` 从 `friendly 0.02` 到 `greedy 0.30`，没写到的性格兜底 0.15
（将来加新性格不会崩）。但概率本身拦不住连点 —— 玩家点五次，30% 就成了必过。

所以被拒之后记 `cool[npcId] = now + 15min`，`canChallenge` 里挡住。
`normalizeContract` 读档时**只保留未到期的**，过期的顺手删掉（否则这个对象只增不减）。

## 4. ⚠️ 结算/认输的 `persist` 必须带邻居

本轮发现的一个真 bug：初版 `persist()` 只 `farmRows(state.farm)`，
而 `settleContract` 输的分支写的是 `rival.bag` —— 对手赢了，产出进了他的背包，
**但那一行没落盘**，玩家重开就白赢。

改法两步：
1. 先试「无条件带 `...state.friends`」—— 34 座农场全量重写，太重；
2. 改成 `dirty.npcs` 开关，只有 `settleContract` / `surrenderContract` 传 true。

带上时补 `emit(EVENTS.FRIENDS)`（邻居页 / 总览里的背包数字要跟着刷）。
这条与「动了才带」的既有约定一致。

## 5. ⚠️ 入口那一行的 `live` 要排除 done

`match` 在 done 阶段还留着（比分存在里面，等玩家看完再清），
所以 `Boolean(match)` 不等于「正在比」。入口行高亮改成
`Boolean(snap.match) && snap.phase !== 'done'`，`refreshMarks` 里同步一份，
否则上一局结束之后那一行还挂着绿杠。

## 6. ⚠️ 对手不在村里 → 整局作废

`normalizeContract(row, save, aliveIds)` 新增第三个参数。村民是按村庄等级过滤出来的
（`npcsAtVillageLevel`），理论上不会「中途消失」，但存档是人手能改的、导入也认外部文件：
对手 id 找不到人时，这一局永远结算不了（`settleContract` 直接 `找不到对手了`），
玩家会一直盯着一块熟了却点不动的比分。读档时直接清掉 `match` 与地块。

于是 `initState` 里多一条顺序约束：`defs = npcsAtVillageLevel(villageLevel)` 必须
**先于** `normalizeContract` 算 —— 它原来是在下面构造 `state.friends` 时才调的。
（原来那条「contract 行必须在 `rows` 过滤前认领，否则被 `dropFarms` 当孤儿邻居清掉」
依然成立，两条都要。）

## 7. 平局判玩家赢

`contractWinner = (py, ry) => (py >= ry ? 'player' : 'rival')`。

产量是掷出来的，两边完全对等就有可能相等。判平局等于「谁都没拿到产出」，
而用户要的是「获胜方拿走两块地的全部产出」—— 平局这条规则就落不了地。
而且玩家已经先付了 5 点好感、又亲手浇水捉虫，让他赢是合理的。

## 8. 其余口径

- **种子不扣玩家的**：`plantBoth` 直接写两块地，不看背包。
- 池子 `max(玩家级, 对手级)` → `cropsNearLevel` → 滤 `special` → 按等级降序：
  跟邻居日常种植、公共地补种同一套。限定作物只能挖到，比赛能种就谈不上限定。
- 两块地 `readyAt` 完全一致（同一时刻种下）；只有浇水之后才会分开，
  所以 `contractReadyAt` 取**最晚**那块，结算要等最后一块。
- 吃村庄产量倍率、**永远普通土**：两边完全对等，`fert` 恒 false，没有施肥入口。
- 照料给经验 `careExp(crop.lv)`，**不给好感** —— 公共地已经「一次照料全村 +1」，
  这里再给就是新的刷好感路子。
- 村民照料走 `ACTIONS.contract`(sweep) + `ctx.contractTick` → `npcContractTick`，
  50% 门，**两块地谁的都照料**（偶尔帮对手，正是「所有人都可以按照意愿打理」）。
- 认输：好感不退（那 5 点应战时已经花掉了），产出按已摇出的给对手，
  一株都没熟就按 `0 : 0` 记、胜负仍判对手。

## 9. 样式

入口是 `.center-line` 里单独一整行（不占 `.center-main` 的格），
`idle` 态浅绿底 + 右侧「可挑战 26 位」；`live` 态加深底色 +
`inset 3px 0 0 var(--green)` 做左竖条。弹窗里两块地是
`.npc-plots.ct-plots`（`grid-template-columns: repeat(2, 1fr)`，只有两列）。

⚠️ 配色照旧用**底色 + `inset box-shadow`**，不写 `border` —— 会撑高 2px 让两张卡不齐。

## 10. ⚠️ 收尾：那一行原来根本没撑满

肉眼看截图才发现的问题：`.center-act` 是 `<button>`，它的 `width: auto` 是
**shrink-to-fit**（收缩到内容宽），不像 `grid` 里那几格能靠 `align-items: stretch`
拉开。把它单独放进 `.center-line` 这个普通 block 容器之后，它只占内容宽 ——
430 屏上实测 **256px**，右侧空出 148px，看着像半个卡片，跟「单独一整行」完全不是一回事。

修法一句：

```css
.center-line .center-act { width: 100%; }
```

修完 404px（＝行宽 430 − 左右 padding 各 13），与村庄卡、`center-main` 左右边距对齐。
五档宽度复查，判据「卡片宽 == 行宽 − 左右 padding」全部成立：

| 视口 | 卡片宽 | 距行右内边距 | 高 | 右侧状态块 | 文字被截 |
|---|---|---|---|---|---|
| 320 | 294 | 0 | 56 | 64 | 无 |
| 360 | 334 | 0 | 56 | 64 | 无 |
| 430 | 404 | 0 | 56 | 64 | 无 |
| 768 | 742 | 0 | 56 | 64 | 无 |
| 1280 | 874 | 0 | 56 | 64 | 无 |

**教训**：静态校验（`check.mjs`）只查 CSS 变量有没有声明、类名有没有引用，
查不出「flex/grid 容器换成了 block」这类布局语义变化；e2e 当时只断言了高度 56 与
「元素存在」，也没断言宽度。**换容器 = 要重新确认拉伸来源**。

# 第 63 轮：承包地入口换成两块地的卡

用户原话：
> 「承包地比赛按钮上显示的两个土地样子太丑了，要显示种植的作物图标，
> 然后作物下面显示当前状态、剩余时间（动态的）以及所属玩家头像与名字」

三个设计点当场问定（AskUserQuestion）：
**保持单行、右侧两块加高** / **剩余时间一直显示具体时长** / **当前状态用生长阶段名**。

## 1. 右侧从「两行小格」换成「一块地的卡」

旧的 `.ct-cell` 是「小标 + 数字」两行：`你的地 / 🌱 32%`、`他的地 / 🌱 41%`。
问题在于它只报了「进度到了哪」，报不出**种的是什么、这块是谁的** ——
玩家得点进弹窗才知道在比什么，而这一行的意义恰恰是「不点进去也看得见」。

新结构 `.ct-card`（`.ctp-crop` 图标 + `.ctp-txt` 三行）：

```
🌾   🧑‍🌾 农场主         🌾   👩‍🦱 林妹妹
     播种                   播种
     1分34秒                1小时59分
```

四样信息，缺一不可：**作物图标 / 头像 + 名字 / 阶段名 / 剩余时间**。
成熟后后两行换成 `成熟` / `可收 N`，卡片加 `.ripe` 转金底（`#fdf3dc`）。

`idle` / `pick` / `done` 三态**不动**，仍用 `.ct-cell`
（那三态报的是「可挑战 N 位 / 挑种子 / 上一局比分」，本来就没有「两块地」可说）。

## 2. ⚠️ 副标题必须跟着瘦身

卡片把「谁 + 什么作物 + 到哪一步」全报了，副标题再报一遍就是拿同一份宽度打两遍架。
实测 430px 上写全 `vs 王大爷 · 🥦 花椰菜 · 比试中` 时左边只剩 **89px**，被截成
`vs 王大爷 · 🥦 花…`。

砍到**只写 `vs 名字`**（ripe 时加 ` · 都熟了`）之后：430px 标题 112px、副标题不截断。
`contractHintText(snap)` 因此**不再需要 `now` 参数**（原来它是为了算百分比才要的）。

## 3. ⚠️ `contractPlotText()`：渲染与秒表只能有一个口径

```js
export function contractPlotText(plot, now = Date.now()) {
  if (!plot?.cropId) return { stage: '空着', left: '—', ripe: false };
  if (now >= plot.readyAt) {
    return { stage: '成熟', left: `可收 ${plot.pendingYield || 0}`, ripe: true };
  }
  return { stage: stageName(stageOf(plot, crop, now)),
           left: fmtDuration(plot.readyAt - now), ripe: false };
}
```

渲染走它、每秒刷新也走它。两处各写一遍的话，边界那一秒就会出现
「倒计时归零了、状态还写着生长」这种自相矛盾的画面。

## 4. 秒表（`views/center.js` 的 `startContractClock()`）

村中心整体重绘是 `VISIT_POLL_MS = 60_000` 一次 —— 等它刷新的话倒计时看着就是死的。
所以在 `enterCenterPage()` 里挂一个 **1 秒 `setInterval`**（全页只有一份 `contractClock`），
每次先过三道门：

| 门 | 判据 |
|---|---|
| 页面可见 | `document.hidden` 为假 |
| 人还在村中心 | `#center` 存在且 `.closest('#page-center.active')` |
| 确实在比 | `snap.phase` 是 `grow` / `ripe` |

过了门按 `[data-role="ct-card"]` 的 `data-slot` 找回那块地，**只改 `textContent` 与 `ripe` 类**。
重建 DOM 会打断 `:active` 的按下反馈（手指按着、每秒被换个子节点，按下态当场丢）。
先比一次再写（`if (left.textContent !== text.left)`），没变就不碰。

## 5. ⚠️ `fmtDuration` ≥ 1 小时不含秒 —— 断言陷阱

验证「秒表在不在走」时，第一版采样到 `3小时51分`，两次一样，误判成卡死了。
实际是 `fmtDuration` 对 ≥ 1h 的输出只到分钟（`h小时mi分`），一分钟内当然不变。

**确定性验证的正确口径**：把一块地设成 **95 秒后熟**（显示 `1分35秒`，秒位会走），
另一块设 2 小时（`2小时 → 1小时59分`，两分钟内只变一次，正好反证口径）。
实测采样 `1分35秒 → 1分34秒`，秒位在减。
