# 07 · 邻居模拟

32 位固定邻居，各有一座会自己生长的农场。
**没有任何后台定时器**，所有成长都按时间差补算 ——
区别只在于**在线期间也每分钟推进一步**，而且到点之后
邻居的动作是**一件一件演出来**的（见「在线演出」）。

## 每位邻居的五项设定

| 设定 | 作用 |
| --- | --- |
| 性格 `personality` | 收获 / 播种 / 打理的行为权重；`tend` 权重同时决定帮玩家照料的积极性 |
| 职业 `profession` | 纯展示（卡片与详情里显示），让 32 个人各有身份 |
| 上线节奏 `schedule` | 固定钟点型，或 2~16 小时的随机间隔型 |
| 偷菜倾向 `steal` | `never / rare / often / always` → 每次上线 0% / 12% / 45% / 90% 会去顺菜 |
| 起始等级 `level` | **不写死**，开局从 1~36 级里随机掷，且低等级更多；之后无上限成长 |

性格权重见 [03-数据层](./03-数据层.md#邻居配置)。

## 等级：开局 1~36，之后没有上限

名单里不写死等级，`createNpc` 时用 `rollNpcLevel()` 现掷：

```js
// random ** 1.7 把分布压向低端：平均约 14 级，
// 一半以上的邻居落在 13 级以内，30 级以上的只是少数
1 + floor(36 * random ** 1.7)
```

这样玩家一进游戏看到的是一批「高不了几级」的邻居，追得上、也偷得着，
而不是被一个 70 级的村长按在地上。初始身家同样由等级推导
（`npcStartCoins = 300 × level^1.6 × 随机浮动`），不再手写。

**成长没有上限**：邻居和玩家一样，收获 / 播种 / 照料都给经验（同一条
「每份产出 = 等级 + 2」的公式），一路涨到满级 200。实测 1 天后最高 36 级、
30 天后 50 级、365 天后 70 级左右 —— 他们是真的在长大，不是卡在某个数字上。

> 旧存档里等级最高的邻居不会被「打回原形」：`normalizeNpc` 只在等级
> 非法（<1 或 >200）时才重掷，已经长到 50 级的照旧继续长。

## 上线模型

两种节奏并存，「每天几点上线」和「多久来一趟」是两种不同的生活：

```js
// 固定钟点：每天 6 点、18 点各来一次，带 ±30 分钟浮动，免得整点一起冒出来
schedule: { type: 'fixed', hours: [6, 18] }

// 随机间隔：每次上线后掷 3~10 小时
schedule: { type: 'interval', min: 3, max: 10 }
```

`nextVisitAt(npc, at)` 统一算出下一次上线时间：固定钟点型找 `at` 之后最近的
一个钟点，都过了就排到明天第一个；间隔型直接加一段随机时长。

```
上线一次 → 按性格权重执行 2~4 个经营行为
        → 有空地就顺手补种
        → 按偷菜倾向顺一手
        → 按热心程度帮玩家照料一块地
        → 按 schedule 排下一次上线
```

一次上线里不会重复做同一件事（用 `seen` 集合去重，最多重掷 4 次）。

## 行为

| 行为 | 做什么 |
| --- | --- |
| `harvest` 收获 | 收掉所有成熟地，产量折算成金币；多次收获作物进入再生轮次 |
| `plant` 播种 | 把**所有空地一次种满**，作物取自「自己等级往下 10 级」的窗口（至少 8 种），尽量不重样 |
| `tend` 打理 | 给自己的缺水的地浇水、生虫的地捉虫（捉虫会增产） |
| `feedDog` 喂狗 | 存量 ≤ 60 时按 `min(0.55, tend × 0.13)` 的概率给自家守护犬添食（要付得起狗粮钱），勤勉的热心、悠闲的懒散 |
| 顺菜 | 按 `steal` 倾向，从「所有成熟且本轮没被顺过」的地里挑一处 —— **邻居家和玩家农场一视同仁** |
| 帮玩家照料 | 按 `tend × 12%` 的概率，替玩家浇一块地或捉一次虫（只在成熟前动手） |
| 寻宝 | 12% 的概率买一张「等级与金币都够」的最高档藏宝图，按玩家同一套规则算奖励 |

顺菜与帮忙是**额外动作**，不占 2~4 个经营行为的名额：上线再忙也可能顺一手。

## 邻居的守护犬

每位邻居都有一条狗，而且**有品种**，不只是饱腹度。玩家与邻居共用同一个
`dog` 结构（见 [06-领域层](./06-领域层.md#守护犬三层模型)）：

| 字段 | 含义 |
| --- | --- |
| `dog.breed` | 品种 id，决定这条狗的基础拦截率（玩家那边空串 = 全部下岗） |
| `dog.satiety` | 槽内存量快照 |
| `dog.at` | 那个快照的时刻 |

还原任意时刻的存量用 `dogSatietyAt(dog, at)`，与玩家同一套 6.25%/小时衰减
（没有狗上岗时槽不消耗），所以邻居离线再久也不会一直满饱腹地替他看着农场。
上线时按 `min(0.55, tend × 0.13)` 的概率添食。

品种由 `rollNpcDogBreed(level)` 分配，品阶上限
`min(8, max(3, 3 + ⌊level / 12⌋))` —— **下限钉在 3**：邻居的狗要是太弱，
「被抓住就封锁全场」这个惩罚形同虚设，玩家会完全无惧偷菜。

读档时 `normalizeNpc` 会在品种不认识时按等级重掷，槽的读数时刻缺了就用上次上线时间。

玩家偷 NPC 被它的狗抓住时（`catchChance` 与玩家侧同一公式），
**这座农场当前所有带作物的地块**都会被标记 `guarded`——
效果等同于「每块地都已被偷过」，右上角显示 🐕。
`isStealable` 会一并检查这个标记；作物重新种下或进入再生轮次时标记自动清除。

## 顺菜规则

- 每块地的每轮作物只能被顺走 **1 个**，作物重新种下后刷新；
- **偷一个就真的少一个**，不做「产量减半」这种翻倍惩罚；
- 邻居收获时按 `stolenCount` 扣减，玩家收获时同样扣减；
- 被顺走的地剩余产量为 0 时自然就不能再偷了。

NPC 之间互相顺菜也走同一套逻辑：玩家看到的「可偷」地，随时可能在下一次结算时被邻居抢先。

### 挑目标的顺序：先农场，再地块

顺菜不是「把所有成熟地摊平了随便挑一块」，而是先挑农场、再挑地块：

```js
targets = 邻居农场（weight = 1）+ 玩家农场（weight = PLAYER_FARM_WEIGHT = 2）
```

为什么要给玩家加权：玩家有 40 块地，而邻居只有 4~12 块。若按地块平摊，
**邻居越多，玩家被偷的概率反而被稀释得越厉害** —— 加人不会带来危机感，
只是让镇子更热闹。给玩家 2 倍权重后，32 位邻居对玩家的实际偷窃量
大约是 20 位时的 2.4 倍，这才叫「地多招贼」。

## 结算：两段式

把一位邻居从 `nextVisitAt` 一路跑到「现在」。
问题来了：离线一年 = 365 × 2 × 20 = **14,600 次上线会话**，逐条模拟会卡死浏览器。

解法是分两段：

```js
while (npc.nextVisitAt <= now && guard < MAX_VISITS_PER_NPC) {
  if (npc.nextVisitAt < boundary) {
    bulkAdvance(npc, boundary);        // 远期：聚合公式一次性推进
  } else {
    runVisit(npc, npcs, npc.nextVisitAt, farm);   // 近 7 天：逐条模拟 + 记日志
    detailed += 1;
  }
}
```

| 段 | 范围 | 做法 | 动态日志 |
| --- | --- | --- | --- |
| 远期 | 超过 7 天前 | `bulkAdvance` 用公式推进等级、财富、地里作物 | 不记 |
| 近期 | 近 7 天内 | `runVisit` 逐条执行行为 | 记，每位 NPC 保留最近 10 条 |

远期那一段**不会动玩家农场**：只有精细会话才有足够信息还原「谁在什么时候偷了哪块地」。

`bulkAdvance` 只算「总量」不算「过程」：按 `expectedGapMs()` 估算上线次数，
乘以该 NPC 的平均单产得出财富增量，按等级窗口内作物的平均经验给经验，
地里作物按随机进度重建（同样取自等级窗口，且尽量不重样）。

### 实测性能

32 位 NPC，离线 1 天到 10 年（一次 Node 内测，机器不同会有浮动）：

| 离线时长 | 精细会话 | 耗时 |
| --- | --- | --- |
| 1 天 | 10 | 1.4ms |
| 7 天 | 743 | 12.2ms |
| 30 天 | 749 | 7.3ms |
| 365 天 | 733 | 7.5ms |
| 3650 天 | 755 | 6.5ms |

（1 天那行会话少，是因为新建的邻居 `nextVisitAt` 本来就排在几小时之后。）

**离线时长对耗时几乎没有影响** —— 这正是分两段的目的。
超过 7 天的部分都是聚合推进，精细会话数封顶在「7 天能跑多少」。
另有 `MAX_VISITS_PER_NPC = 4000` 作为兜底，正常情况远达不到。

## 数据结构

邻居就是 `farm` 表里 `kind: 'npc'` 的一行，和玩家农场同一个形状：

```js
{
  id, kind: 'npc', name, avatar, level, exp, coins, createdAt,
  personality, profession,
  schedule: { type: 'fixed', hours: [6, 18] } | { type: 'interval', min, max },
  steal: 'never' | 'rare' | 'often' | 'always',
  dog: { breed, satiety, at },   // 守护犬：品种 / 槽内存量 / 读数时刻
  lastVisitAt,   // 上次上线
  nextVisitAt,   // 下次上线 —— 模拟引擎的游标
  plots: [{ id, cropId, harvested, plantedAt, readyAt, total,
            stolen, stolenCount, stolenAt, guarded, boost }],   // plot 子表
  log: [{ at, emoji, text }],                                   // log 子表
}
```

`plots` / `log` 在库里不是这一行的字段，而是 `plot` / `log` 两张子表按
`farmId` 关联的行 —— 存档结构与内存结构见 [05-存储层](./05-存储层.md)。

`nextVisitAt` 落盘后，关掉页面再进来也从这个点接着推演。

地块数量随等级增长：`min(12, 4 + ⌊level / 8⌋)`。

邻居的作物成熟时间与玩家**完全一致**（`npcGrowMs` 就是 `crop.grow`），
没有额外倍率 —— 邻居就是「另一个玩家」。玩家能在邻居收之前赶到，
靠的是熟客式的多次拜访，而不是把邻居调慢。

播种用的作物池由 `cropsNearLevel(level)` 决定：只取「自己等级往下 10 级」
以内的作物；如果这么窄的窗口里凑不满 8 种（高等级作物分布稀疏），
就继续往低等级放宽，避免整座农场只种两三种作物、看起来像复制粘贴。

## 分层

`npc-sim.js` 是**纯计算**：

- 不 import `storage.js`，不落盘；
- 不 import 任何 UI，`requestAnimationFrame` 由调用方（`store/social.js`）驱动；
- 只负责把 NPC 对象从旧状态推到新状态。

它对玩家农场的操作通过**传入的 `farm` 对象**完成。这个对象由
`social.farmView()` 构造（结算与轮询共用同一份）：

```js
{
  id: state.farm.id,           // 写时报时标明来源农场
  plots: state.farm.plots,     // 直接改内存，不经过 storage
  stolen: 0, cared: 0, caught: 0,
  log:  (at, emoji, text) => player.addLog(emoji, text, at),
  news: (at, emoji, text) => addNews(emoji, text, { at, who: state.farm.id }),
  dogGuardChanceAt: (at) => guardChance(at),   // 还原「那一刻」的拦截率
}
```

所以 npc-sim 依然不认识 store，只认识「一个能被偷、能被照料、能写日志的东西」。

落盘在 `social.persistFriends()` —— 邻居结算会动玩家地块与日志，
所以它一次性提交「玩家农场 + 全部邻居农场」（每座农场的行、地块、日志一起写），
不会出现「邻居偷了但玩家地没变」的中间态。

## 一趟上线 = 一串动作

一次上线被拆成三步，**离线结算和在线演出共用同一份实现**：

```js
planVisit(npc)   // 规划：返回动作 key 序列（纯数据，没有副作用）
beginVisit(npc, at)  // 开始：结算狗的饱腹度、把游标推到下一次上线
runStep(npc, at, kind, ctx)  // 执行一个动作，把结果写进 npc.log 并返回这条动态
```

| 动作 key | 做什么 |
| --- | --- |
| `harvest` / `plant` / `tend` | 2~4 个经营行为，按性格权重抽，不重复 |
| `replant` | 收尾补种：有空地才种 |
| `feed` | 饿了就按性格决定喂不喂狗 |
| `steal` | 按偷菜倾向顺一手（先挑农场再挑地块） |
| `help` | 按热心程度帮玩家照料一块地 |
| `adventure` | 12% 概率买张藏宝图去寻宝 |

`beginVisit` 里**必须**推进游标：玩家在线时动作是隔几秒逐个执行的，
不推进的话下一次轮询会把同一趟上线再演一遍。

`simulateNpcUntil(npc, npcs, now, farm, onVisit, deferFrom)` 把一位邻居推进到现在，
每次上线回调一个对象：

```js
{ at, entries, delta, levelBefore, deferred }
```

- `entries` —— 这次新写进 `npc.log` 的动态（记下执行前的数组，之后按
  **对象引用**认新的，不靠时间戳）；
- `delta` —— 这次上线对玩家农场的影响 `{ stolen, cared, caught }`（执行前后计数器差值）；
- `deferred: true` —— 这次上线「到点了但不在这里执行」，
  调用方要给玩家演出，见下节。

「谁在玩家看着的时候上线了」只能靠 `at` 与 `sessionStart` 比出来。

## 世界在线推进

世界不再只在进邻居页时结算，而是**玩家打开游戏期间持续推进**。
`store/social.js` 是这一层的所在地，UI 只负责发提示。

### 会话起点

```js
markSessionStart(now = Date.now());   // boot 时调用一次
```

它记下本次在线会话的起点，是后面所有「离线 / 在线」判定的基准。
`boot` 的顺序很重要：**先 `markSessionStart()` 再 `pollOnline()`**，
这样第一轮只会补算离线期间的事，不会把一堆「XX 上线了」弹给刚进游戏的玩家。

### 结算与轮询

```js
settleWorld(onProgress)   // 分帧跑完全部邻居，返回 { total, visits, summary }
pollOnline()              // settleWorld 一次，把结果分门别类存进两个暂存桶
```

`settleWorld` 的三条约定：

1. **单例去重** —— 模块级 `settlePromise` 做去重，同时只会有一次结算在进行，
   重复调用拿到的是同一个 Promise；
2. **分帧执行** —— 每帧预算 12ms，跑完就让出一帧
   （`requestAnimationFrame`），离线很久也不卡死主线程；
3. **`visits.length > 0` 才落盘** —— 轮询每分钟跑一次，每次都写库太浪费。

`pollOnline` 按上线时刻与 `sessionStart` 的关系把结果分到两个**暂存桶**：

| 桶 | 条件 | 内容 |
| --- | --- | --- |
| `pendingOffline` | `at < sessionStart` | 累加 `stolen` / `cared` / `caught` 与上线次数 |
| `pendingArrivals` | `at >= sessionStart` | 排进演出队列时顺手写一条 `{ name, avatar, text }` |

上线提示只说「谁上线了」，具体干了什么由演出队列在后面一条一条报。

取走用 `takeOfflineSummary()` / `takeArrivals()`，**取过即清空**。
这是**取走式消费**：不这样做的话，「谁先轮询谁先拿到」会变成竞态 ——
两个调用方同时来取，先到的把结果拿走，后到的永远看不到。

> 分层注意：store 只负责**算数据**，提示由 UI 层发
> （`ui/views/friends.js` 的 `showToast`）。store 不引用 UI。

### 谁在什么时候调用

| 调用点 | 做什么 |
| --- | --- |
| `main.js` boot | `markSessionStart()` → `await pollOnline()`（只补离线，不弹上线提示） |
| `main.js` 定时器 | 每 60 秒 `checkOnlineVisits()`，`document.hidden` 时跳过 |
| `visibilitychange` | 切回标签页时立刻 `checkOnlineVisits()` 补一次 |
| `views/friends.js` | 进邻居页时 `enterFriendsPage()`：有积压才显示等待画面 |

`checkOnlineVisits()`（UI 层）：`pollOnline()` → `takeArrivals()`，
一人弹一条、多人合并成一条：

```
👩 李大婶 上线了 · 正在你的农场里转悠
👋 李大婶、小雨、赵老板 等 5 位上线了
```

## 在线演出

玩家在线时，邻居上线**不再一瞬间做完**。

`settleWorld()` 遇到 `at >= sessionStart` 的上线时，只把游标推过去
（`beginVisit`），把「这次要做哪些动作」放进 `liveQueue`，
然后由 `store/social.js` 的 `runLiveStep()` 每隔 **3~7 秒**执行一步：

```
王大爷 上线了 · 正在你的农场里转悠        ← 立刻
  3~7 秒后  🧹 打理了 4 块地，浇了水也除了虫
  再 3~7 秒  🥷 从你的农场顺走了 🥕胡萝卜
  ……跑完整串后，队列里下一位接着来
```

几条约定：

- **一步一落盘**：每做完一个动作就提交一次（玩家农场 + 这位邻居 + 时报），
  玩家这时候关掉页面，已经发生的顺菜与照料都不会丢；
- **队列串行**：同时来了好几位也不会交叉，一位演完再下一位；
- **游标先推进**：不这样做的话，下一分钟的轮询会把同一趟上线重演一遍；
- 每步结束都会 `emit(FARM/FRIENDS/PLAYER)`，所以农场页的地块会当场变灰（被偷了）。

延迟常量在 `data/friends.js` 的 `LIVE_STEP_MS = [3000, 7000]`。

## 等待画面

进邻居页时如果有积压（`pendingWork() > 0`，即 `estimateWork(npcs, now)`），
先显示等待画面再结算：

```js
const work = social.pendingWork();
const overlay = work > 0 ? showSimOverlay() : null;

await social.settleWorld((done, total) => overlay?.update(done, total));
if (overlay) await overlay.close();           // 保证至少展示 650ms
```

结算完成后，如果这段时间里邻居动过玩家的农场，会合并成一条提示：

```
🏡 你不在时：被顺走 3 个作物，邻居帮你照料了 2 块地
```

逐条弹的话离线久了会连弹十几条，所以只给汇总，细节去农场日志里看。

`pendingWork() === 0`（刚上线过，没什么要算的）时**直接跳过等待画面**，
避免每次点进去都被挡一下。

## 玩家能看到的动态

邻居卡片展示最近 3 条摘要，详情弹窗里展示最近 **10 条**（含玩家自己的操作，
比如「农场主 来帮忙浇了水」）：

```
3小时前  🌾 收获了一批作物，+2.4万 💰
5小时前  🥷 从 李大婶 那儿顺走了 🥕胡萝卜
7小时前  🧹 打理了 3 块地，浇了水也除了虫
```

卡片上还有等级、职业、财富（`formatCoins` 自动转「万 / 亿」缩写）、
可偷地块数、待照料地块数。详情弹窗的数据卡里有**守护犬状态**
（🐕 田园犬 · 62% 在看家 / 🐶 饿着，不设防）。
**不显示上线时间** —— 邻居的节奏属于后台逻辑，
摆到界面上只会变成一张要一直盯的时间表。

详情弹窗的结构自上而下是：头部（头像 / 性格 / 职业 / 可偷角标）→ 数据卡 →
**🟫 农场**（地块网格 + 一键照料条）→ **📜 最近操作**（10 条日志）→ 底部提示。
农场地块的两个角标不占正文排版：左上角是产量加成（+10~30% 绿 / +40~60% 橙 /
+70~100% 金红），右上角是「这一轮为什么不能再偷」（🥷 已被偷 / 🐕 被狗盯上）。
这样地块上有几个操作按钮都不会把按钮挤下去。

模拟过程中值得上电视的大事（升级、被狗抓、寻宝大奖、邻居互偷）
还会通过 `farm.news` 回调写进**时报**（底部「📰 时报」tab，见 `store/news.js`）。

## 加一位邻居

`data/friends.js` 的 `NPCS` 数组加一条即可：

```js
{
  id: 'npc33', name: 'XXX', avatar: '🐝', personality: 'diligent',
  profession: '养蜂人',
  schedule: { type: 'interval', min: 4, max: 12 }, steal: 'rare',
}
```

等级与身家不用写：`createNpc` 会按 1~36 的加权分布现掷。
存档里没有这位邻居时，`initState` 会按 id 差集补建 —— 本轮把名单从 20 位
扩到 32 位，靠的就是这条。

**加人之前先想清楚动机**：单纯加人不会让人更容易被偷（见「挑目标的顺序」），
要提危机感得动 `PLAYER_FARM_WEIGHT` 或 `STEAL_CHANCE`。
