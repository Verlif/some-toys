# 07 · 邻居模拟

15 位固定邻居，各有一座会自己生长的农场。**没有任何后台定时器**，
所有成长都在玩家进入邻居页时按时间差补算。

## 在线模型

每个 NPC 有一个「下次上线时间」：

```
上线一次 → 按性格权重执行 2~4 个行为
        → 重新掷一个 8~16 小时的间隔
        → 待机
```

8~16 小时（平均 12 小时）正好是**每天 2 次**。

```js
function rollGap() {
  return randInt(VISIT_GAP_MIN, VISIT_GAP_MAX);   // 8h ~ 16h
}
```

一次上线里不会重复做同一件事（用 `seen` 集合去重，最多重掷 4 次）。

### 行为与权重

| 行为 | 做什么 |
| --- | --- |
| `harvest` 收获 | 收掉所有成熟地，产量折算成金币；多次收获作物进入再生轮次 |
| `plant` 播种 | 在空地上种一个当前等级能种的作物，35% 概率种当前最好的几种之一 |
| `tend` 打理 | 清除地里的杂草与害虫（有实际收益：杂草会减产） |
| `steal` 偷菜 | 60% 概率去别的 NPC 农场顺走一个成熟作物，把对方那块地标记为 `stolenAt` |
| `adventure` 冒险 | 16% 概率触发；45% 概率暴富（获得当前财富 0~50% 的金币），其余空手而归 |

性格权重见 [03-数据层](./03-数据层.md#邻居配置)。

## 结算：两段式

玩家进入邻居页时，对每个 NPC 从 `nextVisitAt` 一路跑到「现在」。
问题来了：离线一年 = 365 × 2 × 15 = **10,950 次上线会话**，逐条模拟会卡死浏览器。

解法是分两段：

```js
while (npc.nextVisitAt <= now && guard < MAX_VISITS_PER_NPC) {
  if (npc.nextVisitAt < boundary) {
    bulkAdvance(npc, boundary);          // 远期：聚合公式一次性推进
  } else {
    runVisit(npc, npcs, npc.nextVisitAt, true);   // 近 7 天：逐条模拟 + 记日志
    detailed += 1;
  }
}
```

| 段 | 范围 | 做法 | 动态日志 |
| --- | --- | --- | --- |
| 远期 | 超过 7 天前 | `bulkAdvance` 用公式推进等级、财富、地里作物 | 不记 |
| 近期 | 近 7 天内 | `runVisit` 逐条执行行为 | 记，每位 NPC 保留最近 6 条 |

`bulkAdvance` 只算「总量」不算「过程」：按天数估算上线次数，
乘以该 NPC 的平均单产得出财富增量，按当前等级可种作物的平均经验给经验，
地里作物按随机进度重建。

### 实测性能

15 位 NPC，离线 1 天到 10 年：

| 离线时长 | 精细会话 | 耗时 |
| --- | --- | --- |
| 1 天 | 31 | 1.8ms |
| 7 天 | 213 | 2.7ms |
| 30 天 | 202 | 3.0ms |
| 365 天 | 204 | 2.6ms |
| 3650 天 | 200 | 2.0ms |

**离线时长对耗时几乎没有影响** —— 这正是分两段的目的。
所以「不封顶」和「不卡死」才能同时成立。

另有 `MAX_VISITS_PER_NPC = 4000` 作为兜底，正常情况远达不到。

## 被偷过的地怎么恢复

用**时间戳**而不是布尔标记：

```js
export function isStealable(plot, now = Date.now()) {
  if (!plot.cropId || now < plot.readyAt) return false;
  return !plot.stolenAt || now - plot.stolenAt > STEAL_COOLDOWN;   // 10 分钟
}
```

时间到了自然恢复，不需要任何清理任务，也不会因为页面关着而卡住。
这正是「不用后台定时器」能成立的前提 —— 早期版本用 `stolen: boolean` +
20 秒轮询清理，改造时一并去掉了。

NPC 之间互相偷菜也走同一套逻辑：玩家看到的「可偷」地，随时可能在下一次结算时被邻居抢先。

## 数据结构

```js
{
  id, name, avatar, personality,
  level, exp, coins,
  plots: [{ cropId, harvested, plantedAt, readyAt, total, stolenAt }],
  lastVisitAt,   // 上次上线
  nextVisitAt,   // 下次上线 —— 模拟引擎的游标
  log: [{ at, emoji, text }],
}
```

`nextVisitAt` 落盘后，关掉页面再进来也从这个点接着推演。

地块数量随等级增长：`min(12, 4 + ⌊level / 8⌋)`。

邻居的作物成熟时间是玩家的 **4 倍**（`NPC_GROW_SLOWDOWN`），
这是「去偷菜」有意义的前提 —— 否则玩家总能在邻居收之前赶到。

## 分层

`npc-sim.js` 是**纯计算**：

- 不 import `storage.js`，不落盘；
- 不 import 任何 UI，`views/friends.js` 里才用 `requestAnimationFrame`；
- 只负责把 NPC 对象从旧状态推到新状态。

落盘在 `social.persistFriends()`，分帧调度在 `ui/views/friends.js` 的 `enterFriendsPage()`。

正因为没有 DOM 依赖，我能在 Node 里直接压测它。

## 等待画面

`enterFriendsPage()` 的流程：

```js
const settler = social.createSettler();
const overlay = settler.total > 0 ? showSimOverlay() : null;

await new Promise((resolve) => {
  const frame = () => {
    const finished = settler.run();          // 单帧预算 12ms
    overlay.update(settler.done, settler.total);
    if (finished) resolve();
    else requestAnimationFrame(frame);
  };
  requestAnimationFrame(frame);
});

await social.persistFriends();
await overlay.close();                       // 保证至少展示 650ms
```

`settler.total === 0`（刚上线过，没什么要算的）时**直接跳过等待画面**，
避免每次点进去都被挡一下。

`overlay.close()` 有最短展示时长，因为结算只花几毫秒，
不加这个的话进度条会一闪而过，玩家只会觉得「闪了一下」。

## 玩家能看到的动态

卡片上展示最近 3 条：

```
3小时前  🌾 收获了一批作物，+2.4万 💰
5小时前  🥷 从 李大婶 那儿顺走了 🥕胡萝卜
7小时前  🎲 去山里转了一圈，空手而归
```

加上等级、财富（`formatCoins` 自动转「万 / 亿」缩写）、可偷地块数、
在线状态（离线时显示「X 小时后上线」）。

## 加一位邻居

`data/friends.js` 的 `NPCS` 数组加一条即可，字段：

```js
{ id: 'npc16', name: 'XXX', avatar: '🧑‍🌾', personality: 'diligent', level: 30, coins: 15000 }
```

新存档会自动建；老存档走 `normalizeNpc` 补字段。
**不会**给已有存档追加新 NPC —— 这是有意的，避免老玩家的世界突然多一个人。
需要的话在 `initState` 里按 id 差集补建即可。
