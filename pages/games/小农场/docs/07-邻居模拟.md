# 07 · 邻居模拟

52 位固定邻居（开局 32 位 + 随村庄升级搬来 20 位），各有一座会自己生长的农场。
**没有任何后台定时器**，所有成长都按时间差补算 ——
区别只在于**在线期间也每分钟推进一步**，而且到点之后
邻居的动作是**一件一件演出来**的（见「在线演出」）。

## 每位邻居的五项设定

| 设定 | 作用 |
| --- | --- |
| 性格 `personality` | 收获 / 播种 / 打理的行为权重；`friendly` 决定与所有人**天生的好感度** |
| 职业 `profession` | 纯展示（卡片与详情里显示），让 52 个人各有身份 |
| 上线节奏 `schedule` | 固定钟点型，或 1~8 小时的随机间隔型（第 45 轮整体砍半） |
| 偷菜倾向 `steal` | `never / rare / often / always` → 顺菜概率 0 / 18% / 65% / 95%（第 47 轮再经 `interactChance` 翻倍，实际约 0 / 33% / 88% / 99.7%） |
| 起始等级 `level` | **不写死**，开局从 1~36 级里随机掷，且低等级更多；之后无上限成长 |
| 入场村庄等级 `arrive` | 村子升到几级时这一户才搬进来（缺省 1 = 开局就在）。第 53 轮新增 |
| 等级区间 `levelRange` | 只有新住户写，`[2, 4]` 这样的区间，取代 `rollNpcLevel()` |

性格权重见 [03-数据层](./03-数据层.md#邻居配置)。

## 村子长大，邻居才搬进来（第 53 轮）

开局只有 32 位原住民。村子每升一级，搬进来 5 户新人家：

| 村庄等级 | 新住户 | 农场等级 |
| --- | --- | --- |
| Lv.2 | 小满 / 老陶 / 阿珍 / 二狗 / 沈婆婆 | 2~4 |
| Lv.3 | 阿福 / 陆老师 / 铁牛 / 温姑娘 / 老蔫 | 4~6 |
| Lv.4 | 金娃 / 林场长 / 苗苗 / 老秦 / 胡掌柜 | 6~8 |
| Lv.5 | 白先生 / 大鹏 / 翠婶 / 小北 / 老陈 | 8~10 |

三条实现约束：

1. **读档按村庄等级过滤**，不是照单全收 —— `initState()` 用
   `npcsAtVillageLevel(state.farm.village.level)`。老档里可能存着
   「村子还没升级却已经写进库」的新住户，直接 `map(NPCS)` 会让他们提前入住。
2. **新住户的时间要按到当下**。`createNpc` 会给所有人把上次上线推到
   2~20 小时前（让老邻居一进游戏就看着像离线过一段），但新住户不行：
   世界时钟会拿 `nextVisitAt` 往前补算，等于让他们**入住之前**就在村里
   串了二十小时的门、顺了二十小时的菜。所以 `admitVillageNeighbours`
   会把 `lastVisitAt` / `nextVisitAt` / `dog.at` 全部重设成 `now`。
3. **升级时要连邻居一起落盘**。`invest()` / `pray()` 原来只
   `commit({ farms: [state.farm] })`，新请进来的 5 户只活在内存里，刷新就没了。
   现在两处都写成 `farms: [state.farm, ...state.friends]`。

新住户的初始好感由 `seedRelations()` 按性格补 —— 传全量 id，
它自己会跳过已经有记录的那些对。

## 等级：开局 1~36，之后没有上限

名单里不写死等级，`createNpc` 时用 `rollNpcLevel()` 现掷：

```js
// random ** 1.7 把分布压向低端：平均约 14 级，
// 一半以上的邻居落在 13 级以内，30 级以上的只是少数
1 + floor(36 * random ** 1.7)
```

这样玩家一进游戏看到的是一批「高不了几级」的邻居，追得上、也偷得着，
而不是被一个 70 级的村长按在地上。初始身家同样由等级推导
（`npcStartCoins = 300 × level^1.6 × 随机浮动`），不再手写。

**成长没有上限**：邻居和玩家一样，收获 / 播种 / 照料都给经验（同一条
「每份产出 = 等级 + 2」的公式），一路涨到满级 200。实测 1 天后最高 36 级、
30 天后 50 级、365 天后 70 级左右 —— 他们是真的在长大，不是卡在某个数字上。

⚠️ **第 44 轮起邻居的升级门槛是玩家的 2 倍**（`npc-sim.js` 的 `NPC_EXP_MULT = 2`，
`gainExp` 里阈值与扣减都用 `expForLevel(level) * 2`）。玩家的 `expForLevel` 没动 ——
邻居只是「同样的活、涨得慢一些」。上面那串实测等级是按 1 倍写的，现在整体会更慢一档：
邻居本来就是背景角色，涨太快会挤掉玩家自己的成长感。

> 旧存档里等级最高的邻居不会被「打回原形」：`normalizeNpc` 只在等级
> 非法（<1 或 >200）时才重掷，已经长到 50 级的照旧继续长。

## 上线模型

两种节奏并存，「每天几点上线」和「多久来一趟」是两种不同的生活：

```js
// 固定钟点：每天 6 点、18 点各来一次，带 ±30 分钟浮动，免得整点一起冒出来
schedule: { type: 'fixed', hours: [6, 18] }

// 随机间隔：每次上线后掷 3~10 小时
schedule: { type: 'interval', min: 3, max: 10 }
```

**第 45 轮：间隔整体砍半。** 上线一次要隔 8~16 小时的话，玩家守一晚上也未必碰上谁 ——
而「碰上了才有戏」的玩法（交易、偷菜、帮忙照料、被狗逮住）全靠这个碰上。
于是 32 位的间隔全部对折：间隔型 `min/max` 各除以 2（最短 1~4 小时，最长 4~8 小时），
固定钟点型把 `hours` 里的钟点**翻倍**（`[6,18]` → `[0,6,12,18]`），
`DEFAULT_INTERVAL` 也从 `{8,16}` 改成 `{4,8}`。`expectedGapMs()` 是顺着这两个值算的，
所以离线结算的估时、以及「回来时邻居干了多少事」会跟着自动对齐，不用另外改。

⚠️ **`schedule` 只认名单，不吃存档。** `normalizeNpc` 早先写的是
`schedule: row.schedule || def.schedule`，老档里那份旧区间会永远盖住名单里的新值 ——
砍半之后老玩家一点变化都感觉不到。现在固定写成 `schedule: def.schedule`：
性格 / 职业 / 节奏 / 偷菜倾向都是「这个人是谁」的一部分，属于策划调数值的地方；
等级、身家、地块、游标才是玩家养出来的，才该从存档里读。

`nextVisitAt(npc, at)` 统一算出下一次上线时间：固定钟点型找 `at` 之后最近的
一个钟点，都过了就排到明天第一个；间隔型直接加一段随机时长。

```
上线一次 → 按性格权重执行 2~4 个经营行为
        → 有空地就顺手补种
        → 按偷菜倾向顺一手（只在**好友**里挑，好感越低的人越容易被盯上）
        → 按交情帮别人料理一块地（好感越高越愿意跑腿）
        → 按交情给谁送一份产出
        → 没在进行中的订单就按概率张榜收购
        → 从订单看板接一条交得起的单交货
        → 掷一次好友事务（20%：够格就向玩家递申请，不够格就找村民互加）
        → 按 schedule 排下一次上线
```

一次上线里不会重复做同一件事（用 `seen` 集合去重，最多重掷 4 次）。

## 在线窗口

上线不只是一个时刻，还有一段「挂机」时间：`beginVisit` 把
`onlineUntil = 上线时刻 + onlineMs(npc)` 写上，时长按**性格**定基调、
**身份**（职业关键词）微调，整体夹在 **5~15 分钟**（第 44 轮整体砍半，
原来 10~30 分钟 —— 玩家在线时绿点挂太久，串门像没完没了）：

| 性格 | 时长（分钟） | | 身份关键词 | 微调 |
| --- | --- | --- | --- | --- |
| 勤勉 / 热心 | 13~15 | | 退休 | +2 |
| 爱钻研 | 11~14 | | 司机 / 主播 | −2 |
| 场面人 | 9~13 | | 学生 / 技术员 / 老师 | −1 |
| 精打细算 / 生意人 | 8~11 | | | |
| 悠闲 | 5~8 | | | |
| 爱占便宜 | 5~8 | | | |

窗口内好友页名字后是绿点、头像是全彩；窗口外是灰点 + 头像降饱和
（`grayscale(.55)`，减色不全灰）。两个下游规则：

- 偷**在线**的邻居没有任何额外代价（第 61 轮起罚款整条取消、好感本来就不动，
  原来的「双倍罚款」已不存在）；
- 窗口内他还会**时不时做点事**（见下节）。

只有精细访问走 `beginVisit`，远期聚合（`bulkAdvance`）不设在线态 ——
别让上古上线也「在线」。

### 在线空闲：把 5~15 分钟填满（第 48 轮）

早先一趟上线只做 2~4 件经营的事（加顺路收尾约十几次尝试），而演出节奏是
3~7 秒一步 —— 一分钟就演完了，**剩下十几分钟他只是一颗亮着的绿点**：
自家地里熟透的没人收、旱了没人浇。玩家看到的是「邻居明明在线，农场一片狼藉」，
非常出戏。

现在在线期间每 **1~3 分钟**（`IDLE_MS`）顺手做一件事，排程存在 `npc.idleAt` 上
（跟着存档走，刷新页面不会重头算）。挑什么由 `planIdle` 决定，优先级是
**自家 → 别人**：

```
① 自家有熟透的      → harvest
② 自家有缺水/生虫的  → tend
③ 自家有空地        → plant
④ 都没事            → 掷 IDLE_SOCIAL_CHANCE（0.35），过了从
                      steal / care / gift / feed / adventure / order / fill / pray /
                      contribute / friend / commons 里等概率抽一件
```

第 ④ 步的动作内部还有自己的概率门（顺菜 33% / 送礼 25~55% / 帮忙 ~90%），
所以「抽到」不等于「一定发生」。

第 58 轮加的 `commons`（公共用地）也是第 ④ 步里的一件，同样有两道概率门：
有自己能拿的熟地时 65% 抢收一份，没有熟地时 50% 去浇水 / 捉虫（各占一半）。
顺序刻意排成「先收后照料」—— 熟菜放着不拿，一分钟后可能就被别人拿走了。
它写**两处**：公共地日志（`state.commons.log`，`by` 是这个村民的 id），
以及他自己的动态（`runStep` 统一写，文案是「在公共地拿走一份 X」）。

**提示口径分两条路，别当成 bug**：

| 路径 | 会不会弹 toast | 为什么 |
| --- | --- | --- |
| 在线空闲（`world.js` 的 `idleOnce`） | 不弹 | 每 1~3 分钟一次，弹了就是刷屏；它只对「动到玩家农场」的动作弹 |
| 上线这一趟的演出（`social.js` 的 `runLiveStep`） | 弹 | 一趟上线才几次，玩家正好该知道「有人去公共地抢了」—— 这是参与感的一部分 |

⚠️ **刚上线的 90 秒不做空闲动作**（`IDLE_AFTER_VISIT_MS`）：玩家在线时
「上线这一趟」是 3~7 秒一步演的，十几个动作要跑一分多钟；空闲动作一起插进来
就会**抢跑** —— 队列里那个收获变成空动作，玩家看到「他上线了」却没看到他收菜。

⚠️ **只有动到玩家农场的动作才弹 toast**（偷菜 / 帮忙 / 送礼 / 被狗赶走）：
邻居自家收菜、自己喂狗只写他的动态。否则挂机十分钟会被刷十几条。

### 投不投村建设，看这个人是谁（第 51 轮）

`contribute` 是第 ④ 步里能抽到的一件，但**投入多少由性格决定**（`village.js` 的
`CONTRIB_STYLE` + `contribStyleOf(npc)`）：

| 风格 | 谁 | 出手 |
| --- | --- | --- |
| 积极参与 | 热心 / 勤勉 / 场面人 | ratio 与 cap 都上浮，水晶几乎必投 |
| 意思意思 | 悠闲 / 爱占便宜 / 生意人 | 大幅下调，常常只投一点点甚至不投 |

`CONTRIB_DEFAULT` 兜住未知性格（新加的性格忘了配也不会投出 NaN）。

**第 55 轮：水晶也能卖了，所以还要掷一次「投还是卖」。** `CONTRIB_STYLE`
多了一个 `crystalInvest`：

| 风格 | crystalInvest | 意思 |
| --- | --- | --- |
| 热心 friendly | 0.85 | 几乎都投进村 |
| 勤勉 diligent | 0.80 | |
| 场面人 boss | 0.70 | |
| 爱钻研 scholar | 0.65 | |
| 精打细算 thrifty | 0.55 | |
| 悠闲 leisurely | 0.45 | |
| 生意人 merchant | 0.35 | 更愿意换钱 |
| 爱占便宜 greedy | 0.30 | 三次里投一次 |

⚠️ **最低 0.3，不能再低**：水晶有了卖出口之后，如果让性格把它推到 0，
村民就会一拿到就卖光，村庄进度反而比「根本不能卖」时更慢。
另外「村庄当前用不上的档位」不受这个概率约束，**一律卖掉** —— 留着永远用不上。

⚠️ **第 53 轮去掉了「（很上心）」「（意思意思）」**。原本文案想说明性格差异，但玩家读建设日志
时以为那是 bug 提示 —— 而差异本来就体现在数量上，写出来反而喧宾夺主。现在只记投入了什么。

⚠️ **第 55 轮起建设日志不再记「挖到了 X 级升级水晶」**：捡到只是捡到，
不算给村子做了什么。现在日志里只有「投入了 …」，卖水晶也只写进邻居自己的动态。

为什么值得做这个区分：村庄进度条是**所有人一起推**的，如果每个人出手一样多，
那几十位邻居就只是几十份同样的薪水。性格决定了谁在推、谁在看，玩家才会记住
「王大爷是那个总在投钱的人」。

离线补算时同样跑这一段（它就在世界时钟的 `tick` 里，只是不弹提示），
所以「离线期间邻居在自家地里干活」也能被算进去，第二天回来看到的是
一片被照料过的农场，而不是长满虫子的荒地。

## 订单（张榜收购与互通有无）

NPC 有自己的小仓库（`bag`）：收获时按性格保留**一部分或全部**入库、其余卖成金币
（`KEEP_RATIO`：生意人 15% → 精打细算 / 爱占便宜 **100%**，总上限 60 件，放不下的照卖）。

第 47 轮把上限从 70% 抬到**允许全留**：这两个性格的邻居一件都不卖，
等订单上门再出货 —— 「他家仓里有货」才撑得起订单系统。兜底是仓库上限：
塞满 60 件之后自动回到「收多少卖多少」，不会一贫如洗也不会撑爆存档。

**看榜种地**（`actPlant`）：播种前先扫一眼看板，榜上有人收的作物排在最前面。
271 种作物随机种，仓库里恰好压着订单要的那一味的概率低得可怜 ——
不这么排，「NPC 也会完成订单」就永远停在理论层面：谁都接不了单，订单只能等过期退钱。

订单是一条纯数据（落在农场行上，不新增表）：

```js
{ id, ownerId, itemId, qty, reward, createdAt, deadline }
```

- **发单**（`actOrder`）：上线时手里没有订单才掷，约 30% 概率（生意人 ×1.6、
  场面人 ×1.4）。需求从 **1 级 ~（NPC 自己等级 + ORDER_LEVEL_FLOAT=5）** 之间随机抽，
  **不看玩家等级** —— 高阶邻居就该开出高阶单，接不了是玩家自己的取舍
  （2026-10-24 用户明确要求，早先是「取两者较低等级」）。赏金 = 售价 ×1.2×
  数量，**当场从 NPC 金币托管**（掏不出就不张榜）。期限 1~3 天，每人同时 1 条。
- **接单**（`actFill`）：上线时浏览看板，挑一条不是自己发的、仓库凑得齐的，
  每次上线最多 1 条；优先接玩家的单，其余按赏金挑。完成一笔，接单方与下单方
  **好感 +5**，物品从接单方仓库转给下单方（玩家则进包裹），托管赏金归接单方。
- **玩家侧**：订单页交单 / 发布（赏金托管，上限 5 条）/ 撤销（退还）；
  过期清扫挂在 `settleWorld` 上，退还下单方。
  **列表行直接标「够不够」**（第 44 轮）：`npcRowHTML` 按 `count(order.itemId)` 与
  `order.qty` 渲染 `✅ 够交（N）` 或 `还差 N 个（owned/qty）` —— 原来要挨个点开详情
  才知道自己凑不凑得齐，一屏七八单就是七八次点击。

发单与接单都走 `simCtx` 注入的 `orders()` / `removeOrder()` ——
npc-sim 始终不认识 store。

## 交易：跟邻居按原价买产出

订单是「他有需求、你有货」，交易是反过来的一笔：**他仓库里有货，你要买**。
入口在邻居农场弹窗的**「💬 互动」弹窗**里（第 47 轮从主弹窗的两颗并排按钮收进去，
和送礼、催促上线放在一起）—— 他不在线时那一行压淡、点了只提示「等他上线」。

规则：

| 项 | 口径 |
| --- | --- |
| 商品 | 邻居 `bag` 里所有 `crop_*` 且 `CROPS` 认得的产出，按等级从高到低排 |
| 价格 | **原价** `crop.sell`（不是收购价）—— 邻居不是二道贩子，贵在「现在就要」 |
| 好感消耗 | `tradeRelCost(lv, qty) = max(1, round(lv × qty / 2))` |
| 前置 | **邻居必须在线**（`isNpcOnline`）；离线时按钮灰着、清单也开不出来 |
| 钱去哪 | 进邻居口袋（`friend.coins += 总价`），他才有钱买种子继续种 |

实现分三层，和送礼一个套路：

1. `tradeStock(friend)` —— 有什么、各多少（纯读，给清单用）；
2. `tradeQuote(friendId, cropId, qty)` —— **纯函数报价**：能不能做、总价多少、掉多少好感。
   校验顺序是「在线 → 有没有货 → 数量够不够 → 金币够不够 → 好感够不够」，
   任何一条不过就返回 `{ok:false, reason}`，界面直接拿去显示；
3. `buyFromFriend()` —— 只在真正按下确认时执行：扣钱、扣货、进包裹、扣好感、落盘、发通知。

界面上的份数步进器每动一下就重算 `tradeQuote` 的等价结果（`confirmTrade` 里的 `paint()`），
**不碰任何状态** —— 玩家在弹窗里来回拨份数不应该扣他五次好感。
金币或好感有一头不够，确认按钮当场灰掉，让玩家看见卡在哪。

> 好感是这游戏里最贵的资源（送一次礼也就涨几点），所以交易清单的每一行
> 都直接把「每份花 −N 好感」写在行上，确认框里再摆一次「关系从哪一档掉到哪一档」。

## 行为

| 行为 | 做什么 |
| --- | --- |
| `harvest` 收获 | 收掉所有成熟地，产量折算成金币；多次收获作物进入再生轮次 |
| `plant` 播种 | 把**所有空地一次种满**，作物取自「自己等级往下 10 级」的窗口（至少 8 种），尽量不重样 |
| `tend` 打理 | 给自己的缺水的地浇水、生虫的地捉虫（捉虫会增产） |
| `feedDog` 喂狗 | 存量 ≤ 60 时按 `min(0.95, tend × 40%)` 的概率（第 47 轮起再翻倍）给自家守护犬添食（要付得起狗粮钱），勤勉的热心、悠闲的懒散 |
| 顺菜 | 按 `steal` 倾向，从「所有成熟且本轮没被顺过」的地里挑一处 —— **邻居家和玩家农场一视同仁** |
| `care` 帮忙照料 | 按 `min(0.90, tend × 30%)` 的概率（第 47 轮起再翻倍，热心的接近 99%），替**某个交情够好的农场**浇一块地或捉一次虫，一次最多 2 块（玩家与别的邻居一视同仁，只在成熟前动手）；帮一块 +1 好感。**好感 ≥100 的亲近档优先**：有就只从里面挑，一个都没有才回退全量 |
| `gift` 送礼 | 挑交情最好的那家，再按概率掷一次：**≥100 走 `closeGiftChanceFor × 性格系数`**（100 → 25%，200 → 55%；热心 1.4 ~ 爱占便宜 0.5），<100 维持老门槛 `giftChanceFor`；第 47 轮起两档都再翻一倍。送玩家的是**真东西**（进背包 + 弹窗），送邻居的只是人情 |
| 寻宝 | 12% 的概率买一张「等级与金币都够」的最高档藏宝图，按玩家同一套规则算奖励 |

顺菜、帮忙、送礼是**额外动作**，不占 2~4 个经营行为的名额：
上线再忙也可能顺一手。

`care` 与 `gift` 挑目标时都读好感度（`helpWeightFor` / `giftChanceFor`），
但**好感只决定挑谁，不决定做不做** —— 做不做还是看性格与概率。
玩家农场照旧乘 `PLAYER_FARM_WEIGHT = 2`，所以地多还是招贼，只是「招谁的贼」变了。

唯一的例外是**亲近档（≥100）那道坎**：上线优先登门打理这些农场，
打理完还按性格系数加权概率顺手送一份 —— 是一条完整的「串门」。

> 旧版有个 `help` 动作，只帮玩家、且不看关系。现在换成 `care`：
> 邻居之间也会互相帮忙，镇子才像一个镇子。

### 邻居之间的好感度

邻居 ↔ 邻居同样有关系值，起点也是性格平均，之后靠「互相打理 / 互相送礼 /
互相顺菜」变化。它带来的效果是可见的：**总来偷你菜的那个人，也在偷别人的**，
而交情好的两家会互相送东西 —— 玩家在时报里能看到这些，但插不上手。

关系值由 `store/social.js` 通过 `simCtx()` 注入（`rel` / `relAdjust` / `receiveGift` / `daily`），
`npc-sim.js` 本身不 import 任何 store，保持纯计算。
`daily` 是每日排行榜的记账漏斗：每个动作把「谁、做了什么、发生在哪一刻」
交给 `store/daily.js` 归到正确的日期（见 [06-领域层](./06-领域层.md#每日排行榜)）。

## 邻居的守护犬

每位邻居都有一条狗，而且**有品种**，不只是饱腹度。玩家与邻居共用同一个
`dog` 结构（见 [06-领域层](./06-领域层.md#守护犬三层模型)）：

| 字段 | 含义 |
| --- | --- |
| `dog.breed` | 品种 id，决定这条狗的基础拦截率（玩家那边空串 = 全部下岗） |
| `dog.satiety` | 槽内存量快照 |
| `dog.at` | 那个快照的时刻 |

还原任意时刻的存量用 `dogSatietyAt(dog, at)`，与玩家同一套 6.25%/小时衰减
（没有狗上岗时槽不消耗），所以邻居离线再久也不会一直满饱腹地替他看着农场。
上线时按 `min(0.85, tend × 0.28)` 的概率添食。

品种由 `rollNpcDogBreed(level)` 分配，品阶上限
`min(8, max(3, 3 + ⌊level / 12⌋))` —— **下限钉在 3**：邻居的狗要是太弱，
「被抓住就封锁全场」这个惩罚形同虚设，玩家会完全无惧偷菜。

读档时 `normalizeNpc` 会在品种不认识时按等级重掷，槽的读数时刻缺了就用上次上线时间。

玩家偷 NPC 被它的狗抓住时（`catchChance` 与玩家侧同一公式），
**这座农场当前所有带作物的地块**都会被标记 `guarded`——
效果等同于「每块地都已被偷过」，右上角显示 🐕；**不罚款**（第 61 轮）。
`isStealable` 会一并检查这个标记；作物重新种下或进入再生轮次时标记自动清除。

NPC 偷玩家被狗赶走时同理：`farm.caught += 1`、记一条玩家日志与时报、
给玩家的狗记一次「狗狗王」，**同样不动钱** —— 原来那笔「NPC 倒贴罚款」
也一起删掉了，理由是同一件事只该有一种后果。

## 顺菜规则

- 每块地的每轮作物只能被顺走 **1 个**，作物重新种下后刷新；
- **偷一个就真的少一个**，不做「产量减半」这种翻倍惩罚；
- 邻居收获时按 `stolenCount` 扣减，玩家收获时同样扣减；
- 被顺走的地剩余产量为 0 时自然就不能再偷了。

NPC 之间互相顺菜也走同一套逻辑：玩家看到的「可偷」地，随时可能在下一次结算时被邻居抢先。

### 挑目标的顺序：先农场，再地块

顺菜不是「把所有成熟地摊平了随便挑一块」，而是先挑农场、再挑地块：

```js
targets = 邻居农场（weight = stealWeightFor(好感)）
        + 玩家农场（weight = PLAYER_FARM_WEIGHT(2) × stealWeightFor(好感)）
```

`stealWeightFor` 在好感 200 时给 0.2、−200 时给 2.2 ——
**仇家被偷的概率是挚交的 11 倍**。所以「跟谁结怨」是有后果的。

为什么要给玩家加权：玩家有 40 块地，而邻居只有 4~12 块。若按地块平摊，
**邻居越多，玩家被偷的概率反而被稀释得越厉害** —— 加人不会带来危机感，
只是让镇子更热闹。给玩家 2 倍权重后，32 位邻居对玩家的实际偷窃量
大约是 20 位时的 2.4 倍，这才叫「地多招贼」。

## 催促上线（花好感买时间）

玩家在邻居农场的「💬 互动」里可以**催他上线**：花 `SUMMON_REL_COST = 20` 点好感，
换他尽快出现。交情决定响应速度，公式在 `data/relation.js` 的 `summonDelayRange(rel)`：

```
t  = (rel + 200) / 400        ∈ [0, 1]，挚交 = 1
下限 = 1s   × 300^(1-t)        t=1 → 1s     t=0 → 5 分钟
上限 = 30s  × 20^(1-t)         t=1 → 30s    t=0 → 10 分钟
```

中间按**指数**插值，不是线性：交情越往上越难得，每多 100 分的提速也该越来越明显
（0 分时是 17 秒~2 分钟；线性的 2.5~5 分钟像谁都在磨洋工）。

实现只有三行：`npc.nextVisitAt = min(原游标, now + 随机延迟)`、扣好感、落盘。
**不新造一条「被催促的上线」通道** —— 到点他走的是和平时完全一样的流程
（`beginVisit` 开在线窗口、`planVisit` 抽动作、在线演出一件件做），
不加数值加成、也不保证一定帮你干活。

到点由 `scheduleSummon()` 的定时器**叫醒世界时钟**（`pollOnline`），
而不是等下一分钟的轮询：说好 30 秒到，让玩家干等一分钟就完全不是「催促」了。
定时器 +300ms 缓冲，免得差那几百毫秒被判成「还没到点」。

⚠️ 定时器只活在内存里。中途刷新页面不会丢：`nextVisitAt` 已落库，
下次开机世界时钟从「上次离开」往前推，照样让他在那个时刻上线
（只是那会儿玩家不在，算进离线补算）。

## 结算：世界时钟

第 46 轮之前是「每位邻居各算各的」：7 天内逐条跑，更早的一次性聚合。
问题是离线一个月回来，前 23 天既没有过程也记不上排行榜，地块还是按随机进度
重造的。现在整个镇子只有**一个驱动**：时间。

`store/world.js` 的 `advanceWorld({ from, to, ctx, deferFrom, onVisit, onProgress })`
从「上次离开」逐段走到「现在」，每一段把这段里到点的事按先后做完：

```
每一段：
  ⓪ 在线窗口到头的邻居「下线了」（只在玩家看着时提示）
  ① 邻居上线（按 nextVisitAt 升序，不是按数组顺序）
  ①' 在线中的邻居顺手做点小事（自家 → 别人）
  ② 订单到期（赏金退还）
  ③ 榜单跨 14:00 结算（必须在这一期的动作都记完之后）
  ④ 制造间收炉
  ⑤ 自动机器干活（浇水 / 捉虫 / 收获，不给经验）
  ⑥ 公共用地补种（空地种上、刚熟的摇产量、拿光或摆满 1 天的清空重种）
```

⑥ 是第 58 轮加的，返回 `true` 时置 `report.dirty` ——
这一段里可能一个邻居都没上线，只推进了公共地，全靠这次标记才会落盘。

### 步长是自适应的

| 离线跨度 | 步长 |
| --- | --- |
| ≤ 7 天 | 1 分钟 |
| 7~14 天 | 2 分钟 |
| 14~28 天 | 4 分钟 |
| 每翻一倍 | 再翻一倍 |
| 封顶 | 60 分钟 |

（`data/world.js` 的 `stepMsFor()`。）为什么可以粗：邻居上线间隔是小时级、
照料窗口也是小时级，2~8 分钟的步长只让动作发生时刻偏几分钟，不改变任何数值；
而步长不放大，离线一年就是 52 万次循环。

⚠️ **动作的时刻用真实时间戳，不用步点**。一段里到点的是 `nextVisitAt`，
日志、榜单记账、订单计时都按它写，所以粗步长不会把「上午的活」记成「下午」。

### 离线特别久时的降级

步长解决的是「循环次数」，解决不了「上线次数」——离线一年约 5 万次上线。
`VISIT_BUDGET = 30_000` 是一道预算线：超了就把**最早的一段**交给
`bulkAdvance`（聚合公式：等级、金币、地块照常推进，没有逐条过程），
最近的一段仍然一分钟一分钟地走。时间轴上会如实标一句「更早的部分按汇总补算」。

正常玩家永远碰不到（30 天约 6000 次上线）。

⚠️ 被聚合掉的那一段里**公共用地也不推进**，这是刻意的：公共地不会自己
「收了再种」循环，地里最多长到成熟就停住等人拿，所以「现在这一刻」的状态
永远由最近那段逐条推进算对。离线三天回来看到的是「一轮已熟」，
不是「三轮已经轮完」—— 这一点与邻居农场的补算口径不同，别照着改。

### 落盘只在最后

补算期间所有跨表动作（榜单发奖、订单退款、出种子）都走 `quiet` 模式：
**改内存、不写库、不弹提示**，补算结束由 `flushAwards()` 统一写一次。

⚠️ 这条不是优化而是必需：早先每条订单过期都 `commit` 一次，headless 实测
365 天要 **18 秒**，改完之后 **0.4 秒**。

### 实测性能

32 位 NPC，headless Chrome，430×900（机器不同有浮动）：

| 离线时长 | 上线次数 | 耗时 |
| --- | --- | --- |
| 3 天 | ~520 | 0.2s |
| 30 天 | ~6000 | 0.6s |
| 365 天（触发降级） | ~1400 | 1.3s |

## 数据结构

邻居就是 `farm` 表里 `kind: 'npc'` 的一行，和玩家农场同一个形状：

```js
{
  id, kind: 'npc', name, avatar, level, exp, coins, createdAt,
  personality, profession,
  schedule: { type: 'fixed', hours: [6, 18] } | { type: 'interval', min, max },
  steal: 'never' | 'rare' | 'often' | 'always',
  dog: { breed, satiety, at },   // 守护犬：品种 / 槽内存量 / 读数时刻
  lastVisitAt,   // 上次上线
  nextVisitAt,   // 下次上线 —— 模拟引擎的游标
  onlineUntil,   // 在线窗口截止时刻（性格+身份 10~30 分钟，见 onlineMs）
  bag: { crop_xxx: n },          // 自己的小仓库：收获按性格留一部分
  order: { id, ownerId, itemId, qty, reward, createdAt, deadline } | null,
  plots: [{ id, cropId, harvested, plantedAt, readyAt, total, soil,
            stolen, stolenCount, stolenAt, guarded, boost,
            waterNext, pestNext, waterTimes, pestTimes }],      // plot 子表
  log: [{ at, emoji, text }],                                   // log 子表
}
```

`plots` / `log` 在库里不是这一行的字段，而是 `plot` / `log` 两张子表按
`farmId` 关联的行 —— 存档结构与内存结构见 [05-存储层](./05-存储层.md)。

好感度不在农场行上：它是**两个 id 之间**的东西，单独一张 `relation` 表
（`[a, b]` 复合主键，`a < b`）。邻居地块的照料字段与玩家完全同一套，
见 [06-领域层](./06-领域层.md#照料机制缺水与虫害)。

`nextVisitAt` 落盘后，关掉页面再进来也从这个点接着推演。

地块数量随等级增长：`min(12, 4 + ⌊level / 8⌋)`。

邻居的作物成熟时间与玩家**完全一致**（`npcGrowMs` 就是 `crop.grow`），
没有额外倍率 —— 邻居就是「另一个玩家」。玩家能在邻居收之前赶到，
靠的是熟客式的多次拜访，而不是把邻居调慢。

播种用的作物池由 `cropsNearLevel(level)` 决定：只取「自己等级往下 10 级」
以内的作物；如果这么窄的窗口里凑不满 8 种（高等级作物分布稀疏），
就继续往低等级放宽，避免整座农场只种两三种作物、看起来像复制粘贴。

## 分层

`npc-sim.js` 是**纯计算**：

- 不 import `storage.js`，不落盘；
- 不 import 任何 UI，`requestAnimationFrame` 由调用方（`store/social.js`）驱动；
- 只负责把 NPC 对象从旧状态推到新状态。

它对玩家农场的操作通过**传入的 `farm` 对象**完成。这个对象由
`social.farmView()` 构造（结算与轮询共用同一份）：

```js
{
  id: state.farm.id,           // 写时报时标明来源农场
  plots: state.farm.plots,     // 直接改内存，不经过 storage
  stolen: 0, cared: 0, caught: 0,
  log:  (at, emoji, text) => player.addLog(emoji, text, at),
  news: (at, emoji, text) => addNews(emoji, text, { at, who: state.farm.id }),
  dogGuardChanceAt: (at) => guardChance(at),   // 还原「那一刻」的拦截率
}
```

所以 npc-sim 依然不认识 store，只认识「一个能被偷、能被照料、能写日志的东西」。

落盘在 `social.persistFriends()` —— 邻居结算会动玩家地块与日志，
所以它一次性提交「玩家农场 + 全部邻居农场」（每座农场的行、地块、日志一起写），
不会出现「邻居偷了但玩家地没变」的中间态。

## 一趟上线 = 一串动作

一次上线被拆成三步，**离线补算和在线演出共用同一份实现**：

```js
planVisit(npc, at, ctx)  // 规划：返回动作 key 序列（纯数据，没有副作用）
beginVisit(npc, at)      // 开始：结算狗的饱腹度、把游标推到下一次上线
runStep(npc, at, kind, ctx)  // 执行一个动作，把结果写进 npc.log 并返回这条动态
```

动作本身全部注册在 `npc-sim.js` 的 **`ACTIONS` 表**里（第 46 轮重构）。
加一个新行为 = 往表里加一条，不用再动规划、执行、演出任何一处：

```js
export const ACTIONS = {
  harvest: {
    label: '收获',
    main: 'harvest',          // 占性格名额时，取 PERSONALITIES.weights 里的同名键
    sweep: true,              // 每趟上线再顺路试一次（不受名额限制）
    can: (npc, at) => npc.plots.some((p) => p.cropId && p.readyAt <= at),
    run: (npc, at, ctx) => actHarvest(npc, ctx, at),
  },
  …
};
```

| 字段 | 作用 |
| --- | --- |
| `main` | 进入「这一次上线的 2~4 件事」的加权抽签池 |
| `sweep` | 抽完之后再顺路试一次；收获 / 打理 / 补种 / 喂狗 / 顺菜 / 帮忙 / 送礼 / 冒险 / 订单 / 公共用地都挂它 |
| `can` | **只用来过滤 `main` 的候选池**，必须便宜且无副作用 |
| `run` | 真正干活，做不成返回 `null` |

三个关键约定：

1. **`can` 不给 `sweep` 用**。它在规划那一刻算，而收获会在执行途中腾出空地，
   补种必须等那之后再看有没有地 —— 交给 `run` 自己判断。
   旧版 `planVisit` 固定塞 14 个动作、一半返回 `null`，现在抽签抽到的都能做成。
2. **`harvest` 与 `tend` 必须同时挂 `main` 和 `sweep`**（第 44 轮的教训）：
   只挂 `main` 的话，那 2~4 个名额没抽到它，这一趟就既不收自家作物也不打理自家地，
   玩家看着「XX 上线了」却发现农场毫无变化。
3. **动作必须幂等可空跑**：`sweep` 里的动作每趟都会被执行一次，
   没事可做时返回 `null`，不会刷出空动态。

`beginVisit` 里**必须**推进游标：玩家在线时动作是隔几秒逐个执行的，
不推进的话下一次轮询会把同一趟上线再演一遍。

`runVisit(npc, ctx, at)` 一口气跑完整趟（离线补算用），返回
`{ levelBefore, results }` —— `results` 是这一趟做成的动作（带 `emoji` / `text`，
给时间轴判断「谁给玩家交了单」）。世界时钟每跑完一趟，回调一个对象：

```js
{ npc, at, entries, delta, levelBefore, deferred, steps? }
```

- `delta` —— 这次上线对玩家农场的影响 `{ stolen, cared, caught }`（执行前后计数器差值）；
- `deferred: true` —— 这次上线「到点了但不在这里执行」，
  调用方要给玩家演出，见下节；
- `steps` —— 只有递延时才带：这一趟要演的动作序列已经规划好了。

「谁在玩家看着的时候上线了」在 `world.js` 里按 `at >= deferFrom` 判断。

## 世界在线推进

世界不再只在进好友页时结算，而是**玩家打开游戏期间持续推进**。
`store/social.js` 是这一层的所在地，UI 只负责发提示。

### 会话起点

```js
markSessionStart(now = Date.now());   // boot 时调用一次
```

它记下本次在线会话的起点，是后面所有「离线 / 在线」判定的基准。
`boot` 的顺序很重要：**先 `markSessionStart()` 再 `pollOnline()`**，
这样第一轮只会补算离线期间的事，不会把一堆「XX 上线了」弹给刚进游戏的玩家。

### 结算与轮询

```js
settleWorld(onProgress)   // 让世界时钟从「上次离开」推到「现在」
pollOnline(onProgress)    // settleWorld 一次，把结果分桶，并返回时间轴
```

`settleWorld` 的三条约定：

1. **单例去重** —— 模块级 `settlePromise` 做去重，同时只会有一次结算在进行，
   重复调用拿到的是同一个 Promise；
2. **分帧执行** —— 每帧预算 12ms，跑完就让出一帧
   （`requestAnimationFrame`），离线很久也不卡死主线程；
3. **有变化才落盘** —— 轮询每分钟跑一次，每次都写库太浪费；
   跨表的（榜单奖励 / 订单退款 / 出种子）最后统一 `flushAwards()` 写一次。

起点 `from = min(worldCursor, lastSeen())`：

- `lastSeen()` 优先读存档里的 `progress.lastSeenAt`（每次结算与页面隐藏时写），
  老存档没有就退回「最早的待办上线」，再兜一层 8 小时；
- `worldCursor` 是「世界已经推到哪」，在线心跳每次都从它往前推一分钟。
  两者取小，保证「页面藏了半小时再切回来」也不会漏掉那半小时。

**在线 / 离线的分界**由 `deferFrom` 决定：只有「刚刚这一分钟」到点的上线才演给
玩家看（`deferFrom = sessionStart`）；间隔超过 2 分钟的（说明页面被冻住了），
这段时间的事已经过去，直接算完不演出。

上线提示**当场发**（第 48 轮修）：`enqueueVisit` 里直接
`emit(EVENTS.ARRIVAL, { name, avatar, text: '上线了' })`。

早先它是攒进 `pendingArrivals`、等 60 秒后那次轮询才弹的 —— 而动作 3~7 秒后
就开始演了，于是玩家先看到「金链哥收了一茬菜」，过一会儿才被告知「金链哥上线了」，
催上线时尤其出戏。现在事件排在动作之前，一句「谁上线了」永远先到。

下线也在同一层：`world.js` 的 `noteDepartures()` 在每段推进的**开头**
（上线处理之前）检查有没有谁的 `onlineUntil` 落在 `(prev, next]` 里，
有就 `emit(EVENTS.DEPARTURE)`。放在上线之前是因为「上一趟刚走、这一趟又来」
时两个时刻同在一段内，先跑上线会把 `onlineUntil` 改到新窗口上，那声「下线了」就发不出来。

两条通知都只在玩家在场时发（`until >= deferFrom`）：离线补算跨过几十个下线时刻，
一次性弹一串「XX 下线了」毫无意义。

离线期间的汇总仍然走**取走式消费**：`pendingOffline` 累加
`stolen` / `cared` / `caught` 与上线次数，`takeOfflineSummary()` 取过即清空。
不这样做的话，「谁先轮询谁先拿到」会变成竞态 —— 两个调用方同时来取，
先到的把结果拿走，后到的永远看不到。

> 分层注意：store 只负责**算数据**，提示由 UI 层发
> （`ui/views/friends.js` 的 `showToast`）。store 不引用 UI。

### 谁在什么时候调用

| 调用点 | 做什么 |
| --- | --- |
| `main.js` boot | `markSessionStart()` → `await pollOnline()`（只补离线，不弹上线 / 下线提示） |
| `main.js` 定时器 | 每 60 秒 `checkOnlineVisits()`，`document.hidden` 时跳过 |
| `visibilitychange` | 切回标签页时立刻 `checkOnlineVisits()` 补一次 |
| `views/friends.js` | 进好友页时 `enterFriendsPage()`：有积压才显示等待画面 |

`checkOnlineVisits()`（UI 层）：只管 `pollOnline()` 与重绘名单 ——
提示由事件总线自己送到 `views/friends.js`，一人弹一条、400ms 内的多人合并成一条：

```
👋 李大婶 上线了
💤 李大婶 下线了
👋 李大婶、小雨、赵老板 等 5 位上线了
```

## 在线演出

玩家在线时，邻居上线**不再一瞬间做完**。

`settleWorld()` 遇到 `at >= sessionStart` 的上线时，只把游标推过去
（`beginVisit`），把「这次要做哪些动作」放进 `liveQueue`，
然后由 `store/social.js` 的 `runLiveStep()` 每隔 **3~7 秒**执行一步：

```
王大爷 上线了 · 正在你的农场里转悠        ← 立刻
  3~7 秒后  🧹 打理了 4 块地，浇了水也除了虫
  再 3~7 秒  🥷 从你的农场顺走了 🥕胡萝卜
  ……跑完整串后，队列里下一位接着来
```

几条约定：

- **一步一落盘**：每做完一个动作就提交一次（玩家农场 + 这位邻居 + 时报），
  玩家这时候关掉页面，已经发生的顺菜与照料都不会丢。
  ⚠️ 第 58 轮起这一步**还要带公共用地**（走 `state.js` 的 `farmRows()`）：
  演出队列里可能排着 `commons` 动作（村民顺手去公共地抢收一份），
  只写 player + npc 的话账本留在内存里，玩家重开就能把同一份再拿一遍；
- **整趟共用一份 `ctx`**（第 44 轮修）：`enqueueVisit` 时建一次 `simCtx()` 挂到
  visit 上，后面的每一步都用它。早先每步都新建一份 `farmView()`，于是
  `bagDirty`（邻居交货给玩家的产出要不要落盘）与 stolen / cared / caught 计数
  都是「每步归零」—— 玩家农场上的汇总数永远是最后一步的那一个；
- **收尾补一次 `syncNpcPlots`**（第 44 轮修）：这趟演出里邻居可能升级了，
  离线路径的 `runVisit` 结束时会补新地块，在线演出原先漏了，于是「升到 Lv.N
  却还是老地块数」；现在收尾统一补，并且顺带把 `bagDirty` 一起落盘；
- **队列串行**：同时来了好几位也不会交叉，一位演完再下一位；
- **游标先推进**：不这样做的话，下一分钟的轮询会把同一趟上线重演一遍；
- 每步结束都会 `emit(FARM/FRIENDS/PLAYER)`，所以农场页的地块会当场变灰（被偷了）；
- 某一步抛异常时只记日志、不中断整趟（`console.error` 带上邻居与动作名），
  但这一步的动作就算跳过了 —— 所以动作实现里不要靠抛错来控制流程。

延迟常量在 `data/friends.js` 的 `LIVE_STEP_MS = [3000, 7000]`。

## 等待画面与离线报告

启动与进好友页时，如果有积压（`social.pendingSpan() > 60s`）就先显示等待画面。
进度按**时间比例**算，不按会话数 —— 会话数是掷出来的，做不得准：

```js
const span = social.pendingSpan();                  // 距离上次离开多久
const overlay = span > 60_000 ? showSimOverlay() : null;

await social.settleWorld((p) => overlay?.update(p));  // p = { at, from, to, percent }
if (overlay) await overlay.close();                   // 保证至少展示 650ms
```

画面上的字是「正在补算到 10/24 14:32…」，比早年那句「正在推演 743 次上线活动」
诚实得多 —— 玩家能对上时间。

### 离线时间轴（超过 2 小时）

`pollOnline()` 会返回一份时间轴（`world.createReport()`）：

```js
{ from, to, visits, stolen, cared, caught, degraded, dirty,
  days: { '2026-10-24': { visits, stolen, cared, caught, levelUps, awards, notes } } }
```

按**自然日**（0 点切）分桶，和排行榜的 14 点账期是两套口径，别混。
`notes` 只留「有料」的事（被顺走、狗拦下、有人升级、帮你交单），
每天上限 6 条（`REPORT_NOTES_PER_DAY`）。

离开超过 **2 小时**（`data/world.js` 的 `REPORT_MIN_SPAN`）才弹
`ui/offline-report.js` 那一层：四个总账格子 + 按天列表（最多展开最近 10 天）。
两小时以内的零碎离开只用好友页那句汇总：

```
🏡 你不在时：被顺走 3 个作物，邻居帮你照料了 2 块地
```

⚠️ 弹之前要等出榜庆祝播完（`waitBoardCelebrate()`）：离线补算可能连着结算
好几天的榜，名次卡片一张一张播，两个全屏层叠在一起谁也看不清。

## 玩家能看到的动态

邻居卡片展示最近 3 条摘要，详情弹窗里展示最近 **10 条**（含玩家自己的操作，
比如「农场主 来帮忙浇了水」）：

```
3小时前  🌾 收获了一批作物，+2.4万 💰
5小时前  🥷 从 李大婶 那儿顺走了 🥕胡萝卜
7小时前  🧹 打理了 3 块地，浇了水也除了虫
```

卡片上还有等级、职业、财富（`formatCoins` 自动转「万 / 亿」缩写）、
可偷地块数、待照料地块数。
**不显示上线时间** —— 邻居的节奏属于后台逻辑，
摆到界面上只会变成一张要一直盯的时间表。

详情弹窗自上而下是四段：

```
头部（头像 / 性格 / 职业 / 可偷角标）
数据卡（2×2：等级 / 身家 / 地块 / 好感）
🟫 农场控制台   ← 两行，跟着地块一起滚
地块网格
🎁 送份礼 + 底部提示
```

**农场控制台**把原来散在三处的三样东西收成一块（高约 84px）：

| 行 | 左（读数） | 右（动作） |
| --- | --- | --- |
| 第一行 | 🟫 农场 N 块 | 🚿 一键浇水 · 🧴 一键杀虫（角标 = 待处理块数） |
| 第二行 | 🐕 品种 + 迷你粮槽 + 存量（饿了转红） | 🦴 添狗粮（有粮且槽未满才出现）· 📜 日志 |

守护犬的状态决定「偷菜会不会被逮住」，所以做成进度条摆在访客眼前，
原来它占着数据卡整整一行，还只有一句「62% 在看家」。
控制台是普通文档流，**故意不做 sticky** —— 滚到哪儿退到哪儿，不会一直压在地块上。

**🦴 添狗粮要先过确认框**（`confirmFeedDog`）：花的是访客自己包裹里的狗粮，
点了就没了一份，所以弹一层叠层摆清楚代价 —— 狗粮槽 `before% → after%`、
包裹现有 / 添完后剩余几份，外加一句「这会消耗你包裹里的 1 份狗粮」，
NPC 邻居还标「好感 +1」（联机好友没有好感体系，不标）。
确认才扣粮，和送礼的「送出前确认」同一个次序。

**📜 日志**点开是独立浮层（`openModal` 叠层，最近两天），关掉能回到农场、
滚动位置不变。早先它是常驻在页面最底部的一段 168px 滚动区，
一进邻居农场要滚很久才摸得到送礼按钮。
农场地块的两个角标不占正文排版：左上角是产量加成（+10~30% 绿 / +40~60% 橙 /
+70~100% 金红），右上角是「这一轮为什么不能再偷」（🥷 已被偷 / 🐕 被狗盯上）。
这样地块上有几个操作按钮都不会把按钮挤下去。

模拟过程中值得上电视的大事（升级、被狗抓、寻宝大奖、邻居互偷）
还会通过 `farm.news` 回调写进**时报**（村中心里的「📢 公告栏」看，见 `store/news.js`）。

## 加一位邻居

`data/friends.js` 的 `NPCS` 数组加一条即可：

```js
{
  id: 'npc33', name: 'XXX', avatar: '🐝', personality: 'diligent',
  profession: '养蜂人',
  schedule: { type: 'interval', min: 4, max: 12 }, steal: 'rare',
}
```

等级与身家不用写：`createNpc` 会按 1~36 的加权分布现掷。
存档里没有这位邻居时，`initState` 会按 id 差集补建 —— 本轮把名单从 20 位
扩到 32 位，靠的就是这条。

**加人之前先想清楚动机**：单纯加人不会让人更容易被偷（见「挑目标的顺序」），
要提危机感得动 `PLAYER_FARM_WEIGHT` 或 `STEAL_CHANCE`。
