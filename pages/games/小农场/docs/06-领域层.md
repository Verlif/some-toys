# 06 · 领域层

`src/store/` 是唯一的「可以改状态」的地方，纯业务逻辑，**不出现任何 DOM 符号**。

## mutator 与落盘分离

`player.js` 里函数分两类：

```js
// 内存操作，不落盘
export function addCoins(amount) { ... }
export function spendCoins(amount) { ... }
export function addExpRaw(amount) { ... }

// 落盘 + 广播
export async function flushPlayer() {
  await commit({ farms: [state.farm] });
  emit(EVENTS.PLAYER);
}
```

分成两半是为了**合并事务**：一次收获里金币、经验、地块、背包的变化
应该进同一个 IndexedDB 事务，而不是各写一次。

`inventory.js` 整体是内存操作（`add` / `take` / `count` / `has`），
落盘交给调用方的 `commit`。

## 新档：开局礼包

第一次进游戏（存档里没有玩家那一行）时，`initState()` 会先给仓库放一份家当，
再让界面弹一张清单（`ui/starter-gift.js`）。规则全在 `data/starter.js`：

| 东西 | 数量 | 为什么是这个 |
| --- | --- | --- |
| 当前等级的种子 | 6 颗 | 正好占满开局的 6 块地，一轮就能看见收获 |
| 洒水器 / 杀虫剂 / 采收机 | 各 3 个 | 各 200 金币，新人不会主动买；先用几次才知道「一键」值不值 |
| 狗粮 | 3 袋 | 1 袋 = 狗粮槽 +45，三袋正好喂满一个槽 |

「当前等级的种子」挑的是**等级不超过玩家等级**里最高那一档，
同档里挑**长得最快**的，再平手挑种子便宜的：

```js
// data/starter.js
export function starterCropId(level) { /* lv <= level，取 max lv，再按 grow 升序 */ }
```

所以 1 级玩家拿到的是胡萝卜（1825 秒 ≈ 30 分钟）而不是同样 1 级的小麦（90 分钟）——
开局要能在一轮内看见收获，玩家才留得下来。

三个实现细节：

- **只在新档发**：判据是 `initState()` 里 `playerRow` 不存在，读档路径不走这段，
  所以刷新页面不会重复发；
- **不走 `inventory.add()`**：那一步会顺手记「图鉴已收集」，而种子 / 道具不该算收集；
  直接写 `state.bag` 更准确；
- **弹窗是一次性的**：礼包内容存在 `state.js` 的模块级变量里，
  `takeStarterGift()` 取过即清空 —— 存档里没有必要记「我领过礼包」，
  能进游戏就说明已经发过了。同时往农场日志写一条 `🎁 收到新手礼包：…`，
  玩家事后翻日志还能看见当时给了什么。

## 等级与上限

升级所需经验是累加式的，只跟等级有关：

```
expForLevel(n) = 200 × n + expForLevel(n-1)      // 即 100 × n × (n+1)
```

```js
export function addExpRaw(amount) {
  const farm = state.farm;
  farm.exp += amount;
  while (farm.level < MAX_LEVEL && farm.exp >= expForLevel(farm.level)) {
    farm.exp -= expForLevel(farm.level);
    farm.level += 1;
  }
  if (farm.level >= MAX_LEVEL) farm.exp = 0;   // 满级后不累积
  // ...
}
```

三个细节：

1. `while` 而不是 `if`，因为一次收获可能连升好几级。
2. 满级后把经验**清零**而不是留着 —— 否则 `expForLevel(200)` 返回 `Infinity`，
   HUD 会显示 `0 / Infinity`。清零 + HUD 特判「已满级」最干净。
3. 需要「按等级折算经验」的地方（如签到奖励）用 `expForProgress()`，
   它在满级时返回最后一级的值而不是 `Infinity`。

升级时会顺带 `notify` 并广播给村镇，**但不再送地** —— 地块要花金币买（见下）。

## 地块

### 状态

```js
{
  id,
  usable,        // 这块地买下来了没有（落库存档，等级不再决定）
  cropId, harvested,
  plantedAt, readyAt, total,
  soil, fert, yieldBonus, boost,
  waterNext, pestNext, waterTimes, pestTimes,
  stolen, stolenCount, stolenAt, pendingYield,
}
```

- `plantedAt` / `readyAt` / `total` 是绝对时间戳与当前轮时长，
  所以**关掉页面作物照样在长**，回来时直接看 `readyAt` 判断成熟即可；
- `harvested` 是本轮已收获次数，多次收获作物靠它决定是否还有下一茬；
- `fert` / `yieldBonus` / `boost` 是三种**互不相干**的产量加成（施肥 / 增产剂 / 捉虫），
  收获时相乘而不是相加；
- `waterNext` / `pestNext` 与配套的 `*Times` 是照料排程，见下面的「照料机制」；
- `pendingYield` 是成熟那一刻摇定的产量，「可收 X」与收获都用它 ——
  不是每次看都重摇，否则玩家会看到数字乱跳。

### 买地

开局 6 块可用，之后每块都更贵（`data/plots.js`）：

```
价格 = (已拥有地块数 - 6) × 1000 + 500
```

`farm.unlockPlot()` 只能按 id 顺序买下一块：够钱就 `spendCoins` + `usable = true`，
写一条日志、落盘、广播。`unlockedPlotCount()` 直接数 `usable` 的地块，
HUD 与土地构成统计都跟着它 —— **等级与地块数量已经解耦**。

联机快照只带 `usable` 的地，所以访客看到的就是对方真正在种的那几块
（见 [14-村镇联机](./14-村镇联机.md)）。

### 状态机

```js
plotStatus(plot) → 'locked' | 'empty' | 'growing' | 'ripe'
```

`locked` 优先级最高，其次看有没有作物，最后比较时间。

### 再生收获

```js
function beginRegrow(plot, crop, soil) {
  const done = (plot.harvested || 0) + 1;
  if (done >= crop.harvests) return false;         // 次数耗尽

  const regrowMs = Math.max(30_000, Math.floor(crop.grow * 1000 * soil.timeMul * crop.regrow));
  plot.harvested = done;
  plot.plantedAt = Date.now();
  plot.total = regrowMs;
  plot.readyAt = plot.plantedAt + regrowMs;
  plot.watered = plot.fert = plot.organic = false;
  return true;
}
```

返回 `false` 时调用方 `clearPlot(plot)` 把地清空。

## 签到

字段：`lastSign`（时间戳）、`signDays`（逐日签到的日期键数组，最多 90 条）、
`signStreak`（连续天数，**缓存**）、`signTotal`（生涯总天数）。

```js
export async function signIn(now = Date.now()) {
  if (signedToday(now)) return false;
  const p = state.farm.progress;
  p.signDays.push(dayKey(now));          // ① 先记历史
  p.lastSign = now;
  p.signTotal += 1;
  p.signStreak = streakOf(now);          // ② 计数器从历史现算
  // 发奖励：rewardFor(todayStreakDay(now))
}
```

⚠️ **`signDays` 是唯一数据源，`signStreak` 只是缓存**（第 44 轮统一）。

早先顶部「连续签到 N 天」读的是计数器 `signStreak`，下方日历读的是历史
`signDays`，两套数据各算各的 —— 老存档里计数器是 30 而历史一天都没有，
于是同一个页面上下两处对不上。现在 `streakOf(now)` 从历史往前数连续天数，
`currentStreak()` / `leftInCycle()` / `todayStreakDay()` / `streakBroken()` 全部改用它，
计数器只在读档时对齐一次。

`streakOf` 的口径：今天签过就从今天往前数；今天还没签就从昨天数（今天还能续上，
不算断）；昨天也没有就是 0。老档由 `reconcileSignHistory()`（`main.js` 启动时调用）
按 `lastSign` 往前补出 `signStreak` 声称的那些天，幂等，补完写档。

**中断不清零**，只是从第 1 天重新累计 —— 连着签和断着签都有收益，
不会因为断一天就前功尽弃。

每天固定发三样：

| 奖励 | 说明 |
| --- | --- |
| 普通化肥（缩短 30 分钟）×1 | 固定发这个最低档 |
| 随机商店种子 ×1 | 等级不高于当前农场等级，签到那一刻才掷 |
| 少量金币 | 「该等级一次正常收获的价值」× 循环倍数（1.0 ~ 5.0） |

**不再发经验** —— 经验只跟产出挂钩，签到送经验会让前期节奏整个乱掉。

**周六是大奖日**：除了日常奖励，还能开一个盲盒，
从「玩家等级对应的那一档藏宝图」的奖励池里随机抽一份
（等级不够 10 级、还没有可用的藏宝图时，兜底给金币与化肥）。
日历（`calendarOf`）生成当月网格：周一排第一列，
已签 / 今天 / 过去 / 未来四种状态，周六那格标 🎁。

## 图鉴与新手引导

`codex.js` 同时管这两件事，因为它们都是「记录进度」的领域。

### 统计与收集

统计存在 `state.farm.progress.cropStats`：

```js
state.farm.progress.cropStats = { '小麦': { planted: 3, harvested: 12 } };
```

埋点分布在：

| 位置 | 事件 |
| --- | --- |
| `farm.applyPlant` 之后 | `recordPlanted(cropId)` |
| `farm.harvest` 之中 | `recordHarvested(cropId, amount)` |

**收集规则**：产出**进过一次仓库**就算收集，存在
`state.farm.progress.collected`（`{ 作物id: true }`，**只增不减**）。

记账点只有一处：`store/collected.js` 的 `noteProduce()`，由 `inventory.add()`
调用 —— 收获、偷菜、邻居送礼、签到、冒险的产出入包都走这条路径，
不用逐个业务埋点，也不会漏。卖出 / 送人 / 做成标本之后依然算收集过，
图鉴墙不会因为清仓又变回剪影。

**点亮规则**：做好一份标本（见下文「标本」）—— 比收集更硬的成就。
**解锁规则**：`level >= crop.lv`。

图鉴里**没收集过**的作物以剪影呈现（emoji 打码、名字显示「未收集」），
保留等级作为「下一个目标」的提示。收集到但还没做标本的显示**灰图标**
（去色不打码），点亮之后才是彩色 —— 三档长相对应「没见过 / 见过 / 点亮」。

老存档没有 `collected`，按「收获过（`harvested > 0`）或仓库里还有货」兜底判定，
之后的收集从入包那一刻精确累积。

### 新手引导

取代了原来的每日任务。6 个一次性目标，**达成即自动发奖**：

| key | 目标 | 金币 | 经验 |
| --- | --- | --- | --- |
| plant | 第一次播种 | 50 | 20 |
| harvest | 第一次收获 | 60 | 25 |
| sell | 第一次交易 | 50 | 20 |
| steal | 第一次串门 | 40 | 30 |
| upgrade | 第一块好地 | 500 | 80 |
| feed | 第一顿饭 | 30 | 20 |

```js
await completeGuide('harvest');
```

自动发奖的理由：奖励直接绑在业务动作上，玩家不需要记得回来领，
也不会因为漏点而损失。新手引导的目的是带玩家走一遍，不是制造待办。

## 世界推进

世界推进由 `store/world.js` 的世界时钟负责，`social.settleWorld()` 是它的调用入口：

```js
const { span, report, visits, deferred, summary } = await social.settleWorld((p) => {
  overlay?.update(p);        // p = { at, from, to, percent }
});
```

- `span` 是「距离上次离开多久」，UI 用它决定要不要显示等待画面；
- `report` 是离线时间轴（按自然日分桶，见 [07-邻居模拟](./07-邻居模拟.md)）；
- `visits` 是离线期间算完的上线，`deferred` 是留给在线演出的；
- `summary` 是三个计数器（`stolen` / `cared` / `caught`）的汇总。

同一时刻只会有一次结算在进行：内部用 `settlePromise` 去重，
重复调用会拿到同一个 Promise 的结果，不会跑两遍。

`persistFriends()` 一次性提交「玩家农场 + 全部邻居农场」——
每座农场的行、地块、日志一起写，不能出现「邻居偷了但玩家地没变」的中间态。
落盘条件是 `visits.length || report.idles`：轮询是定时跑的，每次都写库太浪费，
但**在线空闲动作（第 48 轮）同样改了内存**，漏了它就白做了。

## 村庄建设

村庄是**整个世界共有的一份**，但状态挂在 `state.farm.village` 上
（和 `workshop` / `dogHouse` 一样的做法）：为它单开一张表要改存档结构、
读写路径与所有事务，而它每次变化都跟着玩家农场一起落盘。

```js
village: {
  level: 1,                              // 1~5
  coins: 0, crystals: 0, pray: 0,        // 本期三项进度，升级时清零
  stock: { 1: 0, 2: 0, 3: 0, 4: 0 },     // 冒险挖到、还没投出去的水晶
  prayDay: { 农场 id: '2026-10-26' },    // 今天谁祈过（只留今天）
  giveDay: { 农场 id: '2026-10-26' },    // 今天谁投过资源（只留今天）
  logs: [],                              // 建设日志，7 天 / 160 条
}
```

四个入口：

| 函数 | 做什么 |
| --- | --- |
| `villageSnapshot()` | 给 UI 的只读快照（三项进度、当前档水晶、今天祈过没有） |
| `invest({ coins, crystals })` | 玩家投入。金币从自己身上扣、水晶从 `stock` 扣，然后查升级 |
| `pray(at)` | 玩家祈福：每天一次，5% 抽奖，落盘 |
| `prayNpc(npc, at)` | 邻居祈福：**同步、不落盘**（由时钟批量跑，落盘交给调用方） |
| `contributeCore(npc, at)` | 邻居投入：同步、不落盘，返回投了多少（没投返回 `null`） |

### 村民也会投入（第 49 轮）

只有玩家能投的话，村庄就从「全村共建」变成了「一个人凑 63 万金币 + 75 枚水晶」。
所以邻居上线时会顺手投一笔（`ACTIONS.contribute`，注入成 `ctx.contributeNpc`）：

| 规则 | 数值 | 理由 |
| --- | --- | --- |
| 频率 | **每人每天一次**（`giveDay`） | 不限次数时，离线补算里 32 位村民各投五六趟，第一档在玩家进游戏前就满了 |
| 金币 | `min(还差, 800, 闲钱 × 35%)`，闲钱 = 身家 − 1200 | 留够买种子 / 喂狗 / 买图的周转金 |
| 水晶 | `min(还差, 库存 ÷ 2)`，库存 < 2 不投 | 玩家自己挖的那几枚还留得下来 |

三项都达标（需求为 0）时直接返回 `null`，所以他不会在已经满了的档上做无用动作，
日志也不会被同一个动作刷满。全村 32 人 × 800 ≈ 每天最多 2.5 万金币：
第一档（1 万）基本一天就够，后面的档次仍要靠时间 —— **祈福才是真正的闸门**。

因为进度条随时可能被邻居推到 100%，`invest()` 会把投入量**夹到「还差的那点」**：
多投的部分会在升级时被清零，等于白扔。都满了就返回「这一档已经够了」，
界面上「投入资源」也会变成禁用的「资源已齐」。

### 升级是自动的

`checkUpgrade()` 在每次投入 / 祈福之后跑一遍：三项同时达标就升级，
清空三项，写建设日志 + 时报 + toast，`emit(EVENTS.VILLAGE)`。

**不做「点一下升级」的按钮**：祈福每天只有一次，玩家不需要在某个瞬间守着点，
攒够了就该自己升。等级门槛与回报见 [04-数值平衡](./04-数值平衡.md#村庄建设第-48-轮)。

### 为什么祈福要拆成同步内核

`prayCore()` 与 `pray()` 是两个函数：

- `prayCore` 只改内存、返回 `{ ok, reward, leveled }` —— 邻居走这条，
  因为世界时钟一趟上线十几个动作，每个都 `await` 会把补算拖垮；
- `pray` 在 `prayCore` 之后补一次 `commit` —— 玩家走这条，奖励进了背包得立刻写。

⚠️ `prayDay` **只留今天**：它唯一的用途是判断「今天祈过没有」，
昨天的没有意义。攒着会长成 33 × N 的表（写档时 `normalizeVillage` 也会再清一次）。

### NPC 的祈福奖励折成金币

NPC 没有能装种子和道具的地方（`bag` 只收产出，塞种子进去会污染订单链路），
所以按奖励池里那份东西的标价给钱（`npcPrayValue`）。玩家那份是真东西。

## 种子制造间

把仓库里的农产品换回同种作物的种子：**解锁 → 下锅 → 收取 → 升级** 四步。

```js
state.farm.workshop = { level: 0, kinds: {}, jobs: [] };   // level 0 = 还没开张
```

`kinds` 是「作物 id → 造过几次」的记账，**升级只看它有几个 key**（造过多少种）。
这么设计是因为按次数算的时候，拿最便宜的小麦反复制造就是最优解；
按种类算之后，同一种作物造一百次也只算 1 种。
等级与 `kinds` 在读档时清洗（不认识的作物 id 直接丢），旧档的 `uses` 还原不出
「造过哪几种」，只能丢弃 —— 等级保留，概率不会掉回去。

`jobs` 是**排队中的炉子**（第 44 轮新增），形状 `{ id, cropId, need, fee, startAt, doneAt }`：

- 一炉烧 `craftMs(crop) = max(1, crop.lv) × 10 秒`（`data/workshop.js` 的
  `CRAFT_MS_PER_LEVEL = 10_000`）—— 等级越高越难造，但也不会难到离谱；
- **栏位数 = 等级**（`slotCount(level) = level`），Lv.1 同时只能烧一炉，
  Lv.10 能并行十炉，升级的收益一眼可见；
- 时间戳存在存档里，**离线期间照样走**：回来时 `claimJobs()` 一次把到点的炉子全收掉，
  剩下的继续排。`main.js` 启动时调 `resumeCraftTimers()` 把定时器接回来；
- 读档时 `jobs` 清洗：不认识的 `cropId` 丢、`doneAt <= startAt` 的丢、
  最多留 `WORKSHOP_MAX_LEVEL` 条。

| 导出 | 说明 |
| --- | --- |
| `isUnlocked()` / `workshopLevel()` / `workshopKinds()` | 查询（`workshopKinds` = 种类数） |
| `kindTimes(cropId)` / `kindDone(cropId)` | 这一种造过几次 / 造过没有 |
| `unlockState()` | `{ ok, lackLevel, lackCoins }`，UI 拿它决定按钮灰不灰 |
| `unlock()` | 够条件就扣 2000 金币、`level = 1`、落盘 |
| `craftables()` | 份数够的作物，`{ id, crop, have, need, fee, coinsOk }`（金币不够也列出，只是按钮灰） |
| `craftSlots()` / `freeSlots()` | 总栏位数 / 还空几个 |
| `craftJobs()` / `activeJobs()` / `readyJobs()` | 全部炉子（按 `doneAt` 升序）/ 还在烧的 / 可以收的 |
| `jobLeftMs(job)` | 这一炉还剩几毫秒 |
| `craft(cropId)` | 扣产出 + 扣工本费 → **入队一炉**（返回 job 对象；栏位满返回 `null`） |
| `claimJobs()` | 把到点的炉子全收：逐炉摇数量 → 加种子 → `kinds[cropId] += 1`，一次提交 |
| `resumeCraftTimers()` | 启动时接回自动收取的定时器 |
| `upgradeState()` / `upgrade()` | 种类数 + 金币都够了才升，满级返回 `maxed` |

四个要点：

1. **两道消耗先校验再动手**：金币、份数、栏位都在扣之前查好。扣了产出再发现栏位满了
   就得把它加回去，多一条容易漏的回滚路径；
2. **下锅与出种子分成两次提交**：下锅那次写 `{ farms, bag }`（产出与金币没了、炉子进队），
   收取那次写 `{ farms, bag }`（种子进背包、`kinds` +1）。中途关页面不会出现
   「产出没了、种子也没到」—— 炉子还在存档里，下次进来照样能收；
3. **自动收取**：`scheduleClaim()` 按最早一炉的 `doneAt` 挂一个 `setTimeout`，
   到点自己收；`claimJobs` 收完还会再挂一次，处理「一炉接一炉」的情况。
   UI 上的「收取 N 炉」按钮只是给想立刻看到的人一个手动入口；
4. **限定作物也能造**（第 43 轮放开）：`craft()` 和 `craftables()` 不再挡
   `crop.special` —— 挖宝挖多了的限定产出终于有复刻成种子的出路。

消耗份数由 `data/workshop.js` 的 `produceCost(crop)` 按市价现算，
数值理由见 [04-数值平衡](./04-数值平衡.md#种子制造间)。

## 照料机制：缺水与虫害

作物会「出问题」，玩家必须处理：

| 事件 | 什么时候冒出来 | 玩家操作 | 效果 |
| --- | --- | --- | --- |
| 缺水 | 每次浇水后重抽，窗口随次数变长 | 浇水 💧 | **当前生长阶段**的时间砍掉 10% |
| 生虫 | 同上，与浇水各自独立 | 杀虫 🐛 | 这块地**产量 +10%**（上限 +100%） |

**不再是固定周期**。旧版是「每 6 小时缺水、每 12 小时生虫」，与作物自己长了多久
无关，结果短周期作物一次都遇不到、长周期作物又撞在成熟之后（成熟后不出按钮），
等于永不触发。现在每次处理完，按**这一轮处理过几次**抽下一次：

```js
// data/care.js
nextCareAt(now, times, readyAt) {
  下限 = times × 1 小时
  上限 = min((times × 2 + 1) 小时, readyAt - 15min - now)
  if (下限 > 上限) return 0            // 连下限都放不下：本轮结束
  return now + randInt(下限, 上限) 分钟
}
```

- 区间 `[0,1h] → [1h,3h] → [2h,5h] → [3h,7h]`，**处理得越多下一次越晚**。
  下限固定成 1 分钟时，会出现「刚浇完一分钟又缺水」这种折腾人的循环；
- 没有次数上限：下一次一旦落到成熟之后（`now >= readyAt - 15min` 直接返回 0），
  这一轮就自然结束了；
- **成熟前 15 分钟封口**，玩家来不及操作的时间段不排需求；
- 下限顶到封口线上（剩余时间不够再排一次）时同样返回 0 —— 玩家拿不到合理的
  反应窗口，就不该因为「排不下」被扣产量。

地块上因此多了四个字段：

| 字段 | 含义 |
| --- | --- |
| `waterNext` / `pestNext` | 下一次需要浇水 / 杀虫的时刻，**0 = 本轮不会再需要** |
| `waterTimes` / `pestTimes` | 这一轮已经处理过几次 —— 窗口就按它算 |

`needsWater` / `needsPest` / `carePenalty` / `scheduleCare` / `serveCare`
全在 `data/care.js`（纯函数），玩家农场与邻居农场共用一套，**没有第二份实现**。

两个操作只在**真的缺水 / 生虫时**才出现按钮，平时不占地方。
需要处理的地块会亮起红色警示按钮（`.icon-btn.warn`，带呼吸动画）。

**成熟之后就不再需要照料**：判定里都带 `now < plot.readyAt`，
否则作物熟了还在提示浇水，玩家点进去只会看到「这块地还不缺水」。

### 减产：一条 −15%，两条 −40%

成熟时如果还挂着「该浇水 / 该杀虫」的账，产量打折：

| 欠着 | 减产 |
| --- | --- |
| 一条 | **−15%** |
| 两条 | **−40%**（不是 30%，是跳着涨的） |

判据是「排上的那一次有没有落在成熟之前」：

```js
const dry   = plot.waterNext > 0 && plot.waterNext <= plot.readyAt;
const buggy = plot.pestNext  > 0 && plot.pestNext  <= plot.readyAt;
```

处理过一次就会往后挪，挪到成熟之后就变 0 —— 所以**尽责了自然不扣**，
不需要额外记「减产了多少」。成熟之后这两个字段不再变化，随时算都得到同一个结果。

结算发生在**摇产量那一刻**（`rollYield`），结果写进 `pendingYield`。
玩家在地块上能直接看到「照料不周 · −15%」，收获日志里也会说明原因 ——
否则玩家只看到「收得少」，不知道是为什么。

### 浇水的 10% 是怎么算的

「当前阶段」指作物正处在的那个生长阶段（播种 / 发芽 / 生长 / 开花 / 结果）。
浇水时用 `stageBounds()` 算出这一段的时间边界，砍掉其中 10%：

```js
const bounds = stageBounds(plot, crop, now);
const saved = (bounds.stageEnd - bounds.stageStart) * 0.1;
plot.readyAt -= saved;
```

### 杂草机制已移除

早期版本有「杂草」和「害虫」两个字段，但**没有任何地方把它们置为 true**，
所以除害按钮和减产判定对玩家来说一直是死代码。那套「按概率打七折」的减产
（连同 `plot.weed` / `plot.pest`）已经整个删掉，换成了上面这条
「排程 → 欠着就 −15% / −40%」的规则；`pest` 则改造成「生虫 → 杀虫 → 增产」。

## 邻居的照料

邻居的地也会缺水、生虫，规则与玩家**完全一致**（同一个 `data/care.js`）。

```js
await social.waterNeighborPlot(friendId, index);      // 单块
await social.catchPestNeighborPlot(friendId, index);
await social.waterAllNeighborPlots(friendId);         // 一键（要洒水器）
await social.catchPestAllNeighborPlots(friendId);     // 一键（要杀虫剂）
```

单块照料**不消耗道具**，一键版本只扣 **1 个**洒水器 / 杀虫剂
（不管这一次浇了几块）—— 「一块一块点」是免费但要手速，一键是花一个道具省事。

帮一次 **+1 好感**（`REL_PER_CARE`），一键照料按块数累计
（浇 6 块地就是 +6）。这条对玩家和邻居都成立：邻居之间互相帮忙也涨好感度。

> 偷菜与打理是一对反向操作：打理越勤，交情越好，被偷的概率越低。
> 这两个动作都要**真的到那块地上**点，不提供「全镇一键」。

## 照料给的经验：作物等级 ÷ 10（至少 1）

浇水与捉虫的经验**跟着被照料的作物走，但要折十**：

| 操作 | 经验 |
| --- | --- |
| 给自己的地浇水 / 捉虫 | `careExp(crop.lv)` |
| 帮邻居浇水 / 捉虫 | `careExp(crop.lv)` |

```js
// data/care.js
export const careExp = (level) => Math.max(1, Math.round((Number(level) || 1) / 10));
```

规则一句话：**作物等级除以 10，四舍五入，最少 1 点**。
1 级作物 1 点、16 级 2 点、200 级 20 点。

早年的口径是「作物几级就给几点」，在 200 级作物身上会出现
「浇一次水顶别人半级经验」—— 照料从顺手做的事变成了刷经验的最优解，
玩家会专门挑最高级的作物反复浇水而不是好好种地。折十之后高级作物
照样更值钱（20 点 vs 1 点），但不会离谱。

四舍五入而不是截断：`lv × 10 + 5` 处台阶式上升，
玩家不会因为「差一级就是不给」而困惑。

其它「按次发放」的奖励仍然走等级折算：

| 来源 | 折算方式 |
| --- | --- |
| 每日签到 | 见 `data/signin.js` 的倍数表（相对「一次正常收获」） |
| 偷邻居的菜 | **不给经验** |

签到的金币同理，改成「该等级最贵作物的售价 × 3 × 倍数」。

> **满级陷阱**：`expForLevel(200)` 返回 `Infinity`（表示已满级），
> 拿它做乘法会得到无穷大的经验值。
> 所以额外提供了 `expForProgress(level)`，满级时返回 Lv199 的数值。
> `addExpRaw` 也会拒绝任何非有限的输入。
> 照料经验取的是作物等级，本来就有界，不受这条影响。

## 好感度

`data/relation.js` 是纯规则，`store/relation.js` 管读写 —— 和 `care.js` 同样的分工。

- 每对农场一个值，范围 **−200 ~ +200**，键是 `a|b`（a、b 按字典序，一对只有一条）；
- 存在 `state.relations`，落盘在 `relation` 表；
- 0 不落键 —— 「没有记录」和「正好 0」是同一件事；
- 读档时只认当前还存在的一对，换过邻居名单之后的孤儿关系直接丢掉。

| 触发 | 变化 |
| --- | --- |
| 开局（读档补齐） | `baseRelation(性格A, 性格B)` = 两个性格值的平均 |
| 打理一次（玩家给邻居 / 邻居给邻居） | `+REL_PER_CARE`（1） |
| 偷走一份 | 0（顺走不进好感账，被偷的心里有数但不撕破脸） |
| 被守护犬当场逮住 | `−dogCaughtRelLoss(售价)` = `max(1, round(售价/10))` |
| 玩家送礼 | `+giftRelGain(等级)` = `max(1, round(等级/2))` |
| 玩家跟邻居买产出 | `−tradeRelCost(等级, 份数)` = `max(1, round(等级 × 份数 / 2))`（第 45 轮） |
| 玩家催邻居上线 | `−SUMMON_REL_COST`（20，第 47 轮）—— 交情是有限资源，催人上门得付账 |

读写只有三个出口：`getRelation(a, b)` / `setRelation(a, b, v)` / `adjustRelation(a, b, delta)`，
写完 `emit(EVENTS.RELATION)`。界面用 `relationBadge(v)` 拿 `{ key, label, text }`
（`挚交 +176`），**标签和数值成对显示**。

好感度对邻居行为的影响（权重函数在 data 层，模拟层只调用）：

| 行为 | 函数 | 效果 |
| --- | --- | --- |
| 偷菜挑目标 | `stealWeightFor(rel)` | 仇家被偷的概率是挚交的 11 倍 |
| 帮忙挑目标 | `helpWeightFor(rel)` | 反过来，交情越好越愿意跑腿 |
| 送礼 | `giftChanceFor(rel)` | < 60 免谈，最高 50% |
| **登门打理（≥100）** | `REL_CARE_PRIORITY` | 亲近档优先：上线先照顾 ≥100 的农场，一个都没有才回退全量 |
| **亲近档送礼（≥100）** | `closeGiftChanceFor(rel) × giftPersonalityFactor(性格)` | 100 → 25%，200 → 55%，再乘性格系数（热心 1.4 ~ 爱占便宜 0.5） |
| **催上线的等待** | `summonDelayRange(rel)` | 挚交 1~30 秒、结怨 5~10 分钟，中间按指数插值（见 [07-邻居模拟](./07-邻居模拟.md)） |

> 这几条权重只决定「挑谁」，不决定「做不做」——「做不做」还是看性格与概率。
> 否则好感一高就变成一键托管了。
>
> 第 47 轮另有一道统一倍数：`npc-sim` 的 `interactChance(c) = 1 - (1-c)²`
> 把**顺菜 / 串门帮忙 / 送礼 / 喂狗**全部翻一倍（掷两次、有一次算数）。
> 用这个式子而不是 `c × 2`，是为了别把偷菜的「常去」和「见菜就偷」一起顶到 99%。

## 每日排行榜

`store/daily.js` 一个模块管四件事：**记账、结算、发奖、查询**。
数据存在第七张表 `daily`（一天一行，最多留 8 天）：

```js
{ date: '2026-10-22', settled: false,
  stats: { player: { care: 3, manage: 45 }, npc01: { care: 5 } } }
```

11 张榜（冒险王按五档藏宝图拆开）：

| 榜 | 指标 | 口径 |
| --- | --- | --- |
| 🏅 最友善 | `care` | 帮别人农场浇水 / 捉虫的次数（一键按块数记） |
| 🐕 狗狗王 | `dog` | 守护犬拦下偷菜贼的次数（记在**狗主人**头上） |
| 🌾 打理王 | `manage` | **自己农场里最高的那一个**「+加成」角标（`farmMaxBonus`）；不是累计 |
| 🎁 送礼达人 | `gift` | 送出礼物的**总价值**：产出按 `crop.sell`、道具 / 种子按商店价（`itemValue()`） |
| 🐝 农事劳模 | `work` | 播 / 浇 / 虫 / 肥 / 收 / 铲的次数（一键按块数记） |
| 🗺️ 冒险王 ×5 | `adv1`~`adv5` | 当日该档图带回的奖励总价值（按档分榜） |

三条设计底线：

1. **按发生时刻记账**：`bump(actor, metric, n, at)` 归到 `boardDayKey(at)` 那一期 ——
   世界时钟补算出来的邻居访问发生在过去，不能记到「现在」头上；
2. **已结算的期次冻结**：发过奖的行不再接受迟到的动作；
3. **只有逐条模拟进榜**：世界时钟跨过 14:00 就在当场结算那一期
   （`checkRollover(now, { quiet: true })`），所以离线补算的每一天都能上榜；
   唯独「离线久到超过上线预算」的那段聚合（`bulkAdvance`）不记账 ——
   模糊数据不跟精确数据同榜。

### 埋点矩阵（改互动逻辑时对着这张表看）

每条互动链路都必须在**该记的人**头上留一笔。漏掉任何一格，那张榜就永远是 0，
而界面上完全看不出「坏了」—— 只是没人上榜。

| 指标 | 玩家 → NPC | NPC → 玩家 | NPC → NPC | 玩家 → 真人（村镇） |
| --- | --- | --- | --- | --- |
| `care` | `social.waterNeighborPlot` / `catchPestNeighborPlot` / `waterAllNeighborPlots` / `catchPestAllNeighborPlots` / `feedFriendDog` | `npc-sim.actCare` | 同左 | `peer-actions.waterPeer` / `pestPeer` / `fertPeer` / `feedPeerDog` |
| `dog` | `social.steal`（被狗抓住 → 记**狗主人**） | `npc-sim.actSteal` | `npc-sim.actSteal`（`owner.id`） | `peer-actions.handleAct`（主人侧记自己） |
| `manage` | `farm.collectPlot` 的 `bumpMax` + `mergeLiveManage` 实时 | `npc-sim.actHarvest` 的 `dailyMax` + 实时 | 同左 | ❌ 未纳入（联机快照没有 `boost` 字段） |
| `gift` | `social.sendGift` | `npc-sim.actGift` | `npc-sim.actGift` | `peer-gift.handleAccept`（对方**真的收下**才记） |
| `work` | `store/farm.js` 的 7 处（种/浇/虫/肥/收/铲） | `npc-sim` 的 `actHarvest` / `actPlant` / `actTend` | 同左 | —（帮人打理归 `care`） |
| `adv1~5` | `store/adventure.js` | `npc-sim.actAdventure` | 同左 | —（真人之间不联动冒险） |

两条口径约定：

- **`dog` 记给狗主人，不记给被抓的人**。谁家的狗立的功就记谁：
  玩家偷 NPC 被抓 → NPC +1；NPC 偷玩家被抓 → 玩家 +1；
  真人访客偷我 → 我 +1（主人侧 `handleAct` 记账，访客那台设备不记）。
  被抓住的人一分不得，所以「偷菜被狗抓」在自己的榜上是看不到加分的；
- **`gift` 只认「送出去了」**。给 NPC 送礼当场记；给真人送礼要等对方按了「接收」、
  送方回了 ack（`handleAccept`）才记 —— 拒收与超时都会退货，提前记分会虚增。

### 账期：14:00 切日，第二天 14:00 开奖

```js
boardDayKey(ts) = dayKey(ts - 14h)   // 13:59 的 10/23 拨回 10/22 23:59
```

| 概念 | 值 |
| --- | --- |
| 一期 | 该日 **14:00 → 次日 14:00**（24 小时） |
| 行的 `date` | **账期开始那天**，不是结束那天 |
| 开奖 | 期次结束那一刻，也就是**次日 14:00** |
| 玩家看到的说法 | 今天 14:00 开的是「**昨天** 14:00 → 今天 14:00」那一期 |

举例：`2026-10-22` 这一行收的是 10/22 14:00 到 10/23 14:00 的数据，
在 **10/23 14:00** 结算并发奖，界面上叫「昨日榜单 · 10-22」。

这几条容易踩：

- **`date` 是起点不是终点**。写界面时一定要把区间写出来
  （`boardPeriodText(date)` → 「10/22 14:00 → 10/23 14:00」），
  只写「昨日 · 10-22」会让人以为统计的是 10-22 的 0 点到 24 点；
- **上午的活儿算前一天那一期**：10/23 09:00 的动作进的是 `2026-10-22` 这一行，
  当天 14:00 跟着它一起开奖。这是 14:00 切日的必然结果，不是 bug；
- **迟到数据直接丢**：`bump` 撞上 `row.settled` 就返回，不补记、不重算；
- **行里存 `start`（账期起点时间戳）**：读到 `start` 对不上的行就当空行，记账时直接
  重开一行。这样即使存档里还躺着旧口径的行、或玩家把系统时钟调过，14:00 之后
  看到的也一定是「本期从 14:00 起算」的数；
- **打理王是「当前值」而不是「累计」**：实时榜上每个人的数值 = 他自己农场里
  最高的那一个角标（`farmMaxBonus(plots)`），不依赖「收获过」这个事件，
  所以地里挂着高加成没收获也会上榜；收获后角标回落，已记的峰值仍保留（取较大）。
  结算时对**刚刚结束的那一期**再量一次，把「期内没收获但有高加成」的人补进榜里，
  久远补算不做这件事；
- **旧账期的行不能混用**：0 点切日时代留下的行与新账期**同键不同义**
  （同一把 `2026-10-22`，一个是自然日、一个是 22 日 14 点起的 24 小时）。
  所以 `migrateBoardRows()` 在启动时比对 `progress.boardVersion`
  （`BOARD_VERSION = 3`），不一致就把 `start` 对不上的行整行丢掉 ——
  新口径写出来的行原样保留，不白清玩家的当天数据。

结算（`checkRollover`）挂在启动之后与每分钟 tick 上：14:00 那一刻在线 → 当场发奖 + toast；
不在线 → 下次进游戏补结（跨了几期就逐期补）。
14:00 前不会提前结算。**前三名递减发奖，并列都发**（同值共用名次，展示的名次用
`entry.rank`，所以「并列第一」两个人都显示第 1 名）；
NPC 夺冠不发道具，只上报一条时报；**玩家每次获奖（1/2/3 名）也上报一条时报**
（用农场名，句式与 NPC 对齐 —— 早年只写农场日志，公告栏里只剩 NPC 的名字，
玩家自己获奖了却看不见）。金币从严（100/50/30），
大头是道具与「免费藏宝图」—— 发道具不发钱。

玩家拿到的名次会随 `BOARD_AWARD` 事件发出去，UI 层播全屏庆祝动画
（`ui/board-celebrate.js`）：单张最多 2 秒，点一下立即淡出并接下一张，
多个名次按**天数从旧到新、期内按榜的次序**排队播。

UI 在 `ui/subpages/rank.js`（「更多 → 排行榜」）。**第 44 轮按用户要求把两段的顺序调过来了**：
上面是本期的实时排名（含统计区间，不计奖），下面是被结算的**昨日那一期**。
玩家打开这一页多半是想知道自己现在第几，实时榜才是主信息；
昨日榜留在下面是为了看成绩，以及查这一榜的**名次奖励**（卡片右上角的「奖励」按钮）。

奖励弹窗直接读 `BOARDS[].rewards`，用 `rewardText(reward)` 生成文案 ——
与真正发奖时写进农场日志 / 时报的那句话是同一个函数，不会出现
「弹窗写 100 金币、实际发 50」这种对不上的情况。前三名各列一行，并列同名的都发。

## 偷菜规则

偷菜**不给经验** —— 经验只来自自己的收获和照料邻居，否则「到处偷」就变成了最优解。

只有一条限制：**每块地的每轮作物最多被偷 1 个**。
地块上有 `stolen` 标记，作物重新种下时刷新
（`applyPlant` / `beginRegrow` / `clearPlot` 以及 `npc-sim` 的 `actPlant` / `bulkAdvance` 都会重置）。

偷是有代价的：**少 1 个**，外加**掉好感** —— 顺利顺走不掉（被偷的心里有数），
被守护犬当场逮住才按想偷的那个果实售价折算，`max(1, round(售价/10))`：

```js
// 收获时按被顺走的个数扣减，不做「减半」这种翻倍惩罚
amount = Math.max(0, amount - (plot.stolenCount || 0));
```

NPC 之间互相偷、NPC 偷玩家，全部走同一套规则；
玩家地块的 `stolenCount` 由 `npc-sim` 在离线结算时写入。

```js
export function isStealable(plot, now = Date.now()) {
  if (!plot.cropId || now < plot.readyAt) return false;
  if (plot.stolen || plot.guarded) return false;
  return remainYield(plot) >= 1;
}
```

`guarded` 是第二种「不能偷」：**偷菜被对方的守护犬抓住时，这座农场当前所有
带作物的地块都会被标记**，效果等同于「每块地都已被偷过」，直到作物重新种下。
判定用的是对方那条狗自己的品种与饱腹度（`catchChance(品种基础率, 当时存量)`）。

## 守护犬

守护犬现在是**真的在防偷**：邻居顺菜时会先问一句狗在不在岗。
它拆成三个彼此独立的概念，混在一起就没法调平衡：

| 概念 | 存哪 | 规则 |
| --- | --- | --- |
| **品种** | `farm.dog.owned` | 十个品种，决定「这只狗能有多灵」，基础拦截率 20% ~ 80% |
| **上岗** | `farm.dog.breed` | 同一时刻**只有一只**看家（空串 = 一只都不上岗，那就完全不设防） |
| **狗粮槽** | `farm.dog.satiety` | **整个狗窝共用**的一份存货，喂一次所有狗都受益 |

实际拦截率是前两者的乘积（详见 [04-数值平衡](./04-数值平衡.md#守护犬三层模型)）：

```
catchChance(品种基础率, 槽内存量) = 基础率 × (0.5 + 0.5 × 槽内存量 / 100)
```

饱腹度为 0 时直接返回 0，满槽时等于品种基础率。
**槽只在有狗上岗时消耗**（`DOG_SATIETY_DECAY = 6.25`/小时，喂满约守 16 小时），
没狗上岗时它就停在那里不掉。

存档里只存「上次结算时的存量 + 那个时刻」，读到的时候按经过的小时数现算：

```js
// data/dogs.js —— 玩家与邻居共用
export function dogSatietyAt(dog, at) {
  const raw = Math.max(0, Number(dog?.satiety) || 0);
  if (!dog?.breed) return Math.min(DOG_SATIETY_MAX, raw);   // 没狗上岗 → 不衰减
  const hours = Math.max(0, (at - (Number(dog.at) || 0)) / 3_600_000);
  return Math.max(0, Math.min(DOG_SATIETY_MAX, raw - hours * DOG_SATIETY_DECAY));
}
```

所以**不需要任何后台定时器**：关掉页面十天再打开，一读就是掉光的 0。

### `store/dogs.js` 的导出

这个模块是本轮从 `social.js` 里拆出来的，职责单一 —— 只管「我的狗窝」：

| 函数 | 作用 |
| --- | --- |
| `ownedDogs()` / `ownedBreedIds()` | 已收集的品种（按品阶排序）/ 它们的 id 列表 |
| `activeBreed()` | 当前上岗的品种，没有则 `null` |

| `kennelLevel()` / `kennelCapacity()` | 狗窝等级 / 当前槽容量（100 + 30×级） |

`guardChance(at)` 把时间点交给调用方，是**离线结算需要的**：
结算几天的离线时，狗不是一直满饱腹，而是随时间一路掉下去的，
期间玩家换过狗的话也按现在的品种算。`social.js` 通过
`farm.dogGuardChanceAt(at)` 把这个能力透给模拟层。

`setActiveBreed` 切换前会先 `settleSatiety()` 把当前存量写回基准（写进 `dog.satiety` + `dog.at`）——
少了这一步，「没狗上岗」的那段时间会被当成消耗掉。
`feedDog()` 会 `await completeGuide('feed')`，也就是新手引导的「第一顿饭」。

> 狗窝就在 `farm.dog` 里，不会再出现「pet 放错参数被静默丢弃」的问题。

### 品种来源与存档迁移

品种**只能从冒险获得**（低概率、按藏宝图档位分品阶上限、不重复），

读档时 `store/state.js` 的 `normalizePlayerFarm()` 兜底：品种 id 不认识就退回最低档，
没有 owned 时补一只田园犬 —— 不做旧表迁移，这一版直接换了新库。

```js
// 过滤非法品种 id → 一个都没留下就补田园犬 → active 指向一个真拥有的品种
const owned = { ...(pet.owned || {}) };
for (const id of Object.keys(owned)) if (!dogBreed(id)) delete owned[id];
if (!Object.keys(owned).length) owned[FIRST_DOG_ID] = true;
const active = owned[pet.active] ? pet.active : (Object.keys(owned)[0] || '');
```

玩家偷 NPC 被抓住时会给该 NPC 所有带作物地块置 `guarded`，

## 施肥

三类肥料共用**同一个额度** —— 一株作物一轮只能施一次：

| 道具 | 效果 | 价格 |
| --- | --- | --- |
| 普通化肥 30分 | 成熟时间 −30 分钟 | 60 |
| 普通化肥 1时 / 2时 / 6时 / 18时 | 成熟时间 −1 / 2 / 6 / 18 小时 | 110 / 200 / 520 / 1300 |
| 有机化肥 | 直接成熟 | 1800 |
| 增产剂 10% / 20% / 30% | 本轮产量 +10% / +20% / +30% | 1000 / 3000 / 8000 |

- 剩余时间不足一档时，撒下去就是直接成熟，不浪费；
- **额度统一**：`plot.fert` 一个标记，普通化肥、增产剂、有机化肥都用它。
  老存档里的 `plot.organic` 在读档时并进 `plot.fert`（`normalizePlot`）；
- 增产剂不改时间只加产量，加成记在 `plot.yieldBonus`，
  收获时与捉虫加成**相乘**：`数量 × 土地倍率 × (1+捉虫) × (1+增产)`；
- 额度在重新播种或进入再生轮次时清零 —— 新的一轮算新的一株；
- 有机化肥提价到 1800：它比任何一档都强，价格要是还比 18 小时档便宜，那五档就白设计了。

产量加成的角标显示的是**合并后的实际增幅**（捉虫 + 增产相乘后再取整）。

## 一键浇水 / 一键杀虫 / 一键收获

三件「省手」道具（`items.js` 的 `all` 字段 + `store/tools.js`），
把「一块一块点」变成「点一次」：

| 函数 | 作用范围 | 消耗 |
| --- | --- | --- |
| `farm.waterAll()` | 自己农场所有缺水的地 | 1 洒水器 |
| `farm.catchPestAll()` | 自己农场所有生虫的地 | 1 杀虫剂 |
| `farm.harvestAll()` | 自己农场所有成熟的地 | 1 采收机 |
| `social.waterAllNeighborPlots(id)` | 邻居农场所有缺水的地 | 1 洒水器 |
| `social.catchPestAllNeighborPlots(id)` | 邻居农场所有生虫的地 | 1 杀虫剂 |

规则与手动操作**完全一致**（浇水缩 10% 当前阶段、捉虫 +10% 产量、
收获走同一条 `collectPlot`、经验按作物等级折十给），只是消耗 1 个道具、一次处理完。
没有道具或没有需求时，UI 上对应的按钮根本不出现。

### 永久版：`store/tools.js`

每件工具都有消耗版与永久版，判定只有三个出口：

```js
hasTool(kind)       // 有永久版，或消耗版还有货 → 按钮才出现
toolUses(kind)      // 永久版返回 Infinity（界面显示 ∞），否则是背包数量
useTool(kind)       // 有永久版什么都不扣；否则扣 1 个
```

`kind` 是 `'water' | 'pest' | 'harvest'`，映射在 `data/items.js` 的 `TOOL_KINDS`。
自家农场与邻居农场共用这一套，所以「买过永久洒水器，帮邻居浇水也不扣」是自动成立的。

> **顺序不能反**：先查永久版、再查消耗版。反过来的话，手上有永久版的玩家
> 每用一次都会先吃掉一个消耗品，背包会莫名其妙变少。

### 自动机器：`store/automation.js`（第 51 轮）

消耗版与永久版都要求**你在场**。自动机器解决的是第三件事 —— **你不在的时候农场自己动**。

| 道具 | 价格 | 一天时长内做什么 |
| --- | --- | --- |
| 🚰 自动洒水器 | 2,000 | 缺水的地自动浇水（缩短成熟） |
| 🪤 自动捉虫机 | 2,000 | 生虫的地自动杀虫（增产） |
| 🛻 自动收获机 | 1,000 | 成熟的地自动收入仓库 |

- 时效写在 **`farm.progress.auto = { water, pest, harvest }`**（**到期时间戳**，不是剩余毫秒 ——
  存剩余值的话，关掉浏览器那段时间就会白送）。买一个往对应类别上 +1 天，从 `max(now, 旧到期)`
  算起，所以连买三个是三天，**不是覆盖**。
- 判定：**不要写 `permanent`** —— 那个字段会把道具钉在「永久版」上，商店会判定为「已拥有」
  并禁用按钮。自动机器是普通道具，靠 `ITEMS[id].auto` 标记类别，反查表是 `AUTO_KINDS`。
- 执行点在**世界时钟**（`world.js tick()` 第 ⑤ 步 `runAutoStep(prev, next)`），所以**离线补算
  和在线是同一套逻辑**：玩家没上线时机器照转，回来后一次性补上那整段。改动非空 →
  `report.dirty = true` 让调用方额外落盘。
- 效果复用 `farm.js` 的 `water` / `catchPest` / `collectPlot`，但**跳过** `addExpRaw` / `bump` /
  `completeGuide` —— 花钱省的是「惦记」，不是成长。**刻意**不给经验、不记榜单、不算引导。
- 日志走 `player.addLog`，toast 只有在 `at >= deferFrom` 时才弹（补算期别刷屏）。
- 三处发奖要特判 `ITEMS[id]?.auto` → `addAuto`：`adventure.js applyReward`、`titles.js claimTitle`、
  `daily.js grantReward` —— 漏一处就是背包里躺一堆永远用不掉的 `autoSprinkler ×3`。

### 一键收获为什么走 `collectPlot`

`harvest(plotId)` 与 `harvestAll()` 都调同一个 `collectPlot(plot)` —— 产量、照料减产、
被顺走、再生轮次、经验全在那一处算。差别只在汇报：单块收获一条 toast，
一键收获一次落盘 + 一条汇总日志 + 一条汇总提示（含「几块照料不周」）。
再写一份「批量版」迟早会跟单块版算得不一样。

## 称号

称号分三类，条件不同但流程一致：

| 类型 | 数量 | 条件 |
| --- | --- | --- |
| 等级称号 | 26 | 农场等级 |
| 图鉴称号 | 26 | 点亮的图鉴数量（做够标本才算点亮），**每 10 个一档：10 → 260** |
| 金币称号 | 5 | 当前持有的金币 |

- **全部手动领取**：达成条件只让称号「可领」，玩家得自己去称号页点一下；
- 领取时只发**道具**（第 20 轮起不再发金币：称号是里程碑，不该变成按等级缩放的
  自动提款机），道具按收集难度给不同组合，**第 51 轮整体加量**；
- **每个称号至少给一枚限定种子，越难给的等级越高**：种子不是手写的，
  由生成器的 `attachTitleSeeds()` 按「同组内难度进度」自动配 —— 进度 0~1 映射到
  Lv2~Lv200 的目标等级，在 `specialCrops` 里取最接近的那种，进度 ≥0.8 给 2 颗。
  这样调门槛或加称号时种子自动跟着走，不需要人工重新对表；
- 图鉴称号 26 档：图鉴称号必附藏宝图（10~40 一级、50~90 二级、100~150 三级、
  160~200 四级、210+ 五级）；等级称号间隔给图（lv22/50/86/128/200 对应 1~5 级）；
- 自动机器（第 51 轮）从 lv22 起逐档穿插进奖励，高档位给 2~3 天；
- 领到的第一个称号会自动戴上，之后可以随时换着戴，**同时只能戴一个**；
- 佩戴的称号显示在顶栏（「更多功能 → 🏅 称号」里也能换）；
- 数据在 `state.farm.progress.titles = { claimed: { id: true }, equipped: id }`，
  称号表本身由 `tools/gen-data.mjs` 产出（`progression.js` 的 `TITLES`）。

⚠️ **奖励里的自动机器不能走 `inventory.add`**：`claimTitle` 会判 `ITEMS[itemId]?.auto`，
是机器就改走 `addAuto(kind, now, n)` 叠到时效上 —— 否则背包里会躺一堆永远用不掉的
`autoSprinkler ×3`。同样的特判在 `adventure.js applyReward` 与 `daily.js grantReward` 里也有。

老存档没有 `titles` 字段，读档时补一份空的 —— 等级称号不再自动生效，
需要玩家自己领一次。

## 标本

收集只是「见过」，**点亮**才是成就 —— 判定是**做好一份标本**：

- 一份标本要花掉仓库里 **50 个**同样的产出（`SPECIMEN_COST`）；
- 库存不够或已经做过时，图鉴卡上**根本不显示**「制作标本」按钮；
- 制作走确认弹窗，扣料、点亮、写存档一次事务；
- 收获数与种植数仍会统计，只是不参与点亮判定。

**点亮成功会播一段庆祝画面**（第 44 轮）：`makeSpecimen` 在提交存档之后发
`EVENTS.SPECIMEN`，payload 是 `{ cropId, name, emoji, seed, lit, total, litPercent }`；
`ui/codex-celebrate.js` 订阅它，播一张金绿卡片（作物图标 + 「图鉴点亮」+
点亮进度 + 种子奖励）。UI 侧的顺序是**先 `closeModal()` 再播**，失败才把详情弹回来 ——
否则弹窗会盖在庆祝层下面，玩家只看到「点了没反应」。

标本存在 `state.farm.progress.specimens` 里，结构是 `{ 作物id: true }`。

## 时报

`store/news.js` 记录「镇上的大新闻」，与农场日志的分工是：

| | 农场日志 `farm.log` | 时报 `state.news` |
| --- | --- | --- |
| 视角 | 我的农场发生了什么 | 全镇发生了什么事 |
| 来源 | 玩家自己的操作、邻居来串门 | 玩家里程碑 + 邻居的故事 |
| 容量 | 7 天 / 60 条 | 7 天 / 80 条 |

写入走 `addNews(emoji, text, options)`，`options` 是 `{ at, who, crop, cat }`：
邻居的故事由离线结算补写过去的时间点，所以内部按 `at` 倒序重排后再截断，
不假设数组有序。

- `who` 是涉及者的农场 id 数组，界面上给人名标签用；
- `crop` 是相关作物的 id。有值时时报里那枚图标就是该作物本身，点一下打开作物信息
  ——「冒险挖到限定种子」这条就是靠它把图标换成作物、同时在正文里给出可点的作物标签；
- `cat` 是顶部筛选的分类（`level` / `steal` / `dog` / `adventure`）。不传时按图标兜底
  （`🎉 🥷 🐕 💰`），所以图标被换成作物之后仍要显式传 —— 否则它会掉出「寻宝」档。

时报是 `news` 表（`seq` 即排序），落盘时整表重写，见 [05-存储层](./05-存储层.md)。

## 冒险

`store/adventure.js` 只做四件事：

| 函数 | 做什么 |
| --- | --- |
| `ownedMaps()` | 背包里还有哪些藏宝图（`map_1` ~ `map_5`） |
| `startRun(tier)` | 扣掉一张图，生成这一趟的牌堆（`data/adventure.js` 的 `buildRun`） |
| `choose(side)` | 走一边：命中奖励就发到背包 / 金币，并把当前进度 +1 |
| `finishRun()` | 结束这一趟，补一条总结日志 |

关键约定：

- **奖励即时落盘**：每次挖到东西都会 `commit` 一次，所以中途点「退出」、
  甚至刷新页面，已经到手的东西都还在；丢掉的只是没走完的步数。
- **牌堆只存在内存里**（模块级 `run` 变量），不进存档 ——
  冒险是一口气走完的短流程，没必要为它加一套中断恢复。
- 奖励发放复用了现有的 `inventory.add` / `player.addCoins`，
  所以冒险挖到的种子会正常出现在包裹、播种弹窗与图鉴里。

邻居那边不逐张发牌：`data/adventure.js` 的 `rollNpcAdventure(npc)` 直接
按「池子价值 × 35%~80%」结算，买图的钱从 `npc.coins` 里扣。
完整规则见 [12-冒险](./12-冒险.md)。

## 农场日志

`state.farm.log` 是一份「最近 7 天」的操作流水，写入统一走 `player.addLog()`：

| 来源 | 例子 |
| --- | --- |
| 农场操作 | 种下 小麦（红土地）、给 玉米 浇水、收获 土豆 ×12 |
| 交易 | 买入 玉米种子 ×3、卖出全部农产品，+2400 💰 |
| 邻居互动 | 偷了 李大婶 的 胡萝卜、帮 小雨 浇了水 |
| 邻居来串门 | 林妹妹 来你的农场，顺走了 小麦 ×1 / 赵老板 顺手帮你浇了水 |

- 按 7 天裁剪、最多 60 条（`player.js` 的 `LOG_KEEP_DAYS` / `LOG_CAP`）；
- 存 `log` 表的一行一条，按 `[farmId, seq]` 关联到玩家农场；
- 写入时不保证有序 —— 邻居结算是补写过去的时间点，所以**展示时按 `at` 倒序排**；
- 每次写日志都跟随当次业务事务一起落盘，不做单独的存储操作。

界面上是一个从底部上滑的浮窗（`ui/log-sheet.js`），入口是农场页底部那颗
「📔 农场日志」按钮，按天分组、组内按时间倒序。

邻居那边也有自己的日志（`friend.log`，最近 10 条），
玩家的偷菜 / 浇水 / 捉虫也会记进对方的日志里 —— 双方看到的是同一件事的两面。

写入走 `social.logFriend()`（模块内私有，3 行 + `LOG_LIMIT` 截断），
有 6 处调用：偷菜、被狗抓、浇水、捉虫、一键浇水、一键杀虫。

> 踩过的坑：这个函数在某次编辑里被整个删掉过。`npm run check` 的 9 项
> **全都抓不到** —— `node --check` 只查语法，模块内私有的未定义引用不在检查范围内。
> 只有 e2e 真跑一次 `social.steal()` 才炸出 `ReferenceError: logFriend is not defined`。
> 「模块内私有函数」尤其要小心：它没有导出，也就没有任何导入检查兜底。

## 数值清洗（防 NaN）

IndexedDB 用结构化克隆算法保存数据，**`undefined` 会被原样存下来**。
所以存档里可能藏着 `readyAt: undefined` 这种字段，
界面上算 `readyAt - now` 就会得到 NaN，最终显示成「NaN小时」。

两道防线：

1. `normalizePlot` / `normalizeNpc` 把所有时间戳逐个清洗成有限数（`safeNum`）；
2. `fmtDuration` 对非有限输入直接返回「—」，绝不让 NaN 漏到界面上。

`safeNum(value, fallback = 0)` 定义在 `core/utils.js`。
