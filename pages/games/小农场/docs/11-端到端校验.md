# 11 · 端到端校验

`npm run check` 是**静态**校验：语法、导入导出、DOM id、CSS 变量、数据一致性。
它抓不到「运行时才炸」的问题 —— 上一轮就因为这个漏掉了两个崩溃。

所以额外有一套**真实浏览器**的校验：驱动系统 Chrome 跑完整交互，
捕获任何控制台错误、未捕获异常和 4xx 请求。

## 关键技巧：在页面里直接拿游戏内部模块

页面用的是原生 ESM，可以通过 `import()` 拿到**与游戏同一份**模块实例：

```js
const r = await page.evaluate(async () => {
  const state = await import('/src/store/state.js');
  const farm = await import('/src/store/farm.js');
  const inv = await import('/src/store/inventory.js');

  state.state.player.coins = 500000;
  inv.add('seed_小麦', 5);
  await farm.plant(0, '小麦');

  return state.state.plots[0].cropId;
});
```

这比「造一份假数据再点 UI」可靠得多：
既能精确准备测试前提，又能直接断言领域层的真实结果。

**注意**：ESM 的 `import()` 走的是 URL 解析，
`/src/store/state.js` 和主程序里的 `./store/state.js` 解析到同一个 URL，
所以是同一个模块实例（改的是同一份内存状态）。

## 写这类脚本的三个坑（第 14 轮实测）

1. **切页要等 `body[data-page]` 落地**：各页内容启动时就渲染过，
   光等「元素存在」会瞬间通过，点到的是隐藏页面里 0×0 的元素；
2. **邻居页进入有离线结算浮层**（至少 650ms），点击会被它吞掉；
3. **所有浮层都有位移动画**（0.25~0.3s），元素一存在就点会点在动画中途。
   通用解法是等元素及其祖先的 `getAnimations()` 全部 `finished` 再点。

## 写这类脚本的八个坑（第 16 轮实测）

这一轮的验证对象是「点一下之后界面还在原地」这类**状态保持**问题，
比功能正确更难测 —— 断言写得不对就会得到一个绿色的假通过。

### 1. 商店切 tab 是 smooth 滚动，约 1 秒

`switchTab()` 用的是 `scrollTo({ behavior: 'smooth' })`。
动画没停就点下一个元素，点到的位置是移动中的中间态，**会点空**。

```js
// 轮询 scrollLeft 直到连续两次相同，才算真的停稳
let prev = -1, cur = panels.scrollLeft;
while (cur !== prev) { prev = cur; await sleep(100); cur = panels.scrollLeft; }
```

### 2. `element?.click() ?? fallback` 会点两个

`?.click()` 成功时返回 `undefined`，所以 `el?.click() || other.click()`
里 `undefined` 是假值，**两个都会点**。要写成：

```js
const target = querySelector(A) || querySelector(B);
target?.click();
```

### 3. `el.click()` 返回 undefined，不能拿返回值做条件

同理，也别把「点第一个」和「点指定 id」用 `||` 串起来：

```js
const row = qs(`[data-id="${id}"]`) || qs('.row');
```

这里特别阴 —— 弹窗里显示的是**另一位 NPC** 的数据，断言会莫名其妙地失败，
排查方向完全跑偏。

### 4. 验证滚动位置不能只看 `scrollTop === 0`

面板没有可滚长度时 `scrollTop` 恒为 0，测不出「有没有被重置」。三个前置条件：

```js
const panel = qs('.shop-panel[data-panel="seed"]');
assert(panel.scrollHeight - panel.clientHeight > 100);   // 真的有得滚
panel.scrollTop = row.offsetTop - 200;                  // 真的滚到中间
assert(panel.scrollTop > 0);                            // 确认起点非零
// ... 触发重绘 ...
assert(panel.scrollTop === before);                     // 位置保住了
```

### 5. 商店筛选条默认是「现在能种」

新号在这个档位下只有 3 行，根本滚不动。测种子面板要先切「全部」；
而且**未锁定的行只排在列表开头**，得先把 `player.level` 拉高才有铺开的可买行。

### 6. 断言别写死基础拦截率

实际拦截率 = 品种基础率 × 饱腹度修正。槽不满时它**不等于**基础率：

```js
assert(Math.abs(chance - expectedRate) < 0.001);   // 先把槽喂满再断言
```

### 7. 概率性断言要「重复到成立为止」或改用确定性注入

「被狗抓住后全场封锁」这类断言，如果只跑一次，
失败率就是 `1 − 拦截率`，龙犬满槽也有 20% 会漏。
本轮改成指定 `dogBreed = 'longquan'`（80%）+ 循环重试。

更稳的做法是**把随机源替换掉**，让测试从「大概成立」变成「必然成立」。

### 8. store 迁移函数后，老脚本里的引用会静默变成 undefined

从 `social.js` 挪到 `store/dogs.js` 之后，老 e2e 里的
`social.feedDog()` 和从 `data/friends.js` 导入的 `DOG_SATIETY_MAX`
会变成 `undefined` —— **不报错，只是值为空**，断言会以「差了一个数量级」
的方式莫名其妙地失败。改动 store 的导出路径后，必须逐个 grep 旧路径。

## `logFriend` 那个 bug 值得单独说

它是本轮唯一一个**纯逻辑丢失**的 bug，却是最典型的「静态校验盲区」：

`social.js` 里 `logFriend(friend, at, emoji, text)` 被某次编辑整个删掉了，
但文件里还有 **6 处调用**（偷菜、被狗抓住、浇水、捉虫、一键浇水、一键杀虫）。

`npm run check` 的 9 项**一项都没报**：

- 第 1 项 `node --check` 只查语法 —— 没定义但被调用的标识符语法上完全合法；
- 第 2、3 项查导入导出 —— 它是模块内私有的，**没有 export 就没有对账**；
- 其余各项查 DOM id、CSS 变量、数据一致性 —— 都跟它无关。

只有 e2e 真跑一次 `social.steal()` 才炸出来。修法是按 git 版本恢复原实现
（3 行 + `LOG_LIMIT` 截断）。

> 结论：**模块内私有函数没有任何静态保护**。删改这类函数时，
> 除了 grep 函数名，还得确认每个调用点。e2e 至少要覆盖一次每条用户路径。

## 拖拽手势那个 bug 值得单独说

症状是「点种子卡按钮，弹窗自己关掉了，什么都没种上」。
排查过程：

1. `elementFromPoint(按钮中心)` 返回按钮 —— 看起来按钮在最上层；
2. 但真实鼠标点击却落在 `.modal-mask` 上；
3. 于是怀疑坐标算错，量了 `getBoundingClientRect` —— 按钮在 y=322，卡片在 y=126，都对；
4. 最后用 rAF 逐帧记录浮层位置，发现**点击瞬间卡片跑到了 y=461**，还在动画中；
5. 顺着查到 `drag-close`：它的 `mousemove` 挂在 window 上，
   而 puppeteer 的 `mouse.click` 是 move → down → up，
   **move 先于 down 发生**，此时 `startY` 还是 0，
   「鼠标绝对 Y 坐标」被当成拖动位移写进了 `panel.style.transform`。

修法是加 `tracking` 标志，且鼠标的 move/up 只在按下期间监听。
**这是桌面端必现的 bug，静态校验无论如何都抓不到。**

## 写这类脚本的注意事项

- **坐标点击 vs 直接派发**：`page.click()` 是按元素中心点坐标点击的，
  元素在可滚动容器里时容易偏。`element.click()` 是直接派发事件，
  测「处理器有没有被正确绑定」用它更稳；测「点得准不准」才用坐标点击。
- **隐藏页面里的元素点不到**：`page.click` 会报
  `Node is either not clickable or not an Element`。
  切页后要重新 `page.$$` 拿元素。
- **弹窗会挡住后续操作**：切页或点下一个目标前先把 modal / subpage 关掉。
- **断言要比对 before/after**，不要写死数值 —— 前一步的产出会让后面的基准变化。
- **随机性要可控**：邻居有没有可偷的作物、产量多少都是随机的，
  用 `game()` 精确准备一个目标（把某块地的 `readyAt` 改到过去）再断言。
