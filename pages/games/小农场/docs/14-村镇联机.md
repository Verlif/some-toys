# 村镇联机（P1 只读）

> 一个村镇 = 一个房间。填同一个村镇名的人互相看得见，点对方就能打开他的农场。
> 不需要服务器、不需要房主，但**需要 https 与公网信令**（原因见
> [13-联机可行性](./13-联机可行性.md)）。

## 怎么玩

1. `npm run start:https` 启动（自签证书，首次访问点一次「继续前往」）；
2. 两台设备打开 `https://<本机局域网 IP>:5173`；
3. 「☰ 其他 → 🏘 村镇」，填**同一个村镇名**（口令可以留空），点「加入村镇」；
4. 对方会出现在「在线邻居」里，点「访问」就能打开他的农场。

名字存在 localStorage（`sun_farm_village`），下次进游戏会自动回村。

## 村镇浮窗

进村后才出现在底部导航中间（第 3 个位置），没进村时不占位。

- **不做卡片**：一行村镇名 + 一行在线名单，平铺；
- 村镇名**不可编辑**，右边贴着我的昵称（「🏘 桃源村 · 阿黄」），改名后立刻跟着变；
- **点村镇名**展开「连接号 / 在线人数 / 我的昵称 / 离开村镇」，**点空白处**收起 ——
  收起时昵称输入框直接从 DOM 里摘掉，所以不可能误编辑；
- 再点一次空白（已收起时）才关窗。

## 分成四层

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 传输 | `net/link.js` | 连接生命周期、收发 JSON 字符串。换 SSE 中继只改这一个文件 |
| 协议 | `net/protocol.js` | 三种消息 + **外来数据清洗**（名字去标签、地块夹到 40、作物 id 必须在表里） |
| 名册 | `store/peers.js` | `state.peers` 的读写、hello 握手、快照请求/应答 |
| 视图 | `ui/subpages/village.js` | 村镇设置 + 在线名单 + 「访问」 |

库本身固化在 `vendor/webconnect.js`（MIT，0.0.12，未压缩 437 KB），
**按需动态 import** —— 没联机的玩家不会为它付启动开销。

## 状态模型：真人 ≠ NPC

```js
state.friends   // 32 位 NPC：落库、被 npc-sim 推进
state.peers     // 联机真人：只活在内存，关页面就没了
```

- `state.peers` **不落库、不进 `npc-sim`**，所以邻居模拟一行都不用改；
- `getFriend(id)` 先查 NPC 再查 `peers` —— 弹窗、记录里的人名标签、
  时报都只认这一个入口，因此「点开真人农场」与「点开 NPC 农场」是同一套 UI；
- 「不在线就不显示」是自然结果：没有 hello 就不进名册，不存在离线缓存。

## 报文一览

| 消息 | 什么时候发 | 内容 |
| --- | --- | --- |
| `hello` | 进村、发现新 peer、改昵称 | 版本号 + 昵称 / 头像 / 等级；`reply` 标记防止来回弹球 |
| `snap` | 需要对方农场 | 请求号 `req` |
| `snap:res` | 收到 `snap`，或自己农场有变化（`push:true`，无 req） | 快照：可用地块、日志 12 条、狗、等级、身家 |
| `toast` | 升级 / 播种 / 挖到稀有种子 / 冒险结算 / 收礼 | ≤40 字的一句话 |
| `gift:offer` · `gift:accept` · `gift:decline` · `gift:ack` | 送礼四步 | 物品 key、份数、请求号 |
| `act` · `act:res` · `act:pay` | 在别人农场上浇水/杀虫/施肥/偷菜 | 动作、地块序号、道具 id、罚款回执 |

三条纪律：

1. **一律 JSON 字符串**，不依赖库的对象序列化；
2. **`v`（数据版本 = 作物种类数）不一致直接拒绝**，差一种作物就会把对方的地渲染成空气；
3. **外来数据全部过一遍清洗**，昵称里的 `< > & " '` 会破坏邻居弹窗的 HTML。

快照实测约 10 KB，DataChannel 一次就够，不需要分片逻辑。

## 真人农场弹窗

快照进名册时打上 `net: true`，邻居弹窗据此走另一条分支：

- 按钮与 NPC 农场一致：💧 / 🐛 / 🧪 / 偷 1 个，动作名带 `peer-` 前缀；
- 右上角角标写「🛰 联机」，信息格把「偷菜档位」换成「来历 · 联机好友」；
- 不显示好感度（真人之间还没有好感体系，拿本地 0 糊弄人不如不显示）；
- 一键照料（标题右侧的 🚿 / 🧴）对真人仍然是隐藏的 —— 一次点几十块地，
  由对方批量执行需要另一套确认流程；
- 动作分发按类型白名单：只认 `crop-info / peer-* / peer-gift-*`，
  旧 DOM 被点到也不会改坏本地状态。

## 前提与已知噪音

| 项 | 说明 |
| --- | --- |
| https | 页面不是安全上下文时 `crypto.subtle` 为空，库在连房间第一步就抛错。`server.mjs --https` 会用 openssl 生成自签证书（SAN 覆盖 localhost + 当前所有局域网 IPv4），换网络后自动重签 |
| 公网信令 | 库同时接 torrent tracker / MQTT / Nostr。实测其中 `tracker.btorrent.xyz`（500）与 `relay.nostrdice.com`（DNS 失败）会报错，但**连接照常成功** —— 控制台这几条红字是正常的，不代表没连上 |
| AP 隔离 | 路由器开了 AP 隔离会让同 WiFi 的两台机器互相不可达 |
| 换村镇 | 旧连接的回调统一用 `alive()` 拦掉；库里 `Disconnect()` 在一个 peer 都没有时什么都不做，所以额外对三个 room 补一次 `leave()` |

## 孤岛：不联机也要能好好玩

- 进入村镇失败（http + 局域网 IP、两端断网、版本不一致）→ toast
  「🏝 网络不支持联机，你正处在孤岛中」，随后退成单机；
- 村镇页会写清当前是「孤岛模式」，加入按钮照常在；
- 「离开」调用 `quitVillage()`：断连、清名册、把 localStorage 里的 `auto` 置 false ——
  **下次打开就是纯离线环境，不会自己重连**；
- 成功加入时 `auto = true`，刷新 / 重开游戏会自动回到同一个村镇。

## 实时同步：别人点一下，我这边就变

`store/peers.js` 订阅 `FARM / PLAYER / INVENTORY`，**1.2 秒节流**后广播一份新快照
（`snap:res` 且 `push:true`，没有 `req`）。接收方更新名册里的对手农场，
并 `emit(EVENTS.PEER, farmId)`；如果邻居弹窗正开着这个人，`friend-modal` 会
就地重绘地块与信息格 —— 滚动位置不变，不会像重开弹窗那样弹回顶部。

只推这些「看得见的变化」就够了：地块成熟、缺水、再生全靠时间戳算，
不需要逐帧同步。

## 村内广播：哪些事值得让全村知道

`broadcastToast(text)` 一条短句（≤40 字），接收方渲染成「头像 名字：内容」：

| 场景 | 文案 |
| --- | --- |
| 升级 | 🎉 升到了 Lv.N |
| 播种 | 🌱 种下了 某某 |
| 冒险挖到限定种子 | 🌰 挖到了稀有种子「某某」 |
| 冒险结算 | 🧭 冒险归来，带回 N 份奖励 |
| 收下别人的礼物 | 🎁 小绿 送给 阿黄 🌾小麦 ×3 |

没进村镇时这些调用直接返回，单机玩家看不到任何多余提示。

## 在别人农场上动手

访问真人农场时，地块上的按钮与 NPC 农场一样：💧 浇水、🐛 杀虫、🧪 施肥、偷 1 个。
区别只有一个 —— **农场主人是权威**：

```
访客 act{kind, plot, itemId} → 主人校验并执行 → act:res{ok} → 访客只做自己这侧的记账
```

| 动作 | 主人校验 | 访客记账 |
| --- | --- | --- |
| 浇水 | 真缺水且未成熟 | 经验 +作物等级 |
| 杀虫 | 真生虫且未成熟 | 经验 +作物等级 |
| 施肥 | 未成熟、这轮没施过、道具合法 | 扣掉自己包裹里的那瓶化肥 |
| 偷菜 | `isStealable` + 守护犬判定 | 拿到 1 个产出；被抓住则交罚款 |

偷菜与 NPC 完全一致：**每块地每轮只能偷 1 个**（主人侧 `stolen` 兜底，重放无效）；
**被守护犬抓住** → 整座农场当前所有作物本轮 `guarded`，谁都偷不了，
罚款 `售价 × 5` 由访客扣、主人入账（`act:pay`，金额上限是主人自己记下的那笔）。

施肥用的是**访客自己的化肥** —— 不能让访客花主人的存货。

## 玩家之间送礼

清单底部有 **🧺 仓库 / 🎒 包裹** 两个 tab：仓库是农产品，包裹是种子 / 道具 / 藏宝图；
行样式照抄仓库与包裹页，点行本身可以看详情（种子看种子详情，产出看作物详情）。

和给 NPC 送礼是两套逻辑 —— 对方是真人，可能不收：

```
送方  先扣货 → gift:offer
收方  弹出「小黄想送你 🌾小麦 ×3，收下吗？」→ 接收 / 不要
收方  接收 → gift:accept
送方  核对要约还在 → gift:ack{ok:true}
收方  收到 ok 才入包，并广播全村
```

- **先扣后给**：要约发出时就扣，否则对方点接收时东西可能已经被花掉；
- **拒收 / 90 秒不回应自动退回**，并 toast 告诉送方；
- **收方等 ack 才入包**：送方已经退回的情况下再点接收会收到 `ok:false`，
  不会出现「东西退回去了却还被领走」；
- 收到的东西进背包走 `inventory.add`，图鉴收集也会跟着记一笔。

## 只同步「对方用得上的地」

地块从这一版起自带 `usable`（见 [04-数值平衡](./04-数值平衡.md#地块要花钱买)），
快照里**只发 `usable` 的地**：访客看到的就是对方真正在种的地，
不会看到一排没买下来的荒地。对方买地之后，下一次推送自然就多一块。

## 安全加固

联机是「朋友之间玩」，客户端天然可改，所以只做**能挡住的那些**：

| 位置 | 措施 |
| --- | --- |
| 传输 | 单条报文 > 48 KB 直接丢；每人 5 秒内 > 60 条直接丢 |
| 解析 | 消息类型必须是 ≤16 字符的字符串；JSON 解析失败静默丢弃 |
| 快照 | 地块 ≤40、日志 ≤12 条且每条 ≤60 字、等级 1~200、金币非负、时间戳夹到 ±1 天、作物/土地 id 必须在表里（用 `hasOwnProperty`，防 `__proto__`） |
| 文本 | 昵称 / 头像 / 日志全部去 `< > & " '`，按**码点**截断（不会劈开 emoji） |
| 礼物 | 物品必须在白名单（`isItemKey`）、数量 1~999、同一人 3 秒一条、同时最多 10 笔待确认 |
| 罚款 | 主人回执时记下金额，`act:pay` 只能 ≤ 这个数 |
| 刷屏 | 快照请求每人 1 秒一次；全村 toast 1.5 秒一条 |

改不动的是「访客自己那侧」—— 改了内存的客户端总能给自己加东西，
所以数值不与别人交互（偷菜、罚款、送礼）都由**对方**执行或回执。

## 还没做的

- 邻居页展示真人（现在只在村镇浮窗里）；
- 离线排队（现在的语义是「不在线 = 不在名册」）；
- 一键照料（🚿 / 🧴）对真人农场还没开 —— 单块操作已经够用。
