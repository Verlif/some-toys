# 02 · 架构总览

## 分层与依赖方向

依赖是**单向**的，不允许逆向引用：

```
ui  →  store  →  core  →  （浏览器 API）
 └──→  data（纯配置与规则，谁都可以读）
```

| 层 | 位置 | 允许知道什么 | 禁止知道什么 |
| --- | --- | --- | --- |
| core | `src/core/` | 浏览器 API | 任何游戏概念 |
| data | `src/data/` | 纯数据 | 浏览器 API、其它层 |
| store | `src/store/` | core、data、其它 store | **任何 DOM 符号** |
| net | `src/net/` | data、浏览器 WebRTC API | DOM、store 的业务状态（只收发消息） |
| ui | `src/ui/` | core、data、store | 不允许修改 state |

`net/` 只出现在联机场景：`link.js` 管连接与收发、`protocol.js` 管消息与清洗，
业务侧由 `store/peers.js` 读写 `state.peers`。这样换传输（webConnect → 局域网中继）
不会波及任何业务代码，见 [14-村镇联机](./14-村镇联机.md)。

### 为什么 store 不能碰 DOM

不是为了洁癖，而是为了两件具体的事：

1. **领域逻辑可以独立验证**。`npc-sim.js` 是纯计算，能在 Node 里直接跑，
   我用它压测过「离线 10 年结算耗时 2 毫秒」——这在没有 DOM 依赖时才可能。
2. **提示文案不会散落在业务里**。store 只需要表达「我想告诉玩家一件事」，
   具体用 Toast 还是红字还是弹窗，由 UI 层决定。

## 事件总线

`core/bus.js` 提供一个极简的 `on / off / emit`。事件名集中在 `EVENTS` 常量里，
避免各模块拼字符串拼错。

```
store 改完状态
   ├─ 落盘（storage.commit，单事务）
   └─ emit(EVENTS.XXX)
          ↓
      ui 订阅并重渲染对应视图
```

### 事件清单

| 事件 | 何时发出 | 谁监听 |
| --- | --- | --- |
| `state:player` | 金币 / 经验 / 等级变化 | HUD、农场、商店、邻居、子页面 |
| `state:farm` | 地块变化 | 农场页、商店 |
| `state:inventory` | 背包变化 | 农场、商店、子页面 |
| `state:friends` | 邻居数据变化 | 好友页、子页面 |
| `state:pets` | 狗窝变化（添粮、换上岗、冒险挖到新狗） | 农场页底部狗行、狗窝页 |
| `state:sign` | 签到 / 连续签到变化 | 签到页、HUD |
| `state:codex` | 图鉴统计 / 引导进度变化 | 图鉴页、引导页、HUD |
| `state:relation` | 好感度或好友关系变化（打理 / 送礼 / 交易 / 催上线 / 加好友） | 好友页、好友弹窗、村中心村民总览、送礼清单 |
| `state:notice` | 农场通知（信箱）新增 / 领取 / 标已读 | `ui/notices.js`（入口角标 + 列表就地刷新） |
| `ui:board-award` | 每日榜单出榜，玩家拿到名次 | `ui/board-celebrate.js`（全屏庆祝动画，排队逐张播） |
| `ui:notify` | 领域层要弹提示 | Toast |

### 领域层怎么弹提示

```js
// store/farm.js
import { notify } from './notify.js';

await persist();
await completeGuide('harvest');
notify(`收获 ${crop.emoji}${crop.name} ×${amount}`, 'gold');
```

`notify` 内部只做一件事：`emit(EVENTS.NOTIFY, { message, type })`。
`ui/toast.js` 订阅它并渲染。**store 全程没有引用过 `document`。**

## 状态管理

整个游戏只有一份内存状态，在 `store/state.js`：

```js
export const state = {
  farm: null,      // 玩家农场（身份 / 经济 / 看家狗 / 成长档案 / plots / log）
  friends: [],     // 32 座邻居农场，结构与 farm 完全一样
  bag: {},         // 背包 { itemId: count }
  relations: {},   // 好感度 { 'a|b': -200~200 }，0 不落键
  news: [],        // 时报 { at, emoji, text, who, crop, cat }
};
```

`relations` 是唯一**不属于任何一座农场**的状态：它是两个 id 之间的事，
所以单独一张表、单独的读写模块（`store/relation.js`），
不进 `farm` 行 —— 见 [05-存储层](./05-存储层.md)。

**玩家也是一座农场**：`state.farm` 与 `state.friends[i]` 是同一个形状，
区别只有 `kind`（`player` / `npc`）以及玩家这一座多带了 `progress`
（签到 / 图鉴 / 称号 / 引导）和狗窝。

每座农场自带 `plots` 与 `log`，它们其实来自 `plot` / `log` 两张子表，
读档时按 `farmId` 挂回来、写档时再拆回去 —— 见 [05-存储层](./05-存储层.md)。

规则：

- 只有 `store/` 下的领域模块可以改它，`ui/` 只读；
- 任何改动都必须落到 IndexedDB，再由事件总线通知 UI；
- 一次业务操作涉及的多张表，放进**同一个事务**提交。

## 启动流程

`src/main.js` 是组合根，负责启动顺序与跨模块接线：

```
0. 启动画面            「正在连接到农场」—— 开库之前就已经可见（写在 index.html 里）
1. openDatabase()      打开/创建 IndexedDB
2. initState()         读档 + 补齐地块与邻居 + 把补齐结果原样写回一次
3. mountToast()        接管事件总线的提示请求
4. mountModal()        绑定弹窗遮罩与下拉关闭
5. mountHud()          量出顶栏高度写入 CSS 变量，绑定展开交互
6. mountSubpage()      绑定子页面关闭与动作分发
7. mountSheet()        渲染「更多功能」入口
8. mountFarm/Shop/Friends  各视图的事件委托与订阅
9. mountTabs()         底部主导航
10. 首帧渲染 + activatePage('farm')   启动画面切到「正在进入农场」
11. 订阅跨模块事件（子页金币同步等）
12. markSessionStart() → pollOnline(进度回调)   // 首次只补离线，不弹上线提示
13. 启动地块心跳（只在农场页可见时跑）
14. 启动邻居在线轮询（每 60 秒，标签页隐藏时跳过）
```

启动画面分两段文案：**正在连接到农场**（开库）与**正在进入农场**
（读档、搭界面、补算邻居近况）。它写在 `index.html` 里而不是由 JS 插入，
所以 JS 还没跑起来时就已经可见，整个加载过程都不会白屏。

**顺序不能反**：先挂载再首帧渲染。反了会漏掉 mount 阶段触发的事件。
第 12 步的两句也不能反：先 `markSessionStart()` 再 `pollOnline()`，
否则刚进游戏就会收到一堆「XX 上线了」。

## 心跳

全局只有两个常驻定时器（另有邻居演出的短延时，见下）：

```js
// 地块心跳：只刷新进度条与倒计时
setInterval(() => {
  if (currentPage() === 'farm') renderFarm();
}, 500);

// 邻居在线轮询：推进世界 + 弹上线提示
setInterval(() => {
  if (document.hidden) return;
  checkOnlineVisits();
}, 60_000);
```

除这两处之外**没有常驻定时器**。世界状态的推进靠**世界时钟**
（`store/world.js`）：每 60 秒把世界往前推一分钟，离线时从「上次离开」
逐段推到「现在」—— 同一条 `advanceWorld`，只是步长与是否演出不同。
「被偷过的地恢复」「狗粮槽消耗」这类效果仍然靠时间戳判定，
不需要每秒问一次「现在几点了」。

唯一的例外是**在线演出**：玩家在线时邻居到点了，`store/social.js` 会
用一串 `setTimeout` 把这一趟上线拆成动作逐步执行（每步隔 3~7 秒），
队列空了就不再排新的定时器。

## 渲染策略

### 地块：key-diff

40 块地每 500ms 刷新一次，如果无脑重写 DOM 会很难受。
所以给每块地算一个「指纹」：

```js
function plotKey(plot, status) {
  return [status, plot.cropId, plot.soil, plot.harvested,
          plot.watered, plot.fert, plot.organic, plot.weed, plot.pest].join('|');
}
```

指纹没变就不碰 DOM，只更新进度条宽度和倒计时文本；变了才重建这块地的 innerHTML。

### 其它视图：带缓存的 setHTML

`core/dom.js` 的 `setHTML(el, html)` 会比较上一次的内容，
相同则跳过，避免无谓的重排和事件失效。

### 商店：保留横向滚动位置

商店重绘（买东西之后）会重建 `.shop-panels`，
所以 `renderShop` 会先记下 `scrollLeft` 与当前面板的 `scrollTop`，重绘后恢复。

**恢复顺序有硬约束**：必须先 `scrollLeft = keepLeft` 再 `syncTabFromScroll()`，
否则后者读到 `scrollLeft = 0` 会把 `activeTab` 误判成第一个 tab，
纵向滚动随后恢复到错误的面板上。细节见 [09-UI规范](./09-UI规范.md)。

## 新增功能的检查清单

1. 数值相关 → 改 `data/`，需要重算经验曲线就改 `tools/gen-data.mjs` 并重跑
2. 业务逻辑 → 在 `store/` 加模块，**不要引用 DOM**，要提示就走 `notify()`
3. 状态变化 → 在动作末尾 `commit()` 并 `emit(EVENTS.XXX)`
4. 展示 → 在 `ui/` 加视图并订阅对应事件
5. 新的 id → 同步加到 `index.html`，否则静态校验第 5 项会失败
6. 新的 `data-action` → 必须在 `actions: {}` 或 `*_ACTIONS = {}` 里有同名键，否则第 7 项会失败
7. 跑 `npm run check`
