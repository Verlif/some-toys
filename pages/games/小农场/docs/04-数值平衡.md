# 04 · 数值平衡

作物、土地、地块、经验、称号这五张表由 `tools/gen-data.mjs` 统一产出：

```bash
node tools/gen-data.mjs
```

生成器内置自校验，任何一处失衡（等级倒退、售价倒挂、重名、阶段未配齐、
emoji 滥用、地块未对齐满级……）都会报错并**拒绝写文件**。

## 核心思路：经验曲线是反推的

传统做法是先拍一条经验曲线，再让作物去填，结果必然有一处失衡。
这里反过来 —— 先确定「一轮成熟能拿到多少经验」，再由它除以「升一级希望需要几轮成熟」：

```
每轮经验 = 已解锁地块数
         × 作物基础经验
         × 土地经验倍率
         × 多次收获收益系数

升级所需 = 每轮经验 × 每级需要的轮数
```

好处是：**调整土地倍率、再生次数、地块数或作物经验时，经验曲线自动跟随**，
不会出现「前期飞快后期劝退」或者反过来。改平衡只需要改生成器里的一处。

生成器里的对应实现：

```js
function expNeeded(level) {
  const perRound = plotsAt(level)          // 该等级已解锁的地块数
    * baseExp(level)                      // 作物基础经验
    * soilExpMulAt(level)                 // 该等级可用最高土地的经验倍率
    * harvestFactor(harvestsAt(level));   // 多次收获的总收益系数
  return Math.max(20, Math.round(perRound * roundsAt(level)));
}
```

其中 `harvestFactor(n) = Σ 0.8^i`（i 从 0 到 n-1），与游戏内 `farm.REGROW_EXP_DECAY` 是同一套公式。

## 各档公式

| 项 | 公式 | 说明 |
| --- | --- | --- |
| 作物基础经验 | `5 × lv^1.45` | Lv1=5，Lv50≈1455，Lv200≈10840 |
| 种子价格 | `10 × lv^1.75` | Lv1=10，Lv50≈9410，Lv200≈106366 |
| 卖出单价 | `种子价 × (1.2 + lv × 0.016) × 风味系数` | 单次回报越厚，成本回收倍率增长放缓 |
| 产量 | `[2 + ⌊lv/25⌋, 4 + ⌊lv/25⌋ + ⌊lv/40⌋]` | Lv1=2-4，Lv200=10-17 |
| 成熟时间 | 分段，见下 | |

### 成熟时间的分段

```
lv ≤ 20   :  40 + (lv-1) × 18              → 40s .. 6.4min
21 ≤ lv ≤ 60: 380 × (lv/20)^0.55            → 8min .. 12.6min
lv > 60   :  760 × (lv/60)^0.45            → 13min .. 22min
```

成熟时间刻意**允许非单调**：风味（甜/酸/鲜/辛/平）会调制时间，
所以甜菜比前面的作物快、蘑菇比前面的慢。这是有意的调剂。
但生成器加了硬约束：**相邻作物不能差出一倍**，否则观感上像数据出错。

售价则强制单调累计（`max(本次, 上次+1)`），避免「等级更高的种子反而更便宜」。

### 风味系数

| 风味 | 时间 | 价值 |
| --- | --- | --- |
| plain 平 | 1.00 | 1.00 |
| sweet 甜 | 1.10 | 1.18 |
| sour 酸 | 0.95 | 1.10 |
| umami 鲜 | 1.20 | 1.25 |
| pungent 辛 | 0.90 | 1.05 |

鲜味耗时长但贵，酸味快而便宜 —— 玩家能在同一等级段里挑到节奏不同的作物。

## 解锁节奏

145 种作物按用户定的节奏铺开：

| 等级段 | 每级解锁 | 该段作物数 | 说明 |
| --- | --- | --- | --- |
| Lv1-20 | 2~3 个 | 50 | 偶数级 2 个、奇数级 3 个 |
| Lv21-60 | 1~2 个 | 60 | 奇数级 2 个、偶数级 1 个 |
| Lv64-200 | 每 4 级 1 个 | 35 | 从 64 起步，保证最后一个恰好落在满级 200 |

实现：

```js
function buildUnlockPlan(count) {
  const plan = [];
  for (let lv = 1; lv <= 20; lv += 1) plan.push(lv, lv, ...(lv % 2 ? [lv] : []));
  for (let lv = 21; lv <= 60; lv += 1) plan.push(lv, ...(lv % 2 ? [lv] : []));
  for (let lv = 64; lv <= MAX_LEVEL; lv += 4) plan.push(lv);
  return plan.slice(0, count);
}
```

## 地块

40 块，开局送 6 块（都是 Lv1），其余 34 块从 Lv5 均匀铺到 Lv200：

```js
const unlock = new Array(40).fill(1);
const steps = 40 - 6;
for (let i = 0; i < steps; i += 1) {
  unlock[6 + i] = Math.round(5 + (i * (200 - 5)) / (steps - 1));
}
```

得到 `1,1,1,1,1,1, 5, 11, 17, 23, 29, 35, 40, ... 194, 200`。

Lv50 解锁 14 块，Lv100 解锁 19 块，Lv200 全部 40 块。

## 成长节奏预期

| 等级段 | 成熟时间 | 每级轮数 | 预期每级耗时 |
| --- | --- | --- | --- |
| Lv1-10 | 40s → 3.4min | 1.2 | ~4min |
| Lv11-25 | 3.4min → 7.9min | 2.0 | ~16min |
| Lv26-60 | 8min → 12.6min | 2.5 | ~31min |
| Lv61-120 | 13min → 16min | 3.0 | ~48min |
| Lv121-200 | 16min → 22min | 3.5 | ~78min |

满级总投入约 **156 小时**。按每天活跃 3 小时计，约一个半月。
加速手段是土地升级与多次收获作物。

注意这是**满状态**的估算：实际因为土地升级和再生作物会让每轮收益更高，
真实进度会快一些。

## 调平衡的正确姿势

```bash
# 1. 改 tools/gen-data.mjs 里的常量 / 公式 / CATALOG
# 2. 跑生成器（自校验不通过会拒绝写文件）
node tools/gen-data.mjs

# 3. 跑静态校验，确认数据表交叉一致
npm run check
```

**不要手改 `src/data/{crops,soils,progression}.js`** —— 会被覆盖，
而且经验曲线不会跟着重算。

## 生成器的自校验清单

- 作物数 ≥ 140、名称不重复、同一 emoji 最多用 2 次
- 每个 form 都有配置阶段路径
- 每条作物序列都以 `ripe` 结尾
- 等级 / 售价 / 种子价 / 经验 单调递增
- 成熟时间相邻跳变不超过 1 倍
- 地块数 = 40，开局块全为 Lv1，之后严格递增，最后一块恰好 Lv200
- 经验曲线严格递增
- 称号阶梯覆盖到 Lv200
- 土地解锁等级严格递增
