# 04 · 数值平衡

作物、土地、地块、经验、称号这五张表由 `tools/gen-data.mjs` 统一产出：

```bash
node tools/gen-data.mjs
```

生成器里带自校验，任何一处数值失衡（等级倒退、售价倒挂、重名、重复 emoji、
阶段未配齐、分类没生效、成熟时间跳变过大）都会报错并**拒绝写文件**。

---

## 核心思路：经验曲线是反推的

先确定「玩家每小时能拿到多少经验」，再乘以「升一级希望花多少小时」：

```
每小时经验 = 已解锁地块数 × 等级 × 900 × 土地经验倍率 × 多次收获收益系数
升级所需   = 每小时经验 × 每级目标耗时
```

好处是：**调整土地倍率、再生次数、地块数或作物等级时，经验曲线自动跟随**，
不会出现「前期飞快后期劝退」或者反过来。改平衡只需要改生成器里的一处。

那个 900 是这么来的：收获经验公式的时间项是「总时间(秒) / 4 × 等级」，
而一小时的成熟时间里能收获「3600 / 总时间」次，两者相乘就是 `3600 / 4 = 900`。

生成器里的对应实现：

```js
function expNeeded(level) {
  const perHour = plotsAt(level) * level * 900
    * soilExpMulAt(level)                 // 该等级可用最高土地的经验倍率
    * harvestFactor(harvestsAt(level));   // 多次收获的总收益系数
  return Math.max(100, Math.round(perHour * targetHoursAt(level)));
}
```

## 收获经验公式

玩家定的公式，玩家与 NPC 共用同一套：

```
经验 = 总时间 / 4 × 作物等级 + 作物等级 × 收获个数
```

- 「总时间」是这一轮实际要等的秒数，所以再生轮（时间更短）给的经验自然更少；
- 「收获个数」是本次实际收到的数量，含土地倍率与捉虫加成。

这个公式有个漂亮的性质：**时间项与成熟时间成正比，而一轮能收获的次数与成熟时间成反比，
两者正好抵消**。所以稳态下每小时的经验只取决于地块数和等级：

```
每小时经验 = 地块数 × 等级 × 900
```

于是「种哪一类作物」不影响升级速度，只影响**金币** ——
这正是下面三类作物取舍的落点。

实现在 `data/crops.js` 的 `expOf()`，玩家侧和 NPC 侧都调它。

## 成熟时间：小时级

参照《阳光牧场》的节奏，作物成熟时间最短 1 小时、最长约 41 小时（1.7 天）：

```
grow = 3600 × lv^0.7 × 风味系数 × 分类系数

Lv1  = 1.0h      Lv20 = 8.2h
Lv60 = 17.6h     Lv200 = 40.8h
```

之所以要这么慢，是为了让「缺水 / 虫害」这两个每 6 / 12 小时出现一次的照料操作
有意义 —— 如果作物 40 秒就熟，玩家根本遇不到需要浇水的时候。

## 三类作物：玩家的取舍

| 分类 | 判定 | 成熟时间 | 售价 | 每小时金币 |
| --- | --- | --- | --- | --- |
| 经验作物 | 粮食 / 纤维 / 糖料 / 根茎 / 菌菇 / 树木 | ×1.5 | ×0.75 | 0.50 倍 |
| 经济作物 | 水果 | ×0.9 | ×1.35 | 1.50 倍 |
| 普通作物 | 其余 | ×1.0 | ×1.0 | 1.00 倍 |
| 厚积薄发 | 14 种指定作物 | **×3.5** | ×1.0 | 0.29 倍 |

「厚积薄发」是「最长收获时间不一定和等级挂钩」的主角：
一株 Lv10 的菠萝要等 17 小时、一株 Lv24 的石榴要等 36 小时，
比周围高等级的普通作物都久，但单次给的经验也多得多。
它们的倍率是**覆盖**分类倍率的，不是叠加。

分类按生长形态自动判定，玩家很快就能学会「粮食=经验、水果=金币」。

三个分类的实测对比（同等级比较）：

| 等级段 | 普通 | 经验作物 | 经济作物 | 厚积薄发 |
| --- | --- | --- | --- | --- |
| Lv1-20 | 1.00× | 0.55× | 2.08× | 0.47× |
| Lv21-60 | 1.00× | 0.60× | 0.93× | 0.25× |
| Lv61-200 | 1.00× | 0.56× | 1.44× | — |

（数值是「每小时金币收入」相对同等级普通作物的倍数）

## 作物解锁节奏

145 种作物按用户定的节奏铺开：

| 等级段 | 每级解锁 | 该段作物数 | 说明 |
| --- | --- | --- | --- |
| Lv1-20 | 2~3 个 | 50 | 偶数级 2 个、奇数级 3 个 |
| Lv21-60 | 1~2 个 | 60 | 奇数级 2 个、偶数级 1 个 |
| Lv64-200 | 每 4 级 1 个 | 35 | 从 64 起步，保证最后一个恰好落在满级 200 |

```js
function buildUnlockPlan(count) {
  const plan = [];
  for (let lv = 1; lv <= 20; lv += 1) plan.push(lv, lv, ...(lv % 2 ? [lv] : []));
  for (let lv = 21; lv <= 60; lv += 1) plan.push(lv, ...(lv % 2 ? [lv] : []));
  for (let lv = 64; lv <= MAX_LEVEL; lv += 4) plan.push(lv);
  return plan.slice(0, count);
}
```

## 生长阶段与多次收获

每个作物按形态（根茎 / 叶菜 / 谷物 / 果实 / 花卉 / 菌菇…）决定一条阶段序列，
序列里每个阶段占整轮时间的比例由 `data/stages.js` 的 `weight` 决定：

```
播种 → 发芽 → 生长 → 开花 → 结果 → 成熟
```

根茎类没有花果阶段，会自动省略。`成熟` 只是「已可收获」的终点标记，
不参与时间分配 —— 否则会出现阶段显示成熟、地块却还不能收的错位。

**多次收获作物**（`harvests > 1`）收获后不消失，而是进入再生轮次：

- 首次成熟 `grow` 秒，之后每次 `grow × regrow` 秒；
- 再生轮次回到「开花 / 结果」阶段，跳过播种发芽，所以时间能显著压缩；
- 收获经验按新公式算：再生轮的时间更短，经验自然更少。

| 等级段 | 可收获次数 | 再生系数 |
| --- | --- | --- |
| Lv1-20 | 1（一次性） | 0.50 |
| Lv21-40 | 2 | 0.42 |
| Lv41-70 | 3 | 0.42 |
| Lv71-110 | 5 | 0.35 |
| Lv111-150 | 6 | 0.35 |
| Lv151-200 | 8 | 0.28 |

## 调平衡的正确姿势

```bash
# 1. 改 tools/gen-data.mjs 里的常量 / 公式 / CATALOG
# 2. 跑生成器（自校验不通过会拒绝写文件）
node tools/gen-data.mjs

# 3. 跑静态校验，确认数据表交叉一致
npm run check
```

**不要手改 `src/data/{crops,soils,progression}.js`** —— 会被覆盖，
而且经验曲线不会跟着重算。

## 生成器的自校验清单

- 作物数 ≥ 140、名称不重复、同一 emoji 最多用 2 次
- 每个 form 都有配置阶段路径，每条序列都以 `ripe` 结尾
- 等级 / 种子价 单调递增；产量**同一形态内**单调
- 成熟时间允许非单调（厚积薄发作物的存在就是为了这个），但相邻跳变不超过 5 倍
- 售价**同一分类内**单调（分类之间要有价差，不然取舍就没了）
- 三类作物都要有、厚积薄发至少 10 种、产量下限不低于 10
- 同等级比较：经济作物更贵且每小时金币更高，经验作物更便宜且更低
- 地块数 = 40，开局块全为 Lv1，之后严格递增，最后一块恰好 Lv200
- 经验曲线严格递增
- 称号阶梯覆盖到 Lv200，土地解锁等级严格递增
