# 04 · 数值平衡

作物、土地、地块、经验、称号这五张表由 `tools/gen-data.mjs` 统一产出：

```bash
node tools/gen-data.mjs
```

生成器里带自校验，任何一处数值失衡（等级倒退、售价倒挂、重名、重复 emoji、
阶段未配齐、分类没生效、成熟时间跳变过大）都会报错并**拒绝写文件**。

---

## 核心思路：经验曲线是反推的

先确定「每个等级每小时能拿到多少经验」，再乘以「升一级希望花多少小时」：

```
每小时经验 = 平均产量 × 茬数 × (等级 + 2) ÷ 一整轮的等待小时数
升级所需   = 每小时经验 × 已解锁地块数 × 土地经验倍率 × 每级目标耗时
```

好处是：**调整土地倍率、再生次数、地块数或作物等级时，经验曲线自动跟随**，
不会出现「前期飞快后期劝退」或者反过来。改平衡只需要改生成器里的一处。

这一版的经验公式不再含时间项（见下一节），所以 `expPerHourAt()` 要按
「一整轮的等待时间」重新除一遍：茬数越多、再生越慢，每小时经验就被摊得越薄。

生成器里的对应实现：

```js
function expPerHourAt(level) {
  const growHours = growSeconds(level, 'plain', 'normal') / 3600;
  let cycleHours = 0;
  for (let i = 0; i < harvestsAt(level); i += 1) {
    cycleHours += growHours * regrowOf(level) ** i;
  }
  return 平均产量 * harvestsAt(level) * (level + 2) / cycleHours;
}

function expNeeded(level) {
  const perHour = expPerHourAt(level)
    * plotsAt(level)                       // 已解锁地块数
    * soilExpMulAt(level);                 // 该等级可用最高土地的经验倍率
  return Math.max(100, Math.round(perHour * targetHoursAt(level)));
}
```

早期几级的「每小时经验」会因为成熟时间起步更快而略微下滑，
生成器最后会做一次单调平滑（后一级至少比前一级多 1 点），曲线只涨不跌。

## 收获经验公式

玩家与 NPC 共用同一套，只看「收到了几个」：

```
每份产出的经验 = 作物等级 + 2
本次经验      = 收获个数 × (作物等级 + 2) × 土地经验倍率
```

- 收获个数含土地产量倍率与捉虫加成，所以好地、勤捉虫都能多拿经验；
- 与等待时间无关：等 1 小时和等 40 小时，只要收到 20 个，经验就一样；
- 土地的经验倍率（白银 +10% … 神话 +90%）在这里真正生效 ——
  以前商店里写着「经验 ×1.90」但代码没有乘，属于只挂了个标签。

这个公式让**多次收获作物成为「经验流」**：一次种下收好几茬，
每一茬都按「数量 ×（等级+2）」给经验。

生成器给这批作物的平衡规则是「每茬产量缩小 + 再生 0.4」：
一株多茬作物的总产出只比同级单茬作物多三成，总时长也只长一些。
实测 Lv4 的蒜苗（6 茬）对比 Lv5 的豌豆（1 茬）：
**每小时经验 ×1.22、每小时金币 ×0.57**。
多汇报几次换一点经验、少赚一点金币，这就是它带来的新取舍。

实测：Lv1 小麦收 16 个 = 48 经验；Lv50 的作物收 30 个 = 1560 经验。

实现在 `data/crops.js` 的 `expOf()`，`store/farm.js` 在结算时再乘土地倍率。

## 成熟时间：小时级

参照《阳光牧场》的节奏，作物成熟时间最短 1 小时、最长约 41 小时（1.7 天）：

```
grow = 3600 × lv^0.7 × 风味系数 × 分类系数

Lv1  = 1.0h      Lv20 = 8.2h
Lv60 = 17.6h     Lv200 = 40.8h
```

之所以要这么慢，是为了让「缺水 / 虫害」这两个每 6 / 12 小时出现一次的照料操作
有意义 —— 如果作物 40 秒就熟，玩家根本遇不到需要浇水的时候。

## 售价是倒推出来的

早期版本把售价写成 `种子价 × (1.2 + 等级 × 0.016)`，再乘上产量与茬数：
等级越高，同一颗种子能赚回的倍数越大。到 Lv200 时这条链已经把一株作物的
收入推到种子价的 **1000 倍以上**，金币彻底失去意义 —— 一次收获够买十几块顶级土地。

现在反过来，先定「这一整轮最多该赚回几倍种子钱」：

```
整轮收入 = 种子价 × 收益倍率 × 风味系数 × 分类系数
收益倍率 = 4.0 - 等级 × 0.004        // Lv1 4.0 倍 → Lv200 3.2 倍

单价 = 整轮收入 ÷ (平均产量 × 茬数)
```

于是**单价不再是自由变量**：产量高、茬数多的作物单价自然低一些，
但「一株能赚多少」始终被锁在种子价的 2~7 倍区间内（生成器会校验）。

这带来两个直接后果：

1. **单价不再随等级单调**。Lv21 的作物从 1 茬变 2 茬，想维持同样的收益倍率，
   单价必然要掉一截。硬把单价拉回单调，那一级会凭空变成「暴富关」。
   真正该守的是**整轮收入**单调 —— 商店里也同时显示「每株总收入」。
2. **土地升级变慢**。旧曲线下 Lv50 一小时能赚几十万，顶级土地一两小时就买下；
   新曲线下买一块地大约要 10~30 小时的满田产出，土地变成需要规划的投资。

> 生成器的护栏：`cycleIncome(crop) = 平均产量 × 单价 × 茬数`，
> 同分类内必须严格递增，且 `cycleIncome / seed` 必须落在 2.0~7.0。

## 三类作物：玩家的取舍

| 分类 | 判定 | 成熟时间 | 售价 | 每小时金币 |
| --- | --- | --- | --- | --- |
| 经验作物 | 粮食 / 纤维 / 糖料 / 根茎 / 菌菇 / 树木 | ×1.5 | ×0.75 | 0.50 倍 |
| 经济作物 | 水果 | ×0.9 | ×1.35 | 1.50 倍 |
| 普通作物 | 其余 | ×1.0 | ×1.0 | 1.00 倍 |
| 厚积薄发 | 14 种指定作物 | **×3.5** | ×1.0 | 0.29 倍 |

「厚积薄发」是「最长收获时间不一定和等级挂钩」的主角：
一株 Lv10 的菠萝要等 17 小时、一株 Lv24 的石榴要等 36 小时，
比周围高等级的普通作物都久，但单次给的经验也多得多。
它们的倍率是**覆盖**分类倍率的，不是叠加。

分类按生长形态自动判定，玩家很快就能学会「粮食=经验、水果=金币」。

三个分类的实测对比（同等级比较）：

| 等级段 | 普通 | 经验作物 | 经济作物 | 厚积薄发 |
| --- | --- | --- | --- | --- |
| Lv1-20 | 1.00× | 0.53× | 1.57× | 0.37× |
| Lv21-60 | 1.00× | 0.56× | 1.21× | 0.26× |
| Lv61-200 | 1.00× | 0.50× | 1.51× | — |

（数值是「每小时金币收入」相对同等级普通作物的倍数）

## 作物解锁节奏

145 种「计划内」作物按用户定的节奏铺开，另有 20 种多茬作物手写等级插进来，
合计 165 种常规作物（限定作物 35 种不参与解锁计划）：

| 等级段 | 每级解锁 | 该段作物数 | 说明 |
| --- | --- | --- | --- |
| Lv1-20 | 2~3 个 | 50 | 偶数级 2 个、奇数级 3 个 |
| Lv21-60 | 1~2 个 | 60 | 奇数级 2 个、偶数级 1 个 |
| Lv64-200 | 每 4 级 1 个 | 35 | 从 64 起步，保证最后一个恰好落在满级 200 |

```js
function buildUnlockPlan(count) {
  const plan = [];
  for (let lv = 1; lv <= 20; lv += 1) plan.push(lv, lv, ...(lv % 2 ? [lv] : []));
  for (let lv = 21; lv <= 60; lv += 1) plan.push(lv, ...(lv % 2 ? [lv] : []));
  for (let lv = 64; lv <= MAX_LEVEL; lv += 4) plan.push(lv);
  return plan.slice(0, count);
}
```

## 生长阶段与多次收获

每个作物按形态（根茎 / 叶菜 / 谷物 / 果实 / 花卉 / 菌菇…）决定一条阶段序列，
序列里每个阶段占整轮时间的比例由 `data/stages.js` 的 `weight` 决定：

```
播种 → 发芽 → 生长 → 开花 → 结果 → 成熟
```

根茎类没有花果阶段，会自动省略。`成熟` 只是「已可收获」的终点标记，
不参与时间分配 —— 否则会出现阶段显示成熟、地块却还不能收的错位。

**多次收获作物**（`harvests > 1`）收获后不消失，而是进入再生轮次：

- 首次成熟 `grow` 秒，之后每次 `grow × regrow` 秒；
- 再生轮次回到「开花 / 结果」阶段，跳过播种发芽，所以时间能显著压缩；
- 收获经验按新公式算：再生轮的时间更短，经验自然更少。

| 等级段 | 可收获次数 | 再生系数 |
| --- | --- | --- |
| Lv1-20 | 1（一次性） | 0.50 |
| Lv21-40 | 2 | 0.42 |
| Lv41-70 | 3 | 0.42 |
| Lv71-110 | 5 | 0.35 |
| Lv111-150 | 6 | 0.35 |
| Lv151-200 | 8 | 0.28 |

> 只是显示的数字变小了，HUD 上一个 Lv1 玩家看到的是「0 / 378」而不是「0 / 5400」。

## 调平衡的正确姿势

```bash
# 1. 改 tools/gen-data.mjs 里的常量 / 公式 / CATALOG
# 2. 跑生成器（自校验不通过会拒绝写文件）
node tools/gen-data.mjs

# 3. 跑静态校验，确认数据表交叉一致
npm run check
```

**不要手改 `src/data/{crops,soils,progression}.js`** —— 会被覆盖，
而且经验曲线不会跟着重算。

## 生成器的自校验清单

- 作物数 ≥ 140、名称不重复、同一 emoji 最多用 2 次
- 每个 form 都有配置阶段路径，每条序列都以 `ripe` 结尾
- 等级 / 种子价 单调递增；产量**同一形态内**单调
- 成熟时间允许非单调（厚积薄发作物的存在就是为了这个），但相邻跳变不超过 5 倍
- **整轮收入**在同一分类内严格递增，且收入倍率锁在种子价的 2~7 倍之间
- 单价允许在「换茬数」处回落 —— 那正是整轮收入还能继续增长的原因
- 三类作物都要有、厚积薄发至少 10 种、产量下限不低于 10
- 同等级比较：经济作物的整轮收入更高，经验作物更低
- 地块数 = 40，开局块全为 Lv1，之后严格递增，最后一块恰好 Lv200
- 经验曲线严格递增
- 称号阶梯覆盖到 Lv200，土地解锁等级严格递增
