# 09 · UI 规范

## 设计令牌

全部定义在 `styles/base.css` 的 `:root`：

```css
:root {
  --green:    #4caf50;
  --green-d:  #35833a;
  --green-l:  #7cc576;
  --bg:       #eef3e9;
  --card:     #fff;
  --text:     #22301f;
  --muted:    #8a978a;
  --gold:     #f0a92e;
  --line:     #e3e9dd;
  --radius:   16px;
  --danger:   #e05a4e;
  --hud-h:    64px;   /* 兜底值，运行时由 ui/hud.js 量出来覆盖 */
}
```

用 CSS 变量而不是散落的硬编码色值，改主题只需要改这一个 `:root`。

`--hud-h` 特殊：它是运行时测量的，但必须有兜底值，
否则 JS 未执行时依赖它的吸附定位会失效。

## 样式文件分工

| 文件 | 内容 |
| --- | --- |
| `base.css` | 重置、设计令牌、排版基线、`.app` 外壳 |
| `components.css` | 可复用组件：按钮、地块、卡片、弹窗内容、图鉴、日历 |
| `layout.css` | 骨架与浮层：HUD、tabbar、三个浮层、结算画面 |
| `animations.css` | 全部 `@keyframes` |

拆分原则：**按职责而不是按页面**。改一个按钮样式只需要打开 `components.css`，
不会波及别处。

`@keyframes` 集中在一个文件里，引用它们的规则分散在各组件中 ——
这样能一眼看完项目里所有动画。

## 三个浮层

底部浮窗、子页面、模态弹窗共用一套交互规范：

| 特性 | 值 |
| --- | --- |
| 出现方式 | 从底部上滑，`cubic-bezier(.2, .9, .3, 1)`，0.3s |
| 关闭方式 | 点遮罩 / 关闭按钮 / **下拉超过 72px** |
| 圆角 | `24px`（四角，面板不再顶满屏幕） |
| 顶部留白 | `--sheet-top: max(4vh, 28px)` |
| 左右留白 | 12px（移动端不再贴边，桌面端仍是 640px 居中） |
| 底部留白 | 8px + `env(safe-area-inset-bottom)` |
| 最大宽度 | 640px（桌面上居中，不会拉成横贯全屏） |
| 阴影 | `0 -10px 40px rgba(0,0,0,.16~.2)` |
| 顶部 | 都有一根 `.sheet-handle` 拖拽指示条 |

三者的 `max-height` 都要减掉 `--sheet-top`（弹窗和浮窗还要减 `env(safe-area-inset-bottom)`），
否则内容一多就会重新顶到屏幕顶端。

最大宽度限制是刻意的：桌面上全屏宽的底部面板会非常难看。

### 弹窗的内部结构

模态弹窗拆成四段：

```
.modal-card          卡片本体：flex 纵向、圆角、overflow:hidden、不滚动
  .sheet-handle      拖拽把手（留在卡片上，不能跟着内容滚走）
  .modal-head        标题栏 + 右上角 ✕ —— 也在滚动区外面
  .modal-body        真正的滚动容器，padding 也在这里
  .modal-foot        底栏：切换条 / 主操作按钮 —— 同样在滚动区外面
```

四段而不是两段的原因：

- 把手在滚动时始终可见；「边缘渐隐」的遮罩只作用在 `.modal-body` 上，
  不会把卡片自己的白色背景一起淡掉；
- **标题栏必须在滚动区外面**。第 18 轮之前 `openModal()` 只是把整段 HTML
  塞进 `.modal-body`，标题跟着内容一起滚走 —— 往下翻两屏就摸不到标题，
  「拖标题关闭」自然也就无从谈起。现在由 `openModal()` 把模板里的
  `.modal-head` 提到 `body` 前面（`body.before(head)`），走完这一步
  它天然固定在顶部，滚到哪儿都能一把拉下来。
- **底栏同理**，见下一节。

### 弹窗底栏（`.modal-foot`）：只滚内容，不滚操作

写给未来的自己：**弹窗里凡是「滚走了就不好用」的东西 —— 切换条、主操作按钮 ——
都包一层 `.modal-foot`，不要靠 `position: sticky`。**

`openModal()` 会把模板里的 `.modal-foot` 从 `.modal-body` 里提出来挂到卡片上，
所以它和标题栏一样天然不参与滚动：

```js
const foot = body.querySelector(':scope > .modal-foot');
if (foot) {
  card.appendChild(foot);
  body.classList.add('has-foot');   // 关掉 18px 渐隐，见下
}
```

**为什么不能用 sticky**：`.modal-body` 底部有一层 18px 的渐隐遮罩
（`mask-image: linear-gradient(...)`），sticky 的底条贴在 body 的底边，
会被这层遮罩削掉最后 18px —— 按钮下半截直接透明。这个坑很隐蔽：
不滚动时看不出来，内容一长就露馅。

**子页面其实早就是这套结构**：`setFoot(html)` 把内容写进 `#subpageFoot`
（`.subpage-foot`，在 `.subpage-body` 外面），所以仓库的「卖出」条一直不跟着滚。
弹窗这次补齐 `.modal-foot`，两个浮层的做法从此一致 ——
三个浮层里只剩底部浮窗没有底栏（它本来就整块都很短）。

**有底栏时 `.modal-body.has-foot` 要关掉渐隐**：渐隐的语义是「下面还有内容」，
底栏一出现，body 的底边不再是卡片的底边，这层渐隐只会把「已经滚到底」的最后一行
永久淡掉。

底栏自带 `border-top: 1px solid #eef1e9` 与 `padding: 9px 17px 11px`，
里面的条（`.gift-tabs` / `.rm-actions` / `.sd-buybar` / `.adv-confirm-acts`）
只管自己的排布，不要再写 `margin-top` / 上边框 —— `.modal-foot > *` 已经把外边距清零。

当前用到它的地方：

| 弹窗 | 底栏内容 | 不置底会怎样 |
| --- | --- | --- |
| 送礼清单（`peer-gift-picker`） | 🧺 仓库 / 🎒 包裹 切换 | 220 种作物，想换 tab 得一路划到底 |
| 仓库卖出确认 | 合计 + 「确认卖出」 | 卖十几种作物时要滚到底才能确认 |
| 送礼确认（邻居 / 真人） | 数量步进器 + 「确认送出」 | 份数和按钮被正文挤下去 |
| 收礼确认（`ui/peer-gift.js`） | 「不要 / 收下」 | 同上 |
| 种子详情 | 数量 + 「购买」 | 说明文字一长，购买键就没了 |
| 图鉴标本 / 包裹丢弃 | 「制作标本」/「确认丢弃」 | 同上 |
| 铲除 / 制造 / 结束冒险确认 | 确认按钮 | 短弹窗不明显，但规则要一致 |

**弹窗可以叠层**：已经在显示一个弹窗时再 `openModal()`，会把当前整张卡
（`handle + head + body + foot` 的 `innerHTML`）与它的动作回调压进栈；
`closeModal()` 先弹栈、原样还原 DOM 与滚动位置，栈空了才真正收起。
还原时 `has-foot` 这个**运行时加的类**要补回去（快照里没有它）。
典型场景是「邻居农场 → 点作物看详情 → 关闭回到邻居农场」——
没有这一层的话，看详情会把拜访弹窗顶掉，玩家的浏览进度就丢了。

**关闭图标统一由 `openModal()` 补**：`.modal-head` 里没有 `[data-close]`
就 `insertAdjacentHTML` 一个 `.close`；连 `.modal-head` 都没有的弹窗
（自定义头部那种）补一条 `.modal-head.bare`，只放按钮不占地方。

**`.modal-sub` 不许用负上边距**（2026-10-24 修）。标题下面那句说明想贴紧标题，
早期写法是 `margin: -4px 0 11px` —— 而它是 `.modal-body` 的第一个子元素，
body 是 `overflow: auto` 的滚动容器，往上顶出去的那 4px 会被直接裁掉，
表现为「弹窗顶部描述文字被遮住几个像素」。间距只能从上往下给：
`.modal-head` 的 `margin-bottom`（12px）+ `.modal-sub` 的 `margin-top: 0`。

**宽版弹窗走 `openModal` 的第三个参数**：`openModal(html, handler, 'board-modal')`
会把这几个类挂到 `.modal-card` 上（每次打开都会重置，不会从上一次漏下来）。
公告栏就是这么把 body 左右内边距从 17px 收到 12px 的。
所以新写弹窗只需要管标题，不用再各写一遍 ✕。

对应地，`dragToClose()` 的 `canStart(target)` 多了一条：
从 `.modal-head` / `.sheet-handle` 起手时**忽略「内容已滚动」的拦截** ——
这两个区域本来就不在滚动容器里，不该被 `scrollTop > 0` 挡住。

`scrollArea` 支持传**取值函数**：每次 `openModal()` 都会重建 `.modal-body`，
传元素会拿到上一个已被丢弃的节点，导致「内容明明滚动过，下拉却仍然直接关闭」。

## 冒险卡牌页（第四层）

冒险不是浮层，而是一块**全屏页面**：`#adventure`，`inset: 0` + `max-width: 640px` 居中，
`z-index: 105`。层级刻意压在子页面（110）和模态弹窗（130）之下 ——
退出确认是模态弹窗，必须盖在它上面。

| 部分 | 做法 |
| --- | --- |
| 顶栏 | 左侧圆形 ✕ + 标题 + 「剩余 N / M 步」+ 一条 4px 进度条 |
| 卡牌 | `min(100%, 350px)` 宽、`min(52vh, 372px)` 高、26px 圆角、白底 |
| 左右选项 | 挂在舞台层（不是卡片里）、`z-index` 压在卡片之上，拖动时对应一侧浮起，卡片滑出去也不会被带出屏幕 |
| 手势 | `touch-action: none`，Touch 事件 + `preventDefault`，鼠标按住拖动同样支持 |
| 退出反馈 | 挖到东西浮一条金色提示，空手浮一条灰色提示，1.1s 自动消失 |

三条手势铁律（和 `drag-close.js` 同一套经验）：
**阈值用绝对像素**（72px，不用百分比，页面隐藏时 `clientWidth = 0` 会算出 NaN）；
**拖动时 `transition: none`**，否则卡片会追着手指慢半拍；
**结算后清空 `dragging/offset`**，否则下一次轻点会拿上一次的位移再选一次。

## 滚动条与边缘渐隐

滚动条在 `base.css` 里全局隐藏：

```css
* { scrollbar-width: none; }
*::-webkit-scrollbar { width: 0; height: 0; }
```

「还有内容」的提示交给遮罩渐隐，只加在真正滚动的容器上：

| 容器 | 渐隐方向 |
| --- | --- |
| `.subpage-body` | 上下各 12 / 18px |
| `.modal-body` | 底部 18px（正好落在 padding 区，不削内容） |
| `.shop-panels` | 左右各 16px |

> 主页面（农场 / 邻居）原来在底部导航上方压了一条 26px 的渐隐带，
> 现在去掉了：它贴着导航条，看起来就像导航自带一条黑色阴影，
> 和纯白导航撞在一起很脏。导航改成不透明纯白之后，靠列表底部留白就够了。

> 不要把渐隐加在**有背景色**的容器上（比如 `.modal-card` 本身）：
> `mask-image` 会把背景一起淡掉，边缘看起来像被啃掉一块。

## 顶栏与底部导航的配色

- 顶栏是**纯色** `var(--green-d)`，不用渐变：大面积渐变在顶栏上会发脏，
  和下面的浅绿面板也接不上；
- 底部导航是不透明纯白 + 1px 浅色分隔线，**不用毛玻璃**：
  半透明 + `backdrop-filter` 会让下面的内容透出一层灰，看着像阴影。

## 安全区

刘海屏 / 底部指示条区域用 `env(safe-area-inset-*)` 避让：

```css
.tabbar      { padding-bottom: calc(8px + env(safe-area-inset-bottom)); }
.hud-bar     { padding-top: calc(11px + env(safe-area-inset-top)); }
#toasts      { top: calc(84px + env(safe-area-inset-top)); }
.sheet-panel { bottom: calc(8px + env(safe-area-inset-bottom)); }
```

`.app` 也要给 tabbar 留出空间：

```css
.app { padding-bottom: calc(78px + env(safe-area-inset-bottom)); }
```

### 数量步进器（`.qty`）

种子详情弹窗（`ui/seed-detail.js`，商店与包裹共用）里用：`−` / 数字 / `+`，
右侧是购买按钮。包裹里打开时不渲染这一栏，底部换成一句
`.sd-note`「包裹里共 N 个 · 不够可去商店补货」——**种子已经在手上，没有可买的东西**。

- 数量范围 1~99，按住 `−` / `+` 超过 380ms 进入连发（每 70ms 一次，从 1 到 99 约 7 秒）；
- 连发结束后松手会补一次 `click`，用捕获阶段 `stopPropagation()` 吞掉，
  否则「按住减到 1」会多减一次；
- 按钮要写 `touch-action: none`（只写一条，别和 `manipulation` 并列 ——
  后者会被覆盖，读代码的人会被骗），不然移动端长按会先弹系统的选择菜单；
- 数量变化只改数字与按钮状态，**不重建弹窗**，否则连发会被自己打断。

#### 长按是统一委托，不是每处各绑一次

实现在 `ui/hold.js` 的 `mountHoldRepeat(root, fire)`，只在两个地方各挂一次：
`ui/modal.js`（弹窗）与 `ui/subpage.js`（子页面）。业务代码一行都不用改。

为什么做成一层的委托：加减钮在 13 个地方出现（种子 / 送礼 / 交易 / 联机送礼 /
卖货 / 订单 / 分解包装…），每一处都记着去挂绑定，早晚会漏。
而它们**都带 `.qty-btn` 类、都通过 `data-action` 走动作分派**，
所以只要在分派层拦截一次：按住不放时用同一套动作回调反复触发即可。

- 用 `pointer` 事件而不是 `touch`：桌面端鼠标也能按，且不用自己处理两套路径；
- 定时器存 `WeakMap`，随元素一起回收；连发中业务侧把按钮 `disabled` 了会自己停下；
- 只是**多派发几次动作**，不走任何捷径 —— 金币不够、库存不足时业务层的校验照旧拦住。

### 播种 / 购买的分工

| 位置 | 内容 |
| --- | --- |
| 播种弹窗（点地块） | **只列背包里有存货的种子**，右上角一个「🏪 商店」按钮 |
| 商店种子列表 | 点整行开「种子详情」弹窗，数量在弹窗底部调整 |
| 包裹种子行 | 同样点整行开「种子详情」，但用 `{ buy: false }` —— 只读，没有购买栏 |

种子详情只有一份实现（`ui/seed-detail.js`），`buy` 开关决定底部是
「数量 + 下单」还是「只报库存」。两边各写一份的话，
成熟时间、茬数、一轮收益这些数字迟早会说得不一样。

商店按钮通过 `emit(EVENTS.NAVIGATE, 'shop')` 请求切页，
`tabs.js` 订阅这个事件 —— 视图之间不互相 import，避免循环依赖。

### 种子信息的标签（`.meta-tag`）

种子的等级 / 时长 / 茬数 / 产量 / 售价用同一颗胶囊标签，但颜色各不相同：

| 修饰 | 含义 | 配色 |
| --- | --- | --- |
| `.lv` | 解锁等级 | 蓝 |
| `.time` | 一轮总时长 | 灰 |
| `.stack` | 收获茬数 | 按茬数分档，见下 |
| `.yield` | 每次产量 | 按产量分档，见下 |
| `.price` | 单个售价 | 金 |
| `.multi` | 多茬作物 | 浅绿 |

茬数与产量这两个「扫一眼就该读到」的数字，颜色随数值递进：

| 茬数 | 颜色 | | 单次产量上限 | 颜色 |
| --- | --- | --- | --- | --- |
| 1 茬 `.h1` | 灰 | | ≤14 `.y1` | 灰 |
| 2 茬 `.h2` | 青 | | 15~20 `.y2` | 绿 |
| 3 茬 `.h3` | 绿 | | 21~28 `.y3` | 橙 |
| 4 茬 `.h4` | 蓝 | | >28 `.y4` | 金 |
| ≥5 茬 `.h5` | 紫（加粗） | | | |

分档逻辑在 `ui/meta-tags.js`（`stackClass` / `yieldClass`），
商店与播种弹窗共用，避免两处各写一套。
> **类名别用 `.cycle`**：签到卡片上有一个全局的 `.cycle`，会把胶囊撑成 26px 高。

### 商店：固定高度 + 每个面板各自滚动

`#page-shop.active` 是 `position: fixed`（上贴顶栏、下贴导航），
`.shop-panels` 只管横向翻页，纵向滚动由 `.shop-panel` 自己承担。

之前四个面板共用一条滚动条：种子滚到一半切到道具，看到的是「同一个滚动位置」，
道具面板又不长，结果是一片空白，像没有内容。现在每个面板各有各的 `scrollTop`，
重绘时只还原当前面板的位置。

#### 还原位置的顺序是硬约束

```js
if (keepLeft) nextPanels.scrollLeft = keepLeft;
syncTabFromScroll(nextPanels);        // ← 必须在上面之后
if (keepTop) panel.scrollTop = keepTop;
```

反过来的话，`syncTabFromScroll` 读到的是刚重建好的 `scrollLeft = 0`，
会把 `activeTab` 误判成第一个 tab（种子），纵向滚动随后就恢复到了**错误的面板**上。
表现就是「在道具 tab 买了狗粮，列表莫名其妙跳回种子那边」。

面板 key 用局部变量 `tabAtRender` 固定，不能用 `activeTab` ——
`syncTabFromScroll` 会改写 `activeTab`，拿它当 key 等于用改写后的值反查面板。

#### `.shop-filter` 必须无条件渲染

筛选条显隐完全由 `hidden` 属性控制：`filterHTML()` 内部已经写了
`${activeTab === 'seed' ? '' : 'hidden'}`，`switchTab()` 也是靠
`filter.hidden = ...` 切换。

所以**外层不能再加一层条件渲染**。曾经的写法是
`${activeTab === 'seed' ? filterHTML() : ''}`，两者直接矛盾：
在道具 tab 买了任何东西触发重绘后，筛选条被彻底从 DOM 删除，
`switchTab()` 里 `root.querySelector('.shop-filter')` 找不到元素，
点回种子 tab 也回不来。现在是无条件 `${filterHTML()}`。

#### `keepPanelScroll`：什么时候该回顶部

| 场景 | `keepPanelScroll` | 效果 |
| --- | --- | --- |
| 买东西（正常重绘） | `true` | 停在原地 |
| 改筛选（`filter-seeds`） | `false` | 回到顶部 |
| 外部 `setShopTab()` 跳转 | `false` | 回到顶部 |

换列表就该从顶部看起 —— 沿用上一个筛选的滚动位置只会看到一片空白。

### 记录里的人名 / 作物名：就地变成可点标签

`ui/inline-tags.js` 的 `inlineTagsHTML(text)` 在**同一次正则替换**里处理两类：
人名 → 人物标签，作物名 → 作物标签。两者都嵌在句子中间：

```
偷 石头 家被守护犬抓住，罚了 500 金币
  ↓
偷[石头🧒]家被守护犬抓住，罚了 500 金币

农场主 偷 石头 家被守护犬抓住，罚了 500 金币
  ↓
[农场主🧑‍🌾]偷[石头🧒]家被守护犬抓住，罚了 500 金币

王大爷 来你的农场，顺走了 🥕胡萝卜 ×1
  ↓
[王大爷👴]来你的农场，顺走了[🥕胡萝卜]×1
```

```html
<span class="who-tag" data-action="open-farm" data-id="npc04">赵老板<i class="ava">🧔</i></span>
<span class="crop-tag" data-action="crop-detail" data-crop="胡萝卜">🥕胡萝卜</span>
```

两类标签**同时是入口**：点人名打开那座邻居农场的拜访弹窗，点作物打开作物
信息弹窗。动作名写在 class 之外的 `data-action` 上，由 `ui/inline-actions.js`
在 document 上统一接管 —— 所以任何一处渲染出来的标签都自动可点，
新视图一行都不用改。玩家自己那座农场点不开，也就不加动作属性。

几个要点：

1. **不做成单独一行**。早期版本在每条前面摆一个「头像 + 名字」的胶囊，
   一句话被切成「标签 / 正文」两截，读起来要自己拼；
   现在标签就在句子里，谁偷了谁一眼能对上；
2. **按全文匹配名字，不依赖 `who` 字段**。`who` 只记涉及者的 id，
   而句子的主语常常是玩家（`state.farm.name`）；直接扫名字更稳，
   也不需要每个 store 调用点都记得传 `who`；
3. **长名字优先**（按长度倒序进正则），否则「小雨」会把「小雨点」吃掉半截；
   作物名同理 —— `🍇星光葡萄` 整串先试，匹配不上才退到 `葡萄`；
   人和作物**同长度时人优先**：撞名时「谁家的」才是句子的重点；
4. **人名两侧、作物名两侧的空白一起吃掉**（`[ \t]*`）：文案里写 `${name} 家`
   是为了分隔，名字变成标签之后这些空格只会把句子断开。
   只吃空格与制表符，不动换行；
5. **作物标签会连图标一起吃**。文案里通常写成 `🥕胡萝卜`，正则把图标一起
   匹配进标签，否则右边会剩一个孤零零的 emoji；
6. **标签是 `inline-flex`**：中文换行时名字和头像不会被拆到两行；
   上下不留 padding，否则行高被撑开、多行日志会稀稀拉拉；
7. **基线对齐靠 `line-height: normal`**。加了边框和底色之后，
   标签比旁边的字高一截是难免的，但「高」不能变成「歪」：
   - `vertical-align: baseline`：名字坐在正文的同一条基线上；
   - `line-height: normal`（≈字体 ascent + descent，12px 字约 16px）：
     容器基线与正文基线**逐像素相同**，标签总高 16 + 2px 边框 = 18，
     仍落在正文 18.6px 的行盒里，不会把行距顶开。
     写成 `1.15` 这类固定行高时行盒比字体自然行盒矮，字形上下溢出，
     名字看着会比旁边的字高 1px（实测 `nameVsPlain = 1`，改成 `normal` 后为 0）；
8. **与两侧文字固定留 4px**：`margin: 0 4px`。文案里的空格已经被正则吃掉了，
   间距只能由 margin 给 —— 贴着写会像句子里的连写。

配色上**人绿、物黄**：`.who-tag` 浅绿底（人），`.crop-tag` 暖黄底（物），
形状、行高、基线对齐完全一致 —— 一句话里混排时必须齐平。

排版：

- **农场日志 / 邻居日志 / 公告栏（时报弹窗）**：`时间 | 图标方块 | 正文（含标签）`，三处完全一致；
- **公告栏的日期标题不吸顶**：过滤 / 排序栏在弹窗底栏（列表下面），
  日期标题跟着内容滚即可。日志浮窗内部滚动、没有筛选条，日期标题照旧吸顶。

> ⚠️ 写文案时**名字要用真实名字**（`${state.farm.name}`），不要硬编码「农场主」：
> 标签是拿名字去匹配的，写死了改名之后那一处就不会变成标签。

### 地块边框：两圈动效，都不能碰布局

`.plot` 自己的 `::before` 是土地底纹、`::after` 是底部暖色压边，两个都被占了，
所以另起一个空壳 `.plot-aura`（`position: absolute; inset: 0; pointer-events: none`），
由 JS 插在地块内容最前面，两圈边都画在它身上：

| 状态 | 画法 | 颜色 |
| --- | --- | --- |
| `.plot.special`（限定作物） | `::before` + `conic-gradient` 绕圈转 | 金色（`#c8931f` ~ `#fffbe6`） |
| `.plot.warn`（缺水 / 生虫） | `::after` 外扩呼吸 | 与 💧🐛 按钮同色（`#e05a4e`） |
| `.plot.ripe`（成熟待收） | 同上 | 与「收获」按钮同色（`#f08a1e`） |

几条硬规矩：

- **环形描边用 mask 合成**：`padding` 决定边宽 + 两层 `linear-gradient` 的
  `mask-composite: exclude`，只留外环。`border-image` 会把圆角切成直角，不能用；
- **角度动画要 `@property`**：`--plot-spin` 不注册成 `<angle>` 的话
  `--a: 360deg` 不会插值，金边静止。没 `@property` 的老浏览器降级成静态渐变金边；
- **厚度只靠 `padding` 给，不加粗 `border`**：border-box 下加粗 border 会挤压内容区，
  地块里的图标和按钮就得跟着让位。限定地块的金边 4px（常规描边 1px 的两倍），
  整圈**收在 border 内侧** —— 内容区一寸没让，网格也不会因为它错位；
- **只用 `transform` + `opacity`**，并且绝不改宽高与 `border` —— 60fps 之外，
  40 块地排开时任何一像素的尺寸变化都会让整列参差；
- `prefers-reduced-motion` 下关掉动画：金边留静态的，扩散环直接不画。

#### aura 的尺寸与圆角：三个坑连在一起

这套光环曾经「歪掉、圆角处漏底色」，原因是三件事叠在一起：

1. **`inset: 0` 贴的是父元素的 padding box**，比卡片外沿小 2px（卡片的 border 宽度）。
   aura 于是缩在里面，金边看着比地块小一圈 —— 必须写 `inset: -1px` 才对齐**边框盒**；
2. **尺寸小了、半径却 `inherit` 同一个 `--radius`**，曲率就对不上。
   表现是「特效边框比地块更圆」（玩家反馈「土地圆角似乎小于特效边框的圆角」）：
   弧长按半径走，盒子小了 2px 而半径没跟着小，弧就显得更弯。
   对齐外沿之后半径**不该再加**（实测 aura 与卡片同为 209.3×152、同为 16px 时才严丝合缝）；
3. **顶到外沿之后，环的最外圈正好压在抗锯齿的临界线上**，圆角处会透出底下的页面背景
   （玩家反馈「金边的圆角背后能看到背景的圆角」）。这一条是实测截图里看出来的，
   光调半径永远修不掉。

最终解法是**光环整体收进 border 内侧**：

| 层 | `inset` | `border-radius` | `padding` |
| --- | --- | --- | --- |
| `.plot-aura` | `-1px`（对齐边框盒） | `var(--radius)` | — |
| 金边环（限定） | `1px` | `calc(var(--radius) - 2px)` | `4px` |
| 扩散环（缺水 / 成熟） | `2px` | `calc(var(--radius) - 4px)` | `2px` |

**每收进 N px，半径就减 N px** —— 曲率才保持一致。这样环的内外都落在地块自己的
背景上，永远不会碰到页面底色。顺便，这正好是「可以向内扩」：厚度从 border 内侧长出去，
地块自己的 1px border 原封不动。

> 验证方式：把页面底色强制改成纯品红 `#ff00ff`，沿地块左上圆角内侧按 2° 步进、
> 6 档内缩半径采样，统计是否命中品红。normal 与 special 地块命中数都必须为 0。

### 成熟地块的产出堆叠（`.yield-pile`）

一大张图标只能说明「这里有个东西熟了」，说明不了「熟了一堆」。所以成熟地块的主图
换成**一摞同一张图**：张数按 `floor(产量/2) + 1` 算，封顶 16 张
（`data/yield-pile.js` 的 `pileCount` / `pileLayout` / `pileHTML`）。

#### 为什么是 `floor(n/2)+1`，不是直觉的 `ceil(n/2)`

堆叠除了「表示有多少」，还承担一件事 —— **被偷走一个要看得出来**。
两种取整在这一点上正好互补，而游戏里的产量绝大多数是偶数：

| 产量 | `ceil(n/2)` | 偷 1 个后 | `floor(n/2)+1` | 偷 1 个后 |
| --- | --- | --- | --- | --- |
| 5 | 3 | 2 ✓ | 3 | 3 ✗ |
| 6 | 3 | 3 ✗ | 4 | 3 ✓ |
| 10 | 5 | 5 ✗ | 6 | 5 ✓ |
| 30 | 15 | 15 ✗ | 16 | 15 ✓ |
| 32 | 16 | 16 ✗ | 16（封顶） | 16 ✗ |

偶数产量占绝大多数，所以选后者：偷 1 个必然少一张，玩家不用去读
「已被顺走 N 个」那行小字。代价是产量 2 会摞 2 张（略多于「每 2 个一张」），
但那看起来更像「有东西」而不是「孤零零一颗」。

⚠️ 产量 ≥ 30 就顶到 `PILE_MAX`（16 张），这时偷 1 个看不出变化 ——
图能表达的上限就在这里，由地块上的文字提示接手。
产量 1 一定画一张，否则「只收 1 个」的地块会是一片空白。

#### 分布用黄金角螺旋

不是网格也不是纯随机：

| 方案 | 问题 |
| --- | --- |
| 网格 | 一眼看出是按行按列摆的，像货架 |
| 纯随机 | 聚成几团、中间留空洞，像撒的不像一堆 |
| **黄金角 + 抖动** | 任意个数均匀铺开，行列感被打散 |

半径按 `0.5 + 0.5·√t` 增长（开方后点的**面积密度**才均匀），再叠一层角度、
半径、x/y 三重抖动。`z` 随半径递减 —— 越靠中心越高，堆叠才有厚度。

散开的幅度由两个 em 常量控制：`RADIUS_X = 1.62` / `RADIUS_Y = 0.66`
（横向明显大于纵向 —— 地块是横的，横着摊才像「收了一把撒在地上」；
纵向一拉高，几张图就会顶到上面的名字行）。
每张图另有 ±24° 的随机旋转（`MAX_ROT`）：全是正着的图摆在一起像贴纸，
给一点角度之后一眼就能看出这是随手堆的，而不是排版排出来的。

> ⚠️ `RADIUS_X` 是有上界的，靠**实测**定，不是靠手调。横排取消右侧操作列、
> 地块宽度还给作物图之后，10 张图的最外缘到格边只剩十几个像素；
> 再往上加（约 1.7 以上）最外侧那张会被卡片裁掉一角。改完这个值请量一遍。

四条硬约束：

1. **位置必须稳定**。地块每 500ms 心跳重绘，若每次重算 `Math.random()` 图标会疯狂乱跳。
   种子由地块 id 经 djb2 折成 32 位、喂给 LCG，同一块地永远是同一堆；
2. **坐标用 em 不用 px**。紧凑模式下地块只有 90 多像素宽，px 半径会溢出。
   em 之后 CSS 只换一个 `font-size` 档位，整摞等比缩放，半径与旋转都不用另算
   （普通 25px / 宽屏 27→29px / 紧凑 18px；邻居同档）；
3. **数量变了要看得见**。被偷一个就少一张图 —— 自家农场的 `plotKey()` 已含
   `stolenCount` 与 `pendingYield`，不用额外改动就会重建；
4. **自家农场与邻居共用一套**。两边看起来必须是同一堆东西，否则玩家会以为是两种机制。
   邻居的种子要带上邻居 id（`${friend.id}-${plot.id}`），不然两家地块形状会撞车。

容器 `.yield-pile` 固定 `4.4em × 2.6em`（1em = 一颗图），
`pointer-events: none` 让点击穿透到外层 `.plot-art` 的 `crop-info`。

**每张图都带描边 + 双层投影**：只给 `drop-shadow` 时，深浅色的 emoji 叠在一起
边界还是会糊；加一圈 `-webkit-text-stroke`（.035em 白色）之后每张图的轮廓都清楚，
一眼能数出「这是几张」。投影分两层 —— 一层贴地近影、一层扩散远影，堆叠才有厚度。

#### ⚠️ 绝不能给每张图加 `will-change: transform`

这是本项目踩过的最贵的一个坑：一行「看起来是优化」的声明，把整个农场页从满帧
拖到 24fps。

`.yield-pile > i` 一屏最多 **40 块地 × 16 张 = 640 个**。`will-change: transform`
不是「提示浏览器注意点」，而是**立刻把这个元素提升成独立合成层**：
640 个层各占一块 GPU 纹理，还要各自做两次 `drop-shadow` 离屏模糊。

实测（430px 视口、40 块地全部成熟、产量拉满 32、每帧滚动 ±6px 逼重绘）：

| | 平均帧 | p95 | 最差帧 | 卡顿帧（>20ms） |
| --- | --- | --- | --- | --- |
| 带 `will-change` | 40.8ms（≈24fps） | 66.7ms | 83.3ms | **53~60 / 70** |
| 删掉 | **16.4ms（满帧）** | 16.7ms | 16.8ms | **0 / 70** |

同一时刻 JS 侧 `renderFarm()` 只要 **0.06ms** —— 瓶颈完全在合成，不在脚本。
所以别去优化渲染函数，先看有没有这种批量提升合成层的声明。

另外两条实测结论，避免下次白折腾：

- **`filter: drop-shadow` 是清白的**。单删它没有额外收益（16.57 → 16.63ms，
  噪声范围内）。合成层消失后，带 filter 的元素在层内只光栅化一次就缓存了。
  所以为了视觉该留就留，不必为性能牺牲轮廓；
- **换成 `text-shadow` 反而更慢**（26.5ms）。多层模糊文本阴影走的是另一条绘制
  路径，比一次离屏 + 复用更贵。

判断标准很简单：**元素真的要做 transform 动画时**才写 `will-change`，
静态定位的元素一律不写。项目里另外两处（`#subpage` 的滑入、`.adv-card` 的拖拽）
都是个位数元素且真在动，属于合理用法。

> ⚠️ **外层要 `width: 100%` 且给横向 padding**。图标散开后必然比 `.yield-pile`
> 的盒子宽，`.plot-art` / `.np-art` 若与盒子等宽，点到最外侧那几张图的边缘时
> 命中的是父级 `.plot-main`，作物详情打不开 —— 看着能点、实际没反应。
> 这两个类都写了 `padding: 0 .5em`，只把**可点范围**撑到图标外沿，
> 不改布局（只加内边距、不加外边距）。

### 地块的骨架：单列内容 + 悬挂在底边框上的按钮

`.plot` 与 `.npc-plot` 用的是**同一套**结构，改一边必须改另一边：

| 部分 | 类 | 说明 |
| --- | --- | --- |
| 主内容 | `.plot-main` / `.npc-plot` 直接子元素 | 作物图、名称、进度、倒计时，**横向铺满整格** |
| 悬挂条 | `.plot-hang` | 浇水 / 捉虫 / 收获 / 偷，`position: absolute` 挂在底边上 |

以前右侧有 34px 的 `.plot-side` 竖列，地块主内容被挤到只剩 83px（手机），
作物图和产量堆叠几乎没有横向空间 —— 而这块宽度正是最该给图的地方。
现在那一列**整块删掉**，宽度全归作物图。

#### 悬挂按钮：3/4 在格内、1/4 在格外，且不动邻格

```css
.plot-hang {
  position: absolute;
  left: 50%;
  bottom: 0;
  transform: translate(-50%, calc(25% + 1px));
  pointer-events: none;   /* 空白处不吃点击 */
}
.plot-hang > * { pointer-events: auto; }
```

两条硬约束：

1. **必须 `left: 50%` + `translateX(-50%)` 居中**，不能靠 flex 撑 ——
   按钮数量会变（收获 / 浇水 / 捉虫 / 偷），靠撑会把这条压得左半边空；
2. **必须绝对定位**。不占布局是「按钮探出格子却不影响邻格位置」的唯一手段：
   它不参与 flex 与 grid 的行高计算，卡片不会被撑高，下一行也不会被推下去。
   **别为了好写改回 flex 子项。**

> ⚠️ `calc(25% + 1px)` 那个 `+1px` 不能省。绝对定位的包含块是 padding box，
> `bottom: 0` 落在 border **内侧**，探出量会少掉 border 的 1px ——
> 实测 24px 的按钮只露出 5px 而不是 6px（比例 0.79 而非 0.75）。
> 补上这 1px，露出的才真正是高度四分之一。

底部还要给所有地块**统一预留** `padding-bottom`（普通 23px / 紧凑 22px /
邻居 22px），把「按钮探进格内的 3/4」让出来，正文不会压到按钮上。
这条 padding 所有地块都有，有没有按钮都一样高 —— 否则 grid 拉伸之后会参差。

#### 高度必须锁在内容上，不能靠 `min-height`

这一条是踩过的坑，改任何一块地的内容前先读：

**症状**：有操作按钮的地块会把整行撑高，点掉按钮之后整行又缩回去。

**真正的病根不是按钮**（它是绝对定位，实测把全部 `.plot-hang` 摘掉，
每块地的高度变化都是 `0.0px`），而是**内容行数不一样**：

| 状态 | 行数 | 多出来的是 |
| --- | --- | --- |
| 生长中 + 缺水 + 生虫 | 6 | 图 / 名 / 阶段 / **⚠ 警示文字** / 进度条 / 倒计时 |
| 生长中 正常 | 5 | 同上，少警示行 |
| 空 地 | 3~4 | 图 / 名 / 土档标签 / 升级按钮 |
| 成 熟 | 4 | 堆叠图 / 名 / 可收·本应 / 尾行 |

玩家点掉 💧 的同一瞬间，那行「💧 缺水」也跟着消失 → 这块地矮 15px →
grid 把整行都缩回去。所以病根是**警示文字那一行**，按钮只是它的同伙。

**药方**：在内容层锁一个 `min-height`，而不是在外层 `.plot` 上写 `min-height`
（外层只是地板，内容行数一多照样顶穿）：

```css
.plot-main        { min-height: 141px; }   /* 6 行内容 = 137px，留 4px 亚像素余量 */
.grid.dense .plot-main { min-height: 113px; }   /* 紧凑：6 行 = 110px，留 3px */
```

留余量是必须的：卡在 137 上，不同系统差 1px 就会重新把整行顶高。

**另一处必须配合改的**：成熟地块的「照料不周 · −15%」**不能单独占一行**。
成熟那块用的是 4.4em 的堆叠图，比生长中的单图高近 30px，多一行就是 156px，
比「生长中 + 缺水生虫」的 6 行（137px）还高，照样顶穿地板。
所以它和「还可收获 N 次」**挤在同一行**，措辞也压缩成
`照料 −40% · 最后一茬`（完整句在 100px 宽的格里会折行，等于白折腾）。

邻居侧（`.npc-plot`）同理，但更简单：它直接装内容、没有中间层，
行数 3~4，地板 `min-height: 138px` 就够。

验证口径：**同一个 `top` 上所有卡片的高度集合只能有一个值**，且点击
💧🐛 与收获前后高度不变。实测 320 / 430 / 900 / 1200 / 1600 五档宽度、
六个点击步骤，高度全部恒定、无一行参差。

### 施肥 / 铲除：从地块移进作物详情弹窗

施肥与铲除是**低频操作**（一株作物一轮只用一次），常年摆在地块上会占掉
作物图的横向空间，而且会让每块地挂满用不到的按钮。所以两者都移进了
「点作物打开的详情弹窗」（`openPlotCrop` → `extra: plotActionsHTML`）：

| 位置 | 内容 |
| --- | --- |
| 详情弹窗内、加成行之后 | 施肥 + 铲除**同排** |
| 地块上 | 只剩浇水 / 捉虫 / 收获（悬挂底边） |

尺寸规则是 `grid-template-columns: minmax(0, 1fr) auto`：

- **铲除固定成一个方框**（`.pa-square`，36×34）；
- **施肥吃掉剩余宽度**（`minmax(0, 1fr)` 才能让它真缩下去）。
  外层 `.pa-row` 用 `max-width: 300px` + `margin: auto` 做**最长限制**与**居中**，
  宽屏上施肥不会拉成一条横幅；
- 成熟后只剩「铲除」一个按钮（施肥对已成熟的作物没有意义），
  此时不放方框形态 —— 一颗正方形孤零零摆在中间会很怪，改成正常胶囊
  「🪓 铲除这块地」。

点击链路：`data-action="remove"` → `onAction('remove')` → `confirmRemove(plotId)`
→ **二次确认**（叠在详情卡上面）→ 取消回到详情，确认才真铲。

### 地块角标：不占正文排版

产量加成（捉虫累积）与「这一轮为什么不能偷」都做成**钉在格子角上的小标签**
（`.plot-corner` / `.np-corner`，`position: absolute` + `pointer-events: none`）：

- 左上角 = 产量加成，按档位换色：+10~30% 绿 / +40~60% 橙 / +70~100% 金红；
- 右上角（邻居地）= 🥷 已被偷过 / 🐕 被守护犬盯上。

旧版把「产量 +X%」写成正文里的一行 div，按钮多的时候整行会被挤下去。
角标不参与流式排版，按钮数量就不会影响格子高度。
注意类名要对上：HTML 写 `np-corner`，CSS 也曾误写成 `npc-corner`，角标会直接失效。

### 地块上最多剩几个按钮：三个

右侧的操作列（`.plot-side`）已经取消，地块上只剩**悬挂在底边**的按钮，
一株作物身上最挤的情况是三个同时出现：

```
💧 浇水（缺水）  🐛 捉虫（生虫）  🚜 收获（成熟）
```

三个其实互斥得挺干净（成熟之后不会再缺水生虫），实测最宽是「💧 + 🐛」两颗
26px 的圆钮加 4px 间距 = 56px，远小于最窄的格子（紧凑 131px）。
邻居那边再加上「偷 1 个」的胶囊，三颗总宽约 130px，同理放得下。

施肥与铲除已经移进作物详情弹窗（见上），所以**不用再为第四颗按钮算间距**；
真要再加按钮，先回来量一遍格子宽度。

铲除按钮在弹窗里用 `.btn.ghost.danger`（白底红边红字）—— 它是唯一一个
「会亏东西」的操作，不能和浇水、施肥长得一样。

### 铲除：先确认，再动手

铲除不可逆（种子、化肥、捉虫攒的产量加成全部作废），所以点 🪓 只弹确认框
（**入口在作物详情弹窗里**，不在土地上）：

```
作物名 + 剩余时间 / 产量加成
「铲除后这块地会变回空地，种子、化肥和产量加成都不会返还。」
[再想想]  [确认铲除]
```

确认框靠 `ui/modal.js` 的叠层（`stack` 快照压栈）**叠在详情卡上面**：
取消就 pop 回详情，玩家停在原来那一屏，不会被打回农场再点一遍。

已经成熟的地也允许铲（有人就是想立刻腾地），但会多一行金色提示
「先收获再铲更划算」—— 劝一次就够了，不做硬性拦截。

### 被守护犬抓住：全屏闪一下

偷菜被邻居的狗逮住时，除了 toast 还会播一张**全屏画面**（`ui/dog-caught.js`）：
整屏压暗 → 那只狗的品种 emoji 从中间弹出来（带一圈扩散的光）→ 1.7 秒后自己淡出。

为什么值得一个全屏：玩家这时候正盯着地块连点，toast 在顶部一闪就过，
很容易以为「偷成功了」。画面里直接写清三件事 —— **谁家的狗 / 什么品种（拦截率）/ 罚了多少**；
被牵连的其他邻居数（`ripple`）作为第四行附在下面。

实现上的两条：

- **不复用 `#modal`**：这是「事件播报」，不占弹窗的动作分发，也不该把玩家
  正在看的邻居弹窗顶掉。和 `sign-celebrate.js` 一样自己造一层，播完整个移除；
- **点击即关**：全屏层会吃掉点击，所以留一条「点一下提前收起」的路，
  免得玩家等那 1.7 秒。

事件链路：`social.steal()` 罚款后 `emit(EVENTS.DOG_CAUGHT, { breed, owner, fine, ripple })`
→ `main.js` 里 `mountDogCaught()` 订阅 → `showDogCaught()` 播放。

`ripple` 是「被这事牵连的其他邻居数」，>0 时画面底部多一行 `.dc-ripple`：
「😳 消息传遍全村 · 其他 N 位邻居好感 −1」。它比罚款轻一档（半透明白底胶囊、
12px），是**余波**不是**主罚**，所以不给金色、不放大。放全屏卡而不是 toast，
是因为 toast 是药丸形（`border-radius: 99px`），塞不下第二行。

### 农场通知：信箱与两档角标

送礼和排行榜奖励都不再当场入账，而是**寄进信箱**（`ui/notices.js`），
玩家点「收下」才进仓库 / 钱包。以前那层整屏补播礼物的 `ui/gift.js` 已删除。

入口是农场页顶部操作条里的 📬（`#noticeBtn`，与 📔 农场日志并排）。
两颗都是 `.farm-log`，**34×34 / emoji 17px** —— 28px 时它们会和守护犬那行的
文字糊在一起，玩家经常找不到入口。

角标（`.fn-badge`）有**两档形态**，优先级从上到下：

1. 有没领的 → 红色**数字**（「还有 3 件东西没拿」比「有 3 封没读」要紧）；
2. 都领完了、只是没读 → 一颗 9px 的**纯红点**（`.fn-badge.dot`，`line-height: 0`，不写数字）；
3. 既没领的又全读了 → `hidden`。

两种形态都是**绝对定位**（数字 `top/right: -5px`，红点 `-2px`）贴在图标右上角，
**不参与布局** —— 亮不亮都不会把 📬 挤歪。这是硬要求，别改成 `flex` 占位。

已读规则：**打开列表 = 全体已读**（`markNoticesRead()`，只在真的变了才写库），
角标当场消失。但列表是**先渲染、再标已读**的 —— 这一帧里还看得见
`.nt-item.unread` 的红点与加粗标题，玩家能认出哪几条是这次新读的；下次打开就干净了。
领取本身也算已读（`claimNotice` 里 `read = true`）。

### 榜单出榜：全屏庆祝 + 队列

每日榜单下午 2 点结算，玩家拿到名次时除了 toast 还会播一张**全屏卡片**
（`ui/board-celebrate.js`）：整屏压暗 → 金圈从图标后面扩散 → 卡片弹出，
写清四件事 —— **榜单图标与名称 / 名次 / 成绩 / 奖励**（💰100、🚿洒水器×5）。

规则：

1. **单张最多 2 秒**：到点自己淡出，不把玩家按在这儿；
2. **点击即走**：点一下当前这张立刻变淡消失，队列里还有就接着弹下一张
   （点掉的那张是 0.32s 的淡出，淡完再弹下一张，不会闪）；
3. **多个名次排队播**：按**天数从旧到新、期内按榜的次序**（最友善 → 狗狗王 →
   打理王 → 送礼达人 → 农事劳模 → 冒险王一~五档）。离线积压了几天就几张，
   点得完；正在播的时候又结算出新的一期，追加到队尾，不打断当前这张；
4. **z-index 195**：压在弹窗（`#modal` 130）之上、toast（`#toasts` 200）之下 ——
   结算可能发生在玩家开着弹窗的时候，庆祝不能被弹窗挡住；
   而出榜的 toast 又必须能和庆祝同屏看见，所以层级卡在这个位置。

事件链路：`daily.checkRollover()` 结算后 `emit(EVENTS.BOARD_AWARD, playerAwards)`
→ `main.js` 里 `mountBoardCelebrate()` 订阅 → `showBoardCelebrate()` 排队播放。

### 离线时间轴：超过 2 小时才弹

世界时钟补算完之后，如果离开超过 **2 小时**，启动画面收起时弹一层
`ui/offline-report.js`（卡片类名 `.offline-modal`，走标准四段式）：

```
🌙  你不在的 3 天
    10/23 16:37 → 10/26 16:37
┌──────┬──────┬──────┬──────┐
│👋 131│🥷 6  │🤝 0  │🐕 0  │      ← 来访 / 被顺走 / 被照料 / 狗拦下
└──────┴──────┴──────┴──────┘
10月26日 周一   109 位来访
10月25日 周日   22 位来访 · 被顺走 6
  🥷 金链哥 从你农场顺走 1 个作物
  …（每天最多 6 条）
                            [回到农场]
```

四条硬规矩：

1. **2 小时以内不弹**（`data/world.js` 的 `REPORT_MIN_SPAN`）：切个后台、吃个饭
   回来还弹一层报告，那是打扰；这种情况只用邻居页那句汇总；
2. **「不在的几天」按经过的时间算，不按自然日桶数**：23 号 16:37 到 26 号 16:37
   只隔 3 天，桶却有 4 个 —— 标题写 4 天玩家会觉得算错了；
3. **每天最多 6 条事件**（`REPORT_NOTES_PER_DAY`），最多展开最近 10 天，
   更早的压成一行「还有 N 次来访」—— 离线一个月别刷成一条长卷轴；
4. **必须等出榜庆祝播完再弹**（`main.js` 的 `waitBoardCelebrate()`）：
   两个全屏层叠在一起谁也看不清。同理，`board-celebrate` 的层级 195 是给
   「庆祝压在弹窗上」用的，报告不抢这个层级，它是普通弹窗（130）。

### 图鉴点亮：先关弹窗，再播庆祝

图鉴详情弹窗里按下「🧪 制作标本」之后，**弹窗会先关掉**，再由
`ui/codex-celebrate.js` 播一张金绿卡片（`EVENTS.SPECIMEN`）：
金圈扩散 → 作物图标跳动 → 「图鉴点亮」+「名称 · 第 N / M 种」+ 两颗数字滚动
（种子奖励、点亮百分比）→ 2.4 秒后自动收起，点一下提前关。

三条约定：

1. **顺序不能反**：`closeModal()` 必须在 `makeSpecimen()` 之前调用。
   反过来写的话庆祝层会被弹窗盖住（`#modal` 130 vs 庆祝层 210，其实挡不住，
   但玩家会先看到弹窗闪一下再消失，像是点空了）；
2. **失败要把详情弹回来**：`if (!(await makeSpecimen(cropId))) openDetailModal(cropId)` ——
   料不够 / 已经做过时弹窗不该凭空消失；
3. **骨架照抄签到庆祝**：`sign-celebrate.js` 那套「自己造一层挂 body、点击即关、
   定时器自动收」已经验证过，样式换成 `.codex-celebrate` / `.cc-*`，
   关键帧 `ccPop` / `ccRing` / `ccOut` 与 `sc*` 一一对应，z-index 同样 210。

### 土地底纹：左侧土地色 → 右侧普通色

升级过的地块（`plot.soil !== 'normal'`）会挂一个 `soilbg-<id>` 类，
由 `::before` 叠一层横向渐变：左侧是这块地的颜色，44% 之后淡到透明，
底下还是原来的普通地色 —— 「一眼看出哪几块是花钱改过的」。

两个实现约束：

1. **不能直接改 `background`**。成熟（`.ripe`）、缺水（`.warn`）、
   生长中（`.growing`）各有一套背景，覆盖会把状态提示吃掉。
   用伪元素叠一层就没这个问题，alpha 只有 0.17~0.26，压在文字上也不碍事；
2. **颜色写在 `--soil-tint` 里**，每个 `.soilbg-*` 只声明一个变量。
   彩虹地单独一条规则（左侧本身就是多色，一段单色渐变表达不了）。

玩家和邻居共用这套类名：`.plot` 与 `.npc-plot` 都会挂。

**底色也必须统一**。`.npc-plot` 原来是自己一套冷白（`#fafcf7`），
点进邻居页像四十张白卡片，土地色叠上去也看不出来。现在它和 `.plot`
用同一套暖土渐变（`#fffefa → #f8f2e6`）、同一个边框色与底部压边（`::after`），
成熟态也换成同一组金色渐变与光晕。

⚠️ 状态类**只能改边框，不能改 `background`**：`.npc-plot.care`
以前写死了 `background: #fffaf9`，缺水的地一多整窗就被刷成白粉色，
底纹等于白做 —— 现在它和 `.plot.warn` 一样只动 `border-color` 与 `box-shadow`。

顶栏展开后的「当前土地」一格（`.hud-cell.wide`）展示构成：
全普通写 `普通 ×40`，有升级过的按档位从高到低列三项，再多折成「等 N 档」，
`title` 里放完整明细与平均产量倍率。

### 农场页顶部的操作条

`#page-farm` 的第一个孩子就是 `.farm-bar`：**在土地列表之上、跟着列表一起滚走**。
它是一张卡（圆角 14px + 白底 + 细边 + 1px 阴影）：

```
.farm-bar-row     ← 🐕 品种 ▬▬ 拦 32%              [📔 日志]
.farm-actions     ← 🚿 浇水 (6) ×12 | 🧴 杀虫 ×3 | 🚜 收获
```

- 下排是 `grid-auto-flow: column` 的三格，1px 竖线分隔；宽屏封顶
  `190px` 居中（`min-width: 720px`），不让三个小字拉在一条 290px 宽的格子里；
- 每格 `图标 + 名字 + 橙色待办数 + 灰色存量`；`<380px` 时存量退场；
- 存量只认消耗版：`×3`。**买过永久版就不显示数字**（永久 = 无限用，
  挂个 `×N` 反而误导），悬停提示里补一句「永久版，不消耗」。
  邻居农场标题栏的 🚿/🧴 悬停提示同一套规则。

四条规则：

1. **狗那一行永远显示**，和背包里有没有道具无关 —— 它是农场状态，不是道具入口；
2. **不再有 `--farm-tools-h`**。第 37 轮之前 `.farm-tools` 和 `.log-fab` 都是
   `fixed` 浮在底部导航上方，靠实测高度互相让位、`.app` 还要留 118px 空白。
   改到顶部流内之后这套补丁全部删掉；新增浮层**不要**再往底部堆；
3. **整条不能因为没道具就 `hidden`**。早期实现里
   `if (!water && !pest) { if (toolsKey) {...} return; }` 会让首次进入
   （`toolsKey === ''`）永远保持 `hidden` —— 新玩家还没买过洒水器，
   于是永远看不到自己养了条狗。现在统一走 key 比较，没道具时只留狗行；
4. **按钮不置灰**。灰掉整条会像坏了；没待办就只是不挂那个橙色数字，
   真空着点下去 store 会 `notify('现在没有需要浇水的地')`。

狗行的两种形态：有狗上岗显示 `🐕 田园犬 ▬▬ 拦 32%` + 饱腹条；
没有则显示灰色的「🐶 没有狗上岗」。订阅 `EVENTS.PETS` 刷新。

### 一键浇水 / 一键杀虫条

- 自己农场：`.farm-actions` 里的格子只在背包里有对应道具时出现；
- 邻居弹窗：一键按钮在 `.npc-board-top` 的标题行里（🚿🧴），同样按道具存量显隐；
- 按钮上是「待处理块数」+「道具存量 ×N」；数量或需求数没变就不重建 DOM，
  否则 500ms 一次的心跳会把玩家正在按的按钮换掉。

### 作物详情弹窗（`ui/crop-detail.js`）

三个入口共用一份实现：**自家地块的作物图标**、**邻居地块的作物图标**、
**种子制造间的产出行**。三者问的是同一件事 ——「这株东西值不值 / 我现在能不能动它」。

```
sd-hero    图标 + 名字 + 分类标签（与种子详情同一套 .sd-*）
sd-extra   情景胶囊：阶段 / 剩余时间 / 还能收几茬 / 产量加成 / 是不是谁家的
sd-grid    成熟时间 · 茬数 · 每次产量 · 单个售价 · 一轮经验 · 种子单价
sd-gain    一整轮预计收入 + 每小时金币
sd-note    底部一句话（这里能不能偷 / 该不该先收获）
```

几条约定：

- **基础信息固定，情景信息由调用方补**：`openCropModal(cropId, { status, foot })`，
  自己不判断「这是谁家的地」—— 那是调用方的知识；
- **作物图标要挂 `.tappable`**（手型 + 按下微缩 + 悬停光晕），
  否则它看起来只是装饰，没人会想到能点；
- **不提供操作按钮**：浇水 / 施肥 / 铲除 / 偷菜都还在各自的界面上，
  详情只回答「是什么、多久、值多少」，做成就不会跟地块面板打架。

> 从邻居弹窗里打开时是**叠层**：`openModal()` 会把当前整卡快照压栈，
> 关闭这层就还原拜访弹窗（含滚动位置）。见「弹窗的内部结构」。

### 种子制造间（`.ws-*`）

入口在「其他 → 🌱 种子制造间」，页面在 `ui/subpages/workshop.js`。三块：

```
.ws-hero    状态卡：等级 / 已造过几 种 / 制造栏位 / 三条概率条 / 升级进度
.ws-queue   制造队列（第 44 轮）：一炉一行，作物图标 + 进度条 + 还剩多久
.list       产出列表：一行一个作物（emoji + 拥有数 + 已造过 + 需要份数 + 工本费 + 等多久 + 下锅）
.ws-tips    未解锁时的说明，以及「再攒一点就能造」的提示
```

**每一行都要把两笔消耗写全**：`11 份 + 💰5 工本费`（半轮产出 + 四分之一价种子）。
只写「需要 11 份」的话，玩家点完发现金币少了一大截，会以为是 bug。
第 44 轮加了时间之后，行尾还要补一句 `· 等 2 分 30 秒`，三笔成本都摆在明面上。

金币不够时**行不消失、按钮变灰并改写文案**（「金币不足」），
工本费数字标红（`.ws-lack`）—— 整行凭空消失会让人以为这种作物不能造。
栏位满了同样处理：按钮灰掉写「栏位已满」，而不是让玩家点完再弹一条提示。

**升级看「造过多少种」，所以列表要给种类记账**：造过的那种挂一枚
`已造过` 灰标（`.ws-kind`），让玩家一眼看出「再刷这一种不会涨进度」。
状态卡与升级缺口都写成 `造过的作物 12 / 15 种`。

**制造要点两次**：点「下锅」只弹确认框，写清「吃几份 / 花多少金币 / 等多久 /
空闲栏位 / 期望几个 / 造完还剩多少」，点「下锅」才真扣。一次制造同时消耗产出、
金币和时间，高等级作物的工本费就是几万，误触的代价太大。

**队列区块的进度条每 2 秒自己走一格**（`startQueueTicker`），只改宽度和剩余时间文案、
不整页重绘 —— 整页重绘会把玩家正在看的滚动位置弹回去。到点的炉子由
`store/workshop.js` 的 `scheduleClaim()` 自动收掉，队列里的「收取 N 炉」按钮
只是给想立刻看到的人一个手动入口。

**点产出那一行**（不是按钮）开作物详情 —— 制造前玩家想知道这作物值不值。

几条约定：

- **概率条**用三根迷你进度条而不是一串百分比数字，`3 个` 那根用金色，
  一眼能看出它是稀有档；下面跟一行「期望 1.34 个 / 次」；
- **升不了级也要把缺口写出来**：`.ws-up-line` 达标时转绿，
  不达标就保持灰色显示 `累计制造 42 / 45`，玩家不用自己算；
- **解锁按钮的 disabled 跟着 `unlockState()` 走**，条件写在按钮上方的
  `.ws-req` 里（哪一条没达标就显示「还差 X」）；
- 子页面容器本身**没有左右内边距**（`.list` 是 `padding: 0 13px`），
  所以 `.ws-hero` / `.ws-tips` 自己带 `margin: … 13px`，否则会贴到屏幕边缘。

### 狗窝页：四层结构

「☰ 其他 → 🐕 狗窝」自上而下四块，对应狗的四个概念：

```
🦴 狗粮槽（共用）        ← .list 里的 .shop-item
   🐕 狗粮槽 · 守护中     ← .dog-state.on / .off
   ▓▓▓▓▓░░░ 存量 62/100  ← .dog-bar（点数，不是百分比）
   [🦴 添粮 (3)] [🍖 精品 (1)]   ← .dog-feed 竖排两个按钮

🏠 狗窝 Lv.0 · 槽容量 100  ← .shop-item（升级卡）
   每升一级 +30 · 下一级 Lv.1（容量 130）· 2000 💰  [升级]

🐕 我的狗窝（2 / 10）     ← .dog-grid，10 个 .dog-card
   田园犬 · 基础 20% · [上岗/下岗]
   边牧   · 基础 40% · [上岗]
   ???    · 冒险里偶遇      ← 未收集的 .dog-card.locked

说明文案                ← .dog-facts
```

⚠️ **存量是点数（`62/100`）不是百分比**：狗窝升级后容量会变（100 → 250），
百分比会让玩家以为存量「变少了」。农场顶栏那条狗粮条同理，
进度条宽度按 `存量 ÷ 容量` 算。

规则：

| 元素 | 规则 |
| --- | --- |
| 槽的状态文案 | 三选一：「无狗上岗」/「守护中」/「槽里没粮」 |
| 品种卡 | 未收集显示 `???` +「冒险里偶遇」，不给按钮 |
| 点的语义 | 点**已上岗**的那只 = **全部下岗**（`setActiveBreed(null)`） |
| 数量变化 | 底部说明里带上「当前：🐕 田园犬，实际拦截率 32%」 |

`.dog-state.on` 用绿色、`.dog-state.off` 用红色；上岗的卡加 `.dog-card.active`。
十个品种按 tier 顺序**全部列出**，未收集的也占位 —— 让玩家看得见还差哪几只。

### 称号页

- 入口：「☰ 其他 → 🏅 称号」，有可领取的称号时入口挂一个**红点**
  （`.sheet-dot`，`EVENTS.TITLES / CODEX / PLAYER` 都会触发刷新）；
- 结构：顶部大卡（当前佩戴的称号 + 已领数量）→ 待领取横条 → **三组 tab** → 当前组网格；
- **三类称号用 tab 分开**（等级 26 / 图鉴 26 / 金币 5，共 57 个）。57 张卡一次摊开时
  「我现在能领什么」要靠滚动去找，分组之后一屏就是一组；
  `.title-tabs` 吸顶（`top: 0`，上边留 12px 给 `.subpage-body` 的顶部渐隐让位），
  等级称号要滚好几屏，翻下去还得能换组；
- **tab 状态只能挂在模块变量上**：子页面每个动作结束都会 `renderCurrent()`
  整页重绘（`ui/subpage.js`），DOM 上的 `.active` 一重绘就没了。
  同理，切 tab 后要把 `body.scrollTop` 归零 —— 金币组只有 5 张卡，
  从等级组的第 20 张切过去会直接落到空白处；
- 每个 tab 上写「已领 / 总数」，有能领的再挂一枚红点角标（`.tt-dot`）；
- 徽章配色由称号的 `skin` 字段决定（CSS 里 10 套 `.title-badge.skin-N`），
  越往后越亮，一眼能看出哪个稀有；
- **不要重复渲染**：待领取的称号不单独开一区，只在横幅里给个「全部领取」，
  否则同一个称号会在页面上出现两次（列表里本来就有它）。

### 图鉴：卡片只留图标与名字

```html
<div class="codex-card clickable" data-action="codex-detail">
  <div class="codex-emoji">🌾</div>
  <div class="codex-name">小麦</div>
</div>
```

图鉴是一面墙，不是数据表。等级、成熟时间、产量、单价、种植次数
**全部挪进点开后的作物弹窗**（`ui/crop-detail.js`，全游戏共用一个），
卡片上只留图标和名字：一屏能扫过更多，也更容易看出哪一格还是灰的。

四种状态：

| 状态 | 长相 | 能点吗 |
| --- | --- | --- |
| 已点亮 | 彩色图标 + 名字 | 能，看完整数据 |
| 已收集未点亮 | **灰图标** + 名字（`.dull`） | 能，看完整数据 |
| 未收集（等级够） | ❔ + 「未收集」 | 能，看完整数据 |
| 未解锁 | ❔ + 「???」 | 不能（等级不够，看了也用不上） |

灰图标是**去色不打码**（`filter: grayscale(1)`，不是 `shadow` 那套虚框 + 问号）：
认得出来是哪种作物，只是还没做标本。三档长相一眼可分 —— 彩色 = 点亮、灰 = 收集、
❔ = 没见过，图鉴底下那行小字也把这条写在明面上。

**「收集」与「点亮」是两件事**：产出进过一次仓库就算收集（偷来的、邻居送的
都算，只增不减），做成一份标本才算点亮。卡片剪影看的是收集，
点亮只体现在详情弹窗与图鉴称号上。

筛选条三档：**全部 / 可点亮 / 已收集**，每档带数量角标。
「可点亮」是玩家真正需要的那个 —— 仓库里攒够 50 个、就差一下制作；
「已收集」看的是见过多少种，不看有没有做标本。

「制作标本」按钮因此只出现在弹窗里（仓库够 50 个时），
卡片上不再挂按钮：卡片变小之后，一颗按钮就能把它撑回原来的高度。

### 施肥弹窗

肥料有 9 种（5 档缩时间 + 3 档增产 + 1 档直接成熟），一格放不下，
弹窗里分三组列出来，组标题写明效果方向（⏳ 缩短成熟时间 / 💫 提高产量 / ⚗️ 直接成熟）。

### 村庄建设卡（村中心顶部）

```
🏘 西米村   Lv.1                    全村产量 +2%
升到 Lv.2 还差 2 项
💰 金币   ▓▓▓▓▓▓▓▓▓▓  10,000/10,000
🔷 水晶   ▓▓▓▓▓▓▓░░░   4/5
🙏 祈福   ▓▓▓░░░░░░░  29/60
[🚧 投入资源] [🙏 祈福] [📜 建设日志]
```

四条硬规矩：

1. **数字一律千分位，不用 `formatCoins`**。那边是给 HUD 的紧凑写法
   （10,000 → 「1.0万」），而这里是「进度 X / 门槛 Y」—— 两边必须同量级，
   「0 / 1.0万」这种混搭会让人一愣（2026-10-26 实测截图后改的）；
2. **达标那一行转金色**（`.cv-row.done` → 金色进度条）：三行里有一行是金的，
   就知道不用再管它了，瓶颈永远在剩下那两行；
3. **升级没有按钮**。三项同时达标就在下次投入 / 祈福时自动升 ——
   祈福每天只有一次，不该让玩家守着某个瞬间点确认；
4. **满级之后进度区换成一句「已经满级」**，但祈福与建设日志照旧可用
   （满级不代表没有日常）。

投入弹窗（`.village-modal`）只有两个输入框：左边名字、中间数字、右边
「投 N」一按填满。默认值填「还差多少」与「手上有的」取小 —— 差多少投多少，
投多了升级时会一起清零（store 那边也会夹到「还差的那点」，UI 只是不给出错的暗示）。
底部确认按钮 `.cvi-ok` **撑满整行**（`.btn` 本身是行内宽度，`.modal-foot` 也不是 flex）。

因为邻居也会投入（第 49 轮），进度条可能在你没看的时候被推满：
金币与水晶都满时按钮直接变成禁用的「🚧 资源已齐」，
一项都投不进去时点「投入资源」只弹一句 toast，不打开空弹窗。

建设日志复用 `recordItemsHTML`（与农场日志、时报同一套长相），
卡片挂 `board-modal` 把左右内边距收窄 —— 这里的正文密度高。

右上角 `ca-badge`（0 时压成灰的）。以前公告栏是总览右侧一条 78px 的竖窄按钮，

### 邻居弹窗的记录：两天 + 日期标题吸顶

弹窗底部的「最近操作」给**今天 + 昨天**（`recordItemsHTML` 的 `since` 选项），
滚动区高 220px。原来是「最近 10 条」，人一忙就只剩小半天，
玩家看不出这位邻居最近在忙什么。

日期标题（今天 / 昨天）是 sticky 的，但**容器不能有上下 padding**：

```css
.npc-log        { padding: 0 11px; }   /* 上下留 0 */
.npc-log .log-item { padding: 6px 0; } /* 条目自己撑开 */
.npc-log .log-day  { top: 0; background: #f8faf6; }
```

sticky 只能贴到 padding 的**内缘**，上下各留 9px 时标题上方就有一条缝，
滚动时条目会从缝里露出来 —— 玩家看到的「标题没有置顶、上面还有距离」就是它。
标题底下再加一道同色阴影，滚过去的条目不会在字缝里透出来。

─────────────────────────────────────────────────────────────

| 位置 | 元素 | 为什么在这 |
| --- | --- | --- |
| 紧挨「农场 N 块」 | 📜 日志小胶囊 | 和「这座农场几块地」是同一类信息，读的时候一起看 |

| 行尾（`margin-left: auto`） | 💬 互动（`.npc-interact`，32px 高实心绿） | 这颗是「找人办事」的唯一入口，做成这一行最大的按钮；送礼 / 交易 / 催上线全在它打开的弹窗里 |

### 邻居弹窗：互动弹窗（送礼 / 交易 / 催促上线）

`.ia-list` 一行一件事，每行左边一枚 36px 图标方块 + 标题 + 一句说明，
右边是**代价或状态**（`−20 好感` / `离线` / `在线`），行尾一个 `›`。

- 交易对他离线时点不开（整行 `.off` 压淡，点了只 `notify('他不在家')`）；
- 送份礼 → 叠一层挑礼物；交易 → 叠一层挑要买的东西；
  催促上线 → 叠一层**确认框**（花好感的事必须先摆账）；

- 联机好友（`friend.net`）只有一行「送份礼」—— 他的仓库是只读快照，
  交易与催促都做不了，写出来只会让人白点。

**催促上线**的确认框（`.sd-grid` 四格）必须写全四件事：
花费好感（−20）、催完还剩多少、预计多久回来、回来之后照常干活。
底下再补一句两端对照：「挚交喊一声就到（1 秒~30 秒），结怨得磨蹭半天（5 分~10 分）」——
不让玩家算，直接给结论。

### 农场顶部操作条：守护犬整格可点

没有狗时同样可点，文案是「🐶 没有狗上岗」，进去就是狗窝。

`.farm-bar` 现在有四个孩子：**狗 / 📬 信箱 + 📔 日志 / 一键照料 / 自动机器时效**：

### 邻居弹窗：操作后只更新局部

点「偷 1 个」「浇水」「捉虫」之后**不重开弹窗** —— 整窗重建会把滚动位置冲回顶部，
玩家刚翻到第 8 块地，操作一下就得重新往下找。

正确做法是只替换受影响的部分：

```js
slot.outerHTML = plotCardHTML(friend, index, at);   // 只有这一格
badge.textContent = ...;                             // 可偷数量
tip.textContent = ...;                               // 底部提示
board.outerHTML = boardHTML(friend, at);             // 控制台（狗粮槽 / 角标）
```

会同时改动很多格的操作（被狗抓住封锁全场、一键照料）走 `refreshAll()` 整片重绘。
弹窗结构自上而下：头部 → 数据卡（等级 / 身家 / 地块 / 好感）→
🟫 农场控制台（首行：块数 + 日志 + 一键 + 互动；次行：守护犬 + 添粮）→
地块 → 提示。送礼与交易已经收进「互动」弹窗里，主弹窗不再铺按钮。

> **第 47 轮：送礼与交易收进「💬 互动」弹窗。** 它们原本是弹窗顶部并排的两颗按钮
> （第 45 轮从最底部挪上去的），催上线没地方放，而且两排按钮压得地块往下走。
> 现在控制台首行行尾一颗大按钮包办三件事，`.npc-quick` 那套样式整块删掉。

### 好感度标签：标签与数值必须成对

```html
<span class="rel-tag rel-good">友好 +42</span>
```

六档配色（`best / close / good / plain / cold / bad`），字号 11px、药丸形。
只给数字没人能记住 42 算好还是算差，只给标签又不知道差多少 —— 所以两个都给。

两道容易忽略的细节：

- **`plain` 档要有一圈极淡描边**（`rgba(60,80,55,.12)`）：灰底和卡片底几乎同色，
  没有描边就只剩一串数字浮在那儿，不像标签；
- **信息格改成两列**，守护犬与偷菜各占满一行（`.npc-stat.wide`）。
  原来四列时「🐕 柴犬 · 62% 在看家」在手机上塞不进 1/4 宽，被省略号吃掉 ——
  玩家反馈的「守护犬文本超了」就是这个。

### 送礼：三层，清单只负责挑

```
邻居农场弹窗 → 🎁 送份礼 → 清单（挑一样）→ 送这个 → 确认框 → 确认送出
   第 1 层                    第 2 层                      第 3 层
```

- **清单**每行右边写着 `+N 好感`，玩家自己掂量值不值；
- **确认框**再摆四件事：送给谁、仓库有多少、送完剩多少、关系从哪一档走到哪一档
  （`平常 -7 → 平常 -3`）。只写「+4 好感」玩家得自己心算，写成两枚标签的迁移才看得懂；
- 确认框**左下角是数量步进器**（`.qty`），旁边一颗「全送」，
  改动时「剩余 / 好感 / 关系」三格实时重算，按钮文案跟着变成「确认送出 5 份」——
  玩家在按下确认之前就把这笔交易看清楚了；
- 好感按份数**线性**叠加（`单份好感 × 份数`），不做递减：
  递减的话「全送」反而不划算，玩家会一直点 1，数量控件就成了摆设；
- 送出即扣货、**不可撤销**，所以确认这一步不能省。

三层都是 `openModal` 的叠层（整卡快照压栈、`close()` 还原 scrollTop）。
送出成功后要 **`closeModal()` 两次**（确认框 + 清单），回到邻居农场，
再顺手 `refreshChrome()` 把好感与记录刷一遍 —— 少关一层会留下一张过期清单，
多关一层会把邻居弹窗也关掉。

失败（仓库刚好空了）时就地 `notify()` 并**停在确认框**，不要关层。

### 交易：同一套三层，但挑的是他的仓库

```
邻居农场弹窗 → 💰 交易 → 清单（挑一样）→ 买这个 → 确认框 → 确认买入
   第 1 层                  第 2 层                    第 3 层
```

和送礼是镜像的两件事，所以直接复用送礼那套骨架（`.shop-item` 行 + `.gift-confirm`
底栏 + `.qty` 步进器 + 两级 `closeModal()`），只在文案和口径上反过来：

| | 送礼 | 交易 |
| --- | --- | --- |
| 挑谁的仓库 | 自己的（`count(produceId)`） | **他的**（`friend.bag`） |
| 行上写什么 | `送他会涨 +N 好感`（`.rel-gain` 绿） | `每份花 −N 好感`（`.rel-cost` 暖红） |
| 钱 | 不动 | 按原价扣，进他口袋 |
| 好感 | 涨 | **掉** |
| 前置 | 无 | **他必须在线** |

三条容易踩的：

- **离线时这一行压淡、清单也开不出来。** 互动弹窗里用 `isNpcOnline(friend, now)`
  决定「交易」那一行的 `.off` 与文案（`他不在家，等他上线再来`），`openTradePicker`
  进来还要再挡一次 —— 弹窗内容是打开那一刻的快照，玩家可能停留很久才点。
- **步进器只重算、不落账。** `paint()` 里算的是 `tradeQuote` 的等价结果（总价、好感、
  关系胶囊、按钮 disabled），**不调用 `buyFromFriend`** —— 来回拨份数不该扣五次好感。
- **钱或好感有一头不够，确认按钮当场灰掉。** 不灰的话玩家点了才吃一句 `notify`，
  而这里有两个独立的门槛（金币 / 好感），不摆出来根本猜不到卡在哪一头。

联机好友没有交易入口：他的仓库是对方浏览器的只读快照，本地扣不了他的货。

### 空地升级：确认框里把「这一档」讲清楚

空地（`emptyHTML`）在「播种」下面多一颗「升级」，顶档地（神话）不渲染 ——
不摆一颗永远灰着的按钮。

弹窗是标准四段式：`🟫 升级土地 · 地块 N` / `当前档 → 下一档` /
六格属性（产量、成熟时间、经验、价格、当前金币、升级后永久保持）/ 确认。

两条细节：

- **只在真的变化时写箭头**：`delta()` 对 `×1.00 → ×1.00` 这种只写 `×1.00`，
  三行都画箭头反而看不出重点；
- **等级不够 / 金币不够各给一句 `.sd-lock`**，并禁用确认按钮。
  真正的校验仍在 `farm.upgradeSoil()`（逐级晋升、等级门槛、扣钱），
  这里重复判一遍只是为了「点之前就知道」，不是第二套规则。

## PWA 图标

设计源文件是根目录的 `sims-farm.png`（512×512，透明背景）。
图标不是一个尺寸缩到底，而是**按用途各裁一版**：

| 文件 | 尺寸 | 主体占比 | 底 | 用在哪 |
| --- | --- | --- | --- | --- |
| `icons/favicon-32.png` | 32 | 90% | 透明 | 浏览器标签页 |
| `icons/icon-192.png` | 192 | 82% | 透明 | manifest，安卓桌面 / 部分启动器 |
| `icons/icon-512.png` | 512 | 82% | 透明 | manifest，高清屏、应用商店 |
| `icons/icon-maskable-512.png` | 512 | 70% | `#f4f8f0` | manifest 的 `purpose: maskable` |
| `icons/apple-touch-icon.png` | 180 | 82% | `#f4f8f0` | iOS 添加到主屏 |

三条规则：

1. **先裁正方形再缩放，别整图缩**。源图里主体只占 45%×70%（四周是透明留白），
   整图缩到 192 之后图标内容会小得像贴纸。裁框以主体中心对齐 ——
   源图内容是 x 140~368、y 81~436，中心 (254, 258.5)，边长 = 内容高 ÷ 占比
   （82% → 434px，90% → 396px）。
2. **maskable 只放 70%**。安卓的自适应图标会被裁成圆形 / squircle，
   只有中心 80% 的圆是安全区；主体占 70% 才保证麦穗两端的尖角不被啃掉。
   这一版必须铺底色（`#f4f8f0`，与 `manifest.background_color` 一致），
   否则被裁掉的部分会露出系统给的深色底。
3. **iOS 不吃透明**。`apple-touch-icon` 也铺底色，不然主屏上是一片黑底。

改图标时三处要一起改：`manifest.json` 的 icons、`index.html` 的
`<link rel="icon">` 与 `<link rel="apple-touch-icon">`、`sw.js` 的 `CORE` 预缓存列表
（少了某个文件，离线打开时图标就缺一块）。
`sw.js` 的 `VERSION` 同时加一，让老用户的旧图标缓存被清掉。
