# 05 · 存储层

## 两层结构

```
core/db.js         IndexedDB 连接、表结构声明、单条与事务级操作
core/storage.js    存档网关：把「表 + 记录」翻译成「领域对象 + 字段」
```

上层（store / ui）只认 `player / plots / bag / friends / pet`，
不需要知道它们分别存在哪张表、哪个 keyPath 里。

## 表结构

库名 `sun_farm_v1`，结构版本 1。

```js
export const SCHEMA = {
  player:    { keyPath: 'id' },        // 恒有一条 id='player'
  plots:     { keyPath: 'id' },        // 0..39
  inventory: { keyPath: 'itemId' },    // { itemId, count }
  friends:   { keyPath: 'id' },        // 15 位邻居
  pets:      { keyPath: 'id' },        // 恒有一条 id='dog'
};
```

`DB_NAME` 与旧版单文件时代的 `homeland_farm_v2` **完全隔离**，
旧存档不会被破坏，可以随时回退到 `archive/` 里的版本对照。

新增表只需在 `SCHEMA` 里加一行，`onupgradeneeded` 会自动创建。

## 事务

### 单条操作

```js
import { get, getAll, put, remove } from '../core/db.js';

const row = await get('player', 'player');
await put('plots', plot);
```

适合只动一张表一条记录的场景。

### 跨表提交（业务代码里用这个）

一次收获会同时改地块、背包、金币、经验 —— 必须放进**同一个事务**，
否则会出现「钱扣了但没收成」的中间态：

```js
import { commit } from '../core/storage.js';

await commit(
  { player: state.player },              // 单条
  { plots: [plot], bag: state.bag },     // 集合（bag 全量覆盖）
);
```

`commit` 会自动收集需要打开的表，只开一个事务。

> **重要**：`write()` 的回调必须**同步**发出所有请求。
> IndexedDB 事务在事件循环回到空转时会自动提交，中途 `await` 会导致事务失效。
> 这也是 `commit` 不接受 async 回调的原因。

### 背包为什么全量覆盖

背包体量很小（几百条上限），每次改动 `clear()` + 重写最不容易出错。
`commit` 传 `bag` 时就是这么做的。

## 读档

```js
const save = await loadSave();
// → { player, plots, bag, friends, pet }
```

`loadSave` 并行读 5 处并做归一化：

- `player` / `pet` 读不到时返回 `null`，由 `initState` 补默认值；
- `plots` 按 id 排序；
- `inventory` 从 `{ itemId, count }` 的行还原成 `{ itemId: count }` 的对象。

## 存档兼容

游戏会持续加字段，所以每次读档都要补齐新字段。

### 地块

```js
// store/state.js
function normalizePlot(plot) {
  if (plot.harvested === undefined) plot.harvested = 0;
  return plot;
}
```

`harvested` 是「本轮作物已收获几次」，多次收获作物靠它决定还有没有下一茬。
老存档没这个字段，按 0 处理。

### 邻居

```js
// store/npc-sim.js
export function normalizeNpc(npc, fallback) {
  const personality = PERSONALITIES[npc.personality] ? npc.personality : fallback.personality;
  npc.personality = personality;
  npc.coins ??= fallback.coins;
  npc.exp ??= 0;
  npc.log ??= [];
  npc.level ??= fallback.level;
  npc.plots = (npc.plots || []).map((p) => ({ ...emptyNpcPlot(), ...p }));
  return npc;
}
```

注意 `npc.plots` 里的旧记录用的是 `stolen: boolean`，
新版改成了 `stolenAt: number`（时间戳）。旧记录反序列化后 `stolenAt` 是 `undefined`，
在 `isStealable()` 里被当作「从未被偷」处理，等于自动恢复成可偷 —— 这是可接受的降级。

### 玩家档案

`initState` 里直接用 `??=` 补齐：

```js
state.player.cropStats ??= {};
state.player.guide ??= {};
state.player.signStreak ??= 0;
state.player.signTotal ??= 0;
```

**新增玩家字段时记得在这里补一行**，否则老存档会读到 `undefined`。

## 邻居地块

15 位邻居的地块也存进 `friends` 表，整体作为一条记录：

```js
{
  id: 'npc01', name: '王大爷', avatar: '👴',
  personality: 'diligent',
  level: 6, exp: 0, coins: 800,
  plots: [ { cropId, harvested, plantedAt, readyAt, total, stolenAt }, ... ],
  lastVisitAt: 1712345678901,
  nextVisitAt: 1712355678901,
  log: [ { at, emoji, text }, ... ],
}
```

`nextVisitAt` 是模拟引擎的游标 —— 它决定「从哪一刻继续推演」。
落盘后即使关掉页面，下次进邻居页也从这个点接着算。

## IndexedDB 的坑

1. **必须经由 http 访问**。`file://` 下 `indexedDB.open` 可能被限制，
   而且 ESM 也会被 CORS 拦住。
2. **另一个标签页升级数据库时会阻塞**。`db.onversionchange` 里主动 `close()` 让路，
   `onblocked` 时给出可读的错误提示。
3. **事务不能跨 await**。见上面的说明。
4. **结构版本号只在不兼容时 +1**。纯新增表不用改版本号，
   `onupgradeneeded` 会在下次打开时补建。
