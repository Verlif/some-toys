## 作物表

```js
CROPS = {
  小麦: {
    name: '小麦', emoji: '🌾', form: 'grain',
    stages: ['seed','sprout','grow','ripe'],
    lv: 1, seed: 10, sell: 12,
    grow: 40, regrow: 0.5, harvests: 1,
    yield: [2, 4], exp: 5,
  },
  // ...
}
```

| 字段 | 含义 |
| --- | --- |
| `form` | 生长形态，决定阶段序列 |
| `stages` | 实际使用的阶段序列 |
| `lv` | 解锁等级 |
| `seed` / `sell` | 种子售价 / 农产品单价 |
| `grow` | **首次**成熟所需秒数 |
| `regrow` | 再生系数，后续每次成熟 = `grow × regrow` |
| `harvests` | 可收获总次数，1 表示一次性作物 |
| `yield` | 单次产量区间 |
| `special` | 为 true 时商店不卖，只能从藏宝图挖到（`seed` 只是估值） |

## 生长形态与阶段序列

`form` 是分类，决定这条作物走哪条阶段路径：

| form | 含义 | 阶段序列 |
| --- | --- | --- |
| `root` | 根茎类 | 播种 → 发芽 → 生长 → 成熟 |
| `leaf` | 叶菜类 | 同上 |
| `stem` / `shoot` | 茎 / 嫩芽 | 同上 |
| `fungus` | 菌菇类 | 同上 |
| `grain` | 谷物类 | 同上 |
| `cane` / `fiber` | 糖料 / 纤维 | 同上 |
| `pod` / `legume` | 豆荚类 | 播种 → 发芽 → 生长 → 开花 → 结果 → 成熟 |
| `fruit` | 果实类 | 同豆荚类 |
| `flower` | 花卉类 | 播种 → 发芽 → 生长 → 开花 → 成熟 |
| `tree` / `seed` | 树木 / 种子类 | 同花卉类 |

## 阶段推进算法

`stages.js` 的 `stageOf(plot, crop, now)`：

1. `now >= readyAt` 直接返回 `ripe`；
2. 否则按 `weight` 把整轮时间切成若干段，落在哪段就是哪个阶段；
3. **`ripe` 不参与时间分配**，它只是「已可收获」的终点标记。

第 3 条是个踩过的坑：早期版本 `ripe` 也有权重，导致进度 90% 时就显示「成熟」，
但地块还没到 `readyAt`、点不了收获，出现「显示成熟却不能收」的错位。

权重会按作物实际用到的阶段自动归一化，所以 4 段和 6 段的作物都能填满整轮时间。

## 多次收获（再生）

`harvests > 1` 的作物收获后不消失，进入再生轮次：

- 首次成熟 `grow` 秒，之后每次 `grow × regrow` 秒（有 30 秒下限）；
- **再生轮次回到「开花 / 结果」阶段**，跳过播种发芽，所以时间能显著压缩；
- 第 n 次收获的经验按 `0.8^(n-1)` 递减；
- 没有花果阶段的作物（根茎、谷物等）会退回到完整序列。

对应的实现见 `store/farm.js` 的 `beginRegrow`。

## 邻居配置

`friends.js` 里定义 8 种性格，每种给三个「经营行为」的权重。
偷菜不在这张表里 —— 它由每位邻居单独的 `steal` 倾向决定（见下）。

| 性格 | 收获 | 播种 | 打理 | `friendly` | 与玩家天生 |
| --- | --- | --- | --- | --- | --- |
| diligent 勤勉 | 4 | 4 | 3 | 45 | +23 |
| thrifty 精打细算 | 3 | 2 | 2 | 10 | +5 |
| merchant 生意人 | 2 | 2 | 1 | −15 | −7 |
| scholar 爱钻研 | 2 | 3 | 4 | 35 | +18 |
| leisurely 悠闲 | 2 | 1 | 1 | 5 | +3 |
| greedy 爱占便宜 | 2 | 2 | 1 | −45 | −22 |
| friendly 热心 | 3 | 3 | 4 | 75 | +38 |
| boss 场面人 | 3 | 3 | 2 | 25 | +13 |

`friendly` 是**基础好感度**：两个人之间的好感从这里起算
（`round((A + B) / 2)`，玩家没有性格档案按 0 算），之后才靠偷菜 / 打理 / 送礼变化。
所以「与玩家天生」这一列就是 `friendly / 2` 四舍五入。

每位 NPC 的五项差异：

| 字段 | 说明 |
| --- | --- |
| `personality` | 性格，决定经营行为的权重（`tend` 决定帮忙照料的积极性 `min(0.6, tend × 12%)`），也决定基础好感度 |
| `profession` | 职业，纯展示，让邻居有身份感 |
| `schedule` | `{type:'fixed', hours:[6,18]}` 固定钟点（±30 分钟浮动）或 `{type:'interval', min, max}` 随机间隔（小时） |
| `steal` | `never / rare / often / always`，对应 `STEAL_CHANCE` 的 0 / 12% / 45% / 90% |
| `level` | **不写在名单里**：创建时按 `rollNpcLevel()` 从 1~36 级加权随机（低等级更多），之后无上限成长 |

`nextVisitAt(npc, at)` 负责算出下一次上线时间，`expectedGapMs(npc)` 给离线结算估进度。
32 位邻居的名单都在 `NPCS` 里；等级与身家由 `rollNpcLevel` / `npcStartCoins` 现算。

模拟节奏的常量也在这个文件里（动作数、精细窗口等），
细节见 [07-邻居模拟](./07-邻居模拟.md)。

> 守护犬相关的常量（饱腹度上限、每份狗粮恢复量、每小时衰减、拦截概率函数）
> **不在这里**，全部在 `dogs.js` —— 见下节。

## 签到配置

`signin.js` 定义七天循环的奖励表，`rewardFor(streak)` 按连续天数取，
`(streak - 1) % 7` 循环。第 7 天是大赏日（金币 + 经验 + 一批道具）。

中断签到不会归零，而是从第 1 天重新累计。

## 导航配置

`navigation.js`：

- `MORE_MENU_ITEMS` —— 「更多功能」浮窗的入口，`ready: false` 的点击后提示开发中；
- `SUBPAGE_TITLES` —— 子页面顶部标题；
- `SEED_FILTERS` —— 商店种子区的筛选档位；
- `NOT_READY_TOAST` —— 未开发功能的提示文案。

「加工坊」「交易行」两个占位入口已经删掉；`seedshop`（种子制造间）是
第 18 轮加进来的真功能，页面在 `ui/subpages/workshop.js`。

新增子页面时，三个地方都要登记：这里（入口 + 标题）、`ui/subpages/index.js`（注册）。
