## 三个浮层统一交互

底部浮窗、子页面、模态弹窗共用同一套：

- 从底部上滑出现；
- 下拉关闭；
- 收起与展开的 transform 都由 CSS 表达，拖动过程中才写内联 `transform`，松手后交还 CSS。

CSS 状态机很简单：

```css
#subpage           { transform: translateY(100%); transition: transform .3s ...; }
#subpage.show      { transform: translateY(0); }
```

`drag-close.js` 只在拖动过程中写 `panel.style.transform`，
松手时清空内联样式，动画自动交还给 CSS。

## 下拉关闭手势

```js
dragToClose(panel, { onClose, scrollArea });
```

判定逻辑：

- 只有**向下**拖动且超过 8px 才接管，向上推还给内部滚动；
- `scrollArea.scrollTop > 0` 时完全不接管（用户想看内容，不是想关掉）；
- 位移超过 72px 松手则关闭，否则回弹。

### 三个必须记住的实现要点

**1. 用 Touch 事件而不是 Pointer 事件。**
面板是纵向可滚动的容器，CSS 里必须写 `touch-action: pan-y`，
而这会让浏览器接管纵向手势、**忽略 touchmove 上的 preventDefault**，
Pointer 方案会因此收到 pointercancel 而中断。Touch 事件里主动 preventDefault 才能抢回手势。

**2. move 事件必须检查「有没有按下过」。**
这是本项目踩过的最隐蔽的 bug：`mousemove` 挂在 window 上，
在 `mousedown` 之前就会触发一次，此时 `startY` 还是 0，
于是「鼠标的绝对 Y 坐标」被当成了拖动位移，弹窗瞬间被甩出去。
修法是加一个 `tracking` 标志，只有 `begin()` 之后才认 move 事件。

**3. 鼠标的 move / up 只在按下期间才监听。**
按下去才 addEventListener，松开立刻 remove，
避免页面上任何一次普通鼠标移动误触发拖动。

### 可拖拽区域要显式标注

`touch-action: none` 要加在**把手和标题栏**上（它们不是滚动容器），
滚动容器本身保持 `pan-y`：

```css
.sheet-handle { touch-action: none; }   /* 把手 */
.subpage-head { touch-action: none; }   /* 标题栏 */
.subpage-body { touch-action: pan-y; }   /* 内容区，照常滚动 */
```

## 事件委托

列表重绘后不需要重新绑定监听器 —— 全部挂在**容器**上一次：

```js
delegate(root, 'click', '[data-action]', (el) => {
  ACTIONS[el.dataset.action]?.(el.dataset.id);
});
```

> **例外**：`scroll` 事件不冒泡。商店的横向面板是每次重绘新建的，
> 所以滚动监听直接挂在 `.shop-panels` 上（`renderShop` 里）。

## 渲染策略

### 带缓存的 setHTML

```js
export function setHTML(el, html) {
  if (renderCache.get(el) === html) return;   // 内容没变就不碰 DOM
  renderCache.set(el, html);
  el.innerHTML = html;
}
```

### 地块：key-diff

40 块地每 500ms 刷新一次，靠指纹避免无脑重写。详见 [02-架构总览](./02-架构总览.md#渲染策略)。

### 商店：保留滚动位置（顺序有硬约束）

```js
const keepLeft = panels ? panels.scrollLeft : 0;
const tabAtRender = activeTab;                       // 先固定住，别用重建后的 activeTab
const activePanel = panels.querySelector(`.shop-panel[data-panel="${tabAtRender}"]`);
const keepTop = keepPanelScroll && activePanel ? activePanel.scrollTop : 0;

setHTML(root, /* ... */);

if (keepLeft) nextPanels.scrollLeft = keepLeft;
syncTabFromScroll(nextPanels);                       // 必须在恢复 scrollLeft 之后
if (keepTop) nextPanels.querySelector(`.shop-panel[data-panel="${tabAtRender}"]`).scrollTop = keepTop;
```

否则买一次种子就会跳回第一个 tab。两条容易踩的：

1. **顺序不能反**。先 `syncTabFromScroll` 再恢复 `scrollLeft` 的话，
   它读到的是 `scrollLeft = 0`，会把 `activeTab` 误判成第一个 tab（种子），
   接着纵向滚动就被恢复到了**错误的面板**上。
2. **面板的 key 要用 `tabAtRender`**，不能用 `activeTab` ——
   `syncTabFromScroll` 会改写 `activeTab`，拿它当 key 等于用「改写后的值」去找面板。

纵向位置由 `keepPanelScroll` 标志控制：改筛选（`filter-seeds`）和外部
`setShopTab()` 跳转时置 `false`（换列表就该从顶部看起），
正常重绘（买东西）保持 `true`。

## 顶栏（HUD）

收起态只有一行：头像、名字、等级、称号、金币。
点击展开详细信息面板 —— 面板是 `position: absolute; top: 100%`，
**盖在内容之上，不占据布局流**，所以不会把下面的土地区域挤走。

展开内容：当前称号、距离下一称号、升级进度、地块解锁、连续签到、图鉴收集。

顶栏高度会写进 CSS 变量 `--hud-h`（`hud.js` 用 `offsetHeight` 量出来），
供商店的吸附定位使用：

```js
document.documentElement.style.setProperty('--hud-h', `${bar.offsetHeight}px`);
```

`base.css` 里有一个兜底值 `--hud-h: 64px`，避免 JS 未执行时定位失效。
量出来比写死更可靠，因为顶栏高度受刘海屏安全区影响。

## 商店：tab + 横向滑动

```
.shop-top        ← position: sticky; top: var(--hud-h)
   .shop-tabs        种子 / 道具 / 土地 / 藏宝图
   .shop-filter      筛选条（只属于种子面板，非种子 tab 时 hidden）
.shop-panels     ← overflow-x: auto; scroll-snap-type: x mandatory
   .shop-panel × 4   每个 min-width: 100%
```

**筛选条必须放在 `.shop-panels` 之外**。因为 `.shop-panels` 开了
`overflow-x: auto`，浏览器会把它当成滚动容器，里面的 `position: sticky`
会相对它定位而不是相对页面，横向滚动时就被带走了。

`.shop-filter` 必须**无条件渲染**（`filterHTML()` 每次都输出），
显隐完全交给 `hidden` 属性。它内部已经用 `${activeTab === 'seed' ? '' : 'hidden'}`
控制显隐、`switchTab()` 也是靠 `filter.hidden = ...` 切换 ——
如果外层再写一层「只在种子 tab 才渲染这个元素」，两者就矛盾了：
在道具 tab 买东西触发重绘后，筛选条会被整个从 DOM 删除，
`switchTab()` 里 `root.querySelector('.shop-filter')` 找不到元素，
点回种子 tab 也回不来。

交互：

- 点 tab → `scrollTo({ left: index * clientWidth, behavior: 'smooth' })`
- 左右滑动 → 滚动位置反推当前 tab 并更新高亮（rAF 合并高频 scroll）
- 筛选条只属于种子面板，用 `hidden` 切换而不是重新渲染（避免递归）

## 农场页

### 顶部操作条（狗 + 日志 + 一键照料）

`#page-farm` 的第一个孩子是 `.farm-bar`，在土地列表**之上、跟着列表一起滚走**。
它是一张卡（圆角 + 白底 + 细边），不是几颗散落的药丸：

- `.farm-bar-row`：`.farm-dog`（图标 + 品种 + 狗粮条 + 拦截率）在左，`#logBtn` 在右；
- `.farm-actions`：一键浇水 / 杀虫 / 收获，三格等宽 + 1px 竖线分隔。
  图标 + 名字 + 橙色待办数 + 灰色存量（`×N` / `∞`）。

**第 37 轮从底部悬浮改到这里。** 以前 `#farmTools` 和 `.log-fab` 都是 `fixed`，
一起压在底部导航上方：滚到底时最后一排地块永远盖在它们下面，`.app` 还得额外留
118px 空白。改成流内元素后 `--farm-tools-h` 那套「量高度抬日志按钮」的补丁全部作废。

三个按钮不置灰（灰掉整条会像坏了），没待办就只是不挂橙色数字；
真空着点下去 store 会 `notify('现在没有需要浇水的地')`。

**没道具时不能把整条藏掉。** 早期实现写成：

```js
if (!water && !pest) { if (toolsKey) { /* ... */ } return; }   // ← 曾经的 bug
```

首次进入时 `toolsKey === ''` 走不进重绘分支，`el.hidden` 永远保持 `true` ——
**新玩家（还没买过洒水器）永远看不到自己养了条狗**。
现在统一走 key 比较，没道具时只留狗那一行（`.farm-actions[hidden]`）。

### 自动机器时效行（`#farmAuto`，第 51 轮）

`.farm-bar` 的第三个孩子，在 `#farmActions` 之后。`renderFarmAuto()` 与
`renderFarmTools()` 同一套路：先拼 key，没变就一个字符都不碰 DOM。

- **只有买过的机器才出 chip**：一台都没有时整行 `hidden`，不占高度；
- 每个 chip 是「图标 + 剩余时效」，`autoTimeText(remain)` 的格式是硬约定：
  **> 23:59:59 显示「X天X时X分」，否则「X时X分X秒」** —— 剩 25 小时要读成
  「1天1时0分」，而不是「25时0分0秒」；
- 时效是**到期时间戳**倒推出来的，所以页面开着不动也会自然走完；
  `EVENTS.TICK` 每轮会重画（key 里带的是格式化后的文本，跨秒才真的重绘）。

### 未解锁地块折叠

40 块地逐个画锁图标既占地方又没有信息量。规则：

- 未开垦的**最多只画第一个**，那颗格子里直接放「🔓 价格 💰」按钮；
- 如果还有更多，追加一行 `.plot-fold` 汇总「还有 N 块荒地待开垦 · 下一块 X 💰」；
- 折叠行在 `nodes` 里的 key 是哨兵值 `'__locked-more'`；
- **顺序永远是「已解锁地块 → 荒地卡 → 折叠行」**。开垦一块地后新的荒地卡节点
  才新建，`append` 会落到折叠行后面，所以每次渲染完要把折叠行 `appendChild`
  挪回末尾（移动已有节点，不重建 DOM）。

### 紧凑排布

解锁地块超过 15 块时给 `.grid` 加 `.dense`，切换到更小的格子尺寸
（`minmax(102px, 1fr)` + 缩小字号），否则手机上要滚十几屏。

作物图标在这个模式下仍然保持 38px（常规 47px）—— 它是地格上唯一的主角，
缩小就认不出种的是什么。为此 `.grid.dense .plot-main` 的行距压到 2px，
`min-height` 从 122 提到 126，`scrollHeight` 实测等于 `clientHeight`（不溢出）。
放大后的尺寸是量过的：成熟、生长中、缺水、生虫四种状态都不会把格子撑破。

## 邻居页

进入时先补算离线结算，再渲染：

```js
export async function enterFriendsPage() { /* 见 07-邻居模拟 */ }
```

`tabs.js` 里把邻居页的进入函数从 `renderFriends` 换成了 `enterFriendsPage`，
这就是「只在进入时更新」的实现点。

### 在线轮询

邻居页还导出 `checkOnlineVisits()`，由 `main.js` 每 60 秒调一次
（`document.hidden` 时跳过，切回标签页时立刻补一次）：

```js
await social.pollOnline();               // 只结算；提示由事件总线送过来
```

上线 `EVENTS.ARRIVAL`、下线 `EVENTS.DEPARTURE` 都由这一层的
`noteArrival` / `noteDeparture` 接住，400ms 内的多人合并成一条：
「👋 A、B 等 N 位上线了」「💤 A、B 等 N 位下线了」。
store 只算数据、只发事件，**提示由这一层的 `showToast` 发出** —— store 不引用 UI。

下线用普通配色而不是金色：金色在这套配色里表示「好事发生了」，
而一个人的离开不该抢走注意力，格式与上线保持一致，一眼能认出是同一类消息。

列表项**整行可点**（`data-action="visit"` + `role="button"` + `tabindex="0"`），
不用单独的「拜访」按钮；同时绑了 Enter / 空格键的无障碍支持。

卡片上多挂了一枚好感度标签（`.friend-chip.rel-*`，形如「友好 +42」），
它读的是 `getRelation(PLAYER_ID, friend.id)` —— 邻居页只读，不提供修改入口，
改关系的地方在邻居弹窗里（偷菜、打理）与送礼清单。

### 筛选与排序是两条独立的轴

```
筛选：全部 / 可偷摘 / 可帮忙          ← 决定「看哪几位」，单选
排序：等级 / 财富 / 好感              ← 决定「按什么排」，三态
```

排序芯片**点一次换一个方向**：降序 → 升序 → 取消（回到名单原序）。
第一次点必须是降序 —— 玩家点「等级」想看的是最高的那几位，不是最低的。
换到另一个维度时重置为降序。

早先这两件事挤在一个 `sortMode` 里：「可偷摘」被当成一种排序，
点了之后既不能反向也不能取消，「只看能偷的 + 按财富排」这种组合根本做不到。
现在它们分成 `filterKey` 与 `sortKey / sortDir`，可以任意组合。

**筛选条只认点击，不做滑动手势**。早先给排序条加过「左右滑动切上一档 / 下一档」
（touch + mouse 双通道，位移 > 40px 就接管），移动端上横向滑芯片时会频繁误切档位，
而且和芯片行自身的横向滚动抢手势 —— 已整段删掉（`shiftSort` 与四个监听器）。

`renderFriends()` 换的是整个 `#friendsBody`，新 `.filter-bar` 的 `scrollLeft` 会归零 ——
手机上点了右侧的「好感」一刷新，标签条自己滚回最前面。所以重绘前记 `scrollLeft`、
重绘后同步赋值回去（`if (keepLeft)` 那句），和商店页恢复面板位置的套路一致。

## 农场通知（`ui/notices.js`）

送礼和排行榜奖励**不再当场入账**，统一寄进信箱，玩家点「收下」才进仓库 / 钱包。
以前那层整屏补播礼物的 `ui/gift.js` 与 `#giftLayer` 已整块删除。

入口是农场页顶部操作条里的 📬（`#noticeBtn`），角标两档：

| 情况 | 角标 |
| --- | --- |
| 有没领的 | 红色**数字**（`noticeUnclaimed()`，超过 99 写 `99+`） |
| 都领完了、只是没读 | 一颗 9px 的**纯红点**（`.fn-badge.dot`） |
| 既没领的又全读了 | `hidden` |

两种形态都是绝对定位，**不参与布局**，亮不亮都不会把 📬 挤歪。

打开列表 = 全体已读（`markNoticesRead()`），但**不自动领取** —— 用户要的就是手动点。
列表是**先渲染、再标已读**的：这一帧里还看得见 `.nt-item.unread` 的红点与加粗标题，
玩家能认出哪几条是这次新读的。`paint()` 在领取后只重刷 `[data-role="nt-list"]`
与 `[data-role="nt-foot"]`，不重建整张弹窗。

列表动作三个：`notice-claim`（收下一条）/ `notice-claim-all`（全部收下）/
`notice-from`（点来源行打开那位邻居的农场卡，只对有 `by` 的条目挂）。

## 子页面

`subpage.js` 是容器，负责标题、金币同步、内容渲染与动作分发。
具体页面由 `subpages/` 下的模块注册：

```js
// subpages/index.js
export const subpages = {
  bag: bagPage,
  codex: codexPage,
  dog: dogPage,
  seedshop: workshopPage,   // 种子制造间
  orders: ordersPage,       // 订单（NPC 收购 / 玩家发布）
  // 排行榜不在表里：它从村中心以弹窗打开（subpages/rank.js 的 openRankModal）
  // ...
};
```

每个页面导出 `{ render(body, ctx), actions? }`：

```js
export const bagPage = {
  render(body) { body.innerHTML = /* ... */; },
  actions: {
    async sell(el) { await sellProduce(el.dataset.id); },
  },
};
```

容器统一分发：

```js
delegate(body, 'click', '[data-action]', (el, event) => {
  const handler = subpages[current]?.actions?.[el.dataset.action];
  if (!handler) return;
  Promise.resolve(handler(el, ctx)).then(renderCurrent);
});
```

异步动作完成后自动重绘当前页面，省得每个 handler 自己调。

## 新增子页面

1. `ui/subpages/` 建模块，导出 `{ render, actions }`
2. `ui/subpages/index.js` 注册
3. `data/navigation.js` 加 `SUBPAGE_TITLES` 条目
4. `data/navigation.js` 的 `MORE_MENU_ITEMS` 加入口，把 `ready` 改成 `true`

第 4 步的 `ready: false` 是「入口可见但提示开发中」的状态，
用来占位还没做的功能。

### 设置页（`subpages/settings.js`）

存档的导出与导入。规矩和别的子页面一样，但有两处必须单独注意：

**① 文件选择框要挂在 `document.body` 上。** 子页面的动作 handler 跑完，
容器会 `renderCurrent()` 重绘整个 body —— 如果 `<input type="file">` 建在
子页面里，玩家点开的其实是旧节点，选完文件 `change` 落在一个已经被摘掉的
元素上，**静默失效**（没报错、没反应）。所以用 `ensureInput()` 懒建一次，
appendChild 到 body 上，全页共用。

**② 拖拽要同时挡住整页的默认行为。** 只绑拖拽方块不够：文件掉在方块外面时，
浏览器会直接打开那个 zip，把游戏页面顶掉 —— 玩家会以为存档丢了。
所以 `document` 上补一对 `dragover`/`drop` 监听。

这一对监听是常驻的（只注册一次，靠 `bodyGuarded` 挡住重复绑定），
所以**必须判「设置页是不是真的开着」才接文件**：

```js
function settingsVisible() {
  return Boolean(document.querySelector('#subpage.show [data-role="save-drop"]'));
}
```

注意 `#subpage.show` 这一节不能省。关掉子页面只是移除 `.show` 类，
DOM 里的内容还在 —— 只查 `[data-role="save-drop"]` 的话，玩家离开设置页
之后在农场页随手拖进来一个文件，照样会弹导入确认框。

`dragleave` 还要判 `zone.contains(event.relatedTarget)`：鼠标从方块移到
里面的文字/图标上也会触发 `dragleave`，不判的话高亮会一直闪。

导入成功走 `location.reload()`，因为内存里的 `state` 没法热替换
（见 `docs/05-存储层.md` 的「写回的顺序与那个封库开关」）。
