# 《回声躲猫猫》策划说明书

版本：2.2  
类型：非对称对抗 / 潜行 / 声波感知  
平台：Web（浏览器）  
玩家人数：1–2 人（对抗 AI）  
文档性质：策划设计说明

> **2.2 变更**：剩余时间移至 HUD 正中并放大、最后 20 秒开始闪烁；玩家全部被抓后立即开启上帝视角观战。
> **2.1 变更**：从单文件拆分为多文件工程（见第 8 章），并修正了 AI 的敌我识别——同阵营的声波不再触发 AI 的任何反应。变更细节见第 16 章。

## 1. 游戏概述

《回声躲猫猫》是一款以“声波感知”为核心机制的非对称对抗游戏。游戏世界全黑，所有角色只能通过移动或主动发声产生的声波来感知环境。声波会在墙壁间反射，勾勒出地形轮廓，同时也会暴露自己的位置。

玩家可选择扮演 **搜捕者** 或 **躲藏者**，并可在单人模式下与 AI 对战，或在双人模式下与另一位玩家共同扮演同一角色。

- **搜捕者**：目标是在限定时间内抓住所有躲藏者。
- **躲藏者**：目标是至少一人存活到时间结束。

游戏强调信息不对称、声音管理和空间推理，AI 具备记忆、预测与协作能力。

---

## 2. 核心玩法循环

1. 角色移动或主动发声 → 产生声波 → 声波扩散并在墙壁上反射。
2. 玩家根据声波判断地形、寻找目标或躲避追捕。
3. 声波触碰到其他角色时，会向“相关方”发出橙红色闪烁标记。
4. 搜捕者触碰到躲藏者即将其淘汰。
5. 时间耗尽或所有躲藏者被淘汰时游戏结束。

---

## 3. 角色与目标

| 角色 | 默认数量 | 目标 | 特殊能力 |
|------|----------|------|----------|
| 搜捕者 | 1（可调 1–3） | 在限定时间内抓住所有躲藏者 | 声波可探测躲藏者 |
| 躲藏者 | 6（可调 3–10） | 至少一人存活至时间结束 | 无 |

**胜负条件：**
- 搜捕者胜利：所有躲藏者被抓住。
- 躲藏者胜利：时间耗尽时仍有至少一名躲藏者存活。

## 4. 声波系统

### 4.1 声波发射

| 触发方式 | 参数 |
|----------|------|
| 移动时每 0.5 秒自动发声 | 静步：半径 220 px，8 条射线，强度 0.5 |
| | 快步：半径 440 px，8 条射线，强度 1.0 |
| 主动噪声（空格 / Enter） | 半径 660 px（快步的 1.5 倍），16 条射线（双倍），强度 1.4 |

- **静步**：默认状态，速度倍率 0.5。
- **快步**：按住 Shift，速度倍率 1.0。
- **主动噪声**：冷却 4 秒，发出大范围单次声波。

### 4.2 声波传播

- 声波以 **10 格/秒**（240 px/秒）的速度向外扩散。
- 每条声波由多条射线组成，射线遇到墙壁会反射，最多反射 2 次。
- 声波射线以蓝色线条呈现，随传播距离逐渐淡出。

### 4.3 可见性规则

- **声波射线**：玩家只能看到自己阵营发出的声波。搜捕者看不到躲藏者的声波，反之亦然。
- **墙壁轮廓**：声波反射击中墙壁时，墙壁格子会被点亮并保留约 2.4 秒（1.0 秒完全保持 + 1.4 秒淡出）。**墙壁记忆只对发射者本人可见**，队友或其他角色的声波不会点亮你的墙壁轮廓。
- **角色探测闪烁**：当任意角色的声波触碰到其他角色时（不含自己），会在接触点产生一次橙红色闪烁。玩家只能看到与自己相关的闪烁：
  - 自己的声波探测到别人
  - 别人的声波探测到自己

### 4.4 声波对 AI 的意义（敌我识别）

声波**传播本身无差别**：队友的脚步与噪声同样会扩散、同样会被玩家看见、同样会产生探测闪烁。但声波是否会引起 AI 的反应（写入听觉记忆 / 威胁地图），必须经过阵营判定：

| 声源 | 接收方 | 是否触发 AI 反应 |
|------|--------|------------------|
| 躲藏者 | 躲藏者（队友） | ❌ 忽略 |
| 搜捕者 | 搜捕者（队友） | ❌ 忽略 |
| 躲藏者 | 搜捕者（敌人） | ✅ 记入 `heardSound`，可转入调查 |
| 搜捕者 | 躲藏者（敌人） | ✅ 记入 `heardSound`，写入威胁地图 |

判定实现见 `js/ai/reaction.js` 的 `isEnemy()` / `shouldReactToSound()`，这是全项目唯一的敌我识别入口。

## 5. 移动与操作

### 5.1 单人模式

| 操作 | 按键 |
|------|------|
| 移动 | W / A / S / D 或 方向键 |
| 快步 | 按住 Shift |
| 主动噪声 | 空格 |
| 暂停 / 继续 | ESC |
| 重开 | R |

### 5.2 双人模式

双人模式下，两位玩家扮演**同一角色**（同为搜捕者或同为躲藏者）。

| 玩家 | 移动 | 快步 | 噪声 |
|------|------|------|------|
| 玩家 1 | W / A / S / D | 左 Shift 或 Shift | 空格 |
| 玩家 2 | 方向键 | 右 Shift | Enter |

- 双人模式下同角色数量最少为 2。
- 双方各自拥有独立的噪声冷却计时。
- 一个玩家被抓后，若另一玩家仍存活，游戏继续。

### 5.3 基础数值

- 基础移动速度：130 px/秒。
- 静步实际速度：65 px/秒；快步实际速度：130 px/秒。
- 搜捕者速度倍率：1.12（比躲藏者快约 12%）。
- 碰撞体积：搜捕者半径 9 px，躲藏者半径 8 px。

- 地图尺寸由所选大小决定：

| 大小 | 格子尺寸 | 列 × 行 | 障碍物数量 |
|------|----------|---------|------------|
| 小 | 30 px | 32 × 20 | 26 |
| 中 | 24 px | 40 × 25 | 58 |

## 8. 工程结构

作品已从单文件拆分为标准多文件工程，入口为 `index.html`，脚本使用 ES Module（`<script type="module">`），因此需要通过 HTTP 访问（本地可用 `python -m http.server`、`npx serve` 等）。

```text
├─ css/
│  └─ styles.css            # 全部样式（布局、HUD、面板、结算表、动画）
├─ js/
│  ├─ entry.js              # 入口：缓存 DOM → 绑定事件 → 启动主循环
│  ├─ core/
│  │  ├─ config.js          # 全部可配置参数 + 地图预设 + 阵营定义
│  │  ├─ utils.js           # 随机 / 钳制 / 格子坐标 / 时间格式化
│  │  ├─ state.js           # 全局可变状态 gstate + 键盘状态
│  │  ├─ timer.js           # 逻辑时间 nowSec / 表现时间 visualNowSec
│  │  └─ entities.js        # 搜捕者 / 躲藏者工厂 + 开局布阵
│  ├─ world/
│  │  ├─ map.js             # 随机地图生成 + 连通性检测 + 空地缓存
│  │  ├─ collision.js       # 圆 vs 格子碰撞与逐轴移动
│  │  └─ pathfind.js        # BFS 寻路、路径跟随、路口质量评估
│  ├─ audio/
│  │  └─ sound.js           # 射线投射、声波发射、噪声冷却、移动发声
│  ├─ ai/
│  │  ├─ reaction.js        # ★ 敌我识别（同阵营声波一律忽略）
│  │  ├─ seeker.js          # 搜捕者状态机
│  │  └─ hider.js           # 躲藏者威胁地图与逃跑 / 隐藏决策
│  ├─ game/
│  │  ├─ main.js            # 对局主循环、抓捕判定、暂停、开局
│  │  ├─ input.js           # 键盘绑定与玩家移动
│  │  ├─ replay.js          # 回放采样、插值、播放控制
│  │  └─ stats.js           # 结算统计读写
│  ├─ render/
│  │  ├─ sight.js           # 画布适配、世界变换、墙壁记忆、探测闪烁
│  │  └─ renderer.js        # 主渲染 + 回放渲染
│  └─ ui/
│     ├─ dom.js             # DOM 引用集中缓存
│     ├─ hud.js             # HUD 刷新、提示条、全屏
│     ├─ panels.js          # 结果动画与结算面板
│     └─ settings.js        # 主菜单与设置面板
├─ 回声躲猫猫_策划说明书.md
└─ 回声躲猫猫_Steam商店介绍.md
```

**模块依赖方向**（不允许反向依赖，避免循环）：

```text
core → world → audio → ai → game → render → ui → entry
```

- `core/state.js` 里的 `gstate` 是所有可变状态的唯一载体，替代了原本单文件闭包里的共享变量。
- `core/config.js` 中随地图变化的量（`TILE`/`COLS`/`ROWS`/`WALL_COUNT`/`SOUND_SPEED`）通过 ES Module 的实时绑定同步给所有模块，切换地图大小只需调用 `setWorldSize()`。
- `ai/reaction.js` 是唯一的敌我识别入口，任何“谁该对谁的声音有反应”的判断都必须经过它。

## 9. AI 设计

### 9.1 敌对判定（前置规则）

所有 AI 反应都建立在同一条规则上：**只有敌对阵营的声波才会被 AI 当作信息**。

```js
// js/ai/reaction.js
isEnemy(a, b)            // 同阵营 → false；敌对 → true
shouldReactToSound(l, e) // 声音接收方是否应对声源做出反应
```

- 躲藏者 ↔ 躲藏者、搜捕者 ↔ 搜捕者：队友，声波被忽略（不写入 `heardSound`、不产生威胁区）。
- 躲藏者 ↔ 搜捕者：敌人，声波按原有规则触发调查 / 威胁地图 / 逃跑。
- 被抓的躲藏者不再作为有效声源参与判定。
- 声波的可听范围判定本身不变（`maxRadius * 1.15`），变的只是“听到之后要不要当真”。

### 9.2 搜捕者 AI

采用状态机，优先级从高到低：

1. **追击（Chase）**：声波探测到躲藏者后，带速度预判前往命中点，持续约 4 秒。
2. **搜索（Search）**：失去目标后，在最后位置周围生成 11 个搜索点，逐一排查，搜索窗口最长 11 秒。搜索时每约 2.7 秒（`NOISE_AI_MIN_INTERVAL × 0.78`）发出一次噪声扫描。
3. **调查（Investigate）**：听到**躲藏者**的声音（延迟到达）后，前往声源位置调查，持续约 3 秒。
4. **巡逻（Patrol）**：无目标时，选择长时间未访问的格子作为巡逻点，使用快步移动，每约 4.7 秒（`× 1.35`）发出一次噪声。

- 搜捕者会记忆最近 45 秒内访问过的格子，避免重复巡逻。
- 追击、调查、搜索、巡逻时均使用快步。
- 声波路径不可达时不退回巡逻，而是以更高频率重算；被墙角卡住时先走一步切向脱困步。
- **不会再调查队友的噪声**（这是 2.1 修正的行为）。

### 9.3 躲藏者 AI

每个躲藏者维护一张**威胁地图**，记录最近 12 秒内听到的**搜捕者**声音位置（上限 20 条）。

- **逃跑（Flee）**：满足任一条件立即逃跑——被搜捕者声波直接探测到（2 秒内有效）、搜捕者距离小于 150 px、威胁区距离小于 200 px。
  - 逃跑点综合评估 60 个候选位置：方向契合度、与所有追捕者的距离、出口数量、队友距离。
  - 逃跑过程中若威胁换了位置，会立即重新评估逃跑方向；持续超过 5.5 秒则转回隐藏。
- **隐藏（Hide）**：安全时选择藏身点并静步移动；中距离威胁（搜捕者 < 420 px 或威胁区 < 390 px）时静默换到更安全的点，而不是原地不动。
  - 藏身点评分考虑：远离威胁区域、远离追捕者、靠近墙壁、出口数量（优先 2–3 个出口的拐角）、远离队友。
  - 休息后重新选择藏身点，保持动态隐蔽。
- **冻结（Frozen）**：完全静止、不发声的保留状态（当前策略更偏向静默换位）。
- 躲藏者**不会主动感知**追捕者坐标；决策依据来自听到的搜捕者声音与自己的声波命中，追捕者距离只用于“已经知道附近有敌人之后”的取舍。
- **队友（其他躲藏者）的声波不再计入威胁地图**，因此不会出现“对着队友逃跑”的行为。

## 10. 视觉与 UI

- **背景**：纯黑色。
- **声波**：蓝色射线，随传播距离淡出。
- **墙壁记忆**：蓝色高亮格子，只对发射者本人可见。
- **探测闪烁**：橙红色脉动光环 + 十字准星，单次脉冲（快速升起、平滑衰减），仅相关方可见。
- **玩家标记**：
  - 玩家 1：亮青色脉动圆环（外层呼吸光环 + 中间填充圆 + 中心白点）。
  - 玩家 2（双人）：紫色脉动圆环。
- **HUD**（游戏画面上方，不遮挡游戏区域）：
  - **剩余时间**：居中主视觉，字号明显大于其他信息；最后 20 秒变红并开始闪烁，最后 10 秒闪烁更急促、字号进一步放大。
  - 左侧：剩余躲藏者数量、当前身份（双人模式标注 · 双人）、上帝视角角标（玩家全部被抓后显示的观战角标）。
  - 右侧：全屏按钮、退出回放按钮（仅回放时出现）、噪声冷却进度条（显示 P1 的冷却）。
  - 三个区块用绝对定位分区：左右两组贴边，时间永远居中，不会被两侧内容挤偏。

## 11. 游戏流程

1. **菜单**：选择身份，可切换单人 / 双人模式。
2. **设置**：调整角色数量、地图大小、游戏时长。
3. **开局倒计时**：3 秒倒计时，期间游戏完全冻结，时间不走、角色不动。
4. **正式游戏**：玩家操控角色，AI 自主行动。
5. **玩家出局 → 自动观战**：玩家（单人 1 名 / 双人 2 名）全部被抓的瞬间，立即开启上帝视角继续观战。此时半透明显示完整地图、所有角色位置与全部声波，剩余 AI 继续把对局打完，玩家可以看着队友或对手的最终结局。
6. **暂停**：按 ESC 弹出暂停菜单，可继续、重新开始或返回菜单。
7. **结束**：所有躲藏者被抓或时间耗尽时游戏结束。
   - 进入上帝视角，半透明显示完整地图和所有角色位置。
   - 所有声波、墙壁残留、探测闪烁冻结保留在最后一帧。
   - 结算面板显示统计数据，可最小化为按钮以观看最终画面。

## 14. 技术实现要点

- 纯 HTML + CSS + JavaScript（ES Module），使用 Canvas 2D 渲染，无构建步骤、无第三方依赖。
- 地图生成使用随机矩形 + 连通分量标记，确保无闭合区域。
- 声波射线使用步进检测（每 4 px 采样）与墙壁碰撞，反射使用法线向量计算。
- AI 寻路使用 BFS 网格寻路，路径跟随包含卡住检测（连续 0.32 秒几乎未移动则重新规划）。
- 声波命中检测在射线步进中实时进行，探测闪烁仅对相关方可见。
- 墙壁记忆使用 `emitterId,gx,gy` 作为键值，按发射者区分。
- 时间系统使用 `nowSec()` 统一管理，暂停时冻结所有游戏逻辑。
- 敌我识别统一由 `js/ai/reaction.js` 承担，声波传播与 AI 反应解耦：传播无差别，反应分阵营。
- 模块间的可变状态统一放在 `gstate`（`js/core/state.js`），地图尺寸等配置通过 ES Module 实时绑定下发。
