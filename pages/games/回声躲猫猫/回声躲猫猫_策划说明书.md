## 1. 游戏概述

《回声躲猫猫》是一款以“声波感知”为核心机制的非对称对抗游戏。游戏世界全黑，所有角色只能通过移动或主动发声产生的声波来感知环境。声波会在墙壁间反射，勾勒出地形轮廓，同时也会暴露自己的位置。

玩家可选择扮演 **搜捕者** 或 **躲藏者**，并可在单人模式下与 AI 对战，或在双人模式下与另一位玩家共同扮演同一角色。

- **搜捕者**：目标是在限定时间内抓住所有躲藏者。
- **躲藏者**：目标是至少一人存活到时间结束。

游戏强调信息不对称、声音管理和空间推理，AI 具备记忆、预测与协作能力。

---

## 2. 核心玩法循环

1. 角色移动或主动发声 → 产生声波 → 声波扩散并在墙壁上反射。
2. 玩家根据声波判断地形、寻找目标或躲避追捕。
3. 声波触碰到其他角色时，会在接触点产生橙红色闪烁标记 —— **发射方与接触方都能看到**，接触方同时能看见探到自己身上的那道声波。
4. 搜捕者触碰到躲藏者即将其淘汰。
5. 时间耗尽或所有躲藏者被淘汰时游戏结束。

---

## 3. 角色与目标

| 角色 | 默认数量 | 目标 | 特殊能力 |
|------|----------|------|----------|
| 搜捕者 | 1（可调 1–3） | 在限定时间内抓住所有躲藏者 | 声波可探测躲藏者 |
| 躲藏者 | 6（可调 3–10） | 至少一人存活至时间结束 | 无 |

**胜负条件：**
- 搜捕者胜利：所有躲藏者被抓住。
- 躲藏者胜利：时间耗尽时仍有至少一名躲藏者存活。

## 4. 声波系统

### 4.1 声波发射

| 触发方式 | 参数 |
|----------|------|
| 移动时每 0.5 秒自动发声 | 静步：半径 220 px，8 条射线，强度 0.5 |
| | 快步：半径 440 px，8 条射线，强度 1.0 |
| 主动噪声（空格 / Enter） | 半径 660 px（快步的 1.5 倍），16 条射线（双倍），强度 1.4 |

- **静步**：默认状态，速度倍率 0.5。
- **快步**：按住 Shift，速度倍率 1.0。
- **主动噪声**：冷却 4 秒，发出大范围单次声波。

### 4.2 声波传播

- 声波以 **10 格/秒**（240 px/秒）的速度向外扩散。
- 每条声波由多条射线组成，射线遇到墙壁会反射，最多反射 2 次。
- 声波射线以蓝色线条呈现，随传播距离逐渐淡出。

### 4.3 可见性规则

**声波射线**

- **自己阵营的声波**：始终可见。
- **敌方声波**：只有**真正打到自己身上**的那一条才可见——被声波扫到的瞬间，你能看见探到你的那道波，也能据此判断对方大致方位与距离；没有接触到你的敌方声波依然完全不可见。
- 已经出局的躲藏者留下的声波不再显示。

**墙壁轮廓**

- 声波反射击中墙壁时，墙壁格子会被点亮并保留约 2.4 秒（1.0 秒完全保持 + 1.4 秒淡出）。
- 记忆按发射者分开存放（`emitterId,gx,gy`），但**渲染时按阵营共享**：你自己点亮的墙，以及**同阵营队友（含 AI 队友）点亮的墙**，你都能看到。
- 所以黑暗里分头探图是有效的配合方式：队友在前面跑出来的地形，你在后面同样看得见。
- 共享有两条边界：
  - **只共享同阵营**。敌方声波照到的墙不会给你任何地形信息（你顶多能看到那道探到你身上的波，见上一条）。
  - **已经出局的躲藏者不再共享**，与声波射线的处理保持一致。
- 开关：`SHARE_TEAM_WALL_MEMORY`（`js/core/config.js`，默认 `true`）。设为 `false` 时回到“只有自己声波点亮的墙可见”，信息更封闭、潜行压力更大。

**角色探测闪烁**

声波触碰到角色时（不含自己）会在接触点产生一次闪烁，但**玩家画面上只显示自己打出去的那一次**：

| 情形 | 玩家实际看到 |
|------|--------------|
| 我的声波扫到敌人 | ✅ 亮橙色脉冲 + 十字准星 |
| 我的声波扫到队友 | ❌ 不显示（队友不是目标） |
| 敌人 / 队友的声波扫到我 | ❌ 不显示 |
| 队友的声波扫到敌人 | ❌ 不显示 |
| 与玩家无关的接触（AI 打 AI） | ❌ 不显示 |

理由：别人的接触点位置和你没有信息上的关系（你们并没有共享“被声波命中的提示”），画出来只会干扰判断。上帝视角（结算 / 回放）仍然保留全部闪烁。

被打到这件事你依然知道——因为你能看见探过来的那道声波（上一条规则）。

### 4.4 声波对 AI 的意义（敌我识别）

声波**传播本身无差别**：队友的脚步与噪声同样会扩散、同样会被玩家看见、同样会产生探测闪烁。但声波是否会引起 AI 的反应（写入听觉记忆 / 威胁地图），必须经过阵营判定：

| 声源 | 接收方 | 是否触发 AI 反应 |
|------|--------|------------------|
| 躲藏者 | 躲藏者（队友） | ❌ 忽略 |
| 搜捕者 | 搜捕者（队友） | ❌ 忽略 |
| 躲藏者 | 搜捕者（敌人） | ✅ 记入 `heardSound`，可转入调查 |
| 搜捕者 | 躲藏者（敌人） | ✅ 记入 `heardSound`，写入威胁地图 |

注意区分「**看得见**」和「**会当真**」：可见性（4.3）只决定画面上显示什么，AI 反应（这里）只决定 AI 怎么行动。敌方声波打到你时，你既能看到那道波，AI 也会照常把你标记为目标——两边拿到的是同一件事实。

判定实现见 `js/core/teams.js` 的 `isEnemy()` / `shouldReactToSound()`，这是全项目唯一的敌我识别入口。

## 5. 移动与操作

### 5.1 单人模式

| 操作 | 按键 |
|------|------|
| 移动 | W / A / S / D 或 方向键 |
| 快步 | 按住 Shift |
| 主动噪声 | 空格 |
| 暂停 / 继续 | ESC |
| 重开 | R R（连按两次确认） |

### 5.2 双人模式

双人模式下，两位玩家扮演**同一角色**（同为搜捕者或同为躲藏者）。

| 玩家 | 移动 | 快步 | 噪声 |
|------|------|------|------|
| 玩家 1 | W / A / S / D | 左 Shift 或 Shift | 空格 |
| 玩家 2 | 方向键 | 右 Shift | Enter |

- 双人模式下同角色数量最少为 2。
- 双方各自拥有独立的噪声冷却计时。
- 一个玩家被抓后，若另一玩家仍存活，游戏继续。

### 5.3 基础数值

- 基础移动速度：130 px/秒。
- 静步实际速度：65 px/秒；快步实际速度：130 px/秒。
- 搜捕者速度倍率：1.12（比躲藏者快约 12%）。
- 碰撞体积：搜捕者半径 9 px，躲藏者半径 8 px。

### 5.4 碰撞与移动手感

角色是圆，墙是格子，移动时**只有“撞向墙面”的那部分位移被吃掉，沿墙面滑行的分量照常前进**：

- 一整帧的位移会拆成不超过 `COLLIDE_MAX_STEP`（默认 5px）的小步推进，再逐步把“陷进墙里的那一点”沿法线推出来。
- 因此：
  - **贴着墙走**：与墙面轻微相交时不会连沿墙方向的位移一起被撤销，可以正常贴着墙前进；
  - **斜着蹭墙**：不再出现 X、Y 两轴同时被撤销而顶死在墙角的情况，斜插会自然转成沿墙滑行；
  - **进通道**：碰到门框时，法线推力会把小球往开口里带（`COLLIDE_ASSIST_RANGE`，默认 8px 内能脱离接触才算“门框/墙角”）。
- 正面顶着大片完整墙面时，角色**不会**被自动带着横向漂移——辅助只在“浅浅擦到墙角/门框”时生效，避免变成自动寻路。
- 相关参数：`COLLIDE_MAX_STEP` / `COLLIDE_RESOLVE_ITER` / `COLLIDE_SKIN` / `COLLIDE_ASSIST_*`（见 `js/core/config.js`）。

## 6. 地图生成

- 地图尺寸由所选大小决定：

| 大小 | 格子尺寸 | 列 × 行 | 障碍物数量 |
|------|----------|---------|------------|
| 小 | 30 px | 32 × 20 | 26 |
| 中 | 24 px | 40 × 25 | 58 |
| 大 | 20 px | 48 × 30 | 92 |

- 随机生成矩形障碍物，通过连通性检测确保所有空地属于同一连通区域，**不存在闭合区域**。
- 地图每次开局重新生成。

## 7.5 道具系统

每 **20 秒**在地图上随机刷新一个道具，**所有角色都看得见**（渲染不过滤），任何角色碰到即拾取。
人类玩家与 AI 都会顺手去捡（AI 在巡逻 / 休息时会把附近道具作为临时目标）。

| 道具 | 图标 | 效果 | 持续 |
|------|------|------|------|
| 回响之眼 | 👁 | **使对方阵营角色全体现形** | 1 秒 |
| 凝滞之锁 | ❄ | **使对方阵营所有角色定格**（不能移动、不能抓人） | 2 秒 |
| 喧嚣之铃 | 🔔 | **使对方阵营所有角色立即发出一次噪声**（无视噪声冷却） | — |
| 疾行之羽 | ⚡ | **自己加速**（×1.6 移动速度） | 5 秒 |

规则细节：

- **效果永远作用在“对方阵营”上**（`core/teams.js` 判定），所以躲藏者捡到凝滞之锁是冻结搜捕者，反之亦然。
- **显形只对拾取者的阵营生效**：被显形的角色身上带 `revealedUntil` + `revealedFor`，
  只有该阵营的人（玩家与 AI）能看到它；队友不会因为敌方捡了道具而互相暴露。
  AI 也会把被显形的敌人当作“看见”（`core/vision.js` 的 `nearestVisibleEnemy`），
  所以显形对 AI 同样有意义。
- **定格**会清空该角色的路径与朝向，解冻后重新规划；被定格的搜捕者抓不了人。
- **噪声**走 `sim/sound.js` 的 `forceNoise()`，绕过噪声冷却——否则“立即发出噪声”可能被冷却吃掉。
- 道具默认 **30 秒**后自动消失，避免地图上越堆越多；刷新点会避开角色与已有道具 90px 以内。
- 可调参数：`ITEM_SPAWN_INTERVAL` / `ITEM_LIFETIME` / `ITEM_RADIUS` / `ITEM_POOL` /
  `ITEM_HASTE_MUL` / `ITEM_TYPES`（`js/core/config.js`）。
- HUD 左下角实时显示「下一个道具还有几秒」以及自身的定格 / 加速 / 显形剩余时间。

## 8. 工程结构

作品已从单文件拆分为标准多文件工程，入口为 `index.html`，脚本使用 ES Module（`<script type="module">`），因此需要通过 HTTP 访问（本地可用 `python -m http.server`、`npx serve` 等）。

```text

│  └─ styles.css            # 全部样式（布局、HUD、面板、结算表、动画）
├─ js/
│  ├─ main.js               # ★ 应用入口：装配各层 + 固定步长主循环（不写游戏规则）
│  ├─ core/                 # 基础设施与领域规则
│  │  ├─ config.js          # 全部可配置参数（含道具 / AI / 网络）
│  │  ├─ state.js           # 全局可变状态 gstate（可序列化，不放 DOM）
│  │  ├─ utils.js           # 钳制 / 格子坐标 / 插值 / 时间格式化
│  │  ├─ timer.js           # 逻辑时间 nowSec / 表现时间 visualNowSec
│  │  ├─ rng.js             # ★ 可播种随机（联机与回放要能复现同一局）
```

**模块依赖方向**（不允许反向依赖，避免循环）：

```text
core → world → sim(基础) → ai → sim/simulation → input / net / render / ui → main.js
```

规则与理由：

- `core/state.js` 里的 `gstate` 是所有可变状态的唯一载体，只放**可序列化**的对局数据（不放 DOM、定时器、函数）。
- `core/config.js` 中随地图变化的量（`TILE`/`COLS`/`ROWS`/`WALL_COUNT`/`SOUND_SPEED`）通过 ES Module 的实时绑定同步给所有模块，切换地图大小只需调用 `setWorldSize()`。
- `core/teams.js` 是唯一的敌我识别入口，任何“谁该对谁的声音有反应”的判断都必须经过它。
- `core/rng.js` 是唯一的随机来源：地图、AI 采样、道具刷新全部走它，同一颗种子必然得到同一局。
- **`sim/` 绝不 import `ui/` / `render/` / `dom`**：需要通知界面时只 `emit()` 事件（`core/events.js`），由 `ui/flow.js` 订阅。这样同一份模拟可以直接跑在浏览器、无头测试，或将来的房主 / 服务端上。
- **角色位移只有 `sim/movement.js` 一个入口**：玩家指令、AI 寻路、AI 直线扑击都走它，手感与防抖规则因此永远一致。
- `ui/actions.js` 是一层极小的依赖注入容器：菜单 / 结算面板按钮不直接 import 流程模块，避免 `settings ↔ flow ↔ panels` 互相成环。
- **玩家操作 = 指令（`core/command.js`）**：键盘产生指令 → `session.submitCommand()` → 模拟消费。联机时同一条路径换成网络包，业务代码不用改。

## 9. AI 设计

### 9.1 敌对判定（前置规则）

所有 AI 反应都建立在同一条规则上：**只有敌对阵营的声波才会被 AI 当作信息**。

```js
// js/core/teams.js
isEnemy(a, b)            // 同阵营 → false；敌对 → true
shouldReactToSound(l, e) // 声音接收方是否应对声源做出反应
```

- 躲藏者 ↔ 躲藏者、搜捕者 ↔ 搜捕者：队友，声波被忽略（不写入 `heardSound`、不产生威胁区）。
- 躲藏者 ↔ 搜捕者：敌人，声波按原有规则触发调查 / 威胁地图 / 逃跑。
- 被抓的躲藏者不再作为有效声源参与判定。
- 声波的可听范围判定本身不变（`maxRadius * 1.15`），变的只是“听到之后要不要当真”。

### 9.2 搜捕者 AI

采用状态机，优先级从高到低：

1. **碰面追击**：与躲藏者**互相显形**（3 格内）的那一刻立刻进入追击，不必先等声波传回来。
2. **追击（Chase）**：声波探测到躲藏者后，带速度预判前往命中点，持续约 4 秒。
3. **搜索（Search）**：失去目标后，在最后位置周围生成 11 个搜索点，逐一排查，搜索窗口最长 11 秒。搜索时每约 2.7 秒（`NOISE_AI_MIN_INTERVAL × 0.78`）发出一次噪声扫描。
4. **调查（Investigate）**：听到**躲藏者**的声音（延迟到达）后，前往声源位置调查，持续约 3 秒。
5. **巡逻（Patrol）**：无目标时，选择长时间未访问的格子作为巡逻点（偏好约 6 格远、且不在身后），使用快步移动，每约 4.7 秒（`× 1.35`）发出一次噪声。
6. **顺手捡道具**：巡逻时若 320px 内有道具，临时把目标改成道具（目标带 6 秒黏性，不会每帧改主意）。
7. **抓捕**：AI 搜捕者**没有抓捕冷却**（`CATCH_COOLDOWN_AI = 0`），可以连续抓捕；
   只有人类玩家被抓捕冷却限制。想削弱 AI 就调大 `CATCH_COOLDOWN_AI`。

- 搜捕者会记忆最近 45 秒内访问过的格子，避免重复巡逻。
- 追击、调查、搜索、巡逻时均使用快步。
- 声波路径不可达时不退回巡逻，而是以更高频率重算；有路却走不动时由 `sim/navigation.js` 的两级看门狗重规划。
- **不会再调查队友的噪声**（这是 2.1 修正的行为）。

### 9.3 躲藏者 AI

每个躲藏者维护一张**威胁地图**，记录最近 12 秒内听到的**搜捕者**声音位置（上限 20 条）。

- **碰面逃跑**：与搜捕者**互相显形**（3 格内）时立刻当作“被发现了”逃跑——否则会出现玩家看得见搜捕者、AI 却还在原地发呆的不对称。
- **逃跑（Flee）**：满足任一条件立即逃跑——与搜捕者显形、被搜捕者声波直接探测到（2 秒内有效）、搜捕者距离小于 150 px、威胁区距离小于 200 px。
  - 逃跑点综合评估 60 个候选位置：方向契合度、与所有追捕者的距离、出口数量、队友距离。
  - 逃跑过程中若威胁换了位置，会立即重新评估逃跑方向；持续超过 5.5 秒则转回隐藏。
- **隐藏（Hide）**：安全时选择藏身点并静步移动；中距离威胁（搜捕者 < 420 px 或威胁区 < 390 px）时静默换到更安全的点，而不是原地不动。
  - 藏身点评分考虑：远离威胁区域、远离追捕者、靠近墙壁、出口数量（优先 2–3 个出口的拐角）、远离队友。
  - 休息后重新选择藏身点，保持动态隐蔽。
- **冻结（Frozen）**：完全静止、不发声的保留状态（当前策略更偏向静默换位）。
- 躲藏者**不会主动感知**追捕者坐标；决策依据来自听到的搜捕者声音、自己的声波命中，以及**近距离的互相显形**。
- **队友（其他躲藏者）的声波不再计入威胁地图**，因此不会出现“对着队友逃跑”的行为。
- **碰面检测开关**：`PROXIMITY_DETECT`（`js/core/config.js`，默认 `true`）。设为 `false` 时 AI 只依赖声波，近距离照面也不会有反应。

### 9.4 寻路

**平滑：先拉直路径，再按路点走**

- BFS 网格寻路给出四向最短路，直接逐格跟随会走成台阶（对角路程约为直线的 1.41 倍）。
- 现在把「往哪走」固定在**重规划的那一刻**：算完路径立刻做一次 string pulling——
  从当前位置出发，尽量往后跳到「带半径也能直线走过去」的最远节点，得到 1~3 个路点的短列表；
  之后角色只认这几个路点。
- 「迈得出去」用**带半径**的检查（沿连线按 6px 采样，每个采样点都要求角色中心不撞墙）。
- 实测空旷对角「路程 / 直线」= **0.99**（逐格跟随是 1.41）。

**为什么不再“每帧挑一次朝向”（v3.2 修的就是这个）**

- 3.0 的实现是每帧重新在「直接奔目标」和「走下一个路径节点」之间二选一。
  两者会来回抢占：同一个位置上一帧往右、下一帧往左，表现出来就是**贴着墙左右晃**。
- 现在方向来自路点列表，两次重规划之间完全稳定；只有目标真的变了才重算。

**目标变化必须立刻作废旧路径**（`setGoal()`）

- 巡逻点 / 追击点随时可能换。如果沿用旧路点，角色会先把旧路点走完、再掉头走向新目标——
  看起来就是在墙边来回走直线。实测这是“左右晃”的**主要来源**。
- 现在 `sim/navigation.js` 的 `setGoal(e,x,y,tolerance)` 在目标移动超过阈值时立即清空路点并触发重规划。
- 巡逻点选择也加了「别选身后 / 别选 2.5 格以内」的倾向，避免刚到达就掉头。

**防抖与防卡死**

1. **转向锁**：AI 想在一瞬间反向（>100°）时，若刚反向过（0.18 秒内）则先保持原方向，
   避免贴着墙来回蹭。**玩家输入不受此限制**（手感优先）。
2. **步伐级看门狗**：有路可走却连续 0.3 秒几乎没位移 → 重规划。
3. **进度级看门狗**：连续 0.6 秒没有拉近目标 → 重规划（顶着墙角小幅抖动时位移不为零，只看位移抓不到）。
4. 移动统一走 `sim/movement.steer()`（内含最小平移解算的贴墙滑动），
   不再用「探测一步→撞墙就整帧不动→沿 ±90° 硬蹭」那套。

**晃动实测**（`tests/jitter.mjs`，判定口径见 tests/README）：

| 版本 | 可见晃动 | 贴墙晃动 | 连续 1 秒卡死 |
|------|----------|----------|----------------|
| 3.1（旧朝向选择） | 2.3 次/AI·分钟 | 1.5 次/AI·分钟 | — |
| 3.2 开发中（仅重构后） | 3.4 次/AI·分钟 | 1.1 次/AI·分钟 | — |
| **3.2（最终）** | **0.6~0.9 次/AI·分钟** | **0.3~0.4 次/AI·分钟** | **0 次** |

另有 0.15%~0.3% 的「有路却暂时走不动」帧（正常贴墙减速 / 转身），没有再出现连续卡死。
剩下的晃动事件几乎都来自「逃跑点重算 / 换藏身点」这类确实改了目标的情况，振幅也多在 13~29px，
不再是早期那种贴着墙持续来回蹭。

**追击目标失效的处理**

- 被追的躲藏者被别人抓走后，`spottedTarget` 会立刻作废并退出追击状态。否则 AI 会一直追着一具“尸体”：那个格子已经可通行，`findPath` 返回空数组，AI 就卡在“原地重算”里直到追击超时。
- 追击时若目标在 8 格内且中间没墙，直接直线扑上去；判据是**到目标的距离有没有真的变小**
  （只看“有没有位移”会把贴墙侧移误判成追击成功），并且成功后会**保持 0.4 秒**，
  避免“直线扑 / 走寻路”每帧来回切。

## 10. 视觉与 UI

- **背景**：纯黑色。
- **声波**：蓝色射线，随传播距离淡出。
- **墙壁记忆**：蓝色高亮格子，由自己与**同阵营队友**的声波共同点亮（见 4.3）。
- **探测闪烁**：橙红色脉动光环 + 十字准星，单次脉冲（快速升起、平滑衰减）。只有自己声波命中别人时才会出现（见 4.3）。
- **道具**：地图上始终可见（不参与可见性过滤），画成带光晕的圆牌 + 类型图标，
  颜色区分类型（👁 金 / ❄ 蓝 / 🔔 粉 / ⚡ 绿），剩余不足 5 秒时外圈闪烁提示。
- **状态效果**：
  - **定格**：角色外圈出现旋转的虚线冰环；
  - **加速**：角色外圈套一圈绿色光环；
  - **被道具显形**：额外套一圈金色脉冲，明确区分“这是被显形出来的”与“近身看到的”。
- **渲染插值**：模拟固定 60Hz，显示可能是 144Hz；角色的显示位置由 `prevX/prevY → x/y` 按 `gstate.renderAlpha` 插值，避免高刷屏上的轻微顿挫。
- **近身视野**：角色默认互相不可见，但有三条例外——
  - 双方距离**小于 3 格**时互相显形（任何组合、不论敌我）；
  - **同阵营的搜捕者之间**不受距离限制，始终能互相看到位置；
  - **队友视野共享**：队友（人或 AI）靠近了某个角色，同队的你也能看到它；
  - 另有**道具显形**（见 7.5）：被显形的角色在持续时间内对本方阵营完全可见。
  显形的角色画成实心圆（搜捕者红、躲藏者绿）并带一圈细描边；看不见的人就完全不画，所以黑暗中的对手仍然只靠声波暴露。
- **共享视野的边界**：共享是**近身触发**的，不是全知——队友自己也得先靠近（3 格内）才能把对方暴露给你；离所有人都远的角色照样谁也看不见。共享的是「被队友看到的那个人」；地形信息走的是另一条规则（队友声波点亮的墙壁轮廓会一并显示给你，见 4.3 与 `SHARE_TEAM_WALL_MEMORY`）。队友之间本身同样遵守 3 格规则（搜捕者阵营除外），不会出现“队友全场可见”。
- **开关**：`SHARE_TEAM_VISION`（`js/core/config.js`，默认 `true`）。设为 `false` 时只有玩家自己靠近才看得见，黑暗的潜行压力会明显更大。
- **实测影响**：8 名躲藏者 + 1 名搜捕者的一局跑完，玩家「有可见角色」的帧占比约 17%。不过躲藏者 AI 会主动远离追捕者（队友与敌人的最近距离通常 ≥ 188px，远大于 72px 的视野半径），所以队友共享多数时候并不触发——它主要在你和队友挤在一起、或队友即将撞上追捕者时才生效。
- **玩家标记**：
  - 玩家 1：亮青色脉动圆环（外层呼吸光环 + 中间填充圆 + 中心白点）。
  - 玩家 2（双人）：紫色脉动圆环。
- **躲藏者被抓提示**：每当有躲藏者被淘汰（含 AI 队友），画面下方偏中位置弹出低透明度横幅，显示「躲藏者被抓捕 · 剩余 N 人」，2.4 秒后淡出。透明度约 0.72，尽量不遮挡对局画面。
- **HUD**（游戏画面上方，不遮挡游戏区域）：
  - **剩余时间**：居中主视觉，字号明显大于其他信息；最后 20 秒变红并开始闪烁，最后 10 秒闪烁更急促、字号进一步放大。
  - 左侧：剩余躲藏者数量、当前身份（双人模式标注 · 双人）、**状态条（下一个道具倒计时 + 自身定格 / 加速 / 显形剩余时间）**、上帝视角角标（玩家全部被抓后显示的观战角标）。
  - 右侧：全屏按钮、退出回放按钮（仅回放时出现）、噪声冷却条，以及**抓捕冷却条（只有搜捕者阵营能看见）**。
  - 三个区块用绝对定位分区：左右两组贴边，时间永远居中，不会被两侧内容挤偏。
- **双人模式的技能冷却条**：画面左下与右下分别显示 P1 / P2 的**全部技能**冷却——
  - 搜捕者：`抓捕`（抓到人后的冷却）+ `噪声`（空格 / Enter）；
  - 躲藏者：`噪声`。
  每个技能一行，带进度条、剩余秒数与「就绪」状态。这样按哪个键都一定有对应的进度条在动；此时 HUD 右侧不再重复显示冷却条。
- **剩余时间提示**：时间跌破 **30 / 20 / 10 秒**时，画面中心**闪出一个纯数字**（`30` / `20` / `10`），半透明、无边框描述文字，0.6～0.8 秒即淡出；最后 10 秒字号更大、颜色更重。每档每局只提示一次。
- **操作提示**：重开需要**连按两次 R**（第一次会提示「再按一次 R 重新开始」），避免和 WASD / 空格的连按混在一起误触。

## 11. 游戏流程

1. **菜单**：选择身份，可切换单人 / 双人模式。
2. **设置**：调整角色数量、地图大小、游戏时长。
3. **开局倒计时**：3 秒倒计时，期间游戏完全冻结，时间不走、角色不动。
4. **正式游戏**：玩家操控角色，AI 自主行动。每 20 秒刷新一个全场可见的道具，碰到即拾取并立即生效（见第 7.5 节）。人类玩家抓到人后会进入 2.5 秒抓捕冷却，AI 搜捕者没有冷却。
5. **有人被抓**：画面出现低透明度提示（剩余人数同步刷新）；若被抓的是玩家，同时弹出明确提示。
6. **玩家出局 → 自动观战**：玩家（单人 1 名 / 双人 2 名）全部被抓的瞬间，立即开启上帝视角继续观战。此时半透明显示完整地图、所有角色位置与全部声波，剩余 AI 继续把对局打完，玩家可以看着队友或对手的最终结局。
7. **暂停**：按 ESC 弹出暂停菜单，可继续、重新开始或返回菜单。
8. **结束**：所有躲藏者被抓或时间耗尽时游戏结束。
   - 进入上帝视角，半透明显示完整地图和所有角色位置。

   - 结算面板显示统计数据，可最小化为按钮以观看最终画面。

## 14. 技术实现要点

- 纯 HTML + CSS + JavaScript（ES Module），使用 Canvas 2D 渲染，无构建步骤、无第三方依赖。
- 地图生成使用随机矩形 + 连通分量标记，确保无闭合区域；随机数走 `core/rng.js`，**同一颗种子 → 同一张地图**。
- **固定步长主循环**：模拟固定 60Hz 推进（`SIM_HZ`），渲染按剩余时间插值（`gstate.renderAlpha` + 实体 `prevX/prevY`）。
  这样帧率变化不影响对局结果、回放能复现、联机同步有统一时间基准。
- 声波射线使用步进检测（每 4 px 采样）与墙壁碰撞，反射使用法线向量计算。
- 角色移动使用 `world/collision.js`：位移拆小步 → 圆 vs 格子的最小平移解算（每轮只解算最深的**一次**接触，避免同面多格产生假推力、也避免对角缝隙穿模）→ 通道口辅助。AI 的可走性 / 视线查询仍然使用严格重叠判定 `circleHitsWall()`。
- AI 寻路：BFS → string pulling 拉直 → 少量路点；`sim/navigation.js` 按路点推进，两级看门狗（0.3s 没动 / 0.6s 没拉近）重规划。
- 声波命中检测在射线步进中实时进行。可见性以 `wave.emitter` 与 `wave.hits[].target` 为判据：己方声波恒可见，敌方声波仅当 `hits` 中包含玩家时可见；闪烁只对「自己打出的那一次」显示。
- 墙壁记忆使用 `emitterId,gx,gy` 作为键值，按发射者区分存储；渲染时按阵营过滤（自己 + 同阵营队友）。
- 时间系统使用 `nowSec()` 统一管理，暂停时冻结所有游戏逻辑。
- 敌我识别统一由 `js/core/teams.js` 承担，声波传播与 AI 反应解耦：传播无差别，反应分阵营。
- 模块间的可变状态统一放在 `gstate`（`js/core/state.js`），地图尺寸等配置通过 ES Module 实时绑定下发。
- **模拟层不碰 DOM**：`sim/` 只发事件（`core/events.js`），UI 在 `ui/flow.js` 订阅。这让同一份模拟能跑在无头测试里（见第 16 章）。
- 无头测试：`tests/` 下有碰撞 / 道具+联机 / 端到端冒烟 / AI 晃动测量四套脚本，Node 直接跑，不需要浏览器。

## 15. 联机（WebSocket）准备

这一版**还没有**真正的多人联机，但把接入服务器所需的骨架都铺好了，并且用回环传输验证过：
`tests/features.mjs` 里房主与客户端跑在同一进程、通过 `LoopbackTransport` 通信，
客户端能收到种子并生成同一张地图、收到快照后位置和房主一致、发指令能让房主移动角色、
还能用房主广播的“发声描述”在本地重建声波（15 → 28 条）。

**权威模型：房主权威（host-authoritative）**，不是锁步。

| 角色 | 做什么 |
|------|--------|
| 房主 `HOST` | 跑权威模拟；吃下所有客户端指令；按 15Hz 广播快照 + 事件 + 发声 |
| 客户端 `GUEST` | 只发自己的指令；接收快照覆盖本地状态；两次快照之间插值渲染 |
| 单机 `OFFLINE` | 直接推进本地模拟（现在的默认） |

**关键设计**

- **输入即指令**：`core/command.js` 的 `PlayerCommand` 是纯数据（`{p, mx, my, run, noise}`），
  本地键盘与网络包走同一条路径；`normalizeCommand()` 会把任何来源的输入夹到合法范围，
  坏包进不了模拟。
- **地图不上网**：房主只发种子 + 配置，客户端用 `prepareWorldFromConfig()` 本地生成同一张地图。
- **声波不上网（射线）**：一次发声只广播一条极短描述（谁 / 在哪 / 多大 / 射线角度偏移 / 射线数），
  客户端用 `rebuildSoundFromEvent()` 在本地重建同样的射线与墙壁记忆。
  客户端重建时**不写 AI 状态**（不写 `heardSound` / 不让 AI 追击），只影响画面。
- **事件即 UI**：被抓、道具刷新 / 拾取 / 生效、对局结束都通过 `core/events.js` 广播，
  客户端把收到的事件重新派发给 UI —— 联机模式的结算与提示条走的还是同一套代码。
- **传输抽象**：`net/transport.js` 定义统一接口，已实现
  `NullTransport`（单机）、`LoopbackTransport`（测试 / 本地房主）、
  `createWebSocketTransport(url)`（自动重连、心跳，等服务器就绪即可用）。
- **协议**：`net/protocol.js` 有版本号与结构校验；字段变化必须 `PROTOCOL_VERSION + 1`，
  两端版本不一致会被拒绝并给出原因。

**接服务器时要做的（下一步）**

1. 写一个转发用的 WebSocket 服务器：房间管理 + 按 `MSG.INPUT` / `MSG.SNAPSHOT` / `MSG.EVENT` 转发。
2. 玩家槽位仲裁：现在房主把远端指令按 `cmd.p` 直接映射到 `gstate.players`，
   多人需要由房主分配槽位并通过 `WELCOME` 下发。
3. 客户端预测 + 回滚（可选）：目前客户端不做预测，操作会有“一个快照周期”的延迟（15Hz ≈ 66ms）。
4. 带宽优化（可选）：快照改成增量、JSON 换二进制。

接入方式（业务代码不用改）：

```js
// main.js 里把这一行换掉即可
const session = createSession({ mode: MODE.OFFLINE });
// → 联机
import { createWebSocketTransport } from './net/transport.js';
const session = createSession({
  mode: MODE.GUEST,
  transport: createWebSocketTransport('wss://your-server/echo'),
  localPlayerIndex: 1
});
```

## 18. 变更记录

### 3.2

**AI 卡墙左右晃：定位与修复**

- 症状：AI 贴着墙来回走小段直线，看起来像左右抖 / 原地打转。
- 用逐帧追踪（记录位置、目标、路点、移动方向、转向锁）定位到三个独立成因：
  1. **每帧重挑朝向**：老实现每帧在「直奔目标」与「走下一个路径节点」之间二选一，
     两者来回抢占，同一个位置上一帧往右、下一帧往左。
     → 改成「重规划时一次拉直路径，之后只认少量路点」，两次重规划之间方向完全稳定。
  2. **目标变了却沿用旧路**：巡逻点 / 追击点换了以后，AI 会先把旧路点走完再掉头。
     → 新增 `setGoal()`：目标移动超过阈值立刻作废旧路径并重规划。
     这一条是主要原因，实测修掉后晃动从 3.4 降到 1.0 次/AI·分钟。
  3. **巡逻点选得太近 / 在身后**：老评分只看“多久没去过”，于是刚到目标就掉头走向身后 1~2 格。
     → 评分加入“偏好 6 格距离、2.5 格以内重罚、身后的点重罚”。
- 顺带把 AI 移动统一到 `sim/movement.steer()`（贴墙滑动 + 反向锁），
  删掉了原来「撞墙就整帧不动、再沿 ±90° 硬蹭」的补丁——那正是贴墙抖动的直接来源。
- 结果（`tests/jitter.mjs`，4~5 局 × 40s）：可见晃动 **2.3 → 0.7 次/AI·分钟**，
  贴墙晃动 **1.5 → 0.4**，**连续 1 秒走不动的卡死事件 0 次**。

**道具系统（新）**

- 每 20 秒随机刷一个道具，全场可见、碰到即拾取；人类与 AI 都会去捡。

### 3.1

**碰撞手感：从“整步撤销”改为“最小平移解算”**

- 症状：贴着墙走会一步都挪不动；斜着蹭墙会顶死在墙角；进 1 格宽的通道时稍微偏一点就卡在门框上，必须松手重新对准方向。
- 成因：旧实现是「逐轴移动，撞到就把该轴位移全部回退」，且判据是严格相交——
  - 与墙面存在哪怕 0.01px 的相交，沿墙方向的位移也会被一起撤销（贴墙走不动）；
  - 斜向移动时 X、Y 两轴同时被撤销，于是完全没有位移（蹭墙卡死）。
- 现在：位移拆成 ≤5px 的小步推进，每步之后只把“陷进墙里的那部分”沿法线推出来。推力只作用于法线方向，切线分量原样保留 —— 贴墙、蹭墙都自然变成滑行。
- 解算每轮只处理**最深的一次**接触（而不是逐格累加推力）：
  - 同一面墙由多格拼成时，累加会产生沿墙面的假推力，角色会莫名其妙侧滑；只解算最深接触后，实测顶住 24 格长的墙 120 帧横向漂移为 **0.0000px**；
  - 对角相邻的两格墙若把两侧推力相加会互相抵消，角色能从零宽缝隙穿模；逐轮解算最深接触后不再发生。
- 通道口辅助：正面顶住门框、且只是浅接触（深度 ≤3.5px）、且沿墙面 8px 内真能脱离接触时，沿墙面朝更近的开口蹭一点点（单帧 ≤1.2px）。于是 1 格宽通道下横向偏 1～5.9px 只按“上”都能自行滑进去（约 36 帧 / 0.6 秒），而顶着大片完整墙面时横向漂移严格为 0（不会变成自动寻路）。
- 回归验证（`world/collision.js` 无头测试）：贴墙平移、斜向蹭墙、通道进入、高速撞单格厚墙不穿透、对角缝隙不穿透、2 万步随机压力测试（结束后不留在墙里、无 NaN）全部通过。

**队友墙壁轮廓共享**

- 墙壁记忆仍然按发射者分开存储，但渲染时改为「自己 + 同阵营队友（含 AI）」可见，新增开关 `SHARE_TEAM_WALL_MEMORY`（默认 `true`）。
- 边界：敌方声波照到的墙依旧不给地形信息；已经出局的躲藏者不再共享。
- 顺带修正：过期墙壁记忆的清理不再只针对玩家自己，队友的残留同样会按时清出 `wallMemoryMap`。
- 主菜单提示同步改为「墙壁轮廓由自己与队友的声波共同点亮」。

### 3.0

**寻路卡住：定位与修复**

- 症状：AI 会顶着墙角原地抖，或者站着不动。
- 复盘出 5 个独立成因，逐个修掉：
  1. **到达节点不推进索引**：角色站在某个节点格心附近时，距离永远不会变成 0，索引卡死。现在会跳过“脚下节点”，并在到达时把坐标吸附到格心。
  2. **挑到了迈不出去的节点**：BFS 绕墙时的第一个节点常是“斜插墙角”的格子，从格心看连线是通的，但角色有半径，朝那个方向迈步会被墙挡住。现在节点选择加了**带半径的迈步检查**。
  3. **斜插节点挡路**：近端节点迈不出去时，改为沿路径往后找第一个能绕过去的节点（允许跳过近端死角，也允许节点在墙的另一侧），于是贴着墙角也能拐出去。
  4. **卡住检测抓不到“抖动”**：原来的判据是“本帧位移 < 固定阈值”，而顶着墙角时角色会小幅来回抖，位移永远不为零。现在加了**进度看门狗**：盯着“到目标的距离”，连续 0.6 秒没拉近就强制重规划。
  5. **脱困侧移方向反了**：沿“目标方向”的垂直方向侧移时，目标在远处另一侧，垂直方向会随位置在正负之间翻转，结果左右抖着不走。现在改为沿**当前路径节点方向**的 ±90° 试探，且只接受真能挪动的那一侧。
- 效果：1533 次寻路压测的楔住率 **2.02% → 0.13%**；真实对局中“本该移动却原地冻结超过 2.5 秒”的事件 **0 次**（与修复前持平，但绕圈/锯齿同时消失）。

**走直线（不再锯齿）**

- 只做节点平滑还不够：BFS 常给出「先横着走完、再竖着走完」的 L 形最短路，节点全在同一条直线上，怎么挑都会拐直角。
- 现在**目标可直达时直接瞄目标**（用带半径的连线检查确认安全），空旷对角「路程 / 直线」= **0.99**。

**追着尸体不放**

- 被追目标被别人抓走后，`spottedTarget` 仍指向它。那个格子已经可通行，`findPath` 返回空数组，AI 就卡在“原地重算”里直到追击超时（实测这种情况能让 AI 站住 2.5 秒以上）。
- 现在目标一死就作废该目标并退出追击，转为搜索/巡逻。

### 2.9

**寻路不再绕圈**

- 原因：BFS 给的是四向格子路径，逐格跟随时角色会一格一格拐弯，走对角时路程约为直线的 1.41 倍，看起来就是锯齿 / 绕圈。
- 修正：新增 Bresenham 视线检查 + 路径平滑，直接瞄准「能直线到达的最远节点」，只在需要绕墙时才贴格子转弯。空旷对角路线的「路程 / 直线」从 1.41 降到 **1.02**，大幅掉头 0 次。
- 卡住检测改为按“本帧实际位移 < 应有位移的 25%”判断（原来的固定 0.25px 阈值在高速移动时几乎永不触发，导致卡住后不重规划）。

**抓捕硬直**

- 原因：原来的「抓捕冷却」只禁止再抓，不禁移动，所以抓到人后看起来只停了半秒（其实是 2.5 秒内不能抓第二个人，但人一直在走）。
- 修正：抓到人后搜捕者**原地冻结 2.5 秒**（`CATCH_COOLDOWN`），期间不移动、不能抓人，硬直结束才恢复。已用可控时钟精确验证：2.4 秒仍冻结、2.5 秒后恢复。

**碰面触发追击与逃跑**

- 原因：近距离互相显形只是渲染效果——玩家看得见搜捕者，但 AI 仍然“瞎着”，会擦肩而过或在旁边发呆。
- 修正：把「互相显形」接进 AI 决策——搜捕者看见躲藏者立刻转入追击，躲藏者看见搜捕者立刻转入逃跑。双方用的是同一条双向判定，不会出现单方面看见。
- 由 `PROXIMITY_DETECT` 控制（默认开启），关闭后 AI 只依赖声波。

### 2.8

**队友视野共享：AI 队友也算数**

- 上一版只让「人类队友」参与共享，导致 AI 队友靠近敌人时玩家仍然什么都看不到。现在**同阵营的全部在场角色**（人 + AI）都参与共享：队友靠近某个角色，玩家就能看到那个角色。
- 同时修正了一个连带问题：上一版把「同队角色」写成了永远可见，等于全场透视（实测每帧都看得到所有队友）。现在队友之间同样遵守 3 格近身规则（搜捕者阵营仍是原有的远距离互见），共享才是真正的“近身触发”。
- 出局的队友不再提供视野，也不会显形。
- 新增 `SHARE_TEAM_VISION` 开关，想恢复“只能靠自己靠近”的硬核潜行把它设为 `false`。
- 实测：8 躲藏者 + 1 搜捕者的一局里，玩家有可见角色的帧占比约 17%；共享触发较少，因为躲藏者 AI 会主动远离追捕者。

### 2.7

**同队玩家共享视野**

- 双人模式下两名玩家共享情报：队友看得见的角色你也看得见，反之亦然；两人之间永远互相可见。
- 只共享「被队友看到的那个人」，不共享地形；不会借队友的眼睛获得额外信息。
- 参与共享的仅限本局玩家，AI 队友仍按 3 格近身判定，避免 1 人对抗被 AI 送情报。

**探测闪烁只显示自己打出的那一次**

- 之前别人扫到自己 / 队友被扫到 / 队友命中敌人都会在画面上闪，干扰判断。现在只保留「自己声波命中敌人」这一种；上帝视角（结算 / 回放）仍保留全部闪烁。

**倒计时提示改为纯数字**

- 画面中心的提示从「剩余 30 秒」改为只显示 `30` / `20` / `10`，字号显著放大、去掉边框与描述文字，停留时间从 1.2～1.5 秒缩短到 0.6～0.8 秒。

**结算页面以结果为主**

- 面板顶部改为结果主视觉：大号胜负标题（带胜负配色）+ 一句说明「怎么赢的」，不再用「时间到」这种只描述过程的说法。
- 新增比分板（被抓 / 存活的大号数字）与个人高光数字（抓捕数、探测数、噪声数），明细表格下沉到下方。

### 2.6

**结算：每位玩家的抓捕数量**

- 新增 `playerCatchCounts`：谁把人抓到的就记在谁头上，AI 搜捕者得手不计入玩家。
- 搜捕者身份的结算面板新增一行：单人显示「你的抓捕数量」，双人分别显示「玩家1 抓捕数量 / 玩家2 抓捕数量」。

**不再显示打在自己身上的定位闪烁**

- 原来别人扫到自己时，接触点会在自己身上闪一圈脉冲，近身混战时容易糊住自己的角色标记。
- 现在改为**只在自己声波命中别人时闪**；被扫到时你仍然能看到探过来的那道声波，只是不在自己身上叠加光效。
- 由 `SHOW_INCOMING_FLASH`（`js/core/config.js`，默认 `false`）控制，改成 `true` 即恢复双向闪烁。

### 2.5

**技能冷却条：列出全部技能**

- 之前每条只显示一个技能（搜捕者只显示「抓捕」），所以双人搜捕者按空格时看不到任何变化。现在每条列出该玩家的**全部**技能：搜捕者 = 抓捕 + 噪声，躲藏者 = 噪声，按哪个键都有对应的进度条在动。
- 顺带移除了技能条的写值缓存，改为状态变化时重建整块 DOM（只有两个小条，开销可忽略）。显示值与状态永远一致，不再有“缓存不同步导致进度条不动”的可能。

**空格不再误触发按钮**

- 空格会让「当前获得焦点的按钮」被浏览器当作点击激活；点过全屏 / 暂停菜单按钮后焦点会留在那里，于是对局中按空格式噪声就可能顺带触发那个按钮（表现为“有一定概率重新开始”）。
- 修复：在**捕获阶段**拦截空格 / 回车的默认行为（`preventDefault` 对空格只在捕获阶段生效），并在点击后让按钮主动失焦，双保险。

**重开改为连按两次 R**

- 单次 R 现在只会提示「再按一次 R 重新开始」，1 秒内再按一次才真正重开；ESC 会打断这个确认。避免与 WASD / 空格的连按混淆。

**剩余时间居中提示**

- 时间跌破 30 / 20 / 10 秒时，画面中心弹出一次半透明大字（`剩余 30 秒`），每档每局一次，重开一局后重置。与 HUD 时间的红色闪烁、被淘汰提示互不冲突。

### 2.4

**近身视野**

- 新增 `js/render/vision.js`：角色默认互相不可见，但**双方距离小于 3 格**时互相显形（任何组合、不论敌我），**搜捕者之间**则不受距离限制始终互相可见。
- 视野是双向的：a 看得见 b ⇔ b 看得见 a。看不见的角色完全不会被画出来，黑暗中的对手依旧只能靠声波暴露。
- 出局的躲藏者不会因为靠近而显形。

**被抓提示**

- 任何躲藏者（含 AI 队友）被淘汰时，画面下方弹出低透明度横幅：「躲藏者被抓捕 · 剩余 N 人」，2.4 秒后淡出。
- 玩家自己被抓时，原有的明确提示（`toast`）保留不变。

**搜捕者抓捕冷却**

- 新增 `CATCH_COOLDOWN`（默认 2.5 秒）：搜捕者抓到人后进入冷却，冷却期间无法再抓下一个人，避免一次冲撞清空一片躲藏者。
- 冷却进度条只在**搜捕者阵营**的 HUD 上显示。

**双人技能冷却条**

- 双人模式下，画面左下与右下分别显示 P1 / P2 的技能冷却（搜捕者为「抓捕」、躲藏者为「噪声」），带进度条、剩余秒数与「就绪」状态；此时 HUD 右侧不再重复显示。

**顺带修正**

- 修复躲藏者 AI 在「搜捕者贴脸但威胁区为空」时访问空对象导致的崩溃（`js/ai/hider.js`）。这个隐患在单文件版本里就存在，只是正常对局中很难触发（需要搜捕者未发出任何声音就贴到身边）。

### 2.3

**声波可见性**
