## 第三轮迭代（v1.2.0）

### 需求确认结果
- 连击：按对累加，**按错或超过 1.5 秒未按键就断连**
- 结算排行：**按按键平均值 Top5 + 单次极端记录，两者都要**
- 主页面 / 配置阶段的按键：**只高亮，不拦截浏览器默认行为**
- 预览自适应：**自动缩放，键帽下限 12px**，再窄则由容器横向滚动

### 键宽公式统一（重要重构）
原来 TKL 的 F 键区占位用的是 CSS 表达式 `calc((var(--u)*2 - var(--gap))/3)`，无法参与数值估算。改成把占位也表达为「键宽单位」：
- `sp(2/3)`，渲染时和普通键共用 `calc(var(--u) * w + var(--gap) * (w - 1))`
- 数学上 `u*(2/3) + g*(-1/3) = (2u - g)/3`，与原式**完全等价**（已用脚本验证 356.0000 == 356.0000）
- 副产物：`layouts.js` 新增 `estimateWidth(rows, unit, gap, extra)`，宽度对 unit 线性，`K = estimateWidth(rows, 1, 0.2, 0)` 即缩放系数
- `keyboard.js` 里 `num()` 负责把 2/3 这类小数格式化成 4 位，整数直接输出，保持 calc 简短

### 预览自适应
`js/ui/preview.js`：解一次方程 `unit = (可用宽 - 外框) / K`，夹在 [12, 20]；gap = unit*0.2（下限 2px）。用 `ResizeObserver` 监听 `.preview-box`，因此从隐藏（play 阶段）切回显示时会自动重算。**注意 `.preview-box` 横向 padding 为 0，clientWidth 可直接当可用宽度**

### 连击反馈
`js/ui/combo.js`：`createCombo(board)` 在键盘根元素内插入 `.combo-badge`（绝对定位，**bottom 8px 居中，避开字母/数字键区域**，因为挑战出题只用这些键）。命中时：combo+1 → 徽标 pop 动画 + `board.classList.add('is-hitting')` 触发 `boardShake`；combo ≥10 加 `is-hot`（琥珀）、≥20 加 `is-blaze`（红）。1.5s 定时器断连。建议所有动画在 `prefers-reduced-motion` 下关闭

### 结算排行
- `core/stats.js` 新增 `keyRanking(records, top)` → `{keys, fastest, slowest, quickest, slowestHits}` 与 `barRows(list, format)`（组内归一化柱长 + 格式化文本）
- `ui/result.js` 的 section 支持 `tone: 'fast' | 'slow'`，CSS 里 `.result-rows.is-fast/.is-slow` 分别绿/红柱
- 单按键与连续挑战都输出 4 个排行：最快按键 Top5、最慢按键 Top5、单次最快 N 次、单次最慢 N 次
- 单按键的 `times: number[]` 改成 `records: {code,label,ms}[]`；连续挑战从相邻 splits 差值构造 records（首键只作计时起点）

### 其它
- 高亮扩展到主页面 hero 键盘与配置阶段预览键盘（`utils/dom.js` 新增 `isEditable(node)` 判焦点）
- 录制列表行改为 `.rec-item` + `.rec-cap`（键帽图标左浮动，`overflow: hidden` 形成 BFC 包住浮动）
- 版本号统一到 1.2.0（package.json / index.html / about.html）

## 第四轮微调

- **序列条无滚动条**：`.seq-strip` 加 `scrollbar-width: none` + `::-webkit-scrollbar { display: none }`，保持单排横向可滚但不显示滚动条外观
- **预览放大**：`.setup-view` 两栏比例 1.3:1 → **1:1**，`.app--test` 上限 1060 → **1140px**，`preview.js` 的 `MAX_UNIT` 20 → **28**
  - 实测效果：预览可用宽度 406 → 512px，键帽 20px → **约 27.6px**（+38%）
- **背景全量键帽**：`bgKeys.js` 的 `LABELS` 改为 `KEYCAPS`（布局里全部非占位键，61 个），键帽数固定不再按面积取数量；尺寸改为 `clamp(sqrt(视口面积 * 8% / (键数 * 0.9)), 18, 48)`，保证各视口覆盖率恒为 8%
  - resize 时只重算尺寸并把键帽夹回视口内，不重置运动轨迹
  - 注意：`Shift / Alt / Win / Ctrl` 各有左右两个，因此背景里会有重名键帽，这是与物理键一一对应的预期结果
  - 校验：1920×1080 → 48px(封顶)、1440×900 → 43.5px、1024×768 → 33.9px、420×780 → 21.8px、320×480 → 18px(封底)
