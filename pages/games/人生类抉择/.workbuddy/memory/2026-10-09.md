# 2026-10-09

## 人生模拟小游戏：单文件 → 多目录工程重构

把 1100 行的 `人生类抉择.html`（已删除）拆成规范工程：

- `index.html` 只留 DOM 骨架；样式拆到 `src/styles/`（base/layout/components/views/responsive 五层，媒体查询集中在 responsive.css）
- JS 分三层：`core/`（config, rng, state, storage, rules, engine）纯逻辑不碰 DOM；`data/`（meters, traits, aspirations, endings, portraits, events）纯数据；`ui/`（dom, icons, audio, toast, statusBar, card, drawers, views, ending）
- `core/engine.js` 是唯一对外出口，UI 只从它 import
- 采用原生 ES Modules，无构建、无第三方依赖；`file://` 打不开，index.html 里留了传统脚本检测协议并展示引导页
- `tools/serve.mjs` 零依赖静态服务器（`npm run dev`，端口 5173）；`tools/check.mjs` 逻辑自检（`npm run check`）
- 新增可控随机 `core/rng.js`：`?seed=123` 可固定整局，mulberry32；调试入口 `#game` / `#end` / `#end2`，控制台 `window.__LIFE`
- 文档：`README.md`（游戏介绍）+ `docs/` 七篇（架构、目录、数据模型、规则数值、事件编写规范、开发调试、扩展路线）

自检结果：78 条事件合法；一路左滑 25 岁「油尽灯枯」；求生策略 80 岁「圆满人生」446 分；相同种子可复现。

## 约定

- 加事件 → `data/events.js` 按年龄分组追加，id 用 e+序号，先读 docs/05
- 三条硬约束：core 不碰 DOM、ui 不写规则、UI 只从 engine.js import

## 第二轮：剧本 JSON 化 + 去图片

按用户要求做了数据层彻底外置：

- 新增 `data/` 作为独立剧本目录：`manifest.json` + `init/`（meters/config/traits/aspirations/endings）+ `choices/`（9 个按人生阶段划分的事件文件，78 条）
- 启动流程改为异步：`main.js` 先 `await loadAll({base:DATA_BASE})`，再 `boot()`。剧本没加载完进游戏会抛错（app.boot 断言 db.ready）
- 浏览器无法列目录，所以用 manifest 登记文件；加新剧本文件只改 manifest，不改代码
- 删除 `src/js/data/` 全部静态模块；新增 `core/registry.js`（运行时数据库 db + 派生索引 + install 校验）与 `core/loader.js`（fetch 合并）
- 支持注入 `read` 实现，`tools/check.mjs` 用 fs 复用同一套 loader，浏览器与 Node 走相同加载/校验路径
- 心愿 `check(S)` 函数改为声明式条件数组；事件 cond 从扁平 `{rel:'love',relVal:35}` 改为嵌套 `{rel:{id:'love',min:35}}`，并支持 cond 为数组（多项 AND）；新增 `age:{min,max}`
- `core/config.js` 只留代码常量（RULESET_ID 升到 v2、SAVE_KEY、SAVE_VERSION=2、CARD_FLY_MS、DATA_BASE），所有可调数值进 `data/init/config.json`
- 去掉全部外部图片：删除 portraits.js、卡面 `<img>`，改为纯 CSS 卡头（`.cardhead` + 内联 SVG 人像）。项目现在离线可玩
- 文档：新增 docs/05-剧本文件编写规范.md 取代旧的事件库规范，01/02/03/04/06/07 全部同步

自检结果不变（证明逻辑无损）：一路左滑 25 岁「油尽灯枯」，求生策略 80 岁「圆满人生」446 分，seed=777 可复现；新增剧本加载、无外部链接、cond 键合法性、心愿判定四项检查。

## 约定（更新）

- 新剧本文件必须在 `data/manifest.json` 登记

- 特质数值效果写死在 `rules.js#applyTrait()`，JSON 里只有展示文案——加特质要两边都改

## 第三轮：UI 体验改造 + 剧本扩到 193 条

### UI

- **临时结果横幅 → 常驻旁白条**：`.resultbar`（出现 1.8s 后消失，会把卡片顶上顶下）改为 `.narrate`，`min-height` 固定 + chips 行占位，高度恒定。开局播报「你出生了」，选择后播报「你选择了 X」+ 变化 chips，其余时刻按优先级播报：危险告警 > 新里程碑 > 属性偏低提醒 > 阶段氛围句
- **属性条重做**：抽出通用 `.pbar`（13px 高、内阴影 + 顶部高光渐变），游戏页与人生档案（技能/羁绊）共用 `barHTML()`；阈值刻度由 `tuning` 写入 CSS 变量 `--warn-low/--warn-high/--danger-low/--danger-high`，用 `.pbar.ticked::after` 的多层 linear-gradient 画警戒线。危险态描边脉冲 + 「危」徽标，警告态琥珀描边
- **三档响应式**：`<720` 单栏卡片贴底（hintrow 移到卡片上方）；`720-1023` 属性 6 列 + 卡片与侧栏并排；`≥1024` 容器 1080px、字号卡片放大、hover 高亮；`≥1440` 限 1180px；额外处理 `max-height:620px` 手机横屏
- **滑动浮窗 peek**：`.peek.left/.right` 浮出选项文本，JS 按 `|dx|/swipeThreshold` 算 `opacity = 0.15+0.85t` 与 `scale = 0.9+0.12t`；`t>=1` 加 `.hot` 整块反色高亮 + 显示「松手即选」。按钮 pointerenter 与键盘按住方向键会预览（0.62 强度）；键盘改为 keyup 触发
