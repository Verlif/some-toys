## 内容 vs 代码：怎么判断放哪

**放进 `data/`（JSON）**——只要满足任一条件：

- 策划/文案同学可能会改的（事件文案、结局文案、特质描述）
- 需要经常调参的（初始数值、tuning、评分档位）
- 可能需要增删条目的（事件、特质、心愿）

**留在 `src/`（JS）**——只有：

- 写代码必需的常量（存档键名、动画时长、数据目录）
- 逻辑本身（结算顺序、条件求值、特质系数算法）
- 渲染代码

## 放置约定

**新增样式放哪？**

| 你要写的样式 | 放到 |
| --- | --- |
| 新的颜色 / 圆角 / 阴影 | `base.css` 的 `:root` 里加变量 |
| 新的页面区块骨架 | `layout.css` |
| 可复用的控件（按钮、卡片、弹层） | `components.css` |
| 某个视图独有的样式 | `views.css` |
| 任何 `@media` | `responsive.css`（集中管理，别散在各文件） |

**新增代码放哪？**

| 你要写的代码 | 放到 |
| --- | --- |
| 新的事件 / 特质 / 心愿 / 结局 / 数值 | `data/` 对应 JSON，并在 manifest 登记（已存在的文件不用登记） |
| 新的条件类型 | `core/rules.js` 的 `groupPass()` + `core/loader` 无需改 |
| 新的结算规则 | `core/rules.js` |
| 新的渲染逻辑 | `ui/` 新建或扩展模块 |
| 新的流程编排 | `app.js` |

## 命名约定

| 类型 | 风格 | 例子 |
| --- | --- | --- |
| JSON 文件名 | 小写、按内容语义 | `meters.json`、`childhood.json` |
| JSON 顶层键 | camelCase，与 registry 字段名一致 | `meters`、`aspirations`、`flagLabels` |
| 事件 id | 前缀 + 序号 | `e1`、`ch_a1`、`pt_4`、`fm_13` |
| 数据 id（属性/技能/羁绊/特质/心愿） | 小写英文单词 | `health`、`knowledge`、`optimist` |
| JS 函数 | camelCase，动词开头 | `pickEvent`、`renderCard`、`showDeltas` |
| DOM id | kebab-case | `view-start`、`endBadge` |
| CSS 类 | kebab-case | `.aspcard`、`.narrate`、`.peek` |
| CSS 变量 | `--` + 类别前缀 | `--c-green`、`--r-lg`、`--sh-card` |

## index.html 的原则

- 只放 **DOM 结构**，不放 `<style>`、不放 `<script>` 逻辑
- 每个交互元素都要有稳定 id，UI 层通过 `$('id')` 取
- 保留一个传统（非 module）的内联脚本，用于 `file://` 场景给出提示——它是唯一允许留在 HTML 里的脚本
