# 01 · 架构总览

## 分层

```
┌────────────────────────────────────────────────────────┐
│  data/           剧本：全部游戏内容，纯 JSON              │
│  manifest.json  init/*  choices/*                       │
└────────────────────────────────────────────────────────┘
                     │  fetch（启动时）
┌────────────────────────────────────────────────────────┐
│  src/js/core/loader.js    读 manifest → 合并 → install   │
│  src/js/core/registry.js  运行时数据库 db + 派生索引      │
└────────────────────────────────────────────────────────┘
                     │
┌────────────────────────────────────────────────────────┐
│  src/js/main.js   入口：await loadAll() → boot()         │
│  src/js/app.js    控制器：持有状态、编排流程              │
└────────────────────────────────────────────────────────┘
          │                        │
          ▼                        ▼
┌──────────────────┐    ┌──────────────────────────────┐
│  ui/   渲染与交互  │    │  core/  纯业务逻辑             │
│  · dom/icons     │    │  · registry  运行时数据库      │
│  · statusBar 属性│    │  · loader    JSON 加载        │
│    条 / 旁白条  │    │  · config    代码常量          │
│  · card 卡面 +  │    │  · rng       随机数            │
│    滑动浮窗     │    │  · state     状态构造          │
│  · drawers       │    │  · rng       随机数            │
│  · views/ending  │    │  · state     状态构造          │
│  · audio/toast   │    │  · storage   存档             │
│                  │    │  · rules     结算             │
│                  │    │  · engine    统一出口          │
└──────────────────┘    └──────────────────────────────┘
```

## 依赖方向（单向，禁止反向）

```
main → app → { ui, core/engine } → core/* → registry(db)
```

- `ui/*` 只允许 import `core/engine.js`（以及 `ui/dom.js`、`ui/icons.js`）
- `core/*` 内部互相引用；`rules.js` / `state.js` 只读 `registry`，不 import `storage.js`（保持无副作用）
- `registry.js` 不 import 任何业务模块，是依赖图的叶子节点之一

## 启动时序（剧本必须先于一切）

```
浏览器加载 index.html
        │
        ▼
main.js  start()
        ├─ await loadAll({ base: 'data/' })
        │     ├─ fetch('data/manifest.json')
        │     ├─ Promise.all 拉取 manifest.init    → 合并成 meters/stages/skills/
        │     │                                       relations/traits/aspirations/
        │     │                                       endings/config
        │     ├─ Promise.all 拉取 manifest.choices  → 拼成 events[]（每项带 _src）
        │     └─ install()  →  算派生索引 → validate() → db.ready = true
        │
        │     ✗ 失败 → 在页面上显示错误详情（不进游戏）
        │
        ├─ boot()          app.js 绑定事件、渲染开始页
        ├─ handleQuery()   解析 ?seed=
        └─ handleHash()    解析 #game / #end / #end2
```

`boot()` 第一行会断言 `db.ready`，没加载就抛错——避免带着空数据库进游戏产生一堆莫名其妙的 `undefined`。

## 一次抉择的调用时序

```
用户左滑 / 点击 / 按 ←
        │
        ▼
app.js  resolve('left')
        ├─ 校验 isPlaying()              动画中或已结束则忽略
        ├─ choose(S, cur, 'left')        ← core/rules.js：结算 + 判定生死
        │     ├─ applyTrait()            特质修正六项增量
        │     ├─ 写 skills / rel / flags / milestones
        │     ├─ 遍历六项属性，找出第一个越界的作为死因
        │     ├─ S.log.push()            写入履历
        │     └─ 未死则 age++、心情衰减、检查心愿、检查胜利
        ├─ saveGame(S)                   存档
        ├─ audio.swipe() / narrateChoice() / flyOut()
        │                    ↑ 常驻旁白条播报「你选择了 X」+ 各项变化
        │
        └─ setTimeout(CARD_FLY_MS)      等卡牌飞出动画结束
              ├─ renderProgress()        重绘顶栏 / 属性条 / 侧栏
              ├─ showDeltas()            弹出 +N / -N 气泡
              ├─ reportMilestones()      新增大事记 → 旁白条 + toast
              └─ S.ended ? 延迟 720ms 展示结局 : 抽下一张卡 + narrateIdle()
```

## 为什么用「运行时数据库」而不是静态常量

数据从 JSON 来，模块顶层拿不到。可选方案：

| 方案 | 问题 |
| --- | --- |
| `import data from './data.json' with { type:'json' }` | import assertions 浏览器支持度不足，且路径要写死，加文件要改代码 |
| 构建期把 JSON 内联进 JS | 引入构建步骤，违背「无构建」定位 |
| **运行时 install 到单例 db**（本项目） | 唯一代价是必须等 `loadAll()`；换来「加文件只改 manifest」 |

单例 db 的另一个好处：`npm run check` 可以把同一个 loader 接到 `fs` 上复用，浏览器和 Node 走完全相同的加载与校验路径。

## 关键设计决策

**1. manifest 而不是遍历目录**
浏览器没有列目录的能力。manifest 是唯一可行方案，顺带成了「剧本结构说明书」。

**2. `install()` 里做兜底校验**
重复 id、缺选项、缺结局文案，全部在加载阶段抛错。宁可白屏报错，也不要带着坏数据玩到一半崩。

**3. 状态对象就地修改，而不是不可变更新**
`choose()` 直接改传入的 `S`。人生模拟是线性推进的单状态机，不需要时间旅行或 undo，返回新对象只会增加 GC 压力和心智负担。

**4. `choose()` 结束时仍然返回结果**
即使 `S.ended` 为真也返回本次结果，让 UI 能先把「卡牌飞出 + 属性变化」播完，再展示结局页。

**5. 随机数可注入**
`rng.js` 默认 `Math.random`，`setSeed(n)` 后切到 mulberry32 伪随机序列。写测试和复现 bug 时能锁定整局。

**6. 零外部图片**
卡面头部是纯 CSS 渐变 + 内联 SVG 人物标识。不依赖 CDN，离线可玩，也省掉了图片加载失败导致的布局塌陷。

**7. 旁白条常驻，而不是用完即隐**
选择结果原来是一条「出现 1.8 秒就消失」的横幅，它会把下方卡片顶上顶下。改成常驻区域后高度固定（含 chips 行的 `min-height`），开局播报出生、选择后播报结果与变化、其余时刻播报里程碑 / 危险告警 / 阶段状态——常驻条从此有了信息量，而不是只在抉择后闪一下。

**8. 进度条的阈值刻度由数据驱动**
`tuning.warnLow/warnHigh/dangerLow/dangerHigh` 在渲染时写成 CSS 变量（`--warn-low` 等），刻度线用 `.pbar.ticked::after` 的多层 `linear-gradient` 画出来。改 JSON 里的阈值，刻度位置跟着变，不需要动 CSS。

**9. 组合卡牌靠 flag，而不是硬编码顺序**
`cond.flag` / `cond.noFlag` + 选项的 `flags` 就足以表达「养了狗才有狗的卡」。不做强制剧情队列，是为了保持实现简单；代价是链内顺序随机，见 07 的「事件权重与强制剧情链」。
