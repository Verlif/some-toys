# 07 · 扩展路线图

按「投入产出比」排序。前三项是一两个小时能搞定的，后面的需要更多设计。

> **已经做完的**（曾在这份清单里，现已落地）：剧本 JSON 化与多文件拆分 · 去除外部立绘 · 晚年事件补充 · 组合卡牌链（宠物 / 家庭 / 事业 / 生活支线）· 常驻旁白条 · 滑动浮窗 · 手机 / 平板 / PC 三档响应式 · 底部标签栏与底部上浮浮窗 · 事件扩容到 618 条并保证单局不重复。

## 短期（低成本高收益）

### 1. 自研确认弹窗替换 `confirm()`

**现状**：`app.js` 里「重新开始」用的是浏览器原生 `confirm()`，样式与游戏风格割裂，且在部分环境被禁用。

**做法**：
- 在 `ui/` 增加 `dialog.js`，提供 `confirm({title, text, onOk})`
- DOM 结构复用 `views.css` 里已有的 `.overlay` + `.panel`
- `app.js` 里替换掉 `confirm()` 调用

这是从旧项目沿袭下来的约定（ConfirmWindow / FloatingWindow 替换系统弹窗），值得落地。

### 2. 卡面人物区分

**现状**：去掉外部立绘后，所有卡片的头部都是同一个通用人物图标，缺一点辨识度。

**做法（都在纯 CSS/SVG 范围内，不引入图片）**：
- 在 `choices/*.json` 的事件里加一个 `icon` 字段（取值来自 `ui/icons.js`）
- `card.js` 渲染时按 `icon` 取对应 SVG，没有则回退到 `people`
- 或者按 `name` 做确定性哈希，从一组 SVG 里选一个并配上不同颜色

推荐前者：可控，且不需要改代码就能调整。

### 3. 结局页分享图

**现状**：结局页信息很全（评分 + 时间轴 + 六维终值），但只能对着截图。

**做法**：用 `<canvas>` 把结局页画成一张竖版图，提供「保存图片」按钮。
纯前端实现，不需要服务端。

## 中期（需要一点架构调整）

### 4. 成就系统

在 `data/init/` 加 `achievements.json`（结构类似 `aspirations.json`，含声明式 `check`），
在 `choose()` 末尾统一检查。与心愿的区别：

| | 心愿 | 成就 |
| --- | --- | --- |
| 数量 | 开局四选一 | 全局隐藏，可解锁多个 |
| 达成奖励 | +5 心情 | 无数值奖励，只记录 |
| 展示 | 侧栏常驻 | 结算页列表 |

因为 `check` 已经是声明式条件，这一项**纯加 JSON + 少量 UI 代码**即可，不用改规则层。

### 5. 事件权重与强制剧情链

**现状**：`pickEvent` 只做「随机取一张」；组合卡牌靠 flag 自然解锁（养了狗才会遇到狗的卡），但顺序仍不受控。

**改进方向**：
- 给事件加 `weight` 字段，重要事件权重更高（需要改 `pickEvent` 的取样逻辑）
- 加 `chain` 字段：选择某选项后强制下一张是指定事件（比如「创业成功 → 融资」）
- 链式剧情需要在 `state.js` 增加 `S.pending` 队列，`pickEvent` 优先消费

### 6. 存档槽位

**现状**：只有一个存档键，「继续上次的人生」会覆盖。

**改进**：`SAVE_KEY` 改为 `rl-life-{RULESET_ID}-{slot}`，开始页提供三个槽位。
`storage.js` 需要增加 `listSaves()` / `saveTo(slot)` / `loadFrom(slot)`。

## 长期（重设计）

### 7. 属性之间的耦合

现在六项属性互相独立。可以加入联动，让「平衡」这件事更难也更真实：

- 事业高 → 每回合额外扣精力
- 金钱低 → 每回合额外扣心情
- 健康低 → 事业增长打折

实现位置：`choose()` 第 12 步附近，加一个 `applyCoupling(S)` 函数；耦合系数写在 `data/init/config.json` 的 `tuning` 里（比如 `tuning.coupling`），保持「数值进 JSON」的约定。

⚠️ 这会显著改变平衡性，改完必须重跑 `npm run check` 并手动试玩调参。

### 8. 剧本热重载

现在改 JSON 要手动刷新。可以在 `serve.mjs` 里加一个 SSE 端点监听 `data/` 变化，
前端收到通知后重新 `loadAll()` 并保留当前局状态。

调数值时会非常爽：改 JSON → 浏览器自动重载剧本 → 立刻看到效果。

### 9. 单元测试框架

现在 `tools/check.mjs` 是手写断言。事件和规则变多后，可以换成 `node:test`（Node 内置，零依赖）：

```js
import { test } from 'node:test';
import assert from 'node:assert';
import { loadAll, db, choose, newGame } from '../src/js/core/engine.js';

await loadAll({ base: BASE, read });

test('属性归零触发 low 结局', () => { ... });
```

## 明确不做的事

| 想法 | 为什么不做 |
| --- | --- |
| 引入 React / Vue | 20 个模块的体量，框架带来的复杂度大于收益 |
| 加打包器 | 原生 ESM 已经够用，加了就要配构建、热更新、产物路径 |
| 多人 / 排行榜 | 需要服务端，与「纯静态、无依赖」的定位冲突 |
| 商业化 / 内购 | 这是个玩具项目，保持它好玩就够了 |
