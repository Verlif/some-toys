# 03 · 核心数据模型

数据分两类，务必分清：

| | 剧本数据 | 运行时状态 |
| --- | --- | --- |
| 存放位置 | `data/*.json` | 内存里的 `S` 对象（+ localStorage 存档） |
| 谁写 | 开发者/策划直接编辑 JSON | 引擎在 `choose()` 里修改 |
| 一局内会变吗 | 不会 | 会 |
| 跨局共享吗 | 是（所有局共用同一份剧本） | 否 |

本篇讲的是后者 `S`；剧本 JSON 的字段见 [05-剧本文件编写规范.md](./05-剧本文件编写规范.md)。

## 状态对象 `S`

一局游戏的全部数据。由 `core/state.js#newGame()` 创建（初始值取自 `db.config.initial`），被 `core/rules.js#choose()` 就地修改。

```js
{
  age: 6,                     // 当前年龄，从 6 岁起步
  turn: 0,                    // 已做抉择次数

  // ── 六项属性：0~100，任意一项触 0 或 100 即结束游戏 ──
  stats: {
    health: 60, mood: 60, money: 55,
    energy: 60, social: 55, career: 40
  },

  // ── 五项技能：0~100，只增不减，作为事件触发门槛 ──
  skills: { knowledge: 20, cooking: 10, fitness: 20, charm: 15, craft: 10 },

  // ── 三段羁绊：0~100，双向变化 ──
  rel: { family: 60, friends: 50, love: 0 },

  traits: ['optimist', 'thrifty'],   // 本局抽到的特质 id（随机 2 项）
  aspiration: 'rich',                // 心愿 id，null 表示随心而活

  // ── 人生标记：事件链的状态位（键名来自 data/init/config.json 的 flags） ──
  flags: {
    metLove: false,   // 有过心动   → 解锁求婚事件 e33
    married: false,   // 已婚       → 解锁婚礼/生子/金婚等
    hasChild: false,  // 有孩子     → 解锁育儿、空巢、孙辈事件
    house: false,     // 有房子     → 解锁装修事件 e78
    pet: false,       // 养过宠物
    degree: false,    // 有正经工作
    peaked: false,    // 事业巅峰（事业 ≥60 自动置位）
    retired: false,   // 已退休（年龄 ≥60 自动置位）
    biz: false        // 在创业     → 解锁融资事件 e77
  },

  milestones: [{ age: 6, text: '入学 · 人生第一章' }],  // 大事记，结局时间轴的数据源

  log: [],            // 抉择履历：{age, id, name, side, text, died}
  used: {},           // once 事件的消耗记录：{ e24: true }
  lastId: null,       // 上一条事件 id，用于避免连续出现同一张卡
  aspirationDone: false,

  ended: null,        // 结局文案对象 {t, d}，未结束时为 null
  endDetail: null     // {kind:'win'} 或 {meter, kind:'low'|'high', ev, side}
}
```

### 各字段的边界

| 字段 | 下界 | 上界 | 越界处理 |
| --- | --- | --- | --- |
| `stats.*` | 0 | 100 | `clamp()` 夹紧；但**先判定生死再夹紧** |
| `skills.*` | — | 100 | `Math.min(100, ...)`，允许加到 100 就停 |
| `rel.*` | 0 | 100 | `clamp()` |
| `age` | 6 | 80 | 达到 80 触发胜利结局 |

### 生死判定的关键细节

```js
let broken = null;
for (const m of M_IDS) {
  const nv = S.stats[m] + deltas[m];
  if (nv <= 0 || nv >= 100) broken = broken || { meter: m, low: nv <= 0 };
  S.stats[m] = clamp(nv);
}
```

注意两点：

1. **用「加完之后的值」判定，不是夹紧之后的值**。所以 `health=95` 时吃一个 `+8`，会判定为 `high` 结局，而不是被夹到 100 后继续活着。
2. **`broken = broken || {...}`**：如果同一次抉择里有多项越界，**只取六维顺序中最靠前的一项**作为死因。顺序见 `data/init/meters.json` 的 `meters` 数组（health → mood → money → energy → social → career）。

## 事件对象 `Event`

来自 `data/choices/*.json`，加载后被塞进 `db.events`（每项额外带一个 `_src` 字段标明来源文件）。

```js
{
  id: 'e33',                          // 全局唯一
  name: '求婚',                        // 说话人，显示在卡头
  min: 22, max: 49,                   // 可出现年龄区间（闭区间）
  once: true,                         // 可选：一生只触发一次
  cond: { flag:'metLove', rel:{id:'love',min:35} },   // 可选：出现条件（对象或数组）
  chance: 0.5,                        // 可选：出现概率，缺省 1
  text: '你准备好了戒指……',             // 卡面正文
  left:  { label, fx, skills?, rel?, flags?, milestone? },
  right: { label, fx, skills?, rel?, flags?, milestone? },
  _src: 'choices/prime.json'          // 加载器注入，仅用于报错定位
}
```

> 没有图片字段。卡面头部是纯 CSS + 内联 SVG 的人物标识，不依赖任何外部资源。

`fx` 支持：六项属性键 + `skills` + `rel`（`fx.love` 是 `fx.rel.love` 的简写）。

## 存档格式

`localStorage` 键名：`rl-life-reigns-life-sim-v2`（`SAVE_KEY = 'rl-life-' + RULESET_ID`，两者都在 `core/config.js`）

```json
{
  "v": 1,
  "S": { /* 上面那个完整的 S 对象 */ }
}
```

### 读取时的容错

`reviveGame()` 会做字段补齐，容忍旧档缺字段：

```js
const base = newGame(raw.aspiration ?? null);
return {
  ...base, ...raw,
  stats:  { ...base.stats,  ...(raw.stats  || {}) },   // 逐层浅合并
  skills: { ...base.skills, ...(raw.skills || {}) },
  rel:    { ...base.rel,    ...(raw.rel    || {}) },
  flags:  { ...base.flags,  ...(raw.flags  || {}) },
  traits:     Array.isArray(raw.traits)     ? raw.traits     : base.traits,
  milestones: Array.isArray(raw.milestones) ? raw.milestones : base.milestones,
  log:  Array.isArray(raw.log)  ? raw.log  : [],
  used: (raw.used && typeof raw.used === 'object') ? raw.used : {}
};
```

任何环节抛异常（隐私模式、配额满、JSON 损坏），`loadGame()` 一律返回 `null`，游戏当作「无存档」处理，不会崩。

### 需要弃用旧存档时

改 `core/config.js` 里的 `RULESET_ID`（例如 `reigns-life-sim-v3`）。键名变了，旧档自然读不到。
只是加字段的话不用动——`reviveGame` 会自动补齐。

### 剧本换了、存档没换的隐患

`S.traits` / `S.aspiration` 存的是 **id 字符串**，不是内容。所以：

- 删掉某个特质后，旧存档里若还有该 id，展示时会退化成显示 id 本身（已有兜底），不会崩
- 删掉某个心愿后，旧存档的 `aspiration` 会指向空对象，`choose()` 里 `const asp = ... && db.aspirations[...]` 会跳过判定，同样安全

但**属性 id（`meters[].id`）不要轻易改名**——那会直接改变 `S.stats` 的键，属于破坏性变更，需要同时升 `RULESET_ID`。

## 羁绊 `rel` 与属性 `stats` 的区别

|  | `stats` | `rel` / `skills` |
| --- | --- | --- |
| 会触发结局 | ✅ 是 | ❌ 否 |
| 显示在顶栏 | ✅ 是 | ❌ 只在抽屉里 |
| 自然衰减 | ✅ 心情每年 -2 | ❌ 不会 |
| 用途 | 生命线 | 事件门槛 + 结局素材 |

这是刻意的设计：只有六项属性是「命」，羁绊和技能是「人生厚度」，让玩家的注意力集中在平衡上。
