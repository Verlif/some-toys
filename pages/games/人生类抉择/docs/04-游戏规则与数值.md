# 04 · 游戏规则与数值

所有可调数值都在 `data/init/config.json`。改平衡性**只改 JSON 刷新浏览器即可**，不用动代码。

代码常量（`RULESET_ID` / `SAVE_KEY` / `CARD_FLY_MS` / `DATA_BASE`）在 `src/js/core/config.js`，那些是改了就得改代码的东西。

## 初始状态

`data/init/config.json` 的 `initial`：

```json
{
  "age": 6,
  "stats":  { "health": 60, "mood": 60, "money": 55, "energy": 60, "social": 55, "career": 40 },
  "skills": { "knowledge": 20, "cooking": 10, "fitness": 20, "charm": 15, "craft": 10 },
  "rel":    { "family": 60, "friends": 50, "love": 0 },
  "traitCount": 2
}
```

事业给 40（低于其他项），是因为青年期之前几乎没有事业事件，留成长空间。

## 可调参数 `tuning`

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| `winAge` | 80 | 活到该年龄触发「圆满人生」 |
| `retireAge` | 60 | 达到后自动退休并写入大事记 |
| `moodDecay` | 2 | 每次抉择结算后心情自然衰减 |
| `degreeMinCareer` | 30 | 触发「第一份正经工作」的事业线 |
| `degreeMinAge` | 18 | 触发「第一份正经工作」的年龄线 |
| `peakCareer` | 60 | 触发「职场巅峰」的事业线 |
| `aspirationMoodBonus` | 5 | 心愿达成奖励心情 |
| `swipeThreshold` | 70 | 判定为有效滑动的像素距离 |
| `dangerLow / dangerHigh` | 14 / 86 | 属性条变红闪烁的区间 |
| `warnLow / warnHigh` | 25 / 75 | 属性条变黄描边的区间 |

代码里通过 `tuning()` 访问（来自 `core/registry.js`）。

## 一次抉择的完整结算顺序

`choose(S, ev, side)` 内部严格按以下顺序执行，**顺序会影响结果**：

```
1. 记录 lastId；若 ev.once 则标记 used[ev.id] = true
2. 计算六项属性增量 deltas[m] = applyTrait(S, m, fx[m] || 0)
3. 应用技能增量  skills[k] = min(100, skills[k] + sk[k])
4. 应用羁绊增量  rel[k]    = clamp(rel[k] + rl[k])
   （先合并 fx.rel 与 opt.rel，再叠加 fx.love）
5. 应用 flags（Object.assign 覆盖）
6. 触发 milestone（追加一条大事记）
7. 遍历六项属性：nv = stats[m] + deltas[m]
   ├─ nv <= 0 或 nv >= 100 → 记为 broken（取最靠前的一项）
   └─ stats[m] = clamp(nv)
8. 写入 log，turn++
9. 若 broken → 设定 ended / endDetail，直接返回
10. 活着 → age++
11. 检查退休 / 正经工作 / 职场巅峰 三个自动里程碑
12. 心情自然衰减 -2（仅当 mood > 1）
13. 检查心愿是否达成（达成则 +5 心情 + 大事记）
14. 若 age >= 80 → 设定胜利结局
```

### 顺序带来的两个副作用（已知且刻意保留）

1. **心愿检查在心情衰减之后**。`mood=1` 时，第 12 步不衰减，第 13 步的 +5 能让玩家活下来。
2. **胜利判定在最后**。如果一次抉择同时让属性爆表和年龄到 80，**优先算作死亡**（第 9 步先返回）。

## 特质修正 `applyTrait`

**条件与系数写死在 `core/rules.js#applyTrait()`**（JSON 里只有展示用的 `desc`）。增量进入结算之前生效：

| 特质 | 条件 | 效果 |
| --- | --- | --- |
| 乐天派 `optimist` | `mood` 且 `delta > 0` | `× 1.2`（四舍五入） |
| 工作狂 `workaholic` | `career` 且 `delta > 0` | `+ 2` |
| 社恐 `introvert` | `social` 且 `delta > 0` | `× 0.5`，最低保底 1 |
| 节俭 `thrifty` | `money` 且 `delta < 0` | `× 0.8`（损失减少） |
| 健身狂 `gymrat` | `health` 且 `delta > 0` | `× 1.2` |
| 吃货 / 学霸 / 冒险家 | — | 不修正数值，只作为事件 `cond.trait` 的解锁钥匙 |

注意社恐的惩罚是「收益减半」而非「损失加倍」——设计意图是让社交流玩法变慢，而不是让社恐玩家必死。

加新特质并希望它有数值效果时，**必须同时改 `applyTrait()`**，光在 JSON 里加一条只有文案生效。

## 条件求值 `condPass`

事件的 `cond`（出现条件）与心愿的 `check`（达成条件）走同一套 DSL，由 `core/rules.js#condPass()` 求值：

```
cond 是数组 → 每一项都必须是对象，各项之间「与」
cond 是对象 → 对象内各键之间「与」
单个键判定见 groupPass()：trait / flag / noFlag / skill / stat / rel / age
```

完整字段写法见 [05-剧本文件编写规范.md](./05-剧本文件编写规范.md#条件-dslcond)。

## 事件抽取 `pickEvent`

```
候选池 = 年龄符合 ∩ (非 once 或 未用过) ∩ condPass
   ↓
若候选池为空：放宽 once 限制重新筛（只按年龄 + cond）——保证任何年龄都有卡
   ↓
第一轮：过滤 chance（概率事件按 chance 保留）
   ↓ 若为空
第二轮：退回「不带 chance 的候选」
   ↓ 若为空
第三轮：退回整个候选池（保底）
   ↓
若候选 >1：剔除 lastId（避免连续出现同一张卡），再随机取一张
```

剧本里**所有事件都写了 `once: true`**，所以单局内每张卡只会出现一次，不会中途重复刷同一张脸。兜底逻辑只有在某个年龄段的卡真的被抽干时才生效（当前事件量下不会发生）。

## 生死判定

- **归零（low）**：`nv <= 0`
- **爆表（high）**：`nv >= 100`
- 同一回合多项越界时，按 `meters` 数组顺序取第一项（见 `data/init/meters.json`）

## 评分

```js
score = 六项属性之和 + 大事记条数 × 6 + 终年年龄
```

| 分数 | 档位 |
| --- | --- |
| ≥ 430 | 传奇的一生 |
| ≥ 350 | 美满的一生 |
| ≥ 280 | 有滋有味的一生 |
| 其他 | 平凡的一生 |

理论上限：六项满分 600 + 大事记 + 80 岁，但实际不可能（六项都接近 100 会先爆表）。
实测「最低属性优先补给」的求生策略可得 446 分（传奇）——说明策略深度是够的。

## 调平衡的建议

| 想达成的效果 | 改哪里（都是 `data/init/config.json`） |
| --- | --- |
| 游戏太难，活不长 | 提高 `initial.stats` 各项，或降低事件的负向数值 |
| 游戏太简单，没压力 | 提高 `tuning.moodDecay`，或提高 `tuning.dangerLow` 让警告更早出现 |
| 让玩家更容易拿高分 | 下调 `grades` 的 `min` |
| 想延长一局时长 | 提高 `tuning.winAge` |
| 想让警告更醒目 | 调 `tuning.warnLow / warnHigh`（纯视觉，不影响规则） |
| 想改开局随机特质的数量 | 调 `initial.traitCount` |

⚠️ 改完记得跑 `npm run check`，它会用两种策略各跑一局，能立刻看出平衡性变化。
