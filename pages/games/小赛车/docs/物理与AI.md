# 物理与 AI

> 本文讲清两件事：**惯性漂移的物理模型是怎么搭的**，以及**保守 / 激进两种驾驶风格在参数上差在哪、为什么这么差**。

# 一、漂移物理模型

## 1.1 为什么原来的模型漂不起来

改造前 `Car.phys()` 里只有一行转向：

```js
this.angle += steer * C.turnRate * dt * grip * dir;
this.x += Math.cos(this.angle) * this.speed * dt;
```

`angle` **既是车头朝向，也是行驶方向**——两个角是同一个。这意味着车永远不可能"歪着走"：转向就是转向 instantly，没有滞后、没有惯性。而且 `grip = clamp(|speed| / 220, 0, 1)` 随速度上升，所以**高速反而比低速更灵敏**，和真实车辆正好相反。

要做出漂移，必须把这两个角拆开。

## 1.2 两个角、一个侧滑角

```
        heading（car.angle）——车头指向
        ↗
       /
      ●━━━━━━━━━▶ velAngle（car.velAngle）——行驶方向
        ↖
          slip = heading − velAngle
```

| 字段 | 含义 |
| --- | --- |
| `car.angle` | 车头朝向，转向输入直接改它 |
| `car.velAngle` | 行驶方向（速度矢量指向，含倒车时的反向含义） |
| `car.slip` | 侧滑角 = `normAngle(angle − travel)`，`travel` 是行驶方向（倒车时为 `velAngle + π`） |
| `car.drift` | 漂移强度 0~1，只用于表现层（胎痕 / 烟 / 车身侧倾 / HUD） |

位置积分沿 `velAngle`，所以车是**真的**往侧滑方向偏出去的。

## 1.3 侧滑角怎么长出来的

横向轮胎力把行驶方向往车头方向拉，加速度与滑角成正比，但有硬上限：

```
横向加速度 = min( lateralStiff × |slip| , gripMax )
方向变化率 = 横向加速度 / |speed|
```

`gripMax` 随速度下降：

```
gripMax = lateralGrip × (1 − lateralGripFalloff × speed/maxSpeed) × brakeFade
```

**关键就在这里**：速度越高，能用的横向加速度越低，行驶方向追得越慢。车头已经转过去了、车还在往前走，侧滑角就这么攒出来了。

倒过来算临界条件：车头以角速度 `ω` 转、行驶方向以 `ω_path = gripMax / v` 转，只要 `ω > ω_path` 侧滑角就在增长。代入：

```
v² / R > gripMax(v)     →     必然滑
```

- 满速 580 时 `gripMax = 1450 × 0.65 = 942`，最小转弯半径 `580 / (942/580) = 357`
- 也就是说 **满速时半径小于约 360 的弯，正常过不去，一定会甩**——这正好覆盖了赛道生成器里的发卡弯（174~250）与 360° 回湾（285~430）
- 低速时 `grip` 几乎不衰减，但 `grip = clamp(|v|/220)` 把转向权限压下来了，所以挪车、起步打方向不会滑

## 1.4 两个额外的漂移来源

### 行进中按后退（刹车）

踩着 `S` 前进中的车，前轴先失去抓地：

```js
braking  = (throttle < 0 && speed > 10) ? −throttle : 0
brakeFade = 1 − brakeSlide × braking × (speed / maxSpeed)
```

`brakeFade` 直接乘在 `gripMax` 上（满速满刹时抓地塌到 58%），**同时放大转向权限**：

```
yaw = steer × turnRate × grip × (1 + brakeYaw × braking × speed/maxSpeed)
```

后者是真实车"刹车带转向，车头甩得更多"的来源。两者合起来的效果（实测）：

| 操作 | 峰值滑角 | 留痕时长 |
| --- | --- | --- |
| 满速纯刹车 0.5s | 0°（车身点头 0.84） | — |
| 满速**刹车 + 满舵** 0.6s | **43.9°** | 0.37s |
| 满速满舵 1s | 57.8° | 0.92s |

纯直线刹车在物理上不该产生侧滑（没有横向需求），所以做成**车身点头**（`car.pitch`，纯表现层）；真正的甩尾来自"踩着刹车打方向"——这也正是玩家"减速入弯顺手带一点方向"的真实操作。

### 打转保护

满速死打方向时，`gripMax / v = 942/580 = 1.62 rad/s` 恒小于转向的 `2.6 rad/s`，滑角会无限增长。所以加了软上限：

```js
if (|slip| > slipMax) rate += spinRecover × (|slip| − slipMax)
```

`spinRecover = 7` 把满舵死打的稳态滑角兜在 **59.9°**——是"甩出去"，不是"原地打转"。反打方向立刻救得回来（实测反打后 0.1s 内滑角归零）。

## 1.5 漂移的代价

侧滑时轮胎横向摩擦会磨掉沿车头方向的速度：

```
speed −= driftDrag × |sin(slip)| × dt      （driftDrag = 190 px/s²）
```

滑角 17° 时约 −55 px/s²，滑角 40° 时约 −122 px/s²。这就是"漂移能过更紧的弯，但要付速度"的交换，也是 `ai-throttle.js` 里激进档敢用漂移的前提。

## 1.6 参数表

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `lateralGrip` | `1450` | 横向加速度上限（px/s²），满速时实际约 942 |
| `lateralGripFalloff` | `0.35` | 抓地随速度衰减的比例（满速剩 65%） |
| `lateralStiff` | `3100` | 侧偏刚度（px/s² per rad）。回正时间常数 = `速度 / 该值`，所以高速的滑角"赖"得更久 |
| `brakeSlide` | `0.42` | 重刹时抓地最多塌缩到 58% |
| `brakeYaw` | `0.85` | 重刹放大转向的系数 |
| `slipMax` | `0.95` | 侧滑角软上限（≈54°），超过后 `spinRecover` 介入 |
| `spinRecover` | `7.0` | 打转回正速率，把死打方向的稳态滑角兜在 60° 出头 |
| `driftSlip` | `0.17` | 超过这个滑角（≈10°）才算漂移，开始留胎痕 |
| `driftSpeed` | `190` | 低于这个速度不留胎痕（挪车、原地打方向不算） |
| `driftFull` | `0.52` | 滑角达到 `driftSlip + driftFull` 时漂移强度满格 |
| `driftDrag` | `190` | 漂移速度损耗（px/s²） |
| `tireLife` | `5.0` | 胎痕寿命（秒） |
| `tireAlpha` | `0.26` | 胎痕最大不透明度 |
| `tireWidth` | `0.15` | 单条胎痕宽度（相对车宽） |
| `tireStep` | `9` | 相邻胎痕点最小间距（世界单位） |
| `tireMax` | `2200` | 全场胎痕段数上限，超出丢最旧的 |

## 1.7 胎痕的实现

`entities/tire-marks.js`，数据与绘制放在一起（参照 `particles.js` 的做法）：

- 只在 `car.drift > 0` 时取样，取 `car.rearWheels()` 给出的两个后轮坐标，连成折线段
- 一条漂移结束后 `on = false`，下次漂移从新点起，不会拉出一条横穿赛道的直线
- **寿命制**：每段记一个写入时刻，`update()` 从头扫掉过期的（段按时间有序，过期的永远在前面）
- **绘制分桶**：按不透明度分 5 桶，一桶一次 `stroke()`。段数再多也不会掉帧

宽度按**世界坐标**画（车宽的 15%），所以鸟瞰拉远时胎痕会自然变细，像真实路面痕迹那样随透视缩小。

# 二、AI 的转向：侧滑前馈补偿

## 2.1 有惯性之后，按车头修就晚了

改造前转向驾驶员是这样算方向的：

```js
steer = angleDiff × aiSteerGain      // angleDiff = 瞄准方向 − 车头朝向
```

有惯性之后这会慢半拍：车头摆好了，车还在往外甩，跑出来全是弧形外扩，AI 一高速就蹭墙。

**做法是侧滑前馈补偿**——在瞄准偏差上再减掉一段当前侧滑角：

```
steer = (瞄准偏差 − slip × aiSlipLead) × aiSteerGain
```

`slip > 0` 表示车头已经比行驶方向"多转了"，要把行驶方向拉回来就得先把车头收回来，所以是**减号**。系数越大，出弯回正越早、高速越贴线。

实测（同一条赛道、3 车 / 60s / 3 种子中位）：

| 控制器 | 均速 | 全速帧占比 | 均滑角 | 撞墙 |
| --- | --- | --- | --- | --- |
| 追车头朝向（改造前） | 508 | 82% | 9.8° | 1 |
| 速度方向控制器（错误方案，见下） | 245 | 18% | 27.7° | 3 |
| **侧滑前馈** | **566** | **96%** | **5.6°** | **0** |

前馈比改造前还快，原因是补偿让车真的走在线上，而不是靠瞄准误差硬撑——原先那份误差有一部分是被当作"转向权限"用掉的。

### 走过的弯路：速度方向控制器

最初试的是"把行驶方向带到瞄准方向上"的形式：

```
期望车头 = 瞄准方向 − clamp(aiSlipLead × 速度方向误差, ±0.7)
```

这个形式**符号推反了**：`slip > 0` 时前馈把车头进一步推向外侧，而横向力又把行驶方向往车头拉，形成正反馈——车在中线上左右横甩。换成加号同样救不回来（均速 56、滑角 68°，比原方案更糟）。

教训：**有惯性的车不能用"期望速度方向"这一层中间量做控制律**。那是"转向 → 侧滑 → 行驶方向 → 反馈"的非最小相位环路，符号推错必然自激。正确做法是把侧滑当成**已知的、可直接补偿的扰动**，从偏差里减掉。

### 系数

`aiSlipLead` 由档案决定：

| 档案 | 系数 | 含义 |
| --- | --- | --- |
| NPC 新手 / 入门 | 1.15 / 1.20 | 增益低，需要更多前馈才追得回 |
| NPC 普通 / 老练 / 赛车手 | 1.2 / 1.35 / 1.5 | 越高档位越信任自己的转向 |
| 保守（协作） | 1.35 | 出弯回正早，高速贴线 |
| 激进（协作） | 0.95 | 少补偿，等抓地把车慢慢拽进弯 |
## 2.2 弯道限速：转向能力 ∩ 抓地上限

改造前只有一条约束 `v = turnRate × R × margin × skill`。加了漂移之后必须再加一条，否则 AI 会带着满油门冲进抓不住的弯：

```
v转向 = turnRate × R × cornerMargin × align × skill        （转向能力上限）
v抓地 = √( min(lateralStiff × driftCap, gripMax) × R )     （横向抓地上限）
v弯道 = min(v转向, v抓地)
```

`gripMax` 里带两个档案参数，它们**共同决定 AI 在弯里滑不留滑**：

- `aiGripUse` —— 允许用掉几成抓地
- `aiDriftCap` —— 弯里允许滑到多大滑角（横向加速度 = `lateralStiff × slip`，超过就不再有收益）

稳态滑角可以直接从弯道反推：

```
需要的横向加速度 = v² / R
稳态滑角 ≈ min(v² / R, gripMax) / lateralStiff
```

`v弯道` 是 `min` 的结果，所以：

- `v转向` 生效时（AI 只用了部分转向权限），车不会滑
- `v抓地` 生效时（几何上必须用满抓地），车正好滑在 `driftCap` 上

## 2.3 走线：弯心内切权重

`ai.js` 的 `sense()` 里，瞄准点的横向偏移是三份叠加：

```js
bias = apex × 0.32 × 半宽 × aiLineWeight          // 弯心内切
     + lineBias × 半宽 × 0.4 × aiLineWeight      // 每台车自己的走线偏好
     + otSide × 0.42 × 半宽                       // 超车绕行外移
     + 并排避让 / 跟车让位的增量                    // 与风格无关，安全逻辑
最后 clamp 到 ±aiLineRange × 半宽
```

`aiLineWeight` 同时乘在内切和走线偏好上，所以**保守档把两者一并收掉**——`0.26` 意味着几乎贴着中线跑。`aiLineRange` 控制能横向用到多宽的路：保守 `0.44`（连超车外移都收敛），激进 `0.78`（几乎用满路宽去切钳形线）。

## 2.4 刹车时机

| 档案 | `aiBrakeWindow` | 效果 |
| --- | --- | --- |
| 保守 | `1.45` | 刹车前视窗口拉长 45%，提前一个刹车点就开始收油 |
| NPC 普通 | `1.00` | 基准 |
| 激进 | `0.82` | 窗口收紧，几乎贴着弯才刹车 |

配套的还有 `aiAlignLoss`（车头没对准弯道时额外收油的比例）：保守 `0.30`，激进 `0.09`——激进几乎不为"还没摆正"收油。

# 三、两种驾驶风格

## 3.1 设计意图

这不是"AI 强度高低"的分级，是**两种协作契约**：

- **保守**：把你的车当 fragile。宁可慢半拍，也要把车**完整地交回你手里**。它存在的意义是：你只管一个轴，另一个轴不会把你带进墙里。
- **激进**：把你当赛车手。以"你会做完美操作"为前提，把漂移风险和擦碰风险都推给你。它存在的意义是：**它绝不拖你后腿**——圈速由你们两个一起拿。

对应到具体行为：

| | 保守 | 激进 |
| --- | --- | --- |
| 进弯前减速 | 提前一个刹车点就开始收 | 贴着弯才刹车 |
| 走线 | 贴中线，不切角 | 钳形最短路线，贴弯心极限 |
| 跟车距 | `150 + 0.62s` 车速 | `56 + 0.27s` 车速 |
| 超车 | 积极性 0.35 | 0.95 |
| 弯里漂移 | 滑角 ≈9°，**不留胎痕** | 滑角 17~37°，**甩尾留痕** |
| 反应间隔 | 0.09~0.20s | 0.05~0.11s |

## 3.2 稳态过弯对照

以下是把两种档案代进 §2.2 公式得到的**弯中稳态速度与滑角**（技能系数取 0.92）：

| 弯道半径 | NPC 普通 | 保守 | 激进 |
| --- | --- | --- | --- |
| 174（发卡） | 300 · 9.5° | 291 · 9.0° | 395 · 17° |
| 250 | 431 · 13.7° | 352 · 9.2° | 488 · 18° |
| 300（回湾） | 501 · 15.5° | 386 · 9.2° | 532 · 17° |
| 410（缓弯） | 570 · 14.6° | 451 · 9.2° | 580 · 15° |
| 600 | 580 · 10.4° | 546 · 9.2° | 580 · 10° |
| 870 | 580 · 7.1° | 580 · 7.1° | 580 · 7.1° |

三条读法：

1. **保守在所有弯都稳定在 5° 上下**——低于 `driftSlip = 0.17 rad ≈ 9.7°` 的留痕门槛，所以它基本不留胎痕，但弯速仍能到 486（不是龟速）。这是 `driftCap = 0.24` 与 `gripUse = 0.78` 一起调出来的平衡点。
2. **激进在 R ≤ 410 的弯上全部留胎痕**，因为几何要求它必须用满抓地，滑角由 `v²/R` 决定而与 `driftCap` 无关。
3. **R = 870 时三者一样**——弯太缓，不存在"要不要冒险"的决策空间。这说明两档的差异集中在**需要取舍的弯**上，正是玩家关心的区间。

| 参数 | 保守 | 激进 | 决定什么 |

| `driftCap` | `0.24` | `0.64` | 弯里允许的最大滑角。**别调太低**：它直接决定弯道限速 `v=√(刚度×driftCap×R)`，0.16 会把弯速压到 480 而全场龟速 |

| `dodgeRange` | `310` | `250` | 前方避让起始距离 |
| `lookAhead` | `5` | `6` | 前视采样基数 |
| `skill` | `[0.86, 0.96]` | `[0.94, 1.04]` | 每台车开局 roll 的过弯技能 |

## 3.4 与 NPC 五挡的关系

两套档案**互相独立**，通过同一个 `applyProfile()` 写入 `CONFIG`：

- `DRC.AI_LEVELS`（5 挡）→ 全场 NPC，入口是「AI 对手智能程度」
- `DRC.DRIVE_STYLES`（2 挡）→ 玩家车的接管位队友，入口是「AI 队友风格」

所以可以「全场 NPC 都是新手，但你的队友是激进」——`car.driveStyle` 非 0 时 `car.aiLevel` 恒为 0，两套档案不会同时生效。赛内 HUD 的座位小标会写成 `AI 方向 · 激进` / `AI 前后 · 保守`，结算页 meta 同样带风格。

# 四、调参速查

| 想改什么 | 改哪里 |
| --- | --- |
| 漂移更容易 / 更难触发 | `driftSlip`（留痕门槛）、`lateralGrip`（抓地上限）、`turnRate`（转向权限） |
| 甩尾能兜住的角度 | `spinRecover` + `slipMax` |
| 漂移掉速多快 | `driftDrag` |
| 胎痕留多久 / 多明显 | `tireLife` / `tireAlpha` / `tireWidth` |
| 刹车更容易甩 | `brakeSlide`（抓地塌缩）、`brakeYaw`（转向放大） |
| AI 在弯里滑不留滑 | `aiDriftCap` 与 `aiGripUse`，两者一起调 |
| AI 走中线还是切弯心 | `aiLineWeight` / `aiLineRange` |
| AI 提前多久刹车 | `aiBrakeWindow` |
| AI 打方向多早 / 多贴线 | `aiSlipLead` |
| AI 原地打转出不来 | `aiJitterRange`（低档位）、`car.idleTimer` / `car.wallStuck`（兜底） |

# 五、无头测量：怎么判断 AI 是不是真的在开车

手感问题靠肉眼看不准，而且"笨"有好几种完全不同的病因：均速低、走线抖、原地卡死、只会跟车不会超车。定标之前先把指标定下来，否则调参就是瞎试。

## 5.1 六个指标

在 `vm` 沙箱里加载 `constants / car-models / math / track / car / collision / race / ai-*`，替换 `Sound` 与 `Camera` 为空实现，`Track.create()` 同步生成赛道，然后以固定步长 1/60 跑完整循环。每档位跨多个随机种子取中位数（单种子方差极大）。

| 指标 | 定义 | 判读 |
| --- | --- | --- |
| **推进** | `lap × 赛道长 + nearIdx × 步距` | **最硬的指标**。原地打转的档位会卡在几公里，无论均速多高 |
| **均速** | 全帧 `|speed|` 均值 | 高了不等于好，得配合推进看 |
| **全速帧占比** | `|speed| ≥ 500` 的采样点比例 | 低于 60% 说明车常年跑不到顶速，看着就"肉" |
| **均滑角** | 全帧 `|slip|` 均值（度） | 高于 15° 说明车在持续甩，不是正常过弯 |
| **走线 RMS** | `sqrt(mean(lat²))` | 横向抖动程度，比均滑角更能看出"晃" |
| **撞墙 / 车撞** | `wallHits` / `carHits` 累计 | 撞墙是档位定位的一部分，车撞不该有 |

## 5.2 卡死的三种形态

定标时发现漂移模型引入了三种**改造前不存在**的卡死，都表现为"推进卡在几公里"，但成因完全不同，修法也不同：

| 形态 | 现场特征 | 修法 |
| --- | --- | --- |
| **贴墙死锁** | `v ≈ 0`，`slip > 90°`，`wallStuck` 恒为 0，倒车计时反复重启 | `updateStuck()` 的判定要求 `throttlePlan > 0.5`（在给油），倒车期间恒为 −0.55 → 判定永不成立。改成看"贴墙 + 推不动"这个事实本身，不在乎当前是给油还是倒车 |
| **倒车内卷** | 车横在墙里，倒车 + 反打打转十几秒 | 倒车脱困要求车头朝路面方向，横着的车头永远对不上。贴墙卡死改为**前进**脱困（`car.wallStuck`），低速下车头朝哪挪就往哪挪，慢但出得来 |
| **指令自锁** | 车在中线上左右横甩，`lat ≈ 0` | 低挡位"完全没有默契"下，两位驾驶员各按各的赛道理解操作，指令互相抵消。加一道兜底：连续 1.5s 速度低于 90 就强制倒车（`car.idleTimer`） |

**卡死是 bug，不是档位定位。** 档位可以"慢"、可以"撞墙"、可以"圈速难看"，但不能"开不出赛道"。这三层兜底与档案无关，所有挡位共用。

## 5.3 低档位偏差的封顶

`sharedSense: false` 的两位驾驶员各自带一份世界观偏差（瞄准点横向偏移 / 前视采样 / 刹车窗口）。加漂移之前这只会让走线难看（±20px）；现在它直接乘进侧滑补偿里，而油门与转向基于**两套不同的赛道形状**——指令天生对不上，实测 60 秒只能跑 9km。

`aiJitterRange`（默认 7px）封顶偏差幅度，front 视采样收到 ±1、窗口收到 0.88~1.12。偏差依然存在（不默契看得出来），但车能跑完全程。
