# 架构

> 本文面向改代码的人。想了解玩法与参数速查，看 [README](../README.md)；
> 想了解漂移物理与两种驾驶风格的推导，看 [物理与AI.md](物理与AI.md)。

## 全局约定

- **单一命名空间**：所有模块挂在 `window.DRC` 上，各自用 IIFE 包裹（`(function (DRC) { ... })(window.DRC)`），不向外抛任何变量。
- **加载顺序**：`index.html` 底部按 `core → audio → world → entities → systems → render → ui → game → main` 引入。模块之间**只在运行时互相调用，不做加载期依赖**——所以 `car.js` 可以直接读 `DRC.CONFIG`，`ai.js` 可以直接用 `DRC.Car`，哪怕引入顺序看起来"不对"。
- **加载期唯一的硬依赖**是同一个文件内部的执行顺序：`constants.js` 必须最先（它定义 `DRC.CONFIG` / `DRC.AI_LEVELS` / `DRC.DRIVE_STYLES`），`car-models.js` 与 `math.js` 必须早于任何用到它们的地方。
- **风格**：2 空格缩进，无分号，注释写在代码上方而不是行尾；注释解释"为什么"，不复述"做了什么"。

## 每帧的数据流

`main.js` 的 `requestAnimationFrame` 驱动一条**单向链路**，渲染层只读状态，音频层只读车辆：

```
main.loop
  └─ game.update(dt)
       ├─ effects.update / tireMarks.update        纯计时器，与场景无关
       ├─ phase === 'countdown' → 车锁死，只推进特效计时
       ├─ phase === 'running'  → game.stepRace(dt)
       │    ① 输入 + 物理    stepRace 里逐车：
       │    │     玩家车  seatOf() 决定这一轴来自键盘还是 AI
       │    │     NPC     useAiProfile() 套档案 → AI.think() → {throttle, steer}
       │    │     两种轴最后都汇进同一个 Car.phys(dt, throttle, steer)
       │    ② 车车碰撞      Collision.resolveCars
       │    ③ 赛道硬约束    Collision.constrainToTrack（同时刷 nearIdx / lat）
       │    ④ 胎痕取样      tireMarks.sample（必须在③之后，否则会擦到墙里）
       │    ⑤ 圈数与排名    Race.updateProgress / updateRanks
       │    ⑥ 结束判定      checkFinish
       ├─ updateCamera(dt)
       └─ Sound.update(game)   只刷新听者位置

  └─ Renderer.draw(game)
       地面 → 起步箭头 → 轮胎印 → 全部赛车 → 观战光环 → 粒子
       → HUD（屏幕空间）→ 小地图（屏幕空间）
```

**渲染顺序里唯一容易踩坑的是胎痕的位置**：它画在「地面之上、赛车之下」，所以擦出来的痕迹永远压在地上被车挡住，不会盖住车身。加在赛车之后会让胎痕糊在车上，加在地面之前会被路面盖掉。

## 驾驶档案：两套参数、一套写入器

这是本次改造的核心结构，也是最需要理解的一块。

游戏里有两种"AI 在开车"的情况，它们需要**完全不同**的参数：

| | `DRC.AI_LEVELS` | `DRC.DRIVE_STYLES` |
| --- | --- | --- |
| 谁在用 | 全场 NPC 对手 | 玩家车里接管另一个座位的队友 |
| 几档 | 5 挡（新手 → 赛车手） | 2 档（保守 / 激进） |
| 决定什么 | 这台对手有多强 | 这位队友开得多稳 / 多敢 |
| 设置页入口 | 「AI 对手智能程度」 | 「AI 队友风格」 |

两套表**字段名完全一致**，共用 `applyProfile()` 这个写入器：

```js
DRC.applyAiLevel(level)     // 把 AI_LEVELS[level-1] 写进 CONFIG 的 ai* 字段
DRC.applyDriveStyle(style)  // 把 DRIVE_STYLES[style-1] 写进 CONFIG 的 ai* 字段
```

`ai*.js` 全部直接读 `DRC.CONFIG`，不逐层传参。代价是**CONFIG 里的 `ai*` 字段是全局单份的**，所以 `Game.useAiProfile(car)` 在每台车思考之前先把它那套档案套进去：

```js
useAiProfile(car) {
  const key = car.driveStyle ? 's' + car.driveStyle : 'l' + (car.aiLevel || 3);
  if (this._profile === key) return;          // 同一档案连续思考不重复写
  this._profile = key;
  car.driveStyle ? DRC.applyDriveStyle(car.driveStyle)
                 : DRC.applyAiLevel(car.aiLevel || 3);
}
```

于是**一场比赛里可以同时跑着三种不同开法的车**：NPC 用全场挡位，玩家车的队友用选中的风格，而玩家自己那个轴来自键盘。`car.driveStyle` 非 0 时 `car.aiLevel` 恒为 0，两套档案不会同时生效。

> 新增一个字段要改三处：`applyProfile()` 里加写入、`AI_LEVELS` 五项各加一行、`DRIVE_STYLES` 两项各加一行。漏了任何一档，`undefined` 会一路传到 AI 决策里。

## 车辆物理：两个角

`Car` 有两个方向角，**这是整个漂移模型的支点**：

| 字段 | 含义 | 谁改它 |
| --- | --- | --- |
| `car.angle` | 车头朝向 | 玩家 / AI 的转向输入直接改 |
| `car.velAngle` | 行驶方向（速度矢量指向） | 横向轮胎力把它往 `angle` 拉 |
| `car.slip` | `angle − velAngle`，侧滑角 | 每帧由两者相减得到 |
| `car.drift` | 漂移强度 0~1 | `slip` 超过 `driftSlip` 且速度够才起算 |
| `car.pitch` | 刹车点头量 | 刹车深度 × 抓地折减，纯表现层 |

位置积分沿 `velAngle` 而非 `angle`，所以车是**真的**往侧滑方向偏出去的，不是"车头歪着、屁股跟着走"。

三个容易踩的点：

1. **跨零点要翻半个 π**。前进切倒车时速度矢量掉头，`velAngle` 必须同步 `±π`，否则 `slip` 会瞬间变成 π 被当成侧滑。`Car._fwd` 记录上一帧的行驶方向。
2. **`travel` 的定义**。倒车时行驶方向是 `velAngle + π`（因为 `speed` 为负）。所有侧滑计算都在 `travel` 上做，算完再翻回 `velAngle`。
3. **`brakeFade` 要传给渲染**。重刹时抓地塌缩，这个值同时决定点头深度和 AI 的抓地预算。

## 碰撞与胎痕的先后

`stepRace` 里的顺序不能改：

```
② 车车碰撞 → ③ 赛道硬约束 → ④ 胎痕取样
```

撞墙时车会被 `constrainToTrack` 推回路面。如果先取样再约束，擦出来的胎痕会有一小段落点在墙外，看起来像穿墙。同一帧先碰撞再取样，痕迹永远在路面上。

## 渲染层的世界 / 屏幕空间

`Renderer.draw` 里 `ctx.save()` 之后进入的是**世界坐标**（已按 `cam.zoom` 缩放），`ctx.restore()` 之后是**屏幕像素**。判据很简单：

- 会随镜头缩放的（车、赛道、胎痕、箭头、光环）→ 画在世界层
- 固定在屏幕某个角的（HUD、小地图、导播条、倒计时）→ 画在屏幕层
- 屏幕层里需要恒定粗细的描边（观战光环、结算线）→ `lineWidth = 像素 / cam.zoom`

胎痕属于第一类：宽度按世界坐标画，所以鸟瞰拉远时会自然变细，像真实路面痕迹那样随透视缩小，而不是屏幕上恒定粗细的黑带。

## UI 层约定

`panels.js` 持有全部 DOM 引用和事件绑定，通过 `sync()` 把 `game.state` 单向刷成界面。约定：

- **分段按钮的值写在 HTML 的 `data-v` 上**，`sync()` 里用 `setActive(buttons, String(state.x))` 高亮——HTML 是唯一的"真值声明"位置。
- **动态列表**（`seatList` 的座位行）用事件委托：`innerHTML` 整块重绘，`onclick` 在 `renderSeats()` 里重新挂到容器上，逃逸用 `data-p` 标出玩家序号。
- **折叠块**（`fieldTeam` / `fieldSeat` / `fieldScheme`）靠 `.collapse.open` 的 `grid-template-rows: 0fr → 1fr` 过渡；`transitionend` 里要 `refreshPreview()`，否则面板尺寸变化后缩略图会糊。
- **说明文字**分成两层：常驻的 `field-note` 解释机制，动态的（`aiNote` / `styleNote` / `seatNote`）由 `sync()` 按当前选择改写。

## 状态机

`game.state.scene` 只有五个值，切换全部走显式方法：

```
menu ──toStart──▶ setup ──startRace──▶ race ──pause──▶ paused
 ▲                    ▲                   │              │
 │                    └───rerollTrack─────┴──resume──────┘
 │                                    │
 └────────toMenu──────────────────────┴──endRace──▶ result ──again──▶ setup
```

- `setup` → `race` 之间必须先过倒计时：`phase = 'countdown'`，车辆锁死
- 暂停恢复同样重播 3-2-1（`countdownKind = 'resume'`），比赛计时不补
- 换赛道 / 重开一局要 `clear()` 的三样：`effects`、`tireMarks`、`cars`

## 音频

全部 Web Audio 现算波形，没有素材文件。音频层**只读**车辆状态（位置、速度），从不反向影响物理。浏览器自动播放策略要求第一次点击或按键后才创建 `AudioContext`，所以主菜单上前几秒本来就该是安静的。

## 扩展指南

**加一个音效**：在 `sound.js` 里写一个合成函数，在触发点（`collision.js` 撞墙 / `game.js` 倒计时 / 冲线）调 `DRC.Sound.xxx()`，在 `segments` 附近挂进设置页开关。

**加一种车型**：在 `car-models.js` 加一项（尺寸 + 外观参数），开局洗牌逻辑不用改。

**加一条 AI 参数**：见上文「新增一个字段要改三处」。

**加一种协作风格**：`DRIVE_STYLES` 加一项 → `index.html` 的 `segSeatStyle` 加一个 `data-v` → `panels.js` 的 `styleLabel()` 与 `hud.js` 的 `seatTag()` 会自动跟上（都按数组长度 / 下标取，不写死）。想清楚这一档的 `gripUse` 与 `driftCap` 落在哪，就决定了它在弯里留不留胎痕。

**改物理手感**：所有手感常量都在 `CONFIG` 的「惯性与漂移」段里，逐项含义见 [物理与AI.md](物理与AI.md) 的参数表。
