# 五行卡牌战斗 Demo

一个原生 HTML + JavaScript 实现的五行卡牌战斗原型。无构建工具、无依赖：直接打开 `index.html` 即可游玩。

核心规则：**玩家用五行点数支付卡牌费用，支付结果先经相生/相克结算，结算后点数最高的五行成为这张牌本回合的附着属性；词条与效果围绕该属性判定。敌方开局随机获得一个五行属性，技能附着属性克制它时伤害 +50%，否则 -50%。战斗中使用灵力可以重铸本回合五行点数，但出牌后不可重铸。**

---

## 一、对局流程

### 1. 设置阶段
- 玩家在五行分配环中分配 **10 点**五行点数（金、木、水、火、土，单点增减，上限各 10）。
- 从 **24 张玩家卡池**中选出 **10 张**组成卡组。
- 两个条件都满足后才能点击「入局」。
- 也可以点击「随机卡组」：随机抽取 10 张不重复的卡并直接入局；若当前五行分配不满 10 点，会自动恢复为均分（每项 2 点）。
- 卡池列表在独立区域内滚动，勾选卡牌后滚动位置保持不变。

### 2. 战斗阶段
- 玩家气血 40，敌方「凶骸」气血 48。任一方气血归零即结束。
- 回合结构：`玩家回合 → 结束回合 → 敌方回合 → 下一玩家回合`。
- 双方每回合都重新获得五行点数并抽牌；手牌不会跨回合保留（结束回合时全部弃置）。
- 玩家可以在一个回合内打出多张牌，只要剩余五行点数仍满足费用。

### 3. 结算阶段
- 显示胜/败、历经回合数，可「再开一局」（完全重置状态）。

## 二、五行与生克结算

### 2.1 两个环
- 相生环：`金 → 水 → 木 → 火 → 土 → 金`
- 相克环：`金 → 木 → 土 → 水 → 火 → 金`

任意两种不同的五行之间，必然恰好是「相生」或「相克」之一。

### 2.2 结算算法（`XR.resolvePayment`）

给定本张牌的**原始支付** `chosen`：

1. 复制原始点数作为结果 `result`。
2. 对每一个参与支付的五行 `A`（点数 `n > 0`）：
   - 若 `A` 生的五行 `B` 也参与了支付，则 `result[B] += n`，记录一次「A 生 B」事件。
   - 若 `A` 克的五行 `C` 也参与了支付，则 `result[C] -= min(n, chosen[C])` 且不低于 0，记录一次「A 克 C」事件。
3. **生与克都基于原始支付同时结算**，因此结果与遍历顺序无关。
4. 取 `result` 中的唯一最高值对应的五行作为**附着属性**；若最高值并列（或全部为 0），则**无属性**。

示例：

| 原始支付 | 结算过程 | 结算后点数 | 附着属性 | 事件 |
| --- | --- | --- | --- | --- |
| 2金 + 1水 | 金生水，水 +2 | 金2 + 水3 | 水 | 金生水 2 |
| 2金 + 1木 | 金克木，木 -2（下限 0） | 金2 | 金 | 金克木 1 |
| 1金 + 2木 | 金克木，木 -1 | 金1 + 木1 | 无（并列） | 金克木 1 |
| 1金 + 1土 | 土生金，金 +1 | 金2 + 土1 | 金 | 土生金 1 |
| 1金 + 1水 + 1木 | 金生水、水生木、金克木 | 金1 + 水2 + 木1 | 水 | 金生水 1，水生木 1，金克木 1 |

> 注：结算后的五行顺序只用于展示，逻辑上五项是等价的。

### 2.3 支付约束（`XR.canAfford`）
- 已选点数总和必须**恰好等于**卡牌费用（不能多付，也不能少付）。
- 每个五行已选点数不能超过当前可用点数。

## 三、卡牌结算

### 3.1 数据字段（`src/data/cards.js`）

```js
{
  id: 'jin-feng',
  name: '金锋斩',
  cost: 3,
  effects: [{ type: 'damage', value: 6 }],
  entries: [
    { cond: { type: 'contains', el: 'jin' }, text: '含金：伤害+3', bonus: [{ type: 'damage', value: 3 }] },
    { cond: { type: 'shengAny' },        text: '相生：抽1牌',   bonus: [{ type: 'draw', value: 1 }] }
  ]
}
```

- `effects`：基础效果，必定生效。
- `entries`：词条，只有 `cond` 满足时，`bonus` 才会追加到效果列表。
- 结算顺序：先基础效果，再按词条书写顺序追加 bonus；同一条效果按数组顺序依次执行。

### 3.2 效果类型

| 类型 | 行为 |
| --- | --- |
| `damage` | 先由目标护盾抵消，剩余部分扣气血 |
| `shield` | 为自己增加护盾 |
| `heal` | 回复气血，不超过气血上限 |
| `draw` | 从牌库抽牌；牌库空时洗回弃牌堆 |

### 3.3 日志格式

每次出牌写入一行完整链路：

```
你打出「五行轮转」，支付 木1 + 火2 + 土1 → 生克后 木1 + 火3 + 土2，附火属性（木生火 1，木克土 1，火生土 2）
　属性判定：火克金，伤害 +50%
　你造成 12 点伤害（火克金，伤害 +50%），凶骸气血 36
```

## 四、词条判定（`XR.evalCond`）

所有条件都基于**生克结算后的结果**，而不是原始支付。

| 条件类型 | 含义 |
| --- | --- |
| `contains` / `attribute` | 本牌附着属性为指定五行 |
| `lacks` | 本牌附着属性不是指定五行 |
| `noAttribute` | 本牌无属性（结算后最高值并列） |
| `pair` | 结算后两个指定五行点数都大于 0 |
| `pure` | 结算后只剩指定五行一种属性 |
| `elAtLeast` | 结算后指定五行点数 ≥ n |
| `kindsAtLeast` | 结算后属性种类数 ≥ n |
| `shengAny` | 本次支付中实际发生了相生 |
| `keAny` | 本次支付中实际发生了相克 |
| `shengPair` | 两个指定五行之间实际发生了相生（任一方向） |
| `kePair` | 两个指定五行之间实际发生了相克（任一方向） |

> 注意：`含金` 一类文案现在指**卡牌最终附着属性为金**，不再指"原始支付里含金"。
> `shengAny` / `keAny` 看的是真实发生的事件，因此不会出现"支付三种属性就必然同时触发相生和相克"的情况。

## 五、灵力与五行重铸

### 5.1 属性
- 灵力上限 `100`，初始 `100`。
- 每个玩家回合开始时恢复最大灵力的 **15%**（即 +15），不超过上限。
- 重铸消耗最大灵力的 **20%**（即 20 点）。

### 5.2 重铸规则（`XGame.rerollElements`）
必须同时满足：
1. 处于玩家回合，且对局未结束；
2. 本回合尚未重铸过；
3. **本回合还没有打出过任何牌（没有消耗过五行点数）**；
4. 当前灵力 ≥ 20。

满足时：
- 扣 20 灵力；
- 随机生成本回合的 **10 点**五行点数（逐点随机分配到五行，可出现单一属性）；
- 清空当前已选点数（`chosen`），保留当前选中的手牌，玩家可立即重新投点；
- 写入战斗日志。

不满足时操作无效，按钮禁用并显示原因：`已消耗五行` / `本回合已重铸` / `灵力不足`。

> 重铸只改变**当前回合**的可用点数。下一回合开始时，点数仍按设置阶段的固定分配恢复。
> 标记 `pointsSpent` 在每次玩家回合开始时重置，`rerollUsed` 同理。

## 六、敌方属性与伤害克制

- 开局时凶骸随机获得一个五行属性（金/木/水/火/土），整场战斗不变，显示在敌方面板上，同时标注「受某属性克」。
- 技能对敌方造成伤害时，用本牌的**附着属性**与敌方属性比较：
  - **技能属性克敌方属性**（例如技能为火、敌方为金，即 `火克金`）：该牌所有伤害效果 **×1.5（+50%）**。
  - **其他情况**（未克制、被敌方克制、或技能无附着属性）：该牌所有伤害效果 **×0.5（-50%）**。
- 倍率作用于这张牌的全部 `damage` 效果（基础效果与词条 bonus 一视同仁），在护盾抵消**之前**计算。
- 伤害值按 `Math.round(原值 × 倍率)` 取整，例如 5 点伤害被削弱后为 3 点（2.5 四舍五入）。
- 敌方攻击玩家时，玩家没有属性，因此不触发该倍率，伤害保持原值。
- 支付区会实时预览当前技能对敌方的倍率；战斗日志会写明属性判定与倍率来源。

## 七、回合流程细节

### 玩家回合开始（`startPlayerTurn`）
1. 回合数 +1，回合方切为玩家。
2. 护盾清零。
3. 五行点数恢复为设置阶段的分配（默认 10 点）。
4. 灵力 +15（封顶 100）。
5. `rerollUsed = false`，`pointsSpent = false`。
6. 弃掉上一回合剩余手牌，抽 5 张。

### 玩家操作
- 点手牌 → 选牌；点五行环外环节点 → 投 1 点；点内环节点 → 撤回 1 点。
- 「满额」自动选择使词条收益最高的合法支付方案。
- 「打出此牌」消耗点数并执行效果；一旦打出，`pointsSpent = true`，本回合不能再重铸。
- 「结束回合」清空剩余点数并弃掉全部手牌。

### 敌方回合（`enemyTurn`）
1. 敌方护盾清零，五行点数恢复为固定分配：`金2 木2 水1 火3 土2`。
2. 抽 3 张牌。
3. 最多打出 2 张牌，每张都由 `XR.chooseBestPayment` 选择最优支付。
4. 清空剩余点数、弃掉手牌，进入下一玩家回合。

### 敌方 AI（`src/core/rules.js`）
- `enumeratePayments` 穷举所有满足费用与库存的支付组合（上限 400 个）。
- `scorePayment` 评分：每个触发词条 +10，bonus 按类型加权（伤害 1×，其他 0.6×），有附着属性 +2，发生相生/相克各 +1，每投入 1 点 -0.05。
- 取评分最高的组合；同分时取遍历顺序第一个。当前 AI 无意图预告、无随机性。

## 八、文件结构

```
index.html                     页面入口，按顺序加载所有脚本
styles.css                     全部样式（纸面国风、五行环、卡牌、灵力条）
src/
  data/
    elements.js                五行数据、相生/相克映射、名称与颜色
    cards.js                   24 张玩家卡 + 8 张敌方卡
  core/
    rules.js                   生克结算、词条判定、支付枚举与敌方求解
    game.js                    状态机：设置/玩家回合/敌方回合/结算、灵力与重铸
  components/
    card-view.js               卡牌渲染（含词条高亮与附着属性）
    element-ring.js            五行环通用组件（分配/支付两种模式）
    element-allocator.js       设置阶段的五行分配面板
    deck-picker.js             卡组选择页
    battle-view.js             战斗页（状态、灵力、支付、手牌、日志）
    anim.js                    点数飞行、出牌飞行、飘字
  main.js                      渲染路由、事件委托、动画联动
```

状态集中在 `XGame.getState()`，UI 每次事件后整体重渲染；动画作为独立浮层元素播放，不参与状态。

## 九、可调参数

集中在 `src/core/game.js` 顶部：

| 常量 | 默认值 | 含义 |
| --- | --- | --- |
| `PLAYER_MAX_HP` | 40 | 玩家气血上限 |
| `ENEMY_MAX_HP` | 48 | 敌方气血上限 |
| `ENEMY_ALLOCATION` | `金2 木2 水1 火3 土2` | 敌方每回合五行分配 |
| `HAND_SIZE_PLAYER` | 5 | 玩家每回合抽牌数 |
| `HAND_SIZE_ENEMY` | 3 | 敌方每回合抽牌数 |
| `ENEMY_PLAYS` | 2 | 敌方每回合出牌数上限 |
| `SPIRIT_MAX` | 100 | 灵力上限与初始值 |
| `SPIRIT_GAIN` | 15 | 每回合恢复灵力（最大值的 15%） |
| `REROLL_COST` | 20 | 重铸消耗灵力（最大值的 20%） |

## 十、已知限制

- 单一敌人、单一战斗，没有关卡、遗物或局外成长。
- 敌方无意图预告，AI 每次都取当前理论最优支付，行为可预测。
- 敌方属性整场战斗固定，不会随回合重新随机。
- 灵力只有重铸一个用途；重铸后的点数不永久改变设置阶段的分配。
- 没有存档、撤销、音效；所有状态仅存在于内存中。
