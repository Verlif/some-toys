快速开始

1

启用 GitHub Pages

打开仓库 Settings → Pages，Source 选择 Deploy from a branch，Branch 选 main，文件夹选 / (root)，保存。

2

配置 Actions 写权限

打开 Settings → Actions → General，在 Workflow permissions 中选择 Read and write permissions，保存。

3

把 HTML 放进 pages/

直接把 AI 生成的文件丢进去。想分组就建一级子文件夹，文件夹名就是分组标题。

pages/ ├─ demo.html # 第一层直接显示 ├─ 小游戏/ # 分组：小游戏 │ └─ snake.html └─ 工具/ └─ converter.html
4

推送

git add pages/ git commit -m "add new page" git push

Action 自动运行，生成导航页并提交回仓库，GitHub Pages 自动部署。稍等片刻，刷新导航页就能看到新卡片。

自动图标映射

生成脚本会根据文件名或分组名自动匹配图标，无需手动配置。

关键词 图标 说明
game / 小游戏 fa-gamepad 游戏类页面
tool / 工具 fa-wrench 实用工具
demo fa-flask 演示页面
blog fa-pen-fancy 文章页面

其他 fa-file-code 默认图标

想加新图标，只需在 generate-index.js 的 iconMap 里加一条映射即可，值使用 Font Awesome 的类名。

工作流程

# 你只需要做第一步 把 HTML 放入 pages/ ↓ git push ↓ GitHub Actions 触发 ↓ 运行 generate-index.js，扫描 pages/ 并生成 index.html ↓ 提交并 push 回仓库 ↓ GitHub Pages 自动部署 ↓ 导航页更新，新卡片 / 新分组出现

常见问题

Action 报错 ENOENT: no such file or directory, scandir 'pages'

pages/ 文件夹没有被 Git 跟踪。Git 不跟踪空文件夹，放入至少一个 HTML 文件，或添加 pages/.gitkeep 占位文件后提交。

Action 报错 remote: Permission to ... denied 或 403

检查 Settings → Actions → General → Workflow permissions 是否为 Read and write，并确认工作流中声明了 permissions: contents: write。

Action 报错 remote rejected ... (failure)

通常是因为 main 分支有保护规则，阻止了 bot 推送。到 Settings → Branches 删除或放宽保护规则。

访问 Pages 地址显示 404

确认 Pages 的 Source 为 Deploy from a branch，分支为 main，文件夹为 / (root)。刚部署完请等待几分钟再刷新。

分组没有显示出来

确认子文件夹里至少有一个 .html 文件。空文件夹会被跳过。只支持一层文件夹作为分组，嵌套更深的目录会被忽略。

AI 生成的 HTML 里有外部依赖怎么办

只要能独立运行即可。依赖 CDN 的 CSS/JS 保持原样；有本地图片等资源，建议一并放进 pages/ 并保持相对路径正确。
