这是什么

someToys 是一个「只负责展示」的作品架：把作品放进 pages/ 目录，推送到 GitHub，Actions 会自动扫描、生成带分组与搜索的导航页，再由 GitHub Pages 发布。单个 HTML 文件和多文件项目文件夹都收，整个过程不需要手写任何清单或配置。

支持哪些作品

判断规则只有一条：文件夹里有没有 index.html。来源不限、技术栈不限，纯静态就行。

单文件页面

一个 .html 里塞满 CSS / JS，双击就能跑。手写的、AI 生成的、工具导出的都算。

pages/随便什么名字.html

项目文件夹

index.html 加 css / js / img 的多文件项目，整目录收成一张卡片，内部相对路径不用改。

pages/项目名/index.html

分组文件夹

没有 index.html 的文件夹用来归类，里面的页面、项目和子分组会被递归收录，可无限嵌套。

pages/分组名/…

不挑来源：手写页面、AI 生成、脚手架打包产物（Vite / webpack 的 dist）、教学 Demo、数据可视化、小游戏、文档页……只要能用浏览器直接打开就行。

唯一硬要求是「纯静态」：需要服务端、数据库或运行时构建的项目（Node / PHP 后端、SSR）不在射程内 —— GitHub Pages 只提供静态托管。

核心特性

单文件 / 项目都收

单个 HTML 与多文件项目文件夹各自成卡，卡片上会标明是哪一种形态。

自动分组

没有 index.html 的文件夹自动成为分组，子分组可以无限嵌套。

实时搜索

按标题、描述、文件名和标签过滤，命中处高亮，无匹配的分组自动隐藏。

全自动构建

GitHub Actions 在每次推送后自动扫描并重新生成导航页。

中英双语

导航页与介绍页内置中文 / 英文切换，语言偏好自动记忆。

跨端响应式

手机、平板与桌面分别适配：窄屏抽屉导航、单列瀑布卡片。

双主题

暗色与亮色主题自由切换，可跟随系统，选择会被记住。

零成本

基于 GitHub Pages 托管，完全免费，自带 HTTPS 与 CDN 加速。

快速开始

1

启用 GitHub Pages

打开仓库 Settings → Pages，Source 选择 Deploy from a branch，Branch 选 main，文件夹选 / (root)，保存。

2

配置 Actions 写权限

打开 Settings → Actions → General，在 Workflow permissions 中选择 Read and write permissions，保存。

3

把作品放进 pages/

单个 HTML 直接丢进去；多文件项目放进自己的文件夹并确保入口叫 index.html；想归类就建一个没有 index.html 的分组文件夹，文件夹名就是分组标题。

pages/ ├─ demo.html # 根目录单文件页面 → 一张卡片 ├─ games/ # 分组：games │ └─ snake.html └─ 抽卡模拟/ ├─ index.html # 项目文件夹 → 一张卡片 ├─ css/ └─ js/
4

推送

git add pages/ git commit -m "add new page" git push

Action 自动运行，生成导航页并提交回仓库，GitHub Pages 自动部署。稍等片刻刷新即可看到新卡片。

工作流程

# 你只需要做第一步 把作品放入 pages/ ↓ 触发 GitHub Actions ↓ 运行生成脚本，递归扫描并生成导航页 ↓ 提交并推送回仓库 ↓ GitHub Pages 自动部署 ↓ 导航页更新，新卡片 / 新分组出现

常见问题

Action 报错 ENOENT: no such file or directory, scandir 'pages'
pages/ 没有被 Git 跟踪。Git 不跟踪空文件夹，放入至少一个 HTML 文件，或添加 pages/.gitkeep 占位文件后提交。
Action 报错 Permission denied 或 403
检查 Workflow permissions 是否为 Read and write，并确认工作流中声明了 permissions: contents: write。
Action 报错 remote rejected
通常是 main 分支的保护规则阻止了 bot 推送。到 Settings → Branches 删除或放宽保护规则。
访问 Pages 地址显示 404
确认 Source 为 Deploy from a branch、分支为 main、文件夹为 / (root)。刚部署完请等待几分钟再刷新。
分组没有显示出来
确认文件夹（含子目录）里至少有一个 .html 文件，完全空的文件夹会被跳过。
不是 AI 生成的页面，能放进来吗
能，来源完全不限。手写页面、模板导出、脚手架打包产物（Vite / webpack 的 dist）都行，只要是纯静态、浏览器能直接打开。
项目里有 css / js / img 等多个文件，怎么放
整个项目放进一个文件夹，主页面命名为 index.html，再把文件夹放进 pages/ 的任意位置。页面内用相对路径引用资源，不需要改路径。
需要后端或数据库的项目能收吗
不能。GitHub Pages 只做静态托管，服务端代码不会被执行。这类项目请另找托管，等它们能导出成纯静态产物后再放进来。
页面里有外部依赖怎么办
只要能独立运行即可。CDN 上的 CSS / JS 保持原样；本地资源放进项目文件夹并用相对路径引用。
