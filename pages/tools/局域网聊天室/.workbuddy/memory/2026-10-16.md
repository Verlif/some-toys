# 2026-10-16

## 局域网聊天室：单文件 → 多目录工程重构（含二维码/扫码）

**背景**：原为 `deepseek_html_20261016_6010c6.html`（973 行单文件，内联 CSS+JS），
WebRTC DataChannel P2P 聊天 + 手动信令（SIG1 gzip+base64 / SIG0 降级）。

**已确认的方案选型**（用户四项均采纳推荐项）：
- 无构建纯静态，原生 ES Modules
- 二维码库本地 vendor 化（离线可用）
- 扫码 = 摄像头实时识别 + 上传图片降级
- 手机端采用抽屉式侧栏

**产出结构**：
```
index.html                     仅骨架，样式/逻辑全外链
tools/serve.mjs                零依赖静态服务器（默认 5173）
tools/check.mjs                零依赖静态校验
src/styles/  base | layout | components | chat
src/vendor/  qrcode-generator.min.js(20KB) jsqr.min.js(130KB)
src/js/      main | config | state
             utils/ dom bus format clipboard toast binary
             core/  signaling connection peers inbound chat file-transfer
             qr/    qr-render qr-scan
             ui/    sidebar chat-view modal connect-modals
```

**关键设计决策**：
- 分层 `utils → core → ui` 单向依赖；core 不碰 DOM，通过 `utils/bus.js` 事件总线
  广播（PEERS_CHANGED / SELECTION_CHANGED / CHAT_REFRESH / PEER_ONLINE / NAME_CHANGED）
- 信令格式保持 `SIG0/SIG1` 与载荷结构完全不变 → 新旧版本可互连
- DataChannel 绑定集中在 `core/connection.js`，`core/peers.js` 只做注册表与消息仓库（避免循环依赖）
- 二维码用 typeNumber=0 自动选版本、纠错等级 L；canvas 以高分辨率绘制后交 CSS 缩放
  + `image-rendering: pixelated` 保证任意缩放下模块边界清晰
- 新增 `discardPendingAnswer()`，关闭接受向导时释放未被使用的 RTCPeerConnection

**踩过的坑**：
- CSS 层叠：`layout.css` 先于 `chat.css`/`components.css` 加载，同优先级下后加载者胜。
  组件级响应式规则必须写在组件自己的文件里，`layout.css` 只保留外壳与抽屉逻辑。
- `@media` 不增加选择器优先级 —— 容易误以为媒体查询里的规则一定能覆盖基础规则。
- ES Module 不能 file:// 直接打开，必须走 HTTP（故提供 serve.mjs）。
- 摄像头 `getUserMedia` 要求安全上下文：局域网 IP + http 下会被拦截，已实现自动降级提示。

**校验方式**：`node tools/check.mjs`（未做运行时测试，符合用户要求）
→ 22 个 JS 模块语法 / 28 条资源与依赖引用 / 48 个 DOM id / 4 个 CSS 括号配平，全部通过。

**遗留**：原单文件版本保留在同目录作对照，README 已注明可删。

### 2. 闪烁修复（关键）
**根因**：原来每次 `CHAT_REFRESH` 都 `container.innerHTML=''` 全量重建 →
① 所有气泡重放 `fadeIn` 动画造成整屏闪烁；② `<a href="blob:...">` 被重建导致下载被打断；
③ `scrollTop = scrollHeight` 强行拽到底部。

**方案**（`ui/chat-view.js` 的 `syncMessages`）：
- 一条消息只建一次节点，挂在 `m._node` 上，之后复用
- 新节点挂 `.is-new` 播动画，`animationend` 后立即摘类（即使节点被移动也不会重复闪）
- 文件进度只改 `.file-meta` 文字 + `.progress-fill` 宽度，**绝不重建节点**；仅终态(done/failed)
  才换一次 innerHTML（此时没有下载在进行）
- 只在 `node.parentNode !== container` 时 append，避免无谓的 DOM 搬动
- 切换会话才整屏重建 + `releaseNodes()` 释放旧会话引用
- 新增「贴底才跟随滚动」：`scrollHeight - scrollTop - clientHeight < 80` 或自己发消息才滚底

### 3. 拖拽发送（新增 `ui/dropzone.js`）
- `dragenter/dragleave` 计数判定是否真的离开窗口（子元素间移动会成对触发）
- `!e.relatedTarget` 判定拖出窗口；`dragend` 兜底收起
- **非文件拖拽不 preventDefault**，文本仍可正常拖进输入框
- 支持多文件顺序发送，超 500MB 二次确认

### 4. 二维码带页面地址
- `core/signaling.js` 新增 `buildShareUrl(code)`（非 http(s) 返回空串）与
  `extractSignalCode(text)`（原始码 → 原样；链接 → 取 `#code=` / `?code=`）
- 二维码内容 = `origin + pathname + #code=<encodeURIComponent(码)>`，
  **超出容量自动回退为纯码**并在 hint 里说明
- 用 `decodeURIComponent` 而非 `URLSearchParams` 优先解析（后者会把 base64 里的 `+` 当空格）
- 新增「复制链接」按钮
- 启动时 `applyCodeFromUrl()`：解析地址栏 `#code=` → 解压判断 type →
  offer 则开「接受连接」填码；answer 则开「创建连接」填码并**明确提示**
  「应答码只有发起方能用，请回到原页面」→ 处理完 `history.replaceState` 清掉 hash

**重要认知**：`state.pendingOfferPc` 只在内存里，页面刷新即丢。所以**应答码链接在全新页面
永远无法完成连接**（协议固有限制），已用提示文案引导用户回到原页面用内置扫描读取。

## 第三轮：修复「粘贴邀请码后按钮不亮」+ 站内对话框

### 修复的 bug：粘贴邀请码后「生成应答码」按钮不亮

**根因**：`refreshAnswerState` / `refreshFinishState` 用的是严格的 `isSignalCode(box.value)`，
即 `/^SIG[01]:/`。只要粘贴的内容不是「以 SIG0:/SIG1: 开头的裸码」就判定失败：
- 粘贴**分享链接**（上一轮刚加的「复制链接」按钮，极容易踩到）❌
- 粘贴被 IM 换行 / 加了尾注的码 ❌
- 前面带零宽字符或说明文字（「邀请码：SIG1:...」）❌

**修复**（`core/signaling.js`）：
- `isSignalCode` 改为先归一化再判断：`CODE_PREFIX.test(extractSignalCode(text))`
- `extractSignalCode` 重写为三段式：① 分享链接取 `#code=`/`?code=` →
  ② 全文搜索 `SIG[01]:` 定位后清洗 → ③ 清掉空白与零宽字符兜底
- 新增 `sanitizeCode()`：只保留 base64 字符，**并在首个 `=` 处截断**（base64 的填充符
  只出现在末尾）—— 否则「...AAAA==（共 812 字符）」里的数字会被当成码的一部分

**修复**（`ui/connect-modals.js`）：
- 新增 `readBoxCode()`：所有读取码的地方统一走归一化（生成应答码、完成连接、按钮状态）
- 新增 `bindCodeBox()`：`input` 实时刷新按钮 + `change`/`paste`（延时 0）归一化并校验
- 新增黄色校验提示 `#acceptFlowHint` / `#answerBoxHint`：内容不是有效码时明确说明原因，
  不再是「按钮不亮但不知道为什么」

**用真实用例验证过**（临时目录跑完即清理，未留在项目里）：裸码 / SIG0 降级码 /
百分号编码链接 / query 形式链接 / 已被外部解码的链接 / 带前缀说明 / 6 个位置断行 /
5 种尾部附着文字（含数字与 emoji）/ 链接+说明文字 / 4 种非码输入 —— 全部通过。
过程中还靠这组用例发现 `=` 截断缺失这个真实缺陷。

### 新增 `ui/dialog.js`：站内对话框

- `promptDialog({title,message,value,placeholder,maxLength,confirmText,validate})` → Promise<string|null>
- `confirmDialog({title,message,confirmText})` → Promise<boolean>
- 单实例，同时只服务一个请求；新请求会按「取消」结掉旧 Promise，避免悬挂
- 绑定：Enter 确认、Esc 取消、点击遮罩取消、validate 返回错误文案则不关闭
- `modal.js` 的 Esc 处理增加 `#dialogMask` 判定，主动让位给对话框
- 替换点：昵称修改（sidebar）、大文件确认（chat-view 与 dropzone）
- 现在全项目除 `dialog.js` 内 DOM 缺失时的兜底外，**再无 window.prompt/confirm/alert**

### 校验
24 个 JS 模块、63 个 DOM id、46 个 CSS 变量、10 个图标引用，全部通过；
另外单独确认了 index.html 标签配平与对话框 8 个 id 齐备。

## 第四轮：昵称广播 + 图片直接预览

### 1. 昵称同步给所有在线连接

协议新增 `{ type:'name', name }`。链路：
- `state.setName()` 统一做 trim + `NAME_MAX_LENGTH`(20) 截断
- `core/peers.js`：`broadcast(payload)` 给所有在线 peer 发；
  `syncMyName(name)` = 广播 name 帧；`changeMyName(raw)` = 本地保存 + 广播的**原子动作**，
  返回 `{ok, synced}`，避免调用方漏掉同步
- `core/inbound.js`：`case 'name'` → `updatePeerName(peer, name)`：
  长度截断、同名短路、改名后 emit PEERS_CHANGED + CHAT_REFRESH，
  并追加系统消息「旧名 改名为 新名」
- `ui/sidebar.js` 调 `changeMyName`，toast 会说明同步给了几个连接 / 无线可同步
- **额外**：`connection.js` 的 channel onOpen 里对一次昵称，覆盖
  「对方生成邀请码之后、连接建立之前才改名」的时序差（同名时 updatePeerName 短路，无副作用）

### 2. 图片直接预览

- 协议：`file-start` 增加 `mime` 字段（向后兼容，旧版不发则按扩展名兜底）
- `file-transfer.js` 新增并导出 `isImageFile(name, mime)`：
  **有 MIME 就以 MIME 为准，没有才看扩展名**（避免 a.png 声称 application/pdf 时误判）
- 消息对象带 `isImage`：**传输中显示文件卡片 + 进度条，done 才换成缩略图** ——
  避免布局跳动
- `ui/image-preview.js`（新增）：全屏预览，点图片/空白/Esc 关闭，带下载原图按钮；
  关闭时摘掉 `img.src` 让浏览器尽快停止解码
- `chat-view.js`：`#messages` 上做事件委托，点 `.img-thumb` 用 `src` + `data-name` 打开预览
- CSS：缩略图 `max-width:100% / max-height:300px` 保比例不裁剪；
  `.msg.has-image` 单独收窄内边距与最大宽度
- `modal.js` 的 Esc 让位检查新增 `#imageViewer`
