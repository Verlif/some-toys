# 2026-10-17

## 排查并改善二维码扫描准确率

### 诊断（用 vendored 库算的真实数据）

载荷 1100 字符 → **v24 → 113×113 模块**。jsQR 稳定识别需 ≥3 px/模块。

三个叠加原因：
1. **采集端主动丢分辨率**：`decodeMaxEdge: 720` 把整帧 1280×720 缩到 720×405 才识别，
   双线性降采样还糊掉模块边缘 → 实际 2.55 px/模块
2. **`image-rendering: pixelated` 用反**：canvas 1287px 缩到 300 CSS px，
   最近邻采样让模块宽度在 2px/3px 间交替 → 几何失真
3. **物理尺寸太小**：300 CSS px 在手机上约 47mm，摄像头 25cm 处只占画面 ~15%

另外发现：上一轮给二维码加页面地址后，载荷 900→1100，矩阵 101→113，密度实打实上了一档。

### 落地改动（用户确认「四项全改、不动载荷」）

**采集端**（`qr/qr-scan.js`）
- `decodeMaxEdge` 720 → 1080；`drawVideoFrame()` 只取**中心正方形裁剪**，
  `scale = min(1, 1080/side)`，720p/1080p 摄像头**完全不需要缩放**
- 图片识别单独走 `drawImageFrame()`（二维码位置不确定，按整图 + 1600 上限）
- `getUserMedia` 请求 1920×1080 + `advanced: [{ focusMode: 'continuous' }]`
- fps 8 → 12；扫描框 62%/260px → 70%/280px（更贴近裁剪区）
- 3 秒未识别 → 提示「靠近一些 / 点二维码放大后再扫」

**显示端**（`qr/qr-render.js`）
- `createQRCanvas(text, targetCssSize)`：按 `cssSize × dpr` 反算整数 `unit`，
  1:1 设备像素绘制，再据实际像素反推 CSS 尺寸 → **零重采样，模块宽度绝对均匀**
- 删除 `QR.maxCanvasSize` / `QR.minModuleSize`，改为
  `maxDisplaySize:340`、`displayViewportRatio:0.78`、`maxZoomSize:720`、`denseThreshold:100`
- 显示尺寸还受 `innerHeight*0.52` 限制，避免矮屏把弹窗撑得要滚
- CSS 移除 `image-rendering: pixelated/crisp-edges`，`.qr-canvas` 尺寸交给行内样式
- **点二维码本身即可放大**（原来只有按钮）；编码内容挂在 `blockEl.dataset.qrText`，
  不再依赖「最后渲染的那个」这种隐式状态
- 矩阵 >100 时 hint 追加「码较密，建议放大后再扫」

### 量化收益
- 采集端：2.55 → 4.53 px/模块（**1.78x**）；达到 3px/模块阈值所需画面占比 47% → 27%
- 显示端：PC dpr1 3px/模块、dpr2 6px、手机 dpr3 8px，且**全部均匀**
  （旧方案是 2~3px 交替）

### 明确不做
- **不提高纠错等级 L→M/Q**：会让矩阵更密、每模块像素更少，在分辨率受限场景是净负收益
- **不精简载荷**（过滤虚拟网卡 ICE 候选能省 10~15%）：为二维码小 10% 去动连接路径不值

校验：25 模块 / 69 DOM id / 46 变量 / 11 图标引用全通过，无旧参数残留。
