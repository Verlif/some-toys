## 随机抽奖工具：单文件 → 多目录工程化重构 + 样式重做

**背景**：原 `随机抽奖.html`（约 2050 行，HTML+CSS+JS 全内联）重构为规范的多文件项目，并重做 UI、支持亮暗主题切换。

**最终结构**
```
index.html
css/main.css（@import 入口）
  base/  reset.css · theme.css · responsive.css
  layout/ header.css · layout.css
  components/ button · form · item-list · result · scroll-stage · dropdown · history · modal .css
js/main.js
  core/    state.js · dom.js · storage.js
  modules/ theme.js · modal.js · items.js · scroll.js · history.js · result.js · config-panel.js
  utils/   debounce.js · array.js · stats.js
```

**关键决策**
- 采用 ES Module（`type="module"`），需通过 HTTP 打开，不能用 file:// 双击。
- 主题用 `<html data-theme>` + CSS 变量双套令牌，取代原先 `.dark-mode` 的 30+ 条覆盖规则；旧键 `darkMode` 自动迁移到新键 `drawTheme`，且首次访问跟随系统偏好。
- 状态集中到 `core/state.js`；localStorage 读写收口到 `core/storage.js`。
- 拆出 `utils/stats.js` 存放 `getMostFrequent`，避免 result ↔ history 循环依赖。
- 所有用户内容改用 `textContent` 渲染（原来用 innerHTML 拼串，存在注入与引号转义问题）。
- 权重就地编辑改为「隐藏 label + 兄弟 input」，不再在 button 内嵌 input。

**修复的既有缺陷**
- 全局重置里 `input:not([type="range"])` 的优先级(0,1,1) 会压过 `.field`(0,1,0)，导致输入框边框/背景被清掉 —— 已改为只重置 button。
- 长按↓时只刷新被点行，其他行百分比会短暂失真 —— 统一改为 `syncWeightDisplays()` 全量刷新。
- 历史删除后未 `saveState()`；启动时未渲染已恢复的历史/结果 —— 已补。
- 原 `stopDraw()` 用 `clearTimeout` 遍历清空所有定时器（会误杀弹窗定时器）—— 改为只记录并清除滚动定时器。
- `getArrayGCD` 传入空数组会抛错 —— `arrayGcd` 加了空数组兜底。

**静态校验方式**（沿用用户偏好，不写运行时测试）
- `node --check` 全部 14 个 JS 文件。
- css-tree 解析全部 14 个 CSS：语法 + var() 声明/引用闭环（40 个变量）。
- jsdom 加载：资源/import 链路可达、dom 引用 30 个全命中、主题切换、长按权重上下限、就地编辑(Enter/Esc/非法值回滚)、完整抽奖流程、历史排序、配置存取、Esc 关闭弹窗、状态持久化。
- 校验脚本为一次性使用，跑完即删，不留在项目里。

**预览**：本地静态服务 `http://127.0.0.1:5183/`（脚本在工作区 node workspace，不在项目内）。

## 迭代 2：权重就地编辑框重做

**问题**：点击项目弹出的权重输入框是一个 62px 的裸小方框浮在进度条上，与整体风格割裂。

**方案**：把 `.item__label` 从「铺满进度条的文字层」改为**数值胶囊**——
- 胶囊自带 `--surface` 底色 + `--shadow-sm`，无论进度条填充到多少，文字永远有稳定对比度（原先在深色主题下浅色文字压绿底只有约 2.6:1）。
- 文字拆成三段：`.item__label-prefix`（权重:，`--text-2`）、`.item__label-value`（数值，`--text-1` 加粗，固定 30px 居中）、`.item__label-suffix`（百分比）。
- 编辑时**只替换数值那一段**为透明输入的 input，前后文案原位不动；胶囊加 `.is-editing` 显示 `--accent-ring` 光环，视觉上仍是同一个组件，不再有"浮框"感。
- 隐藏数字框的上下微调箭头。

**顺带修掉的 bug**
- 编辑框内按 Enter 后 keydown 冒泡回胶囊，会立刻重新打开编辑器（表现为"改完又变回输入框"）。加 `event.target !== label` 守卫拦截。
- 移除已无用的 `--weight-shadow` 令牌（两套主题各一处）。

**新增校验项**：胶囊三段结构、编辑态 role/tabindex 让位与恢复、Enter 提交 / Esc 取消 / 非法值回滚 / 失焦提交、步进后胶囊数值同步。

## 迭代 3：权重文案改为透明压条（用户反馈胶囊底挡住进度条）

**问题**：迭代 2 的不透明胶囊底把进度条挡住了，看不到填充比例。用户要求去掉底色。

**方案**：`.item__label` 彻底去掉 `background` / `box-shadow` / `border-radius` / `padding`，改为**纯文字直接压在进度条上**。
- 可读性改用 `text-shadow: 0 0 3px var(--surface), 0 0 6px var(--surface)` 的柔和描边托底。**用 `--surface` 做描边色天然自适应两套主题**：亮色主题深字配白描边、暗色主题浅字配深描边，无需新增令牌。
- 编辑框收到 34px × 20px，仅遮住数值那一小段，带 2px accent 环标示激活；`.item__label-value` 的 `min-width` 同步改成 34px，进出编辑不产生位移。
- 移除随之失去意义的 `.is-editing` 类与 CSS 规则（JS + CSS 各一处）。

**新增回归校验**：解析 CSS AST 断言 `.item__label` 规则中**不存在** `background`/`background-color`/`box-shadow`，且必须含 `var(--surface)` 的 `text-shadow`——防止以后有人手滑把底色加回来。

**经验**：`.item__label` 这类压在进度条上的文字，用主题表面色做 text-shadow 描边比加不透明底色更好——既不遮挡数据，又能双主题自适应。

## 迭代 4：去掉文字阴影（用户反馈反色描边太丑）

**问题**：迭代 3 的 `text-shadow` 双色描边在视觉上脏，用户要求去掉。

**方案**：删除 `.item__label` 的 `text-shadow`；同时把文字颜色从 `--text-2` 提为 `--text-1`——去掉托底后，次级灰压在绿色填充区上对比度仅约 1.8:1（暗色主题更低），主文本色才能保证可读。层级改由字重区分：前缀/百分比 500、数值 700。

**校验脚本升级（重要经验）**：
- jsdom **不执行** `<script type="module">`，`runScripts: "outside-only"` 下手动注入内联 module 也不会跑。
- 早期用"剥掉 import/export 后拼接 bundle 再 eval"的方式**有缺陷**：`items.js` 与 `result.js` 都有顶层 `createRow`，拼接后后者覆盖前者，`renderList()` 会渲染出 `result-row`——这是校验方法的假象，不是项目 bug。
- **正确做法**：Node 原生 ESM `await import(pathToFileURL(...))`，import 前把 jsdom 的 `window`/`document`/`localStorage`/事件类等注入 `globalThis`（Node 22 的 `navigator` 只读，需 `Object.defineProperty`）。作用域隔离、无冲突，模块图由 Node 自动解析。
- css-tree 注意：AST 顶层是 `ast.children`（数组，无 `.each`），序列化用 `csstree.generate` 而非 `stringify`。

**新增回归校验**：断言 `.item__label` 无 `text-shadow`/`background`/`box-shadow` 且颜色为 `var(--text-1)`；`item-list.css` 与 `theme.css` 全文无 `text-shadow` 残留。
