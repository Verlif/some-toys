# 城市地图 · 编辑器 + 路线 — 开发文档

> 本文档面向开发者，说明项目的目录结构、模块职责、数据模型、关键算法与扩展方式。
> 重构目标：从单文件 `地图连线.html` 拆分为规范的多文件结构，同时保持原有交互行为。

---

## 一、目录结构

```
地图连线/
├── index.html              # 入口：引入下方 css/js，承载全部 DOM 与 SVG defs
├── 地图连线.html           # 原始单文件（保留作对照/回退，可删除）
├── css/
│   ├── variables.css       # 主题变量（配色 / 字体 / 圆角 / 阴影）
│   ├── base.css            # 重置 + 应用外壳 + 道路/地点共享样式 + 完成态
│   ├── editor.css          # 编辑器专属 UI（模式栏 / 提示 / 底部操作 / 地点编辑框）
│   ├── game.css            # 游戏专属 UI（标题 / 缩放控件 / 路线面板 / 路径链 / 提示）
│   └── responsive.css      # 多设备响应式（平板 / 桌面卡 / 横屏压缩 / 粗指针）
├── js/
│   ├── config.js           # 全局配置：预设图标、示例地图、阈值与限制常量
│   ├── utils.js            # 工具函数：选择器 / 夹取 / 哈希 / 道路路径 / 转义
│   ├── viewport.js         # Viewport 类：平移缩放变换（编辑器与游戏共用）
│   ├── storage.js          # 持久化：JSON 导出下载、文件读取、localStorage
│   ├── editor.js           # 编辑器逻辑（放置/连线/删除/拖动/撤回/导入导出）
│   ├── game.js             # 路线游戏逻辑（连接规则/渲染/提示）
│   └── main.js             # 引导与编排（初始化、屏幕切换、开始游戏、resize）
└── docs/
    ├── 使用说明.md
    └── 开发文档.md
```

### 加载顺序与依赖
`index.html` 按依赖顺序用经典 `<script>` 引入（**非 ES Module**，因此可直接 `file://` 打开）：
`config → utils → viewport → storage → editor → game → main`。

所有模块挂载到全局命名空间 **`window.App`**，互不污染全局作用域：
`App.config / App.utils / App.Viewport / App.storage / App.Editor / App.Game`。

## 二、模块职责

### `config.js` — `App.config`
集中所有可调参数：预设地点 `PRESETS`、示例地图 `SAMPLE_PLACES/SAMPLE_EDGES`、
阈值（`NEW_PLACE_MIN_DIST`、`LONG_PRESS_MS`、`MOVE_THRESHOLD` 等）、缩放范围、本地存储键。

### `utils.js` — `App.utils`
- `$`：按 id 取元素。
- `clamp`：数值夹取。
- `hashCode(str)`：稳定哈希，用于道路弯曲方向（保证连线确定性，便于复现）。
- `edgeKey(a,b)`：无序道路键（A-B 与 B-A 等价）。
- `roadPath(a,b)`：两点间道路路径（两段三次贝塞尔，中间外弯避免反向边重叠）。
- `placeScale(scale)`：地点随地图缩放的补偿缩放（保持视觉大小恒定）。
- `esc(str)`：HTML 转义，用户文本注入 SVG 前进行，避免 XSS。

### `viewport.js` — `App.Viewport`
维护世界坐标 → 屏幕坐标的变换（属性 `scale / tx / ty`），并对外提供：
- `applyTransform()`：刷新世界层变换、对地点做补偿缩放、更新缩放百分比、按需隐藏名称。
- `set / panTo / zoomAround / zoomAtClient / zoomCenter / screenToWorld / resetView`。

> 设计取舍：Viewport 仅负责**变换数学与刷新**，不处理「点击 / 长按 / 拖动地点」等
> 业务手势判定（这些留在 `editor.js` / `game.js` 各自实现），以此在复用与可控之间取得平衡。

### `storage.js` — `App.storage`
- `downloadJSON(data, filename)`：下载 JSON 文件。
- `readFileText(file)`：Promise 读取文件文本。
- `saveEditor(state)` / `loadEditor()`：localStorage 持久化（带 try/catch 容错）。

### `editor.js` — `App.Editor`
编辑器核心。`init()` 绑定事件并恢复或载入示例；对外暴露 `init / resetView / getMap`。
状态对象 `editor = { places, edges, mode, pending, history, nextId }`。
支持：三种模式、拖动、双击编辑、撤回栈、示例、导入导出、拖拽导入、自动保存。

### `game.js` — `App.Game`
路线游戏核心。`init()` 绑定事件；`loadFrom(map)` 载入地图；`resetView()` 自适应。
状态对象 `game = { places, edges, placeMap, adj, startId, path, finished }`。
连接规则：相邻即可走；回到起点需已走过 ≥3 个不同地点。

> **已修复的类型一致性 Bug**：原单文件版中 `dataset.id`（字符串）与邻接 `Set`（数字）比较
> 会导致点击连接失效。本版在读取 `dataset.id` 处统一 `Number()` 归一化，确保游戏可正常游玩。

### `main.js` — 引导
`Editor.init()` + `Game.init()` → 绑定「开始游戏」→ 切换屏幕并 `requestAnimationFrame` 复位视图 →
监听 `resize` 做 200ms 防抖的视图自适应。

## 三、数据模型

### 地点 Place
```js
{ id: Number, x: Number, y: Number, icon: String, name: String, color: String }
```
- `x/y` 为**世界坐标**（SVG 用户坐标系），不绑定屏幕像素，视图缩放/平移时保持稳定。
- 渲染时通过 `style="--c:<color>"` 注入主题色，供 `.place-halo/.place-ring` 使用。

### 道路 Edge
```js
[fromId: Number, toId: Number]   // 无序对
```
- 渲染与查重统一走 `edgeKey(a,b)`（排序后拼接 `|`），保证 A-B 与 B-A 视为同一条。

### 游戏邻接表
```js
game.adj = { [id]: Set<id> }   // 无向图
```
从 `edges` 双向构建；`canConnect` / `tryConnect` 基于它判定可走性。

## 四、关键算法

### 1. 道路路径（贝塞尔弯曲）
`roadPath(a,b)`：以两端点中点为基准，沿法线方向偏移（方向由 `hashCode(a.id+b.id) % 2` 决定，
**确定性**），生成 `M … C …` 两段三次贝塞尔。偏移量 `min(len*0.13, 60)`，既避免与反向边重叠，
也让直角连线更有“路感”。

### 2. 视口变换
- 世界层：`transform="translate(tx ty) scale(scale)"`。
- 地点补偿：地点随世界一起被缩放，为保持视觉大小恒定，对每个地点额外施加
  `scale(k)`，`k = clamp(1/scale^0.8, 0.5, 3.6)`。
- 缩放锚点：以指针/中心为不动点重算 `tx/ty`，保证“放大时指针下的点不动”。
- 自适应：`resetView(bounds)` 按内容包围盒 + padding 计算 fit，并限制缩放范围。

### 3. 手势判定（编辑器）
- **点击 vs 拖动**：位移超过 `MOVE_THRESHOLD`(10px) 视为拖动（平移或移动地点）。
- **长按拖动地点**：按下后超过 `LONG_PRESS_MS`(480ms) 且未移动 → 进入地点拖动模式。
- **双击编辑**：两次点击间隔 < `DOUBLE_TAP_MS`(280ms) 视为双击，打开编辑框。
- **双指捏合**：两根指针时按间距比例缩放。

### 4. 路线闭环判定
`tryConnect`：
- 与当前地点不相邻 → 报错。
- 点起点且 `new Set(path).size >= 3` → 完成闭环（`finished = true`）。
- 否则把地点压入 `path`。

## 五、样式与响应式策略

- **分层 CSS**：共享样式（道路/地点/画布/完成态）在 `base.css`；编辑器与游戏各自独立文件；
  主题色集中 `variables.css`；响应式集中在 `responsive.css`。
- **响应式断点**：
  - `>=600px`：放大触控目标与字号。
  - `>=900px`：桌面端居中为「设备卡」（圆角 + 阴影 + 最大宽度），`body` 变 flex 居中。
  - `>=1400px`：卡片更宽。
  - 横屏矮屏（`max-height:560px`）：压缩面板高度与缩放控件尺寸。
  - `@media (pointer: coarse)`：进一步放大最小点击区域。
- 画布 SVG 始终 `width/height:100%`，配合 Viewport 自适应，任何分辨率下均可完整呈现地图。

## 六、如何扩展

1. **新增预设地点**：在 `config.js` 的 `PRESETS` 数组追加 `{icon,name,color}`。
2. **调整交互阈值**：统一在 `config.js` 修改（`LONG_PRESS_MS`、`MOVE_THRESHOLD` 等）。
3. **换肤**：仅改 `variables.css` 的 CSS 变量即可整体换色。
4. **新增玩法**：在 `game.js` 的 `canConnect / tryConnect` 扩展规则；渲染状态类已预留
   `on-path / current / back / available` 四种高亮，可直接复用。
5. **持久化后端化**：当前编辑器状态存 localStorage；如需多设备同步，可将
   `storage.saveEditor / loadEditor` 替换为后端接口（保持函数签名即可，调用方无需改动）。
