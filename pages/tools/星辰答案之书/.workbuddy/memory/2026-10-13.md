## 星辰答案之书：单文件重构为多目录项目（v2.0.0）

原 `星辰答案之书.html`（约 590 行单文件）已删除，内容全部迁移并重构为：

```
index.html / package.json / README.md
data/texts.txt            文案库，一行一段，# 为注释
docs/DEVELOPMENT.md       开发文档
scripts/build-texts.mjs   txt -> src/data/texts.fallback.js
styles/{base,sky,text}.css
src/config.js             全部可调参数集中于此
src/main.js               装配 + 主循环
src/utils/{math,random}.js
src/core/{viewport,loop}.js
src/data/{texts.js, texts.fallback.js}
src/scene/{sprites,stars,meteors,blackhole}.js
src/ui/answer-text.js
```

### 关键决策

- **模块方案：经典 `<script>` + `window.AnswerBook` 命名空间，刻意不用 ES Modules。**
  原因：ESM 在 `file://` 下被 CORS 拦截，会破坏"双击 index.html 直接看"的使用方式。
  加载顺序是硬约束（多数模块在 IIFE 执行期就读 `NS.config` / `NS.viewport`）。
- **文案双份机制**：`data/texts.txt` 是唯一数据源，`src/data/texts.fallback.js` 由
  `scripts/build-texts.mjs` 自动派生，供 `file://` 下 fetch 被拦截时兜底。
  改完 txt 必须跑一次构建脚本（`npm run build:texts`）。
- **文本节奏参数只定义在 `config.text`**，由 `answerText.start()` 写回 CSS 变量
  `--text-fade`，避免 JS 与 CSS 两处写死时长。

### 黑洞重做要点（改动最大的部分）

原实现是几圈同心"科技感流光弧"，观感更像科幻道具。改为物理上更自洽的结构：

1. 倾斜椭圆吸积盘：局部坐标下按圆盘处理，再 `rotate(roll) + scale(1, squash)`，
   `squash = cos i` 即视线倾角压缩比。局部 `sinθ>0` 为远侧半环、`sinθ<0` 为近侧半环，
   按"远侧 → 视界 → 近侧"顺序绘制即得经典遮挡关系。
2. 新增光子环（1.07R 细亮环）、引力透镜弧（远侧 1.18R 渐隐细弧）、
   多普勒增亮（亮带方向绑定 `spinDir`，亮斑同向加权）。
3. 星点扰动由"任意切向力"改为 `径向内拉 + 同向旋进`，合成为旋进螺旋，
   切向与径向比由 `swirl` 控制。吞没改为 `smoothstep(dimNear, dimFar, dist)`
   连续淡出后再重生（重生点已完全透明，视觉无瞬移）；新增贴边淡入淡出。
4. 需要精确线宽/逐段透明度的地方（透镜弧、流动亮斑）走自算屏幕坐标的
   `project(bh, radius, theta)`，不使用 ctx 变换，避免 `squash` 各向异性拉伸线宽。

### 文本加速

单条周期从约 4.5~6.5s 降至约 2.4~3.2s：
`fade 1500→900ms`、`hold 3000~5000→1500~2300ms`、`gap 700~1500→300~600ms`。

### 校验方式

沿用静态校验约定（不写测试）：对所有 js/mjs 逐文件 `node --check`，全部通过。
未做浏览器运行时验证。

## 追加：黑洞边缘光效精简（v2.1.0）

用户反馈"边缘光效要简洁，只要细细的流光，不要光环"。

**移除**：`drawHalo`（外层引力透镜辉光，半径 8.5R）、`drawPhotonRing`
（0.96R~1.55R 渐变 + 1.07R 细亮环）、`drawLensedArc`（远侧 1.18R 透镜弧），
以及配置项 `haloSpan`。

**新增** `drawEdgeStreak`：绕视界扫掠的单条细弧，半径 `1.06R`。
关键手法是把整条弧拆成 40 小段逐段描边，让透明度与线宽沿弧长连续变化：
`alpha = streakAlpha * (1-t)^2.2`（幂次渐隐，尾巴干净）、
`width = baseWidth * (1 - t*0.65)`（头粗尾细）—— 这正是"流光"与"亮环"的区别，
亮环是一根等宽等亮的线，流光有头有尾。

**新参数**：`streakRadius / streakWidth / streakSpan / streakAlpha / streakSpeed`。
`streakSpan` 取 2.4 rad（约整圈 38%），保证既不成闭环也不会偶尔完全消失。
绘制顺序：远侧盘 → 视界 → 近侧盘 → 流光（放最后，不被近侧盘遮住轮廓）。

**结论/偏好**：用户偏好干净剪影、亮度集中于主体，反对在边缘叠加成圈的装饰性光效。
后续若要加视觉元素，先问是否属于"成圈光环"类。

## 追加：为星点引入真正的惯性（v2.3.0）

用户第三轮反馈："星星被黑洞吸引要有惯性，不是碰到了就跟着转圈，而是靠近时就会
受到引力而开始做移动，然后按照惯性慢慢进入黑洞边缘轨道。"

**根因**：旧模型给星点存了「原位 (x,y) + 位移 (dx,dy)」两套坐标，位移用弹簧-阻尼
拉回原位。位置被弹簧绑住 → 根本没有惯性 → "引力捕获"只能靠一条硬边界，
一碰线就吸附到固定轨道，观感就是"碰到就转圈"。

### 改法

1. **星点模型换成速度积分**：每颗星持有 `(vx,vy)` 当前速度与 `(bvx,bvy)` 基线漂移，
   位置完全由速度积分。删除 `dx/dy/dvx/dvy`、`spring`、`damping`、`maxOffset`。
2. **速度回归只在脱离引力井后发生**：新增 `s.inGravity` 标志，
   由 `blackhole.attract` 置位、`stars.update` 读完即清（自纠正，黑洞中途消失也不卡住）。
   井内保持纯惯性 —— 这是"惯性感"能否成立的关键。
   新增配置 `stars.relaxSec`（默认 2.5s）。
3. **入轨参数由实际速度换算**（`enterOrbit`）：把速度分解为径向 `v_r` / 切向 `v_t`，
   `omega = v_t / radius`（方向 100% 来自惯性，正反都可能），
   `shrink` 由 `max(-v_r, 0)` 钳在 `span/orbitLife*` 与 `span/orbitSettleSec` 之间。
   黑洞的 `orbitDir` 退化为"正面撞上"时的兜底方向。
4. **角速度 + 内落速率一起收敛**（`orbitSettleSec`，1.6s）：
   `orb.omega → orb.targetOmega`、`orb.shrink → orb.targetShrink`。
   只收敛角速度的话总速度仍会突变，两个都要。

### 参数随之调整

`influence` 10 → **6.5**、`pull` 300 → **105**、`captureRadius` 3.2 → **2.8**。
理由：改成全程惯性后俘获量会大幅上升（引力有充足时间把星拽进来），
必须收窄作用范围与强度。若日后觉得卷入的星太多/太少，`pull` 与 `influence` 是主旋钮。

### 意外收获

因入轨时切向速度被钳到 `orbitOmegaMin*0.3`，在入轨半径处切向速度（≈52 px/s）
与原先的径向落速（≈45 px/s）量级相当，所以入轨瞬间的**总线速度几乎连续**，
不会出现明显的"刹车"观感。

## 追加：尾流通用化 + 黑洞力学重做为真实积分（v2.4.0）

用户第四轮反馈：①尾流不该"进入黑洞才突然生成"，应按速度形成轨迹，且要兼容流星；
②去掉"在黑洞边缘运动"，改成被吸引后的惯性环绕，轨迹先从椭圆慢慢变成圆，符合物理。

### 尾流：新增 `src/scene/trail.js`

通用位置缓存，对"黑洞"一无所知：按**固定时间间隔**采样位置点，连成由旧到新、
由淡到浓、由细到粗的折线。接口 `create(spanSec, steps)` → `push(x,y,dt)` /
`reset()` / `draw(ctx, alpha, width, rgb)`。

三个关键性质：
- **长度 = 速度 × span** —— 快则长、慢则短、静止收缩成点，不需要任何开关；
- **按时间采样而非每帧** —— 与帧率无关；
- **通用** —— 星辰与流星（`meteors.js`）共用，流星原来的手算线段端点逻辑删掉。

亮度随速度渐显：`clamp((|v| − trailMinSpeed)/(trailFullSpeed − trailMinSpeed), 0, 1)`。
基线漂移只有 1.2~8.2 px/s，远低于 `trailMinSpeed=25`，所以平时无尾流；
被引力加速到 150 px/s 才满亮度 → 彻底消除"突然生成"的突兀感。

**实体被瞬移（吞没后重生）必须 `trail.reset()`**，否则从旧位置拉出一条长线。
尾流必须画在星点之前（`stars.drawTrails()` 先于 `stars.draw()`）。

### 黑洞：删掉全部参数化轨道，改成两项力的真实积分

删除 `orbit` 状态、`enterOrbit` / `advanceOrbit`、`captureRadius` / `orbitOmega*` /
`orbitSettleSec` / `orbitLife*` / `orbitDir`。现在只有：

| 力 | 形式 | 作用 |
| --- | --- | --- |
| 引力 | `a = gm·R²/(r²+soften²)`，径向，`influence·R` 处平滑收尾 | 无矩 → 角动量守恒 → 真椭圆 |
| 吸积流耦合 | `v += (v_flow − v)·k·dt`，`v_flow = sqrt(a·r)·flowInflow` 切向 | 耗散 → 注入角动量、圆化、内落 |

星点全程只是被积分的质点，没有"入轨"这一刻，所以"俯冲 → 环绕"完全连续。
吞没判定退化为 `r < R`。

### 两条标定结论（重要，别再踩）

1. **切向力不行**：`a_t = swirl·a` 始终与运动同向、持续做正功 → 能量不断灌入 →
   **所有星点最后都逃逸**。必须用"速度耦合"（耗散项，把 v 拖向固定目标速度）。
2. **纯引力自然绕行在本项目尺度下物理不可能**：圆轨道角动量
   `L_c = sqrt(gm)·R·sqrt(r)`，而星点自带 `L = b·v ≤ influence·R·v`（v≈34~68 px/s），
   差一到两个数量级。真实吸积盘物质之所以绕行是**它本来就带着轨道角动量进来**。
   所以吸积流耦合不是作弊，是对"物质被卷入吸积流后获得角动量"的显式建模。

### 标定方法（值得复用）

参数对观感极敏感，做了 7 轮一次性数值仿真（黑洞固定在原点、星点以不同撞击参数掠过，
统计圈数/耗时/半径演化），选定 `gm=2600`、`influence=6.5`、`soften=1.2`、`taper=0.65`、
`flowCoupling=10`、`flowInner=1.5R`、`flowRange=5R`、`flowInflow=0.92`。
脚本是临时的，**没有留在仓库**。方法已写进 DEVELOPMENT.md 4.7。
典型半径演化：9→8.3→…→4.5（俯冲）→3.5→2.8→…→2.3（被抓住）→2.0→…→1.1（圆化内落），
圈数 2~3。

## 续：渐变黑球 / 流星重做 / 回绕亮线 bug（版本 2.5.0）

用户反馈三点：黑洞加"中心纯黑、最边缘透明"的渐变边框并变小；流星太快只能看到
闪烁线条且要带角度。另有一个**没被点名但真实存在的 bug**。

### 1. 真正制造"闪烁线条"的是星点回绕，不是流星

星点出界回绕时只挪了 `(x,y)`、没挪尾流缓存 → 最旧的点在屏幕这头、最新的点在那头，
`trail.draw` 会把两点连成一条**横贯整个画面的亮线**，持续一个 trailSpan（0.5s）。
慢速漂移星因为 `vis` 门槛不画尾流，所以只在"刚被黑洞甩出画面、速度还很快"的星上暴露
—— 看起来就像"流星太快了"。已用逐帧抓取描边线段的方式量化：修复前最长线段
1516.7px，修复后 6.7px。修复方式是新增 `trail.shift(dx,dy)`（整体平移轨迹），
回绕位移用 `目标坐标 − 当前坐标` 而不是固定值。

### 2. 黑洞变小必须按"像素尺度不变"重锚参数

`influence`/`gm`/`flowInner`/`flowRange` 都以 R 为单位或与 R 挂钩，只改
`radiusMin/Max` 会让引力场在像素尺度上一起缩水。本次锚定表（已写进 DEVELOPMENT 4.7）：

| 量 | 锚定条件 | 原 → 现 |
| --- | --- | --- |
| 作用半径 | `influence×R` ≈ 156px | 6.5×24 → 7.8×20 |
| 远场加速度 | `gm×R²` = 1.5e6 | 2600×576 → 3750×400 |
| 耦合带 | `flowInner/Range×R` = 36/120px | 1.5、5.0 → 1.8、6.0 |

仿真验证：同一撞击参数下 落 16.7s/0.17圈 ↔ 落 16.7s/0.18圈，轨迹一致。
半径 18~30 → 15~25，新增 `edgeSoft: 0.3`（径向渐变内半径 = `(1-edgeSoft)R`，
**颜色始终是黑、只渐变异 alpha**，所以是"越来越淡的黑"而不是灰）。

### 3. 流星重做

速度 700~1350 → 240~500 px/s；角度 28~50° → 18~64° 随机；**寿命由几何算出**
（`min(tx,ty)` 飞到边界为止）；入射边与角度绑定（陡的从上边、缓的从侧边）。
两个踩过的坑：① 上边生成的 x 取 `[-0.1w, 1.1w]` 会让起点落在出口侧之外 →
寿命算成负数/极小值；② 上边生成的横向起点还要按"飞到屏幕下方所需时间能横移多远"
再收一档，否则贴着出口边缘生成的流星一露头就溜走。

### 4. 静态校验补强（本次最大收获）

`npm run check` = `scripts/check-syntax.mjs`（全量 node --check）+ `scripts/audit-config.mjs`。
后者防的是**静默失效**：`meteors.js` 写 `C.speedMax` 而配置里是 `speedSpan` →
不报错、速度全 NaN，靠一次性仿真脚本才抓到。
**审计必须按段落比对键名**：整份文件搜会让 blackhole 段落的 `speedMax`
误判为 meteors 的命中（第一版审计就是这么漏的）。脚本还反查"定义了但没用"的冗余键。

### 结论/偏好

- 用户对"突兀"极其敏感：闪现线条、边缘硬切、寿命算错导致的角落一闪，都会直接点名。
- 用户要的"渐变透明边框"= alpha 渐变，不是颜色渐变；视觉上球明显变小（实心盘约 0.7R）。
- 用户认为流星"太快"的标准是**能否看清角度**：横穿画面需数秒，而非真实流星的零点几秒。
- 临时仿真/验证脚本很有价值（本次抓出 2 个真 bug），但不留在仓库，方法写进文档 7.2。
