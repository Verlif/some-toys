# 星辰答案之书 · 项目长期约定

## 技术约定

- **模块方案：经典 `<script>` + `window.AnswerBook` 命名空间，不用 ES Modules。**
  原因：ESM 在 `file://` 下被 CORS 拦截，会破坏"双击 index.html 直接看"。
  代价是 `index.html` 里的加载顺序成为硬约束，多数模块在 IIFE 执行期就读
  `NS.config` / `NS.viewport`，加新模块必须插到依赖项之后。
- 每个文件一个 IIFE + `'use strict'`，ES5 语法为主（`Promise` 是唯一例外）。
- **不在业务代码里写裸数字**，一律进 `src/config.js` 并附单位说明。
- 坐标 / 半径 / 速度统一用**秒**与 **CSS 像素**（不用毫秒）。
- 更新与绘制分离（`update(dt)` / `draw()`），绘制函数无副作用。
- 布局宽度一律用 CSS 变量（如 `--text-fade` 由 JS 注入），避免 JS/CSS 两处写死。

## 关键机制

- **文案双份**：`data/texts.txt` 是唯一数据源（一行一段，`#` 为注释），
  `src/data/texts.fallback.js` 由 `scripts/build-texts.mjs` 自动派生，
  供 `file://` 下 fetch 被拦截时兜底。**改完 txt 必须跑 `npm run build:texts`**，
  fallback 文件是生成物，不要手改。
- **星点是纯速度积分模型**（v2.3.0 起）。每颗星持有 `(vx,vy)` 当前速度与
  `(bvx,bvy)` 基线漂移，位置完全由速度积分得到——**不要再退回
  "原位 + 位移偏移 + 弹簧回弹"的写法**，那种模型位置被绑住、根本没有惯性，
  引力只能靠硬边界吸附表现，观感会变成"碰到就转圈"。
  速度只在脱离引力井后回归基线，标志位 `s.inGravity` 由 `blackhole.attract` 置位、
  `stars.update` 读完即清。
- **黑洞里的星没有"轨道状态"**（v2.4.0 起）。不要再引入 `orbit` / `enterOrbit` /
  `captureRadius` 那套参数化轨道——它必然表现为"碰到边界就被塞进固定轨道"。
  星点全程只是一个被两项力积分的质点（见下），吞没判定就是 `r < R`。
- **尾流是通用模块**（`src/scene/trail.js`，v2.4.0 起）。尾流＝运动本身的痕迹：
  按固定时间间隔采样位置点连成折线，长度 = 速度 × `trailSpan`，亮度随速度渐显。
  **不要再用"进入某状态才开始画尾流"的写法**（那会突兀），也不要把尾流绑在
  黑洞模块里——它必须能被星辰与流星共用。
  **瞬移分两种，别用错**：吞没后重生 / 重建星场用 `trail.reset()`；
  出界**回绕**必须用 `trail.shift(dx,dy)` 把轨迹一起平移，否则会画出一条
  横贯整个画面的亮线（v2.5.0 修的就是这个，用户会把它当成"流星太快了"）。
- **黑洞力学只有两项力**（v2.4.0 起，见 DEVELOPMENT.md 4.1~4.3）：
  径向软化平方反比引力（无矩 → 角动量守恒）+ 吸积流速度耦合（耗散 → 圆化/内落）。
  **两条禁令**：①不要加切向力（持续做功会让星点全部逃逸）；
  ②不要指望削弱引力让星点自然绕行（角动量差一到两个数量级，物理上做不到）。
- **改黑洞半径必须按"像素尺度不变"重锚参数**（v2.5.0 起，锚定表见 DEVELOPMENT 4.7）。
  `influence` / `gm` / `flowInner` / `flowRange` 都以 R 为单位或与 R 挂钩，
  只改 `radiusMin/Max` 会让引力场在像素尺度上一起缩水，观感全变。
- **黑洞造型必须保持极简**（详见下）。当前是"中心纯黑、边缘渐变到透明"的小球
  （`edgeSoft`，alpha 渐变而非颜色渐变），实心盘只有约 `0.7R`。

## 审美偏好（重要）

用户**反复要求削减装饰**，两轮反馈依次是"边缘光效要简洁，不要光环"→
"黑洞不要样式了，就是一个黑色小球"。教训：遇到"简化"类需求时一次做到位，
不要层层递减。

当前取向：**留白、干净剪影、视觉重心集中于主体**，反对成圈的装饰性光效
（外发光 / 光环 / 吸积盘之类）。若要新增视觉元素，先确认是否属于此类。

黑洞的表现力全部来自它对星点的力学作用（吸引 → 加速 → 环绕 → 尾流 → 吞没），
本体几乎没有装饰。

## 工作方式

- **不写测试**，只做静态验证，入口是 `npm run check`：
  ① `scripts/check-syntax.mjs` 全量 `node --check`；
  ② `scripts/audit-config.mjs` 配置键引用审计。
- **配置键审计必须按段落比对**（`blackhole`/`stars`/`meteors`/`text` 各自一段），
  不能整份文件搜键名——跨段同名键（如两个段落都有 `speedMax`）会造成误报命中。
  这类错误是**静默**的：`C.xxx` 拼错只会得到 `undefined`，画面照样能跑。
- **改生成几何时值得跑一次性仿真脚本**（不留在仓库，方法见 DEVELOPMENT 7.2）：
  本次用它抓出"回绕亮线"和"流星寿命算成负数"两个真 bug。
- 用户不要浏览器运行时验证，改完直接交付预览。
- 交付时用 `present_files` 打开 `index.html` 预览。
