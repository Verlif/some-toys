## 修复：editor.js:549 运行时 TypeError（getElementById 返回 null）
- 根因：重构时把所有 `$()` 调用写成 `$('#id')` 带前导 `#`，但 `utils.js` 的 `$` 是 `document.getElementById(id)`，`getElementById('#edUndo')` 会把 `#` 当 id 一部分 → 全部返回 null。edSvg 等仅赋值未立即调用方法所以此前没报错，到 `$('#edUndo').addEventListener` 才炸。
- 原单文件用 `$('id')` 不带 `#`，是重构引入的问题。
- 修法：`$` 改为兼容前导 `#`（带则 slice(1)）。所有 js 调用统一带 `#` 均可正常工作。
- 之前两个静态校验均被 `#` 欺骗（ID 校验正则自剥 `#`；mock 对任意 id 返回伪元素），故未暴露；后用 jsdom 加载真实 index.html 复现并验证修复。

## 编辑器交互优化（用户反馈三处）
1. 切到「连线」模式时自动关闭地点编辑浮窗：在 `setMode` 中调用 `closePlaceEditor()`，并清理残留的单击/双击延时状态（`edTapTimer`/`edTapInfo`），避免从 place 模式遗留的单击延迟在 road 模式误触发连接。
2. 连接地点卡顿（点两个地点后约 0.5s 才出路径）：根因是 `edPointerUp` 对地点点击统一先等 `DOUBLE_TAP_MS` 再执行 `handlePlaceTap`（连接逻辑就在其中）。改为模式感知——road/delete 模式立即 `handlePlaceTap`，仅 place 模式保留双击编辑。
3. 长按偶发不触发：根因 `MOVE_THRESHOLD=10px` 太小，触屏按住 480ms 抖动超 10px 即被置 `moved`，长按判定 `!moved` 失败变平移。将阈值提到 16px，并在 `edPointerMove` 确认拖动时清除长按定时器（平移与长按互斥）。
- 验证：node --check 全部通过；jsdom 加载真实 index.html 跑 init 无异常。

## 修复：导出 PNG 路径颜色错误
- 根因：`export-image.js` 的 `EXPORT_STYLE` 是手写硬编码颜色，与页面实际 CSS 不一致——编辑器道路落到默认黑色（变黑），游戏已走路线被写成紫色 #7a68ff（页面进行中实为绿色，绿变紫）。
- 修法：废弃硬编码 `EXPORT_STYLE`，改为「计算样式内联」：新增 `buildInlineSvg()` + `inlineComputedStyles()`——把克隆的 SVG 临时挂到离屏文档（position:fixed;left:-99999px），用 `getComputedStyle` 读取每个图形元素在页面上的真实颜色/描边并写回 inline style，再序列化栅格化。这样导出永远与页面显示一致，且以后改 CSS 不会再错位。
- 仅对图形叶子标签（path/circle/rect/text 等）内联，跳过 <g> 容器，避免无 fill 子元素继承到黑色。
- `edExportImage`/`gmExportImage` 改为调用 `App.ExportImage.buildInlineSvg({width,height,viewBox,bg,layers,removeGrid})`，导出对象移除 EXPORT_STYLE。游戏导出 removeGrid:true 去掉网格底图。
- 验证：node --check 全过；grep 确认无 EXPORT_STYLE 残留；jsdom 加载真实 index.html 跑 init 无异常。真实颜色需浏览器刷新实测（jsdom 无法渲染 CSS/canvas）。

## 二次修复：导出 PNG 仍黑线 / 绿变紫（真因）
- 第一次"计算样式内联"方案仍失败，根因有二：
  1) 把克隆挂到 `position:fixed;left:-99999px;width:0;height:0` 的离屏容器再读 getComputedStyle，0×0 容器内 SVG 计算样式不可靠（回退默认黑）。
  2) inlineComputedStyles 跳过了 `fill:none`/`stroke:none` 等 "none" 值；而 `.road-outer/.road-inner` 在 base.css 明确 `fill:none`，不内联该值时道路回退到 SVG 默认黑色填充 → 黑线。
  3) 绿变紫：游戏进行中路线本就是紫色 #7a68ff（base.css:85），仅闭环完成态为绿色 #34b55c（base.css:186）；之前 EXPORT_STYLE 写死进行中紫色。
- 修复：① inlineComputedStyles 改为读【页面真实可见源元素】的 getComputedStyle，写入克隆（不再读离屏克隆）；② 对 fill/stroke 不再跳过 "none"（必须内联 fill:none 覆盖默认黑）；③ edExportImage/gmExportImage 补传 `srcLayers:[edRoads,edPlaces]` / `[gmWorld]`（此前漏传，内联根本没执行）；④ STYLE_PROPS 增加 filter 并内联 drop-shadow 发光（跳过 url() 跨文档引用）。
- 验证：node --check 全过；jsdom 注入真实 CSS 验证——编辑器道路 fill 透明+stroke 浅灰/白（非黑）、游戏完成态 computed stroke=rgb(52,181,92) 绿色且导出内联为绿、地点 place-bg 白（非黑）；端到端点击"加载示例"(10路7点)后真实 editorRoads/editorPlaces 作为 srcLayers 导出，road-outer/place-bg 全部非黑。
- 局限：Playwright 因网络 502 装不上，无法真实浏览器像素级对比；jsdom 不解析 CSS 变量，地点 halo 在 jsdom 中显示 fill:var(--c) 字面量，真实浏览器 getComputedStyle 会解析为具体颜色（非黑）。建议浏览器刷新实测。
