# 2026-10-14

## 缩放卡顿排查与优化（地点距离绘制）

### 背景
- 导入地图 `柳玛海岸城｜分区路网布局`：84 个地点 / 84 条路线，`#world` 内约 900 个 SVG 节点（含 168 个 `<text>`，84 个中文名带 `paint-order: stroke` 描边）。
- 缩放路径：wheel → rAF → `renderer.zoom()` → `applyView()`。

### 定位到的三个开销点
1. `world.style.transform` 每帧改 scale：SVG 内容（尤其带描边的文字/emoji）在新的小数缩放比例下需重新栅格化，字形缓存每帧失效 → 主要卡顿源。
2. `#grid-bg` 是 100% 视口大小的 pattern 矩形；旧的 `beginZoom` 用 `pattern` 元素上的 `visibility:hidden` 隐藏，对引用它的矩形不可靠，缩放时整屏 pattern 仍在重绘。
3. 每帧 `svg.getBoundingClientRect()`（在写完 `world.style.transform` 与 `#zoomLabel.textContent` 之后）→ 强制同步回流；`#zoomLabel` 每帧写文本也持续使样式失效。

### 改动
- `js/renderer.js`
  - 新增 `measure(refresh)` 缓存画布 rect，`zoom/centerMap/screenToWorld/resetView` 全部走缓存，`resetView` 强制刷新 → 去掉每帧强制回流（顺带优化拖动平移）。
  - `beginZoom/endZoom` 改为对 `#gridBg` 用 `display:none` 真正移除整屏 pattern 重绘，并加 `zooming` 类（带重入保护）。
  - `applyView` 仅在百分比变化时写 `#zoomLabel`。
  - 新增 `zoomCenter(state, factor)`，导出替换原按钮里的手写 rect 计算。
- `css/map.css`：`#map.zooming` 下把 `.place .name`、`.edge .distance-bg`、`.edge .distance-label` 设 `opacity:0` —— 缩放手势期间只绘制圆/线几何，停止后约 160ms 恢复（LOD 策略）。
- `index.html`：grid 矩形加 `id="grid-bg"`。

### 备选手段（本次未采用，若仍卡再试）
- 去掉 `#world` 的 `will-change: transform`（若 Chrome 为其分配了按内容包围盒 × 缩放比的超大图层栅格，会非常卡）。
- 缩放比例量化到阶梯值，减少字形缓存失效次数。
- renderer 全量 `innerHTML` 重建（`render()`）改为增量更新（当前只在增删/连线时触发，与缩放无关）。
