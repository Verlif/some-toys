## 总体架构

整站没有框架、没有构建步骤，只有三个东西：

```text
扫描(pages/, templates/)  →  字符串替换生成 index.html  →  浏览器端 JS 负责交互
```

| 阶段 | 执行者 | 产物 |
| :--- | :--- | :--- |
| 扫描 + 渲染 | `generate-index.js`（Node，零依赖） | `index.html` |
| 布局 + 视觉 | `assets/nav.css` | — |
| 交互（搜索 / 折叠 / 抽屉 / 主题 / 国际化） | `templates/nav-template.html` 内联脚本 | 随 `index.html` 一起下发 |
| 文案字典 + 运行时 | `assets/i18n.js` | — |
| 二维码编码 | `assets/qrcode.js` | — |
| 项目说明（README） | `generate-index.js` 内置的 markdown 渲染 | 随 `index.html` 一起下发 |
| 对外介绍页 | `pages/介绍.html`（独立静态页） | — |
| 持续构建 | `.github/workflows/generate-nav.yml` | 推送回仓库的 `index.html` |

数据流：

```text
pages/**            generate-index.js         index.html
  │  <title>            │  scan()                 │  静态 HTML + 数据属性
  │  <meta desc/date>   │  renderTree()           │
  │  index.html?  ───►  │  replace {{placeholders}}
templates/             │
nav-template.html   ───►
```

> `index.html` 是生成物，**不要手改**，改模板或脚本后重跑生成器。

**设计前提**：只收录纯静态作品。生成器不解析构建产物、不执行任何页面脚本，只做「读文件 + 抽元数据 + 拼 HTML」，因此任何能用浏览器直接打开的东西都能原样收录，不受技术栈与来源限制。

## 收录模型：三种目录形态

`pages/` 下的每一个条目靠一条规则分流：**文件夹里有没有 `index.html`**。

| 形态 | 判定 | 构建函数 | 卡片表现 |
| :--- | :--- | :--- | :--- |
| 单文件页面 | 任意 `.html` 文件 | `buildPage()` | 标题取 `<title>`（无则用文件名），体积 = 单文件大小 |
| 项目文件夹 | 目录内含 `index.html` | `buildProject()` | 右上角带「项目」角标，体积 = 整个目录，页数 = 目录内 HTML 数 |
| 分组文件夹 | 目录内无 `index.html` | `scan()` 递归 | 可折叠分组，子条目递归收录，层数不限 |

要点：

- 项目文件夹**不会**再被展开成分组，它就是一张卡片；分组**不会**变成卡片。
- 项目文件夹里的 `README.md` 会被渲染进弹窗的「项目说明」；没有 README 时只显示 `meta description`（兜底为正文摘要）。
- 完全没有任何 HTML 的目录会被跳过并打印 `跳过空文件夹`。
- `pages/index.html` 被视为模板文件，不参与扫描。
- 来源不参与判定：手写、AI 生成、脚手架打包产物走的是同一条路径，只是目录形态不同。

## 生成脚本 generate-index.js

零第三方依赖，用 Node 内置 `fs / path / child_process`。

### 扫描规则

递归扫描 `pages/`，同层先文件后文件夹，均按 `localeCompare('zh-Hans-CN')` 排序：

```
scan(dir)
  ├─ 每个 *.html 文件  → buildPage()   （单文件页面）
  └─ 每个子目录
       ├─ 含 index.html → buildProject()（整目录算一个项目）
       └─ 否则          → scan() 递归  （分组）
```

分组按遍历顺序分配稳定锚点 `nav-1 / nav-2 / …`，同时生成侧栏索引。

### 元数据读取

| 函数 | 作用 |
| :--- | :--- |
| `readTitle(content, fallback)` | 读 `<title>`，读不到用文件名 / 文件夹名 |
| `readMeta(content, names)` | 按 `name` 或 `property` 取 `content`，兼容属性顺序颠倒的写法 |
| `extractDescription(content)` | 兜底：剥掉 `script / style / head / header / nav / footer / svg / canvas` 等标签后取正文首段，优先截到第一个句末标点，最长 58 字 |
| `lastCommitDate(path)` | `git log -1 --format=%ad --date=format:%Y-%m-%d -- <path>`，失败退回文件 mtime，再退回今天 |
| `totalSize(dir)` / `countPages(dir)` | 递归统计目录体积与 HTML 数量 |
| `decodeEntities(str)` | 先把源码里的常见实体还原成字符，避免渲染时二次转义出 `&amp;amp;` |

### 站点信息

站点名称、简介、GitHub 地址等个人信息不再是脚本里的硬编码常量，而是从仓库根目录的 `site.config.json` 读取：

```text
readConfig('site.config.json') ─┐
                                ├─► buildSite(config) ─► site
parseGithub(config.github) ─────┘
```

- `readConfig(file)`：文件缺失、顶层不是对象或 JSON 解析失败时返回 `{}` 并打印警告，全部字段退回默认值。
- `parseGithub(input)`：从地址里取出 `owner` / `repo`，兼容 `https://github.com/o/r`、`github.com/o`、`o/r`、`o`，以及带 `.git`、查询串、结尾斜杠的写法。
- `buildSite(config)`：按「配置文件 → 地址解析结果 → `DEFAULT_SITE` 默认值」的优先级合并。
- 派生字段：`githubUrl`（主页）、`repoUrl`（仓库）、`avatarUrl`（默认 `avatars.githubusercontent.com/<owner>`，可用 `avatar` 覆盖）、`docsBase`（`<repoUrl>/blob/<branch>/<docsDir>/`，拿不到 owner 或 repo 时为空字符串）。

### 渲染产物

每个卡片带这些属性，供浏览器端脚本使用：

```html
<div class="card has-more" data-name="小写拼接头（参与搜索）" data-kind="page|project">
  <a class="card-link" href="…">…</a>
  <span class="card-tag" data-i18n="nav.projectTag">项目</span>
  <button class="card-more" data-i18n-title="nav.viewMore">…</button>
</div>
```

- `data-name` = `标题 + 描述 + 原始名 + tags` 拼接后转小写 —— 搜索就是在这个字符串上做 `indexOf`。
- `data-kind` 区分「单文件页面」与「项目文件夹」，决定是否渲染角标。
- 「共 N 页」等带数字的文案用 `data-i18n-vars='{"n":1}'` 传参，交给前端字典插值。

### 模板占位符

| 占位符 | 含义 |
| :--- | :--- |
| `{{siteTitle}}` `{{ownerText}}` `{{bio}}` | 站点名称 / 作者名 / 简介，取自 `site.config.json` |
| `{{githubUrl}}` `{{avatarUrl}}` | GitHub 主页与头像地址（由配置里的 `github` 解析派生） |
| `{{siteConfig}}` | 注入给浏览器的 `window.SITE` 脚本，供 i18n 填充 `{siteTitle}` 等占位符 |
| `{{sideNav}}` `{{railNav}}` | 侧栏 / 横向分组索引 |
| `{{content}}` | 渲染好的卡片与分组树 |
| `{{statProjects}}` `{{statPages}}` `{{statGroups}}` | 项目 / 页面 / 分组数量 |
| `{{generatedAt}}` | 生成时间（UTC） |
| `{{introUrl}}` | `pages/介绍.html` 的编码后地址（扫描得到，找不到按约定路径兜底） |
| `{{docDevUrl}}` `{{docUserUrl}}` | `docs/` 下两份文档的 GitHub 阅读地址 |

替换完成后，脚本会检查残留占位符并打印警告。

`window.SITE` 的形状（导航页注入，介绍页没有注入）：

```js
window.SITE = {
  siteTitle, owner, repo, branch, docsDir, bio,
  githubUrl, repoUrl, avatarUrl
}
```

## 导航页模板 templates/nav-template.html

### DOM 结构

```text
.app-shell
├─ aside.sidenav#sidenav        侧栏（宽屏常驻 / ≤1199px 抽屉）
│  ├─ .brand                   头像 + 作者 + 简介
│  ├─ nav.side-links           分组索引（含深度缩进）
│  └─ .sidenav-foot            统计、文档链接、GitHub、生成时间
├─ .scrim#scrim                抽屉遮罩
└─ .content
   ├─ header.topbar#topbar     菜单键 + 搜索 + 折叠/置顶/语言/主题
   ├─ nav.rail#rail            窄屏横向分组条
   ├─ main#content
   │  ├─ .page-head            标题 + 副标题 + 三个统计块
   │  └─ {{content}}           分组 / 卡片树
   ├─ .no-result#noResult
   └─ footer.site-foot
```

### 前端脚本模块（IIFE，无框架）

| 模块 | 要点 |
| :--- | :--- |
| 主题 | 读 localStorage `theme`，否则跟随 `prefers-color-scheme`；首屏内联脚本提前落 `data-theme` 防闪烁 |
| 分组折叠 | **不用纯 CSS 的 `max-height + overflow:hidden`**，改用 JS 测量高度做过渡，动画结束后清空内联样式回到 `overflow: visible` —— 这样卡片悬浮阴影不会被祖先容器裁剪 |
| 搜索 | 80ms 防抖；命中处用 TreeWalker 遍历文本节点包 `<mark>`，不清空 DOM 结构；`data-name` 做匹配 |
| 相对时间 | `relTime()` 把 `YYYY-MM-DD` 转成「今天 / 昨天 / N 天前 / N 个月前 / N 年前」 |
| 抽屉 | ≤1199px 时侧栏变 `position: fixed` 抽屉，遮罩点击 / Esc / 窗口变宽自动关闭 |
| 滚动联动 | IntersectionObserver 选最靠上的可见分组，高亮对应索引项；点击索引会先清空搜索并逐层展开祖先分组 |
| 详情弹窗 | 从卡片 DOM 里取标题/描述/图标/统计，支持复制链接（回落 `window.prompt`）；README 在生成期已渲染好、存在卡片的 `<template class="card-readme">` 里，打开时搬进 `.md-body`；底部按 `modalOpen.href`（自动解析为绝对地址）用 `assets/qrcode.js` 画二维码，本地地址额外提示「仅同一网络可访问」 |
| 国际化 | 启动时 `I18N.apply(document)`，语言变化时重算相对时间、按钮 title、计数文案，并重绘打开的弹窗 |

快捷键：`/` 或 `Ctrl/Cmd+K` 聚焦搜索，`Esc` 逐层退出，`D` 切主题，`L` 切语言。

## 项目说明（README）与弹窗详情

### 约定

- 每个项目文件夹放一份 `README.md`（大小写不敏感），这是项目说明的唯一来源。
- 生成时读取并渲染成 HTML，塞进卡片的 `<template class="card-readme">`；弹窗打开时搬进 `.md-body` 显示，模板本身不参与渲染，也没有重复 id 的问题。
- 没有 `README.md` 的项目退回原逻辑：只显示 `<meta name="description">` 或从 HTML 正文抓的摘要。

### 支持的 markdown 子集

| 语法 | 输出 |
| :--- | :--- |
| `#` ~ `####` | `<h4>` ~ `<h6>`，配 `md-h1` ~ `md-h4` 类 |
| 段落 / 软换行 | `<p>`；中英文之间自动补空格，中文之间不补 |
| 有序 / 无序列表 | `<ul>` / `<ol>`，支持缩进嵌套与续行 |
| 表格（GFM） | `.md-table > table`，窄屏横向滚动 |
| 围栏代码块 | `<pre class="md-pre" data-lang="…">` |
| 引用 / 分割线 | `<blockquote>` / `<hr>` |
| 行内 | 代码、粗体、斜体、删除线、链接、图片 |

README 里手写的 HTML 标签会被转义成文本（不做白名单放行），避免往页面里注入结构。

### 链接与图片改写

- `http(s)` / `mailto` 原样保留，外链自动带 `target="_blank" rel="noopener"`。
- 站内相对路径按「项目目录 + 扩展名」解析：
  - `.md` 与其他文件 → `https://github.com/<owner>/<repo>/blob/<branch>/<项目目录>/<路径>`；
  - 图片 → `https://raw.githubusercontent.com/<owner>/<repo>/<branch>/<路径>`；
  - 仓库信息缺失时退回「相对当前页面」的路径。
- `#锚点` 会做 slug 化，与标题 id 对应；重复标题自动加序号。
- 占位符替换统一用函数形式（`template.replace(re, () => value)`），README 里的 `$&`、`$'` 不会被当成替换模式。

### 描述兜底与搜索

`buildProject()` 的描述取值顺序是 `meta[name="description"]` → HTML 正文摘要 → **README 首段**。README 首段同时进入 `data-name` 搜索索引，所以搜 README 里出现的关键词也能命中。

### 体积

README 是**构建期内嵌**的：11 份 README 让 `index.html` 从约 48KB 变成约 145KB（gzip 后增量很小），换来离线可用、file:// 可预览、弹窗零请求。

## 样式 assets/nav.css

### 主题变量

所有颜色走 CSS 变量，`:root` 为暗色，`[data-theme="light"]` 为亮色。常用项：

| 变量 | 用途 |
| :--- | :--- |
| `--bg` / `--bg-gradient` | 页面底色与背景光斑 |
| `--panel` / `--panel-solid` | 顶栏、侧栏、弹窗面板 |
| `--card-bg` / `--card-bg-hover` / `--card-border` | 卡片三态 |
| `--accent` / `--accent-glow` / `--accent-faint` / `--accent-line` | 强调色及三档透明度 |
| `--shadow-color` / `--shadow-close` / `--shadow` | 阴影（悬浮时三层叠加） |
| `--card-min` / `--grid-gap` | 卡片最小列宽与栅格间距（由断点改写） |
| `--side-width` | 侧栏宽度 |

### 响应式断点

| 断点 | 布局 |
| :--- | :--- |
| ≥1600px | 列宽提到 288px、间距 22px（超宽屏多列） |
| ≥1200px | 侧栏常驻 + 内容区，卡片 `auto-fill minmax(272px, 1fr)` |
| ≤1199px | 侧栏改为抽屉，出现 ☰ 按钮与横向分组条 |
| ≤1023px | 卡片列宽 240px（平板竖屏约两列），页头纵向堆叠 |
| ≤767px | 单列卡片、搜索框换行占满、弹窗变底部抽屉式、操作按钮常驻 |
| ≤420px | 统计块等分、隐藏语言按钮文字只留图标 |
| `hover: none` | 触屏设备取消位移效果、常驻显示 `…` 按钮 |

另外适配了 `env(safe-area-inset-*)`、`prefers-reduced-motion` 与 `@media (prefers-color-scheme)` 的 `theme-color`。

### 滚动条

根元素（`html` / `body`）用 `scrollbar-width: none` 与 `::-webkit-scrollbar { display: none }` 隐藏了页面滚动条：折叠 / 展开分组会改变页面高度，隐藏滚动条后它不再反复出现 / 消失，内容宽度保持稳定，不会出现横向位移。滚动能力不受影响；`.side-links`、`.modal-desc` 这类页面内滚动容器仍保留细滚动条。

### 阴影不被裁剪的实现

悬浮卡片需要外扩阴影，因此：

1. `.group-body` 默认 `overflow: visible`、`max-height: none`；
2. 折叠动画由 JS 临时写入 `overflow: hidden` + `max-height`，动画结束立刻清空内联样式；
3. 卡片 `:hover` / `:focus-within` 时 `z-index: 2`，保证阴影盖在相邻卡片之上；
4. `.cards-grid` 用 `padding + 负 margin` 预留 4~8px 呼吸位，避免边缘卡片的阴影贴边。

## 国际化 assets/i18n.js

导航页与介绍页共用这一个文件，没有额外依赖。

### 用法

给节点加任一 supported 属性，脚本会自动替换：

```html
<span data-i18n="nav.home">首页</span>
<span data-i18n="nav.pages" data-i18n-vars='{"n":3}'>共 3 页</span>
<button data-i18n-title="nav.search" data-i18n-aria-label="nav.search" title="搜索项目">
<meta name="description" data-i18n-content="nav.metaDesc" content="…">
```

| 属性 | 写入位置 |
| :--- | :--- |
| `data-i18n` | `textContent` |
| `data-i18n-html` | `innerHTML` |
| `data-i18n-title` | `title` |
| `data-i18n-content` | `content`（给 `<meta>` 用） |
| `data-i18n-placeholder` | `placeholder` |
| `data-i18n-aria-label` | `aria-label` |

字典里用 `{n}` 占位，通过 `data-i18n-vars` 传值。

### 站点变量

字典里还可以用站点变量：`{siteTitle}` `{owner}` `{repo}` `{branch}` `{docsDir}` `{bio}`。运行时优先取 `window.SITE`（生成脚本从 `site.config.json` 注入到 `index.html`），取不到时用 `assets/i18n.js` 里的 `SITE_DEFAULTS`，因此介绍页这类没有注入的静态页面也能正常渲染。`data-i18n-vars`（或 `I18N.t(key, vars)`）传入的同名变量会覆盖站点变量。

### 运行时 API

```js
I18N.lang            // 'zh' | 'en'
I18N.t(key, vars)    // 取文案并插值
I18N.apply(root)     // 翻译某个子树
I18N.set(lang)       // 指定语言（会写 localStorage 并广播）
I18N.toggle()        // 中英互换
I18N.onChange(fn)    // 注册语言变化回调
I18N.nextLabel       // 按钮上显示的「另一种语言」标签
I18N.site            // 站点变量快照：{siteTitle} {owner} {repo} {branch} {docsDir} {bio}
```

语言优先级：`?lang=xx` > localStorage `lang` > `navigator.language` > `zh`。

### 加一条新文案

1. 在 `assets/i18n.js` 的 `DICT.zh` 与 `DICT.en` 里各加同一个 key；
2. 在 HTML 上写 `data-i18n="key"`，默认文本内容写中文（便于抓取与兜底）；
3. 如果该文案是 JS 动态生成的，用 `I18N.t('key')`，并在 `I18N.onChange` 回调里重算。

> key 尽量用 `模块.语义` 命名：`nav.*` 导航页、`intro.*` 介绍页、`common.*` 通用、`time.*` 相对时间。

## 介绍页 pages/介绍.html

对外的图文介绍，也是 `pages/` 里的一个普通作品页面——它同样会被扫描成一张卡片，因此**必须保持自洽**：任何改动都不能破坏「能独立打开」这个前提。

与导航页的关系：

| 维度 | 导航页 `index.html` | 介绍页 `pages/介绍.html` |
| :--- | :--- | :--- |
| 来源 | 由模板 + 生成器产出 | 手写静态页 |
| 站点信息 | 读 `window.SITE`（来自 `site.config.json`） | 没有注入，走 `I18N.site` 的 `SITE_DEFAULTS` |
| 双语 | `assets/i18n.js` + `data-i18n` | 同上 |
| 主题 / 语言按钮 | 顶栏 | 顶栏（同样支持 `D` / `L` 快捷键） |

**链接解析**：页面里的 GitHub 与文档链接不写死仓库地址，改由脚本拼装：

```html
<a href="…" data-gh="repo">…</a>    <!-- → https://github.com/<owner>/<repo> -->
<a href="…" data-gh="owner">…</a>   <!-- → https://github.com/<owner> -->
<a href="…" data-doc="dev">…</a>    <!-- → <repoUrl>/blob/<branch>/<docsDir>/开发文档.md -->
<a href="…" data-doc="user">…</a>   <!-- → …/使用文档.md -->
```

`resolveLinks()` 从 `I18N.site` 取 `owner / repo / branch / docsDir` 后覆盖 `href`。HTML 里保留的 `href` 是**无 JS 时的兜底**（指向仓库内的相对路径），所以禁用脚本也不会出现死链。Fork 仓库后无需改介绍页就能指向自己的地址。

页面结构：粘性工具条 → Hero → 流程条 → 这是什么 → 支持哪些作品（三种形态 + 来源说明 + 静态限制）→ 核心特性 → 目录结构 → 快速开始 → 图标映射 → 工作流程 → 常见问题 → 页脚。

| 想改什么 | 改哪里 | 要不要重新生成 |
| :--- | :--- | :--- |
| 配色、间距、断点 | `assets/nav.css` | 不需要 |
| 二维码画布/纠错参数 | `assets/qrcode.js`、模板里的 `drawQr()` | 改模板需要 |
| 项目说明的内容 | 各项目目录下的 `README.md` | 需要 |
| markdown 渲染 / 链接改写 | `generate-index.js` 的 `renderMarkdown()` | 需要 |
| 弹窗 README 排版 | `assets/nav.css` 的 `.md-body` 系列 | 不需要 |
| 文案、新增语言 | `assets/i18n.js`（+ 各页面 `data-i18n`） | 不需要 |
| 导航页结构、交互脚本 | `templates/nav-template.html` | 需要 |
| 扫描规则、排序、卡片字段 | `generate-index.js` | 需要 |
| 站点信息（名称 / 简介 / GitHub 地址） | `site.config.json` | 需要 |
| 图标映射 | `generate-index.js` 里的 `iconMap` | 需要 |
| 介绍页内容 | `pages/介绍.html` | 需要（它自己也是一张卡片） |
| 触发时机 | `.github/workflows/generate-nav.yml` | — |

`site.config.json`：

```json
{
  "siteTitle": "someToys",
  "bio": "单页面与项目文件夹作品集",
  "github": "https://github.com/Verlif/someToys",
  "branch": "main",
  "docsDir": "docs"
}
```

- `github` 由 `parseGithub()` 解析出 `owner` / `repo`，也可用同名的顶层字段直接覆盖；
- `avatar` 可指定自定义头像，`branch` / `docsDir` 决定文档链接；
- 缺字段一律走 `generate-index.js` 里的 `DEFAULT_SITE`，所以配置文件可以只写想改的那几项。

新增占位符的流程：在模板里写 `{{xxx}}` → 在 `generate-index.js` 的替换链里加一行 `put(/\{\{xxx\}\}/g, value)`，并把 `xxx` 登记到 `KNOWN_PLACEHOLDERS`。生成器收尾时会检查这些已知占位符是否都替换成功并警告（不按 `{{...}}` 通配检查，因为 README 正文里可能合法地出现 `{{var}}` 这种示例文本）。

改 `iconMap` 时注意两点：键是**子串**（不是全等），`Object.keys().find()` 命中即停，所以更具体的词要写在更泛的词前面；介绍页里有一张图标对照表，加完记得同步。

## 约束与已知问题

1. **`index.html` 永远由脚本生成**，手改会在下次 CI 时被覆盖。
2. **Git 不跟踪空目录**，新分组里必须至少放一个 HTML（或用 `.gitkeep` 占位）。
3. **CI 是全新 checkout**，`git log` 取不到提交时间时会退回当天日期；需要固定日期就写 `<meta name="date">`。
4. **搜索只做小写包含匹配**，不分词、不支持正则；中文连写时命中依赖子串匹配。
5. **分组锚点 `nav-N` 由遍历顺序决定**：新增分组会让后面的编号整体位移，旧分享链接可能跳转偏移。
6. **卡片标题 / 描述不会翻译**：它们来自作品的 `<title>` 与 `description`，切换语言只影响界面文案。
7. **relTime 依赖客户端时间**：时区差异可能让「今天 / 昨天」差一天，`title` 属性里始终保留原始 ISO 日期。
8. 打开的卡片页均为新标签页（`target="_blank"`），嵌套第三方页面无法被导航页控制。
9. **站点信息只驱动导航页 `index.html`**：介绍页（`pages/介绍.html`）是独立的静态作品页面，不读 `site.config.json`；它共用的 `assets/i18n.js` 会退回内置的默认站点信息，链接则由 `data-gh` / `data-doc` 在运行时拼装。
10. **只收录纯静态作品**：需要服务端、数据库或运行时构建的项目无法运行 —— GitHub Pages 只做静态托管。打包产物请先导出成带相对路径的 `dist`。
11. **二维码最多 213 字节**（byte 模式 + 纠错等级 M + 版本 10）：超长 URL 会直接隐藏二维码，不会画出一张扫不出来的图。
12. **README 参与页面体积**：内嵌意味着 `index.html` 随 README 总量增长；README 建议控制在 200 行以内，长篇设计文档放 `docs/` 再由 README 链接过去。
