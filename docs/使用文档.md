## 它解决什么问题

手头零散的纯静态作品越攒越多：一个小游戏、一个数据看板、一份简历页、一个 AI 顺手生成的工具……它们形态不一，但都有一个共同点——**能用浏览器直接打开**。

someToys 就是把这些东西收进一个网站的架子：

```text
把作品放进 pages/  →  git push  →  Actions 自动重建导航页  →  GitHub Pages 上线
```

你不需要维护任何清单、列表或配置文件。

### 收录范围的唯一标准

**纯静态**，也就是说：

- 不需要服务端代码被执行（Node / PHP / Python 后端、SSR 都不行）；
- 不需要数据库；
- 不需要在访问时构建。

满足这条，其它一律不限。

## 哪些东西能放进来

| 形态 | 例子 | 怎么放 |
| :--- | :--- | :--- |
| 单文件页面 | 手写的小工具、AI 一次性生成的页面、从 CodePen 导出的 HTML | 一个 `.html` 直接丢进 `pages/` |
| 多文件项目 | `index.html` + `css/` + `js/` + `img/` 的完整项目 | 整个文件夹放进 `pages/`，入口叫 `index.html` |
| 打包产物 | Vite / webpack / Rollup 生成的 `dist`、静态站点生成器（VitePress、Docsify、VuePress）的输出 | 把产物目录整个放进 `pages/`，确保里面有 `index.html` |
| 演示与教学 | 课程 Demo、算法可视化、组件示例 | 同上，按单文件或文件夹放 |
| 文档与说明 | 手写的 Markdown 转出的 HTML、README 渲染页 | 同上 |

**来源完全不限**：手写的、AI 生成的、模板套的、脚手架打包的，只要打开就能跑，导航页一视同仁。

> 需要后端 / 数据库 / 运行时构建的项目不在射程内。等它们能导出成纯静态产物（比如 `npm run build` 出来的 `dist`）之后再放进来。

## 三分钟上线

### 1. 启用 GitHub Pages

在仓库里打开 **Settings → Pages**：

| 配置项 | 选择 |
| :--- | :--- |
| Source | `Deploy from a branch` |
| Branch | `main` |
| Folder | `/ (root)` |

保存后等待几分钟，访问 `https://<用户名>.github.io/<仓库名>/` 即可。

### 2. 给 Actions 开写权限

Action 需要把重新生成的 `index.html` 推回仓库：

打开 **Settings → Actions → General → Workflow permissions**，选择 **Read and write permissions**，保存。

工作流里已经声明了写权限，一般不用改：

```yaml
permissions:
  contents: write
```

### 3. 放文件、推送

```bash
git add pages/
git commit -m "add new page"
git push
```

刷新页面，新卡片就在那儿了。

> 如果 push 时报 `Permission denied` / `remote rejected`，检查分支保护规则是否挡住了 `github-actions[bot]`，详见 [常见问题](#常见问题)。

## 添加作品的三种方式

判断规则只有一条：**看文件夹里有没有 `index.html`**。

| 放法 | 判定 | 导航页里的呈现 |
| :--- | :--- | :--- |
| `pages/xxx.html` | **单文件页面** | 一张卡片，点击直接打开 |
| `pages/项目名/index.html` | **项目文件夹** | 一张卡片（右上角带「项目」角标），标题取 `index.html` 的 `<title>`（没有则用文件夹名） |
| `pages/分组名/`（无 `index.html`） | **分组文件夹** | 一个可折叠的分组，内部递归收录 |

### 方式一：单文件页面

```text
pages/
├─ 介绍.html              → 顶层卡片
└─ tools/
   └─ 随机抽奖.html        → tools 分组下的一张卡片
```

直接把 HTML 丢进去就行，文件名不限中英文，来源不限（手写、AI 生成、工具导出都算）。

### 方式二：项目文件夹（多文件项目推荐）

```text
pages/games/回声躲猫猫/
├─ index.html        ← 主页面，必须叫这个名字（小写）
├─ README.md         ← 项目说明，会显示在导航页的弹窗里
├─ css/style.css
├─ js/main.js
└─ img/hero.png
```

- **文件夹名就是项目名**：写在 `index.html` 里的 `<title>` 优先级更高。
- 页面里用相对路径引用 `css/`、`js/`、`img/` 即可，**不需要改路径**。
- 卡片上的「共 N 页」= 该文件夹内（含子目录）HTML 文件数；体积 = 整个文件夹的总大小。
- 只要存在 `index.html`，这个文件夹就只算「一个项目」，不会再被展开成分组。
- **建议放一份 `README.md`**：卡片右下角 `…` 打开的弹窗会把它渲染成「项目说明」正文（标题、列表、表格、代码块、链接、图片都支持），比 `meta description` 一行字详细得多。没有 README 时退回显示描述。

> 打包产物同理：把 `dist` 整个拷进来，只要里面有 `index.html`，它就是一张项目卡片。若构建配置把资源路径写成了绝对路径（`/assets/...`），记得改成相对路径（`./assets/...`），否则部署到子路径下会 404。

### 方式三：分组与嵌套

```text
pages/
├─ 介绍.html                      → 顶层卡片
├─ games/                        → 分组 games
│  ├─ 贪吃蛇.html                 → 分组内的单文件卡片
│  └─ 解谜/                       → 子分组（可无限嵌套）
│     └─ 数独/index.html          → 一张项目卡片
└─ tools/                        → 分组 tools
   └─ 抽奖.html
```

分组在导航页里可折叠，左侧索引按层级缩进显示；**完全不含 HTML 的文件夹会被跳过**，脚本会打印 `跳过空文件夹`。

## 让卡片更好看：元数据约定

在页面 `<head>` 里写这几行，导航页会自动读取：

```html
<head>
  <meta charset="UTF-8">
  <title>桌面宠物</title>
  <meta name="description" content="一只会在桌面上乱跑的像素猫，支持喂食和换装。">
  <meta name="date" content="2025-03-08">
  <meta name="tags" content="像素, 桌宠">
</head>
```

| 标签 | 用途 | 没写会怎样 |
| :--- | :--- | :--- |
| `<title>` | 卡片标题 | 单文件页面用文件名；项目文件夹用文件夹名 |
| `description` | 卡片描述（卡片显示 3 行，右下角 `…` 看全文） | 从正文开头截一句；截不出来就不显示 |
| `date` | 更新时间 | 取该文件最近一次 git 提交日期，再退回文件修改时间 |
| `tags` / `keywords` | 参与搜索匹配 | 只匹配标题、描述、文件名 |

`description` 也认 `og:description`，`date` 也认 `article:modified_time`。

> 小提示：卡片搜索是「标题 + 描述 + 文件名 + 标签」拼接后做包含匹配，所以关键词写进 `tags` 能显著提高命中率。

> 项目文件夹读的是 `index.html` 里的这些标签，子页面不需要重复写。

## 导航页怎么用

| 能力 | 怎么用 |
| :--- | :--- |
| 搜索 | 输入关键词实时过滤，命中文字会高亮；分组计数变成 `命中/总数`，无命中的分组自动隐藏 |
| 分组折叠 | 点分组标题折叠 / 展开；顶栏 <kbd>⤢</kbd> 按钮一键全折 / 全展；折叠状态记在浏览器里 |
| 分组索引 | 宽屏看左侧栏，窄屏看顶部横向条（也可点左上 <kbd>☰</kbd> 打开抽屉）；滚动时自动高亮当前分组 |
| 卡片详情 | 卡片右下角 `…` 弹出详情：一句简介 + 项目 `README.md` 正文（可滚动），可一键打开、复制链接，或扫右下角二维码在手机上打开 |
| 区分形态 | 右上角带「项目」角标的是项目文件夹，没有角标的是单文件页面 |
| 主题 | 顶栏 <kbd>◐</kbd> 按钮切换深色 / 浅色，默认跟随系统，选择会记住 |
| 语言 | 顶栏 <kbd>🌐 EN / 中文</kbd> 切换中英双语，选择会记住；也可用 `?lang=en` 直接指定 |
| 回到顶部 | 滚动一段距离后右下角出现浮动按钮 |

键盘快捷键：

| 按键 | 作用 |
| :--- | :--- |
| `/` 或 `Ctrl / Cmd + K` | 聚焦搜索框 |
| `Esc` | 关闭弹窗 / 抽屉 → 清空搜索 |
| `D` | 切换主题 |
| `L` | 切换语言 |

移动端：卡片操作按钮常驻显示，分组导航走抽屉，卡片单列排布；平板横屏两列，宽屏三列以上。

## 本地预览

仓库根目录就是站点根目录，请用静态服务器打开（**不要**直接双击 `index.html`，`file://` 下相对路径与剪贴板 API 会受限）：

```bash
node generate-index.js          # 扫描 pages/ ，重新生成 index.html
npx serve .                     # 或：python -m http.server 8000
```

改了 `templates/nav-template.html` 或 `generate-index.js` 之后，**需要重跑一次** `node generate-index.js`；只改 `assets/nav.css` 或 `assets/i18n.js` 不需要，刷新即可。

## 改站点信息（可选）

站点名称、简介、头像与 GitHub 链接都写在仓库根目录的 `site.config.json` 里，改完推送即可（Action 会自动重新生成导航页）：

```json
{
  "siteTitle": "someToys",
  "bio": "单页面与项目文件夹作品集",
  "github": "https://github.com/你的用户名/仓库名",
  "branch": "main",
  "docsDir": "docs"
}
```

| 字段 | 说明 | 不写时 |
| :--- | :--- | :--- |
| `siteTitle` | 站点名称（页头、页脚、浏览器标题） | 用项目默认名称 |
| `bio` | 一句话简介（侧栏作者名下方） | 用项目默认简介 |
| `github` | 你的 GitHub 地址，会被解析出用户名与仓库名，用来自动拼头像、主页与文档链接 | 用项目默认地址 |
| `avatar` | 自定义头像图片地址 | 用 GitHub 头像 |
| `branch` / `docsDir` | 文档链接指向的分支与目录 | `main` / `docs` |

> 通常只填 `github` 就够了，其它字段没写都会自动用默认值补齐；删掉整个文件也能正常生成。

## 常见问题

**Q：Action 报错 `ENOENT: no such file or directory, scandir 'pages'`**

`pages/` 没被 Git 跟踪。Git 不跟踪空文件夹，放至少一个 HTML 文件，或提交一个 `pages/.gitkeep` 占位文件。

**Q：Action 报错 `Permission denied` / `403`**

确认 **Settings → Actions → General → Workflow permissions** 是 `Read and write`，且工作流里写了 `permissions: contents: write`。

**Q：Action 报错 `remote rejected ... (failure)`**

`main` 分支的保护规则挡住了 bot 推送，去 **Settings → Branches** 放宽或删除规则。

**Q：访问 Pages 地址是 404**

确认 Source 为 `Deploy from a branch`、分支 `main`、目录 `/ (root)`；刚部署完等几分钟再刷新。

**Q：我的项目文件夹被当成组展开了**

主页面必须叫小写的 `index.html`，`Index.html`、`main.html` 都不算。本地跑一次 `node generate-index.js` 看输出的项目数对不对。

**Q：建了子文件夹但分组没出现**

文件夹（含子目录）里至少要有一个 `.html`，完全空的会被跳过。

**Q：导航页没更新**

检查 Action 是否跑成功、`index.html` 是否被提交。只想重新生成时，可以在 **Actions** 页面手动 `Run workflow`。

**Q：不是 AI 生成的页面能放吗**

能，来源完全不限。手写、模板导出、脚手架打包产物（Vite / webpack 的 `dist`）都行，只要是纯静态、浏览器能直接打开。

**Q：项目里有 css / js / img 等多个文件怎么放**

整个项目放进一个文件夹，主页面命名为 `index.html`，再把文件夹放进 `pages/` 的任意位置。页面内用相对路径引用资源，不需要改路径。

**Q：打包产物需要改配置吗**

产物里必须有 `index.html`，且资源引用要写成相对路径（例如 Vite 里设 `base: './'`），否则部署到 `<用户名>.github.io/<仓库名>/` 这种子路径下会找不到资源。

**Q：需要后端或数据库的项目能收吗**

不能。GitHub Pages 只做静态托管，服务端代码不会被执行。这类项目请另找托管，或导出成纯静态产物后再放进来。

**Q：更新时间看着不对**

优先读 `date` 元数据，其次取 git 提交日期。Actions 是全新 checkout，取不到提交时间时会退回当天日期；想固定显示就写 `<meta name="date" content="2025-03-08">`。

**Q：卡片是怎么打开的？**

新标签页打开（`target="_blank"`），方便同时对比多个作品，也不会离开导航页。
